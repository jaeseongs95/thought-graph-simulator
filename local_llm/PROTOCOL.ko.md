# v0.4.3 실행·평가 범위

새 `decision-v043`은 기존 `micro-v042` 원문 네 조건을 고정한 진단 계약이다. 일반 A/D/M 성공률에 합산하지 않는다. format-only와 단계형 파이프라인을 분리 보고한다.

원본 모델이 출력한 observed/primitives를 후속 호출의 입력으로 투영한다. 모델 정답을 host가 계산하여 입력으로 넣지 않으며 source 조건 성공 여부로 선별하지 않는다. 정답은 오직 별도 평가기에 있다. 기존 실패는 불변이고, 후속 파이프라인은 원본 전제와 최종값이 모두 맞아야 성공이다.

형식 제약만 변경하는 군은 messages/options/seed/model 바이트를 그대로 유지한다. 단계형 군은 prompt·output burden·호출 경계의 묶음 변경이므로 순수 필드 순서 효과를 증명하는 실험이 아니다. 반환 JSON 필드 순서는 별도 telemetry이며 내부 사고 시간 순서로 해석하지 않는다.

원본 스냅샷과 원문 무결성·전체 상태 재현은 검토한 v042 지문에 한정한다. 첨부 source_snapshot 코드를 동적 실행하지 않는다. 사용자 core는 확인된 기준본만 기본 허용한다. 더 강한 모델, 다른 엔진, 다른 양자화로의 성능 비교는 이번 실행 범위 밖이다.

# v0.4.1 추가 계약

기존 v0.4 실험·프롬프트·검증 계약은 아래 원문대로 유지한다. 이번 변화는 진단/거짓 양성 수정과 별도 `causal-v041` 12회 계획이다.

1. 전체 schema 과제는 모든 노드의 view.kind가 universal_schema이고 내용도 유효해야 한다. core.metrics.A는 최종 노드만 뜻하므로 이것만으로 all_schema를 판정하지 않는다.
2. 선택된 지지 부분의 유효성은 전체 제출물 유효성과 별개다. 무관한 잘못된 노드를 삭제해서 모델 답을 성공으로 바꾸지 않는다. ID가 중복되어 참조가 모호하면 부분 판정도 성공으로 세지 않는다.
3. causal-v041의 proof baseline/compact 대응은 문제·format·sampling·seed를 고정한다. 변경은 프롬프트 묶음이며 그 하위 구성요소 효과를 각각 분리했다고 하지 않는다.
4. schema 세 조건은 messages/seed/options가 같다. format만 union/schema_only/json으로 바꾼다. schema_only는 호스트가 kind를 강제한 진단이며 A 좌표 조작 성공이 아니다. JSON만 조건도 JSON 형식 제약을 사용한다.
5. 12회 전체 성공은 ADM 가설 검증이 아니다. 서로 다른 진단의 성공을 본 실험 성공률에 합산하지 않는다.
6. 기존 69건의 판정·오류와 기본 요청은 유지한다. 코드가 달라진 실행은 새 출력 폴더를 사용한다.

# v0.4 실험 계약과 해석 범위

## 목적과 고정 조건

기존 최소 검증기의 문제·목표·규칙·A/D/M 정의를 유지한다. A는 사례 표현/보편 명제 도식, D는 제출한 실제 지지 DAG의 최장 의존 깊이, M은 문제 도출/논증 검토/수락 기준 검토다. 모든 역할에 같은 문제와 목표, 공통 출력 스키마, 해당 실행의 동일한 생성 예산을 제공한다. 동시 호출은 1개다.

측정 대상은 **지시된 역할에 맞는 외부 증명 기록을 소형 LLM이 생성하는가**이다. 내부 신경망 사고 좌표·축의 보편적 독립성·히든 레이어 제어·연산 절감의 입증으로 확대하지 않는다. 최소 구현과 별도 LLM 진단은 연구의 서로 다른 증거다.

## 실행 전제 검사

메타데이터에서 실제 체크포인트를 식별하고 공식 모드와 대조한다. 별칭 이름, HTTP 정상 종료, selfcheck 통과 중 어느 하나도 모드 호환성의 충분한 근거가 아니다. Instruct-2507에는 `think`를 보내지 않고, Thinking-2507에는 `think:true`를 보낸다. 모드/메타데이터 불일치는 추론 전에 중단한다. 실제 `thinking`/`content` 분리는 첫 응답에서 확인하며 잘못된 채널을 대신 사용하지 않는다.

현재 자동 정책은 식별 가능한 Qwen3 Instruct/Thinking-2507에 한정된다. 모델 계열이 불분명하면 capability만으로 하이브리드라고 추정하지 않는다. 공식 권장 샘플링과 로컬 제한 예산을 분리해 기록한다. 이 정책은 실행 전제를 정리하지만 해당 조합의 실제 성능 향상을 보증하지 않는다.

## 실험과 진단의 분리

통합 실험은 전체 증명·도식·검토를 한 응답에서 생성한다. 분리 진단은 증명만 생성하거나 호스트가 미리 제공한 증명의 표현/검토/기준 판정을 요구한다. 고정 입력은 모델 산출물이 아니다. 분리 진단 성공을 통합 A/D/M 성공으로 합산하지 않는다.

전체 제출물의 성공은 기존 `adm_minimal.verify()`와 단순 지지 경로 요건으로 판정한다. 모델이 쓰지 않은 근거/검토를 채우거나, 불필요한 노드를 삭제하거나, 틀린 ID를 교정해 성공으로 바꾸지 않는다. 모델에 현재 문제의 정답 경로·참조 깊이·검토 정답을 넣지 않는다. 고정 설명 예시는 현재 평가 문제와 별개이며 모든 통합 역할에 동일하게 제공한다.

## 무엇을 따로 기록하는가

형식/전송, 국소 규칙 적용, 선택된 연결 부분, 전체 증명의 제출 범위, 표현 의미, 검토 의미, 역할 요청 준수를 분리한다. 전체 지지 그래프가 무효면 의미적 A/D/M 역할 일치를 false로 채우지 않고 null(평가 불가)로 둔다. 전체 실패 자체는 유지한다. 원문에 나타난 표현 종류/검토 종류/선택 부분 깊이는 별도 관측값이다.

`role_matches`의 true/false/null은 일치/불일치/평가 불가다. `task_checks`의 true/false는 검사 일치 여부이고, 모델이 출력한 불리언 값이 아니다. 진단에서는 모델 실제값과 정답을 나란히 제공한다.

본 실험의 M2는 기존 '고정 목표를 근거 없는 사실로 주장하는 probe'를 유지한다. 기본 문제의 M2 정답 패턴이 같다는 사실을 보고서에 표시한다. 다양한 수락 기준 판단은 별도 진단의 세 정답 패턴에서 검사한다. 반복된 정답만으로 일반적인 오류 탐지 능력을 확인했다고 하지 않는다.

## 예시 효과/작성 부담에 대한 대조

`factorized-v4`는 D의 증명 선택, A의 동일 증명 표현 대안, M의 검토 구성요소를 분리한다. `definitions-v4`는 공통 예시만 제거한 대조다. 예시 제거는 입력 길이도 바꾸므로 신경망 내부 원인의 단일 증명으로 해석하지 않는다.

동일 고정 증명에 대해 전체 노드 도식/최종 노드 도식 하나를 각각 작성하게 한다. 최종 노드 단독 과제에서만 중간 노드의 instance view를 호스트가 진단용으로 붙인다. 최종 도식은 원래 최종 노드와 모든 조상의 사실/규칙을 보존해야 한다. 이것은 통합 검증 기준을 느슨하게 하는 처리와 다르다.

추가 구조 세 개를 기본 문제로 제공하되 더 넓은 일반화가 검증됐다고 하지 않는다. 원자명/규칙명/규칙 순서의 재배치는 고정 시드로 이루어지고 역할마다 다시 뽑지 않는다. 원자 이름만 달라진 반복을 새로운 문제 구조로 세지 않는다.

## 실패, 중단, 반복의 분모

배정된 모든 조건을 기록하며 실패/미시작을 분모에서 숨기지 않는다. 모델 의미 오류는 다음 호출을 막지 않는다. readiness 게이트는 기록/설정/모델/모드/서버/정상 종료 조건을 재검사하며 성능 성공 게이트와 구분한다. strict 모드는 사용자가 별도로 선택하는 성능 제한이다.

자동 재시도와 최선 결과 선택은 없다. 완성 여부를 확인하지 못한 요청도 자동 재호출하지 않는다. 모델·소스·설정 변경 후 기존 결과 폴더에 이어 붙이지 않는다. 같은 문제의 반복/시드는 반복 측정이지 독립 문제 수가 아니다. 비용 합계에는 실패 호출도 포함하며 미수신 비용을 0으로 만들지 않는다.

## 이번 릴리스의 검증 경계

실행한 것은 정적 문법 검사, 오프라인 단위/회귀/Mock 통합시험, 보존된 사용자 응답의 재검사다. 새 모델의 다운로드·Ollama 실제 추론·GPU 실행·Windows 실행은 수행하지 않았다. Mock 정답과 결정론적 시험 픽스처는 하네스 점검용으로만 사용한다.

v0.3의 잘못된 모드 요청이 전체 실패를 얼마나 설명하는지는 아직 실측하지 않았다. v0.4 기본값은 새 모델 체크포인트/새 프롬프트/추가 문제를 함께 포함한 수정된 기준선이다. 따라서 개선이 나와도 단일 변경의 인과효과라고 단정하지 않는다. 예시 유무, 문제 집합, 모델별 조건을 분리한 추가 대조는 별도 결과로 남긴다.

# v0.4.2 별도 진단 계약: micro-v042

상기 통합 ADM 및 calibration-v4 정의는 변경하지 않는다. `micro_probe`는 별도 측정이다.

입력복사는 알려준 값을 재현하는 대조이며 추론 성과가 아니다. edge_map은 경로/규칙/원자를 제공하고 부모 선택만 측정하므로 D 계획 성공으로 계상하지 않는다. schema의 fact_first는 일반적인 사실절 작성 순서를 추가한 지시 대조이고 누락된 사실을 런타임이 대신 넣지 않는다.

criterion_witness는 입력 사본, 두 기본 판정(같은 목표인가/초기 사실인가), 세 최종 판정을 모두 모델이 작성한다. 필드 순서나 실패 위치를 비공개 내부 사고 순서로 해석하지 않는다.

모든 format 대조는 같은 완전 스키마를 메시지에 포함한다. API format만 schema/json/없음으로 변경하며 출력 검증은 동일하다. 진단 총점은 기본 대조와 호스트 보조 작업을 포함하므로 일반 추론/ADM 성능 수치로 쓰지 않는다.

기존 기록을 재검사할 때 새 진단 필드만 추가한다. 원문/성공 판정/참조 연결/최초 사실절은 변경하지 않는다.
