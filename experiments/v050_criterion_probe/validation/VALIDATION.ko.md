# v050 실제 검증 기록

## 실행 환경과 구분

실제 시험 환경은 Linux / Python 3.13.5다. Windows 또는 PowerShell에서 직접 실행한 결과는 아니다. 새 코드·새 시험 20개 Python 파일은 Python 3.10 문법으로도 AST 파싱했으나, 이는 Python 3.10 런타임 실행 시험을 대체하지 않는다.

사용자의 실제 모델에 새 추론을 수행하지 않았다. 실제 LLM 원문 분석은 첨부된 v049 실행 480건이며, 아래 560회는 테스트용 합성 HTTP 서버에 대한 실제 요청·응답이다. 준비 단계는 원문을 재감사할 뿐 네트워크 추론을 하지 않는다.

## 첨부 자료 재검증

v049 ZIP manifest 대상 파일 1,000개와 외부 계획을 재검사했다. 원문으로 다시 만든 report 전체가 저장된 summary.json과 일치했다. 별도 식 해석기·수동 진리표로 요청·응답 480건과 실제 NOT 부모값 전달 80건을 검사해 같은 결과를 얻었다.

최종 v050 코드에서 실제 v049 ZIP을 입력한 prepare가 정상 완료됐다. `ACTUAL_V049_PREPARE_FINAL.log`, `.exit`(0)에 결과가 있다. 고정된 모델·10 seed·두 반복·최대 560회와 외부 계획 기준선이 출력됐다. 작업 과정의 임시 계획 파일은 배포하지 않는다. 사용자는 자신의 경로에서 새 계획을 만든다.

## 기능·회귀·반례

| 시험 | 실제 결과 | 로그 |
|---|---|---|
| 초기 코어 시험 | 32개 통과 | INITIAL_SELFTEST.log |
| 기본 기능·무결성 시험 | 64개 통과 | FUNCTIONAL_SELFTEST.log |
| 검토 후 추가한 오류 위치 반례 | 수정 전 네 시험 실패 | REVIEW_BEFORE_FIX.log |
| 같은 오류 위치 반례 재실행 | 수정 후 네 시험 통과 | REVIEW_AFTER_FIX.log |
| 최종 전체 시험 | 322개 통과, 종료 코드 0 | FINAL_SELFTEST.log |

최종 322개는 기존 회귀 243개와 신규 v050 시험 79개다. 회귀 중 v047/v048/v049 Python 코어 및 기존 subprocess helper 26개 파일은 이전 배포본과 바이트 단위로 동일하다. 대조 목록은 COMPATIBILITY.json에 있다.

한 차례 도구 실행 제한에 걸려 종료까지 수집하지 못한 시험 로그가 있다. `AFTER_REVIEW_SELFTEST.log`와 `AFTER_REVIEW_TIMEOUT_NOTE.txt`에 그대로 보존했다. 그 실행을 성공으로 세지 않았다. 위 FINAL_SELFTEST는 이후 정상 종료 코드까지 확보한 별도 실행이다.

## 실제 수정한 결함

후행 형식 오류나 미실행이 이미 정답인 상위 observed/primitives를 실패 또는 미측정으로 덮어쓰던 집계 결함 한 가지를 네 반례로 재현했다. 전체 witness를 먼저 완성해야 부분 점수를 인정하던 전제를 버리고, 관측된 각 층을 별도로 채점하도록 수정했다.

잘못된 proof가 올바른 gap 점수까지 지우지 않게 했으며, NOT 형식 오류는 입력 추출 실패가 아닌 NOT_format으로 기록한다. 전체 경로 성공은 여전히 입력·원자 판단·세 finding·필요한 NOT 중간값 모두가 정답일 때만 인정한다.

## 합성 서버 전체 실행

`reproduce_synthetic.py`는 80개 대응 블록에서 계획한 560회 호출을 실제로 로컬 가짜 HTTP 서버에 전송했다. 원식은 일부러 양성 입력을 틀리게 만들고, 나머지 경로는 올바르게 응답하는 데이터다.

| 경로 | 세 finding·전체 경로 정답 |
|---|---:|
| oneshot_original | 60/80 |
| oneshot_commuted | 80/80 |
| staged_commuted | 80/80 |
| staged_pipeline | 80/80 |

이 표는 소프트웨어가 의도적으로 넣은 오답을 올바르게 실패 처리하는지 시험한 결과다. 사용자 모델의 다음 실험 결과가 아니다.

서버 프로세스 종료 후 저장된 원문만으로 재감사했으며 report 전체 객체가 실행 직후 결과와 일치했다. `OFFLINE_REAUDIT.json`에 기록했다.

`independent_raw_check.py`는 제작한 감사기·채점기·요청 모듈을 import하지 않는다. 원문·외부 계획·수동 진리표를 이용하여 manifest 1,169파일, HTTP 560건, 부모 연결 400개를 별도로 확인했다. 네 경로의 집계도 일치했다. `SYNTHETIC_INDEPENDENT.json`과 로그에 기록했다.

## 강한 반례·무결성 경계

- 네 원본 입력 × 여섯 bool 조합 = 256개 합성 경우에서 중간값이 틀린 경로를 최종값 일치만으로 통과시키지 않았다.
- 잘못된 입력 추출값이 형식상 유효하면 그대로 다음 요청에 전달됐다. 정답표로 보정하지 않았다.
- NOT 값이 틀려도 최종값 일부가 맞을 수 있는 자료에서 최종 finding과 전체 경로 점수를 구분했다.
- 부모 응답을 바꾸고 event 해시까지 다시 만들어도 자식 입력이 맞지 않으면 감사가 거부했다. 부모 ID를 바꾸고 전체 해시 체인을 재계산한 경우도 거부했다.
- 형식 오류, 중복 키, bool 대신 숫자·문자열, 비정상 완료·thinking 응답, 다른 모델 응답, 통신 오류, 실행 중 모델 정보 변경을 구분해 시험했다.
- 미완료 실행·차단 자식·오답을 자동 재시도하지 않았고, 미완료 결과에 완결 대응 분석을 부여하지 않았다.
- 실패한 재감사는 과거 PASS 파생 보고서를 무효화하되 실제 요청·응답 원문은 보존했다.
- 외부 계획/snapshot/하드링크, 무등록 파일, source snapshot 변경, ZIP 안전 경로, 덮어쓰기를 검사했다. 묶을 바이트를 임시 복사한 뒤 그 복사본을 다시 감사했다.
- 한글 경로를 쓰는 실제 자식 Python CLI를 시험했다. 기존 CP949/UTF-8 회귀시험을 그대로 포함했다.

## 배포본 확인

배포 후보 ZIP을 새 폴더에 풀어 전체 시험을 별도로 실행했다. **322개 모두 통과, 종료 코드 0**이다(RELEASE_SELFTEST.log/exit). 새 폴더의 코드로 동봉 합성 증거를 오프라인 재감사한 결과도 전체 report가 일치했다(RELEASE_OFFLINE_AUDIT.json). 최종 배포의 실행 코드·시험·PowerShell 스크립트 68개 파일은 이 새 폴더에서 시험한 바이트와 동일하다(RELEASE_CODE_COMPARISON.json). 검증 로그·문서·배포 해시 목록만 이후에 추가했다.

해시와 파일 지문은 기록·계획·실행 코드 사이의 일관성을 검사한다. 외부 독립기관의 전자서명이나 실제 사용자 PC의 GPU 실행에 대한 원격 증명은 아니다.
