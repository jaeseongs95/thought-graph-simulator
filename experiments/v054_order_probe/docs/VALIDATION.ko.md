# 실행한 검증과 그 범위

## 실제 v053 자료의 재검산

원본 evidence ZIP의 manifest 대상 321개 파일, 동봉 외부 계획, 요청·응답 원문, event chain, 모델/서버 identity, 생산 소스 71개를 검사했다. 원본 생산 감사기로 만든 전체 report 객체는 저장 summary와 동일했다.

생산 채점기를 사용하지 않는 기존 독립 검증기의 의미 필드 680개와, 이번에 별도로 작성한 원문 그래프 재계산기의 의미 필드 680개 모두 불일치가 없었다. 이 둘은 같은 120회 자료를 검사한 것이며 별도 실험 표본 1,360개가 아니다. v052와 동일한 방향 요청 40개를 실제 원문 기준으로 대조했고 요청 바이트 및 D 판정이 모두 일치했다. v053 정의 추가 대조 요청 60쌍은 정의 문단만 달랐다.

## 실제 실행한 시험

| 실행 | 결과 |
|---|---|
| 수정하지 않은 v053 전체 시험 | 546개, 186.439초, OK |
| 초기 신규 시험 | 73개 중 1개 실패; 중립 대조 설명 누락 |
| 보고서 교정 및 추가 시험 후 v047~v054 전체 | 630개, 253.498초, OK |
| 보존된 구버전 생산 소스 | 71개 바이트 일치 |
| 실제 v053 기준선으로 새 계획 생성 | 모델 호출 없이 성공 |
| 새 original 요청과 실제 기준선 요청 | 60개 바이트 일치 |
| swapped 요청의 변경 범위 | 60개 모두 rules 배열 순서만 변경 |

완성 ZIP을 다시 풀어 실행하는 배포 후 검사의 로그와 ZIP 해시는 별도 분석·검증 ZIP에 기록한다. 이 문서에 포함한 로그는 패키징 전 완료된 실제 실행 기록이다.

## 합성 HTTP 7종

각 조건을 실제 로컬 HTTP 전송 경계로 120회 실행하고, 서버가 종료된 후 ZIP의 원문을 재감사했다. 각 860개 독립 비교에서 불일치가 없었다.

| 합성 응답 | 유효 증명 | 선택적 대응 /40 | 두 순서 모두 /20 | 순서별 깊이 변화 /60 |
|---|---:|---:|---:|---:|
| perfect | 120 | 40 | 20 | 0 |
| ignore_roles | 120 | 0 | 0 | 0 |
| first_branch | 120 | 0 | 0 | 60 |
| bad_final | 0 | 0 | 0 | 비교 불가 |
| misspelled_rule | 0 | 0 | 0 | 비교 불가 |
| only_original_control | 120 | 20 | 0 | 20 |
| truncated | 0 | 0 | 0 | 비교 불가 |

`summary.json`의 `order_changed_pairs=0`은 유효 비교 중 변화가 관측된 수다. 유효한 비교 자체가 없는 세 실패 조건에서는 원래 개별 대조 값이 null이며, 0/60 '불변'으로 해석하지 않는다. 길이 제한 종료는 증명 오답이 아니라 proof_valid=null인 미측정이다.

## 실제 제약

실행 환경은 Linux와 Python 3.13.5다. Windows PowerShell 자체는 실행하지 않았다. Windows 실행 파일은 기존 검증된 경계 구조를 유지하고 새 모듈·기준선·경로로 변경했다. 사용자 PC의 실제 Qwen에 새 v054 추론을 실행하지 않았으며, 합성 840회와 첨부된 실제 v053의 120회를 구분한다.

이 검사는 자료 일관성과 구현 동작을 검증한다. 전체 자료와 해시를 함께 바꾸는 공격이나 서버의 물리적 추론을 제삼자 서명으로 증명하지 않는다. 증거 snapshot을 실행하지 않고 배포 소스와 대조한다.
