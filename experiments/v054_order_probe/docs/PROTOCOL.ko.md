# v054 사전 고정 실험 프로토콜

## 1. 관찰에서 출발한 연구 질문

실제 v053은 120회 모두 수집했다. 기존 지시 original은 유효 증명 60/60, 정의 추가 defined는 56/60이었다. 같은 seed의 shallow/deep 선택적 성공은 original 0/20, defined 0/20이다. K01은 유효한 응답에서 깊이 2, T02는 깊이 1을 고정적으로 선택했다. 정의 추가의 미등록 규칙 4건은 실패로 보존하며 자동 교정하지 않는다.

기존 v052 D 단독과 동일한 요청 40개에서도 깊이와 유효성·방향 이행 결과가 그대로 재현됐다. 따라서 정의 문단을 추가하는 개입이 해결책이었다는 결과는 얻지 못했다.

두 문제의 반복 선택은 각각 배열에서 먼저 제시된 경로 블록과 일치한다. 이 일치는 **규칙 순서가 원인이라는 확정이 아니라**, 같은 의미를 유지한 순열 대조를 선택한 근거다.

질문: **규칙 블록 순서만 바꾸면 경로 선택이 바뀌는가? 그와 별개로 동일 순서 안에서 shallow/deep 요청에 맞춘 제어가 나타나는가?**

## 2. 실험 구성

2개 문제(K01/T02) × 2개 순서(original/swapped) × 3개 방향(shallow/deep/neutral) × 기존 전체 10개 seed = 120회.

주 분석은 방향 지정 80회이며, neutral 40회는 별도 대조다. 요청별 1회, 총 1 cycle이다. 실행 순서는 5401729를 포함한 고정 해시로 섞고 계획에 동결한다. 점수에 따른 조건 선택, 중간 성공 시 종료, 추가 재시도는 없다. 네트워크 오류 또는 identity 불일치는 실행계층 중단으로 보존한다.

규칙 순열은 `design.RULE_ORDERS`에서 방향과 무관하게 고정한다.

| 문제 | original 배열 | swapped 배열 |
|---|---|---|
| K01 | k10, k17, k03 | k03, k10, k17 |
| T02 | r83, r21, r57, r04, r69 | r21, r57, r04, r69, r83 |

K01은 연쇄 경로 두 규칙을 한 블록으로, 직접 경로 규칙을 다른 블록으로 다룬다. T02는 연쇄 네 규칙과 직접 규칙 한 개를 교환한다. 전체 배열을 뒤집어 연쇄 내부 순서까지 동시에 바꾸지 않는다.

## 3. 불변조건

규칙 ID·전제·결론·초기 사실·목표의 집합과 값이 동일하다. 규칙 순열은 방향·seed·응답을 보지 않는다. 요청의 system 메시지, 모델명·digest/show/server identity, 옵션, seed, JSON schema도 유지한다.

original 요청 60개는 실제 v053 original과 바이트 동일하다. swapped는 대응 original에서 user 메시지의 rules 순서만 다르다. 의미의 동등성과 직렬화의 차이를 별도로 확인한다.

호스트는 생성 시 목표 깊이나 정답 경로를 계산해 채우지 않는다. 최소/최대 깊이, 사용할 규칙, 정답 그래프를 모델에게 제공하지 않는다. 요청 생성 모듈은 채점기·oracle·fixture·calibration을 import하지 않는다.

## 4. 판정 지표

**유효성:** JSON 형식, 최종 참조의 존재, 근거·규칙·부모 연결에 따른 증명 유효성을 별도로 계산한다. 미등록 규칙을 사용한 응답은 최종 ID가 있어도 증명 실패다. 증명 실패 시 유효한 D는 미측정이다.

**선택적 D 제어:** 같은 문제·순서·seed의 shallow/deep이 모두 유효하고, 실제 최종 지지 깊이가 각각 가능한 최소/최대여야 한다. 그래프 깊이는 요청 라벨을 보지 않고 간선에서 계산한다. 불필요한 노드나 대안 경로를 덧붙인 응답도 엄격한 원래 계약에 따라 실패한다. 배정 대응쌍은 40개다.

**순서 견고성:** 같은 문제·seed에서 original과 swapped 두 순서 모두 선택적 제어를 만족해야 한다. 4개의 기존 방향 응답을 묶어 평가한 20개 파생 묶음이다. 별도 표본을 추가한 것이 아니다.

**순서 효과:** 같은 문제·방향·seed의 original/swapped가 모두 유효할 때 실제 깊이 및 증명 구조가 달라지는지 본다. 60개 파생 비교다. 둘 중 하나라도 유효하지 않으면 변화 없음(false)이 아니라 비교 미측정(null)이다. 이 지표만 높아져도 D 제어의 성공으로 세지 않는다.

**중립 대조:** neutral 1개를 두 방향에 재채점한 평균과 방향 지정 응답의 평균을 비교한다. 재채점을 별도 호출이나 독립 문제로 세지 않는다.

모든 문제·seed·순서·방향의 실패를 포함한다. 40+60+20을 합쳐 독립 표본 120개라고 주장하지 않는다. 실행 호출 자체는 120개지만 연구 문제는 고정된 2개다. 탐색적 대응 기술통계이며 p-value를 만들지 않는다.

## 5. 사전 정한 해석

| 관측 | 허용되는 결론 | 허용되지 않는 결론 |
|---|---|---|
| 순서에 따라 깊이는 바뀌지만 각 순서 안의 shallow/deep은 같음 | 선정한 제시 순서가 경로 선택에 영향을 줌 | D 제어 성공, 순서만 맞춰 배치하면 원래 가설 입증 |
| 두 순서에서 모두 shallow/deep을 구별 | 이 고정 문제·모델·설정에서 순서에 견디는 D 제어 관측 | A/M 통합 또는 모델 내부 사고 제어의 입증 |
| 한 순서에서만 구별 | 순서 조건부 D 성공 | 순서에 무관한 안정적 제어 |
| 순서를 바꿔도 경로 고정 | 이 순열 대조는 원인 설명을 개선하지 못함 | 모든 가능한 순서 영향의 부재 |
| 형식/증명 실패 증가 | 해당 실패 계층을 따로 보고 | 실패 응답을 빼고 유효 표본만으로 성공률 상승 주장 |

다음 단계도 이 결과를 보고 결정한다. 순서 효과만 나타나면 지시에 반응하는 제어와 구분된 관측으로 남긴다. 효과가 없다면 순열 변형을 끝없이 늘리기보다 깊이 평가·비교 선택·증명 구성 중 어느 단계가 가능한지를 분리하는 진단을 검토한다. 이번 실행 안에서 후속 조건을 자동으로 생성하지 않는다.

## 6. 구현·재현성 경계

외부 계획, 요청·응답 원문, event hash chain, source snapshot과 런타임 identity를 재검사한다. 입력된 snapshot 코드를 실행하지 않는다. 동결한 배포 코드로 과거 자료를 감사한다. 기준선 점수가 낮아도 완료·무결성이 충족되면 수입하며, 저장 summary와 원문 재계산이 다르면 수입하지 않는다.

해시는 동봉 자료의 일관성을 보장하는 검사다. 전 자료·해시를 함께 바꾼 조작이나 실제 물리적 모델 실행을 외부 전자서명으로 입증하지 않는다. 순서 대조는 특정 제시 변경의 효과를 관측하며, 내부 attention·cache·탐색 알고리즘을 직접 계측하는 실험이 아니다.
