# v055 실험 프로토콜 — 모델 × 규칙 순서

## 1. 연구 판단

v054는 표현 순서가 출력 행동에 영향을 준다는 실제 증거를 제공했다. K01은 방향과 무관한 유효 경로 교체, T02는 방향과 무관한 잘못된 부모 연결이다. 따라서 단순한 '모델이 언제나 같은 논리 경로만 생성한다'라는 설명은 K01에서 유지되지 않는다. 그러나 D 지시보다 어떤 내부 학습 정책의 우선순위가 높다고 직접 측정한 결과도 아니다.

다음 질문은 같은 실행 계약에서 다른 4B급 계열도 같은 실패를 보이는가다. 더 큰 모델로 용량과 계열을 함께 바꾸거나, 프롬프트/채점 기준을 동시에 수정하는 대신 모델 패키지를 비교한다. 후보를 고르기 위해 다수 모델의 점수를 미리 보고 우수한 것을 선별하지 않았다. 앞선 대화에서 논의한 Gemma3 4B를 지정했다.

## 2. 고정 문제와 개입

K01 facts `[Ca]`, goal `Cc`, 규칙 `k10:Ca→Cb`, `k17:Cb→Cc`, `k03:Ca→Cc`는 고정한다. 깊이는 1 또는 2다. 기존 순서 `k10,k17,k03`, 교환 순서 `k03,k10,k17`을 모두 유지한다.

T02 facts `[Lp,Ls]`, goal `Lg`도 고정한다. 직접 규칙 `r83:[Lp,Ls]→Lg`, 연쇄 `r21:Lp→Lq`, `r57:[Lq,Ls]→Lr`, `r04:Lr→Lt`, `r69:Lt→Lg`를 유지한다. 깊이는 1 또는 4다. 기존 순서 `r83,r21,r57,r04,r69`, 교환 순서 `r21,r57,r04,r69,r83`을 유지한다.

규칙 순열은 방향과 무관하다. 호스트가 deep일 때만 긴 경로를 앞에 놓거나 shallow일 때 짧은 정답을 주지 않는다. 프롬프트에는 정답 경로나 목표 깊이 숫자를 새로 넣지 않는다. v053 defined 조건을 다시 추가하지 않는다. 새로운 자유도를 늘리기보다 v054 계약을 반복한다.

## 3. 모델과 런타임 동결

Qwen은 첨부 v054가 사용한 정확한 태그/digest/show hash/서버 버전을 요구한다. 태그 이름만 같은 다른 가중치는 거부한다. 후보는 `gemma3:4b`, family `gemma3`, metadata 3.5~4.5B, Q4_K_M을 요구한다. 두 모델이 같은 digest인 경우를 거부한다. 후보의 실제 digest는 사용자의 로컬 모델 metadata에서 먼저 캡처하고 이후 동결한다. 이 문서에 실제로 조회하지 않은 후보 digest를 만들어 넣지 않는다.

모델 기본 template·parameters·model_info를 raw metadata와 함께 보존한다. 사용자 지시문/옵션/출력 schema는 같아도 모델의 native chat template와 tokenizer는 달라질 수 있다. 이것은 모델 패키지 비교에 포함되며 학습 데이터 효과 하나로 분리할 수 없다. 기존 프롬프트는 한국어다. 영어 위주라는 이전 설명을 따르지 않고 실제 바이트를 기준으로 고정한다.

## 4. 대응 배정과 실행

2모델×2문제×2순서×3방향×10seed=240회. 모델당 방향 지정 80회, 중립 40회. 모든 seed를 유지한다.

각 seed에서 두 모델 모두 동일한 12조건 순서를 사용한다. 모델별 12회 연속 블록으로 실행하고 seed 순번에 따라 먼저 실행할 모델을 번갈아 배정한다(기준 모델 먼저 5seed, 후보 먼저 5seed). Qwen120도 새로 실행하므로 과거 Qwen과 새 Gemma만 비교하는 시간차 대비가 아니다. 다만 동일한 물리적 순간의 실행은 아니며, 캐시/모델 로드가 있을 수 있어 속도 차이의 확증 실험으로 해석하지 않는다.

모든 `/api/chat` 요청은 한 번만 실행한다. 모델 로드용 숨은 warmup 추론은 없다. 모델 교체는 요청의 model 필드로 한다. 서버의 모델 로드/퇴거 정책을 변경하는 별도 호출은 넣지 않는다. 블록당 전후 metadata를 조회해 실행 중 가중치/template/server 변화에 fail-closed로 대응한다.

## 5. 측정 층

(1) HTTP/모델 identity/정상 종료, (2) JSON/출력 schema, (3) 최종 참조 존재, (4) 규칙과 실제 부모 연결의 증명 유효성, (5) 유효한 목표 지지 DAG 깊이, (6) 방향 이행을 분리한다.

증명 깊이 계산 함수에 요청 방향을 넣지 않는다. 가능한 최소/최대 깊이는 평가기에서만 계산한다. 잘못된 부모, 미등록 규칙, 틀린 final ID, 중복 ID, 양쪽 경로를 함께 출력한 기록을 보정/가지치기하지 않는다.

파싱되지 않은 응답의 증명은 미측정이다. 파싱된 명백한 잘못된 증명은 오류다. '무효 증명의 D'를 실제 유효 깊이처럼 보고하지 않는다. 형식이 틀려도 내부에 완전한 증명이 있으면 형식 실패와 증명 유효성은 분리할 수 있다. 최종 성공에는 둘 다 필요하다.

## 6. 1차·2차 결과

1차 결과는 모델/문제/순서별 10seed의 shallow/deep 대응쌍이 양쪽 지시를 모두 만족하는가다. 모델당 40쌍이다. 단일 응답의 목표 깊이 일치율이 50%여도 매번 같은 경로라면 대응 제어는 0일 수 있다.

2차 결과는 두 순서 모두에서 제어를 유지한 20seed-문제 묶음, 순서 변경 시 유효한 두 응답 간 깊이/구조 변화, 중립 응답 대비 방향 이행 차이다. 중립 1개를 두 방향에 다시 채점해도 2개 독립 응답으로 늘리지 않는다.

모델 간 대비는 같은 문제·순서·seed에서 두 모델의 선택적 성공 여부를 비교한다. 둘 다 관측된 쌍에 대해 둘 다 성공/기준만 성공/후보만 성공/둘 다 미성공을 계산한다. 양쪽 중 미실행이 있으면 미관측 쌍이다. 전체 미완료이면 차이율은 null이다. 완료된 실험의 무효 응답은 배정 분모에 남는다.

2문제와 10seed의 기술통계이며 모델 모집단/문제 모집단 전체의 성능 순위로 확장하지 않는다. 같은 숫자 seed는 서로 다른 tokenizer와 생성분포에서 같은 난수 실현을 뜻하지 않는다. 응답 재집계의 분모를 합쳐 표본 수를 부풀리지 않는다.

## 7. 결과별 후속 판단

| 관측 | 채택할 판단 | 그다음 |
|---|---|---|
| 후보는 두 순서에서 D를 이행, 기준은 실패 | 이 계약의 D 제어는 모델 패키지에 따라 다름 | 성공 모델의 제어 재현/확장. 학습 원인은 별도 개입 필요 |
| 두 모델 모두 유효하지만 방향에 무반응 | 공통 실행 계약에서 D 선택이 작동하지 않음 | D 요구의 인식과 실제 그래프 구성 단계를 분리하는 진단 |
| 한 모델의 형식/증명 구성만 실패 | 비교 실패 층은 형식/구성 | 그 층을 먼저 분리. 이를 곧바로 D 개념 부재로 판정하지 않음 |
| 특정 순서/문제에서만 성공 | 조건 의존적 제어 | 성공 범위를 보존하고 문제/순서 일반화 실험 |
| 두 모델 모두 제어 성공 | 이 배치의 성공 인정 | 이전 배치와 차이/반복 안정성 점검. A/M 분리 검증으로 복귀 검토 |
| metadata/HTTP 중단 | 실험 불완전 | 원문 오류 확인, 별도 새 계획/RunName으로만 재실행 |

## 8. 연구 주장 경계

이 실험은 외부에 생성된 증명 기록의 제어를 측정한다. hidden layer의 실제 사고, 자율성, 모델의 의도, 학습 당시의 우선순위 규칙을 직접 읽지 않는다. 모든 LLM에서 A/D/M이 가능 또는 불가능하다는 주장을 이 두 문제로 결론내리지 않는다. 동시에 현재 조건에서의 명확한 성공/실패는 흐리지 않고 기록한다.
