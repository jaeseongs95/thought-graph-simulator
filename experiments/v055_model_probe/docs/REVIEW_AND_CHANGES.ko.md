# 다각도 검토와 재검토 기록

별도 외부 심사자나 독립 에이전트를 호출한 기록이 아니다. 서로 다른 심사 관점에서 반론을 세웠고, 기술적으로는 생산 재감사와 생산 채점기를 import하지 않는 별도 구현, 실제 raw 기록, 반례 시험을 대조했다. 의견을 다수결로 채택하지 않았다.

## 1. v054 결과 심사

| 관점 | 반론/선택 | 증거와 판단 |
|---|---|---|
| 실행 무결성 | 또 추론 전 실패한 것 아닌가 | 실제 요청/응답120, metadata/계획/event 연결 일치. 완료 결과로 판정 |
| 측정 타당성 | 순서 변경을 D 성공으로 세면 되는가 | K01은 순서 내 shallow/deep/neutral 모두 같은 깊이. 순서 변화30/30이지만 D0/20 |
| 논리 정확성 | T02는 긴 경로를 생성했으니 deep 성공 아닌가 | 최종 r69의 실제 부모는 Lp/Ls, 필요한 것은 Lt. 30개 모두 무효. 유효 D 미측정 |
| 구현 오류 | 감사기 버그가 실패를 만들었나 | 독립 원문 계산860필드 일치. 이번 결과를 바꿀 생산 채점 결함 미발견 |
| 원인 해석 | 학습된 깊은 기본 정책이 확정됐나 | K01의 논리 경로가 순서만 바꿔 변함. 입력 표현에 따른 행동 차이는 확인, 내부 우선순위는 미계측 |
| 일반화 | Qwen 하나로 일반적 D 제어를 판단할 수 있나 | 한 모델·두 문제의 제약. 비슷한 크기의 다른 계열 비교를 먼저 시행 |

채택: 기존 결과와 무효 T02 조건을 보존한 모델 비교. 더 큰 모델로 바꾸기/답안 수정/쉬운 문제만 선택/영어 번역/프롬프트 강화는 이번 버전에서 제외한다.

## 2. 새 v055 설계 심사

모델만 바꾸겠다고 하면서 다른 prompt/template를 수동 수정하거나, 과거 Qwen만 기준으로 쓰거나, 모델 식별 gate를 끄는 구현은 거부했다. 실제 v054 요청120개를 바이트 보존하고 후보는 model 필드만 변경한다. Qwen120도 새로 실행한다. 후보 identity는 capture에서 명시적으로 별도 동결하며, 이후 일치 검사를 완화하지 않는다.

모델별 native template와 tokenizer 차이는 실제 모델 패키지 차이다. 따라서 동일 API 요청이라는 이유로 학습 정책 하나만 변했다고 주장하지 않는다. 실제 지시는 한국어이며 번역하지 않았다.

## 3. 구현 후 발견·교정한 실제 문제

초기 새 코드의 55개 시험은 통과했다. 그 뒤 미완료 실행의 모델 간 비교를 다시 읽으면서, 아직 실행하지 않은 후보가 False 상태의 대응쌍으로 나타날 때 '기준 모델만 성공' 또는 '두 모델 모두 미성공'에 섞일 수 있음을 발견했다.

원인: 양쪽 관측 여부를 필터링하지 않고 `reference_selective`/`candidate_selective` 불리언만 합산했다.

교정: 둘 다 관측한 쌍만 성공 대비 네 범주에 포함한다. 미관측 쌍은 `unobserved_pairs`로 분리한다. 미완료 차이율 null은 그대로 유지한다.

동일한 새 회귀시험4개를 교정 전에 실행했을 때 실제 비교값 오류2개와 새 미관측 필드 부재2개로 실패했다. 교정 후4개 모두 통과했다. 수정 전/후 로그를 동봉한다. 완료된 정상/실패 답안의 성공 기준은 바꾸지 않았다. 이 결함은 아직 배포하지 않은 새 v055의 미완료 보고 문제이며, 첨부된 완료 v054 결과를 바꾸는 결함이 아니다.

별도 독립 구현에서는 top-level 형식과 내부 증명 타당성을 분리했다. 실제 v054 데이터에서 쓰인 기존 독립 계산은 그대로 두고, 새 verifier는 추가 top-level 필드처럼 '형식 실패지만 그래프는 유효'한 반례도 생산기와 교차검사한다. 통과한 검사를 '원본 결함을 고친 실패→성공'으로 과장하지 않는다.

## 4. 반대 결과 검출

합성 응답은 시험 서버에서만 만든다. 실제 실행 경로의 runner/requests는 테스트 정답 생성기나 depth 정답 계산기를 import하지 않는다. '후보가 이긴다'는 결과만이 아니라 기준 모델만 성공하는 경우, 둘 다 성공, 둘 다 앞 경로만 따름, 미등록 규칙, 파싱 불가, HTTP 중단 등을 검사한다.

순서만 따르는 응답은 순서 대비 깊이가 바뀌어도 D 제어는0이다. 후보가 형식적으로 실패하거나 실제로 더 못하는 결과도 유지한다. missing usage를0으로 바꾸지 않는다. wrong model 응답은 답안 오답이 아니라 실행 identity 오류다. raw/계획/요청/소스/metadata 변경, 위조 완료, 기존 PASS 잔존도 검토한다.

## 5. 남는 실제 경계

두 모델의 실제 로컬 추론은 사용자 환경에서 실행할 단계다. 이 환경에서 합성 서버가 정답을 반환한 성과를 모델의 성과로 사용하지 않는다. Windows PowerShell은 직접 실행하지 않았다. 중단 시 자동 복구·재개를 보장하지 않으며 raw를 보존한 새 실행을 요구한다. 완성된 증거와 hash를 모두 함께 바꾸는 공격을 제삼자 전자서명으로 막는 시스템은 아니다.
