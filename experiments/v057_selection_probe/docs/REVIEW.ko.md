# 다각도 검토와 논문 핵심 대응

외부 심사자/에이전트 호출이 아니라, 같은 작업자가 상충하는 제3자 심사 기준을 적용하고 생산 코드와 별도 구현으로 기술적 교차검증한 기록이다.

| 관점 | 질문 | 채택한 판단 |
|---|---|---|
| 측정 | 두 모델 모두 0/40이면 같은 실패인가? | Qwen은 유효90/120, Gemma는 2/120이다. Gemma의 관측은 주로 증명 구성 실패다. |
| 구현/전달 | 동일 JSON 요청 옵션이면 같은 역할 처리인가? | 모델 package의 native template이 다르다. 실제 기록에서 Gemma는 system/user 각각을 user로 매핑한다. |
| 인과 | 그 배치가 실패 원인인가? | 현재 자료는 원인 확정이 아니다. 내용 고정 split/merged 대조로 시험한다. |
| 공정성 | Gemma만 포맷을 바꿀 것인가? | 두 모델 모두 두 배치를 실행한다. 기존 Qwen 비교와 문제/규칙 순서를 빼지 않는다. |
| 이론 | 단순 유효성 향상을 A/D/M 성공으로 포장하는가? | 증명 유효성, 선택적 D, 중립 대비, 순서 견고성을 따로 계산한다. A/M 단독·통합은 이번 실험의 성공 주장에 포함하지 않는다. |
| 시스템 | JSON 크기/PowerShell 오류가 재발하는가? | 기준선은 별도 ZIP으로 유지한다. strict32MiB 계획 재읽기를 시험하며, 네이티브 stderr 문자열 대신 종료 코드를 확인한다. |

## 작성 후 검토에서의 실제 발견

초기 독립 검산기에서 요청 바이트 비교에 정렬 JSON을 사용했지만 생산 요청은 원래 삽입 순서를 유지했다. 정상 병합 요청을 거부하는 시험 오류가 나와, **원래 직렬화의 삽입 순서를 유지하는 독립 인코더**로 교정했다. 평가 조건/응답을 완화하지 않았다. 추가로 시험 경로의 .plan/.plan.json 불일치를 교정했다.

개발 도중 진행 중인 시험의 소스를 변경해 fingerprint gate가 거부한 실행이 있었다. 이것은 완료 시험으로 세지 않고 소스 동결 후 다시 실행했다. 실패 로그를 보존하며 이를 모델 결과나 발견하지 않은 채점 결함으로 표현하지 않는다.

배포 전 검증은 실제 v055 전수 재감사, 독립 그래프 검산, 새 요청 은행 비교, 실제 합성 HTTP, 미관측/HTTP 오류/잘못된 부모·규칙/변조 반례, 전체 누적 회귀, ZIP 재추출 검사, 자동화 하위 프로세스 전 과정으로 구성한다. 실제 완료 여부와 횟수는 별도 검증 기록에 적는다.
