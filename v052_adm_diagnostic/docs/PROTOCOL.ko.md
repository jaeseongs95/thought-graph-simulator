# v052 사전 고정 프로토콜

## 1. 연구 질문

문제와 목표를 고정하고 역할 조건만 바꿀 때, 유효한 표현 수준 A, 실제 증명 지지 깊이 D, 검토 대상 M이 요청한 방향으로 선택적으로 달라지는가? v051이 실패했으므로 성공 경로를 전제로 하지 않는다.

## 2. 과제

K01은 facts=[Ca], Ca→Cb, Cb→Cc, Ca→Cc, goal=Cc다. 모든 K01 역할에서 이 입력을 바꾸지 않는다.

T02는 기존 simulator의 conjunction_4와 동형인 구조 전이 과제다. facts=[Lp,Ls], 규칙 Lp&Ls→Lg, Lp→Lq, Lq&Ls→Lr, Lr→Lt, Lt→Lg, goal=Lg다. 규칙명은 경로 의미를 이름으로 미리 주지 않도록 비의미적 ID를 사용한다. 모든 T02 역할에서 입력은 동일하다. 두 문제 사이의 목표가 다른 것을 같은 문제의 목표 조작으로 해석하지 않는다.

T02는 현재 LLM 실행 계열의 구조 전이 탐색이다. 모델의 사전학습 노출 여부를 모르는 만큼 '학습 데이터에 없는 문제'라고 주장하지 않는다.

## 3. 조건·배정

기존 10개 seed 전체, temperature와 나머지 옵션 유지, 요청별 1회, 고정 해시 순서의 같은 배치.

K01 legacy 12역할×10 seed=120. explicit factorial 두 문제×12역할×10 seed=240. explicit neutral 두 문제×10 seed=20. 정답 제공 복사 두 문제×10 seed=20. graph_only 두 문제×얕음/깊음×10 seed=40. 총 440.

순서는 미리 동결하지만 모든 위치/직전 조건의 완전 균형설계는 아니다. 새 호출은 독립 HTTP 요청이며 앞 응답을 다른 과제에 전달하지 않는다. 복사 예시는 본 실험 메시지에 포함하지 않는다. 학습이나 대화 이력 누적을 수행하지 않는다.

## 4. 생성·측정 분리

실행기와 요청 생성기는 정답 계산기를 호출하지 않는다. 실제 `nodes`, `parents`, `rule`, `final_node_id`, 표상, 검토 응답을 보존한다.

측정기는 요청 A/D/M를 입력으로 사용하지 않는다. 역할 부합 비교는 의미 측정이 끝난 뒤 별도로 수행한다. 역할 라벨을 실제 좌표처럼 읽으면 반례 시험이 실패한다.

K01의 D 범위는 1/2, T02는 1/4다. 평가기는 고정 규칙에서 가능한 의존 깊이를 다시 계산한다. D는 텍스트 길이·토큰·규칙 수와 같은 의미가 아니다. 규칙의 원자성은 문제 내부에서 고정한다.

A의 schema는 실제 사용한 초기 사실·규칙과 정확히 연결돼야 하며, 모든 Boolean 배정에서 가정 전체가 결론을 함의해야 한다. 변수 이름만 바꾸거나 목표를 가정으로 추가해 통과할 수 없다.

M은 검토 대상이 증명인지 기준인지와 finding의 진위를 분리한다. M2는 무근거 단독 목표 주장에 대한 두 수락 기준의 차이를 실제로 판정해야 한다. `M2`라는 자기평가 라벨은 근거가 아니다.

## 5. 엄격한 성공과 부분 관측

전체 역할 성공은 형식, 증명 전체, 표현, 검토 대상, 검토 finding, 요청 좌표가 모두 맞아야 한다. 최종값만 맞거나 개별 노드만 맞는 것은 전체 성공이 아니다.

실패/미측정을 구분한다. 파싱이 안 된 기록의 proof를 실제 잘못된 증명으로 확정하지 않는다. 유효한 JSON에서 잘못된 최종 노드 참조를 낸 경우에는 증명 전체가 실패다. 개별 노드가 맞았다는 관측은 별도로 남는다.

중복 JSON 키를 마지막 값으로 덮어써 채점하지 않는다. 중복 view/binding 배열도 제거하지 않는다. final_node_id를 목표 원자 이름에서 추정하거나 그래프의 대안 경로를 호스트가 잘라내지 않는다.

## 6. 핵심 효과와 대조군

주요 분모는 factorial 240개 배정이다. 정답 복사·D 단독 실행·legacy는 각각 별도 결과다.

각 seed에서 factorial의 12역할 부합률과 neutral 출력 하나를 같은 12역할로 재평가한 균등 기준 부합률을 비교한다. neutral 재채점은 독립 표본 12개로 계산하지 않는다. p-value나 모집단 성공률의 확증적 신뢰구간을 계산하지 않는다.

축별 대응은 한 축 지시만 다른 두 출력에서 해당 축이 요청대로 바뀌고 나머지 축이 유지되는지를 본다. A나 M을 바꿀 때는 단순 D 숫자만 같아서는 부족하며, 노드 ID를 제외한 실제 지지 구조 서명도 같아야 한다. 실패한 기록을 삭제해서 분모를 줄이지 않는다.

구조·대상 조작과 finding까지 유효한 선택적 조작을 따로 보고한다. 한 축의 몇 쌍이 성공했다고 범용 독립성을 선언하지 않는다.

## 7. 결과별 의사결정

- 복사도 실패: 현재 형식 전달·생성 경계가 불안정하다. 본 가설 성공을 주장하지 않는다. 형식 구체 원인을 별도 비교한다.
- 복사는 성공하지만 graph_only가 실패: 참조를 복사할 수 있는 것과 경로를 구성·선택하는 것을 구분한다. 생성 제어의 실패를 기록한다.
- D 단독은 성공하지만 factorial은 실패: D 구성요소는 작동하지만 통합 계약의 수행이 실패했다. A/M까지 성공으로 확장하지 않는다.
- factorial이 유효하지만 neutral과 역할 부합률이 같고 선택적 조작이 없다: 형식·증명 생성 성공이지 요청 A/D/M 제어의 증거는 아니다.
- factorial이 중립보다 잘 맞고 유효한 선택적 조작도 나온다: 해당 문제에서 외부 기록 제어의 근거다. T02의 성공/실패는 따로 보고한다.
- 모든 핵심 조건 실패: 현재 구성에서의 가설 지지는 없다고 보고한다. simulator의 구성 가능성과 실제 LLM의 실행 성공을 혼동하지 않는다.

가설 성공을 얻을 때까지 정답 보정·조건 삭제·검증기 완화로 반복하지 않는다. 다음 설계 변경은 새 계획과 새 버전으로 기록한다.

## 8. 해석 한계의 위치

legacy와 explicit의 차이는 표현 인터페이스 묶음이며 세부 원인을 식별하는 완전 요인설계는 아니다. T02를 추가했어도 문제 수는 두 개다. 생성된 외부 trace가 내부의 실제 연산 순서와 일치하는지는 이 실험이 계측하지 않는다. 이 한계들은 기존 실제 실패나 정상적인 부분 관측을 취소하는 이유로 사용하지 않는다.
