# 다각도 심사와 변경 기록

별도 외부 심사자·독립 에이전트를 호출한 결과는 아니다. 서로 다른 심사 기준을 적용해 반론을 세우고 실제 소스·시험으로 판정했다. 독립 의미 검사는 생산 채점기를 import하지 않는 별도 코드로 수행한다.

## 1. 이론/방법론 심사

반론: 실패할 때마다 형식만 바꾸면 원하는 성공이 나올 때까지 실험을 이동하는 것 아닌가?

판정: v051 실패를 원문 그대로 보존하고 동일 legacy 요청 120건을 동시 대조한다. 명시적 인터페이스의 본 실험에는 12역할 전체와 모든 seed가 남아 있다. 그 결과도 실패할 수 있고, 실패를 긍정적인 가설 결과로 바꾸지 않는다.

반론: 예시를 복사시키면 높은 성공률이 나오는 것은 당연하다.

판정: 정답 제공 복사 20건은 형식 진단으로만 보고하고 본 가설 성공 분자·분모에서 전부 제외했다. 복사만 성공하고 본 과제가 실패하는 합성 반례를 검사한다.

반론: 잘 작동하는 JSON 생성만으로 A/D/M 가설을 지지할 수는 없다.

판정: 실제 역할별 부합, 중립 기준과의 차이, 한 축 변화 시 비조작 축 및 실제 지지 구조 유지, 두 문제별 구조 전이 결과를 별도 보고한다. 역할을 무시하는 정상 생성기는 핵심 제어 성공으로 통과하지 않는다.

## 2. 구현/채점 심사

반론: final=Cc를 노드 id로 바꿔주면 현재 자료가 통과하는 것 아닌가?

판정: 240건 모두 대안 경로가 함께 있어 참조만 교정해도 계약 위반이다. 호스트의 참조 추정·경로 가지치기를 넣지 않았다. v052의 어댑터는 필드명과 배열 표현만 바꾸고 값·경로를 수정하지 않는다.

반론: 모든 요약이 0이면 실제 무엇이 틀렸는지 알 수 없다.

변경: 개별 노드, 최종 참조, 증명 전체, 표현, 검토, 전체 성공을 나누고 성공/실패/미측정을 표시한다. v051의 전체 성공 조건은 유지한다.

반론: 새 형식으로 바꿨으니 원인까지 특정할 수 있는가?

판정: 아니다. final_node_id 명시, nodes 선행 선언, views/bindings 배열화, 단일 경로 선택 설명을 묶은 인터페이스 대조다. 개선이 관측돼도 그중 어느 하나를 단독 원인으로 확정하지 않는다.

## 3. 새 코드 검토와 시험에서 실제로 있었던 일

초기 의미 검사 23개와 설계 검사 16개가 통과했다. 이후 실제 HTTP 실행, 역할 무시, 잘못된 최종 참조, 잘못된 M2, 통신 오류, 손상 원문, 외부 계획, 증거 ZIP, 한글 경로 subprocess 등을 추가했다.

새 코드에 대해 추가한 미측정/오답 구분 검사 두 개도 처음부터 통과했다. 이를 '수정 전 실패했다가 교정했다'고 꾸미지 않았다. 초기 묶음 실행 한 번은 도구의 실행 제한시간에 중단됐으며, 그 뒤 완료된 실행에서 신규 시험 63개와 전체 시험 480개의 종료 상태를 확인했다.

기존 v047~v051 코어와 Windows subprocess helper 48개 Python 파일은 바이트를 변경하지 않았다. 변경은 추가 v052 모듈 및 설명·실행 문서에 한정된다. 원래 점수를 올리기 위한 채점기 완화는 하지 않았다.

## 4. 보안·자료 무결성

원문 바이트, event hash chain, 외부 계획, 런타임 모델/서버 identity, 실제 파일 목록, source snapshot을 다시 검사한다. 증거 ZIP은 실제로 묶을 바이트를 별도 폴더에 고정해 재감사한 뒤 생성한다. 자동 재시도, 외부 endpoint 전송, source snapshot 실행, 자료 덮어쓰기를 하지 않는다.

검사된 정상성은 동봉 계획·원문의 일관성이다. 모든 자료와 해시를 함께 조작한 공격이나 모델 서버의 물리적 실행 여부를 제삼자 전자서명으로 증명하지는 않는다.

## 5. 합의

현재 이론 자체의 논리 모순이 검출된 것은 아니다. 현재 v051의 실제 생성·제어는 실패했다. 다음 실험은 그 실패를 인정하면서 핵심 가설이 작동할 여지가 어디에 있는지 직접 검사해야 한다. 정답 복사/출력 형식 성공과 핵심 A/D/M 조작 성공을 구분하는 v052 방향을 채택한다.
