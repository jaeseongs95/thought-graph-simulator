# v082 구현 검토

## 변경한 범위

v081 소스를 기준으로 두 군의 선택 출력을 모두 candidate_id로 유지하고 `profiled_id`군의 선택 입력에 두 계산표 원문을 추가했다. 계산표 작성은 후보 한 개의 명시적 구조 수치 산출이며 내부 추론 과정의 기록이라고 가정하지 않는다. 프롬프트·스키마 원문은 data/protocol.json에 동결했다.

생산 `design082.py`와 독립 `audit082.py`는 스케줄과 요청을 각각 구성한다. 계산표 슬롯은 각 block의 metadata 확인 뒤, 모델 선택 전에 두 개 배정된다. 후보 순서는 block 간 균형화한다. 각 계산표는 표시/지표/방향 전체에 원문 그대로 공유된다. 계산표의 `trial_id`는 회계상 처리군 소속을 표시하는 포인터이며, 계산 요청에는 그 시행의 요구나 후보 ID가 들어가지 않는다.

## 이전 요청과 불필요한 변동 통제

candidate_id 대조군과 공통 참조의 v081 실제 요청 739개는 기존 원응답 이력을 넣어 바이트 일치를 검사한다. 두 군이 같은 선택 ID 문자열 및 같은 생성 이력을 갖는 합성 경우, 각 생성 요청도 바이트가 같다. 계산표 및 물리적인 군 이름은 생성 입력에 넣지 않는다.

직접 선택기는 계산표 응답을 받지 않는다. 호출이 앞서 수행됐다는 서버 상태 영향까지 제거한 실험이라고 주장하지 않으며, 두 선택군 호출 순서를 조건 간 균형화한다. 모든 실제 호출은 독립 메시지 본문을 사용하고 대화 객체를 누적하지 않는다. 모델 seed만으로 실제 응답 동일성이 보장된다고 가정하지 않는다.

## 독립성 범위

legacy Python 9개는 v081 evidence와 바이트 단위로 보존한다. 생산 graph/단계 판정과 기존 독립 graph/단계 판정은 다른 구현이다. 계산표는 생산의 순차 깊이 전파와 독립의 재귀 원자 의존 깊이 계산으로 각각 채점한다. 요청·스케줄·집계·추가 계약 계산 역시 생산/독립 경로를 분리한다. 한국어 렌더러와 JSON/파일 형식 유틸리티는 공유/기존 구현을 사용한다. 모든 코드가 서로 완전히 독립적이라고 주장하지 않는다.

## 무보정 및 실패 분류

실행기에는 D/W 정답을 계산해서 후보를 고르는 경로가 없다. 계산표의 잘못된 수치, JSON/스키마 오류를 정답으로 치환하지 않는다. 선택 매핑은 candidate_id 완전 일치만 허용한다. 계산표 검산기는 실행이 아니라 사후 요약에만 사용한다. 정상 호출에서 형식이 틀린 계산표도 원 문자열을 선택기에 전달하며, 잘못된 선택은 그대로 증명 생성한다.

HTTP·transport·identity 오류는 중단한다. 길이 종료·형식 오류·실제 의미 오류는 각각 별도로 측정한다. 미관측/미완료 자료를 D=0이나 오답으로 보완하지 않는다. 파싱 불가 선택 때문에 생성이 생략된 경우 선택 계약 실패와 미실행 graph를 분리한다. 원응답 저장 직후 기록 확정 전 중단된 경우 관측 개수에는 포함하지만 완료 시행의 의미 점수로 사용하지 않는다.

## 검사와 범위

시험은 합성 교환기 및 기존 v081 evidence의 읽기 전용 재감사를 사용한다. 실제 신규 모델 호출은 하지 않는다. 계산표가 틀렸는데 graph가 맞는 경우, 숫자는 맞지만 중간 전제 깊이가 틀린 경우, 계산표는 맞고 선택이 고정된 경우, 전부 역방향이지만 D/W 반응은 달라지는 경우, 선택·계산표·요청 변조를 검사한다.

파일 경로·해시·plan·event chain·모델 identity·조건부 생략·응답 계측값을 검산한다. 이 검증은 번들 내부 일관성이지 실제 로컬 모델 실행의 외부 인증은 아니다. 개발 환경에서 실제 수행한 시험 결과와 PowerShell 네이티브 검사 여부는 외부 배포 검증 기록에 따로 적는다.

## 계산표 출력 예산

새 계산표 호출은 최대 출력 1,024토큰으로 사전 제한했다. 두 원응답이 같은 선택 입력에 들어가므로 보조 출력이 불필요하게 커지는 것을 제한한다. 기존 선택·생성의 API 옵션과 4,096토큰 상한은 유지한다. 길이 종료는 계산 실패나 D=0으로 채우지 않고 별도 미측정 상태로 보존하며 자동 재시도하지 않는다. 이 상한이 실제 모델의 작성 성공을 보장하는 것은 아니다.
