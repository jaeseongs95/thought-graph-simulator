# v082 사전 계획 — r1

작성일: 2026-09-15 KST. 상태: 소스 및 오프라인 검증. 실제 v082 Qwen 결과는 아직 없다.

## 1. 근거와 닫은 분기

v081 완료 evidence의 SHA-256은 `8e6be3196a49b3ed5dffbb926bceaa978030b6c0df7b00fe8d86de26a27db74a`, plan SHA-256은 `6bd369d07d63e63417cbd54836d4821d1e96c3738a9f093910169ad5955eb709`이다. 원 자료의 분석보고서에서는 rule_ids군이 96/96 후보 목록을 정확히 복사했지만 모두 첫 후보를 골랐고, D 양방향 종단은 ID군 2/32 대 목록군 0/32, W는 8/16 대 0/16이었다. 이 실패를 목록 복사 오류로 바꾸어 설명하지 않는다.

rule_ids 방식은 기본 선택기로 승격하지 않는다. 비교 기준은 기존 candidate_id + explicit_rule이다. H01의 제한된 D 부분 성공과 W 적게 선택의 성과는 보존하며 H02 긴 경로의 생성 실패도 별도로 남긴다.

## 2. 이번에 추가하는 가설

**비교 요구와 분리하여 후보를 하나씩 구조 계산하게 하고, 모델이 쓴 계산표 원문을 선택기에 제공하면 실제 요구별 선택과 graph 종단이 개선되는가?**

이것은 분석에서 확인된 사실이 아니라 후속 개입 가설이다. 복사 형식만 다시 바꾸는 대신, 요청한 구조 기준을 실제로 계산하는 보조 작업을 먼저 수행한다. 내부 원인이 계산·비교·ID 대응 중 무엇이라고 확정하지 않는다.

v071의 깊이 숫자 계산→비교와 관계가 있으나 단순 반복으로 기술하지 않는다. 이번에는 후보 하나씩 사실·각 규칙 전제 깊이·결론 깊이·목표 D·규칙 수 W를 작성하며, 동일 계산 원문을 위치×ID×요구 방향에 공유하고 실제 생성 graph까지 기존 기준으로 검사한다. 정답 수치 제공 대조는 포함하지 않는다. v071~v073에서 드러난 숫자 정확도와 실제 선택의 구별을 그대로 유지한다.

## 3. 두 군과 통제

| 요소 | candidate_id | profiled_id |
|---|---|---|
| 문제·규칙·목표·후보·표시·seed·API | v081 기준 유지 | 동일 |
| 선택 답 | 후보 ID 하나 | 같은 스키마의 후보 ID 하나 |
| 계산표 원문 입력 | 없음 | 모델이 각 후보를 별도 계산한 원문 2개 |
| 선택 안내 | 원문 유지 | 계산표의 출처·사용 안내만 추가 |
| 생성기 | explicit_rule | 동일 |

계산 요청에는 단일 후보의 규칙·사실·목표만 넣는다. 상대 후보, 후보 ID, 표시 위치, D/W 어느 지표를 선택할지, 작은/큰 방향은 제공하지 않는다. 문제×seed×후보별 1회, 총 16개를 호출한다. 후보별 호출 순서는 균형화한다. 그 두 응답은 같은 문제×seed의 4표시 및 D/W·양방향에 공유한다. 반복 사용을 독립 계산 표본으로 세지 않는다.

계산표의 모든 숫자와 원자/규칙 표기는 모델이 작성한다. 호스트가 규칙의 정답 깊이·목표 값·부모 ID·완성 graph를 제공하지 않는다. 출력 스키마에는 문자열·정수 및 배열의 넓은 범위만 지정한다. 실제 전제 수나 정답 값으로 배열 길이/enum을 고정하지 않는다.

계산표 원문은 오류가 있어도 그대로 선택기에 전달한다. 정상 HTTP 응답의 JSON/스키마/의미 오류 때문에 정답 계산표로 교체하거나 재질의하지 않는다. HTTP·transport·identity 오류는 배치를 중단하며 자동 재시도하지 않는다.

선택 단계는 원 후보들도 계속 받는다. 계산표를 반드시 신뢰하도록 강제하지 않으며 원 규칙을 다시 검토할 수 있다. 두 군 모두 동일 candidate_id JSON을 반환한다. 호스트는 그 ID를 제공 후보에 정확히 대응시키기만 한다. 잘못된 경로도 그대로 생성한다.

계산표는 생성기에 직접 전달하지 않는다. 각 군이 작성한 선택 ID 원문과 그 군의 실제 생성 이력만 전달한다. 같은 ID 원문/동일 이전 이력이라면 생성 요청도 같다. 서로 다른 선택·이력 이후에는 두 군 입력이 같다고 주장하지 않는다.

## 4. 배정과 호출량

구조: 기존 H01~H04 네 개. 새로운 독립 구조 0개, holdout 아님. 두 seed와 위치 2×ID 2를 유지한다.

- 군별 D: 64조건, 양방향 32쌍. 군별 W: 32조건, 양방향 16쌍.
- 실제 ID 선택 호출: 두 군 합계 192회. 과거 결과로 대조군 응답을 대신하지 않는다.
- 본실험 증명: 192개. 공통 생성기 지정 경로 참조: 16개를 한 번만 실행. 총 증명 208개.
- 후보 계산표: 16개. 참조에 추가하거나 본실험 증명으로 세지 않는다.
- 모든 선택이 요구 경로일 때 총 추론 1,420회. 모두 매핑 가능한 최단 경로일 때 최소 1,356회. 최대 1,484회.
- 최대 진행 슬롯 1,500개: 추론 가능 슬롯 1,484개 + metadata action 16개. 실제 길이에 따른 미사용 규칙 슬롯은 생략 사유를 기록한다.

비용에는 계산표 16회를 한 번만 포함한다. 계산표를 받는 96선택마다 새 호출을 했다고 합산하지 않는다. 추가 계산과 길어진 선택 입력을 포함하는 시스템 개입이며, 토큰 예산을 맞춘 순수 표현 효과가 아니다.

## 5. 주평가와 추가 계약을 분리

**주평가:** 실제 graph의 모든 초기 사실·규칙 단계·부모 연결·goal 조상·경로 충실성·D/W를 재검사한 요구 지표 종단. 우선 지표는 D 양방향 종단 및 같은 조건 군간 짝비교다. 네 표시 전수 성공과 D/W 네 요구 모두 성공은 별도 결과다. W를 D 성과에 합산하지 않는다.

**추가 계약:** 두 후보의 계산표 전체가 정확하고 선택부터 graph 종단까지 모두 성공한 경우. 이는 더 강한 조건이며 주평가를 덮어쓰지 않는다. 계산표가 틀렸지만 graph가 맞은 경우 주평가 성과는 보존하되 전체 계산-종단 성공은 아니다.

**진단:** 계산표 자체 16개의 사실·규칙 단계·산술·최종 D/W 정확도, 두 후보의 보고된 수치를 요구 방향에 맞게 선택했는지, 실제 지표에 맞는지 분리한다. 보고 수치가 동점이면 정답 후보를 호스트가 추정하지 않으며 `reported_tie`로 표시한다. 보고 극값을 따랐다는 결과는 내부 사고가 그 계산표와 같다는 증거가 아니다.

| 관측 | 현재 가능한 해석 | 하지 않을 확대 |
|---|---|---|
| 계산표 정확 + 선택/종단 개선 | 해당 계산 지원 계약의 개선 효과 | 계산 생략만이 확정 내부 원인 |
| 계산표 정확 + 선택 계속 실패 | 명시적으로 보고한 수치가 정확해도 이 선택 계약은 불충분 | 수치를 모른다 또는 모델 전체 불가능 |
| 계산표 오류 + 선택이 그 값을 따름 | 잘못된 보조 계산과 일치하는 오류 전달 | 모델 내부 인과 과정 확정 |
| 계산표 오류 + 실제 graph 성공 | graph 성과는 보존, 추가 계약 실패 | 처음부터 끝까지 모두 정확했다 |
| 마지막 수치만 정확 + 중간 계산 오류 | 수치 정답과 계산표 충실성 분리 | 수치 정답만으로 과정 성공 |
| 한 군 미관측 | 비교 불가 | 다른 군 단독 승리 |
| 선택은 맞으나 H02 긴 경로 생성 실패 | 생성 잔여 문제 | 선택 효과 부정 또는 graph 자동 보정 |

현재 D는 고정 원시 규칙 체계에서 실제 산출 graph의 의존 깊이다. 인간의 사고 깊이 전체, 내부 hidden state, 비용 우월성, A/M 축 및 세 축 독립성은 이번 실험의 직접 측정 대상이 아니다.

## 6. 중단과 후속 경계

단일 동결 배치 후 종료. v081을 덮어쓰지 않는다. 시작 가드·계획·소스·요청·응답·완료/미완료 사건을 보존한다. 새 RunName·가드 삭제로 재시도하지 않는다. 모델 다운로드/업데이트/Ollama 자동 시작 없음.

개선이 없으면 이 후보 계산표 지원 분기를 종료한다. 같은 네 문제에서 계산 안내·seed·수치 표기만 계속 바꾸며 성공을 탐색하는 후속을 자동 생성/실행하지 않는다. 개선이 있어도 기존 네 문제의 진단 결과로 한정하며 일반화는 별도 사전 동결 확인으로 다룬다. 결과를 본 뒤에 다음 연구 질문을 정한다.

## 계산표 출력 예산

새 계산표 호출은 최대 출력 1,024토큰으로 사전 제한했다. 두 원응답이 같은 선택 입력에 들어가므로 보조 출력이 불필요하게 커지는 것을 제한한다. 기존 선택·생성의 API 옵션과 4,096토큰 상한은 유지한다. 길이 종료는 계산 실패나 D=0으로 채우지 않고 별도 미측정 상태로 보존하며 자동 재시도하지 않는다. 이 상한이 실제 모델의 작성 성공을 보장하는 것은 아니다.
