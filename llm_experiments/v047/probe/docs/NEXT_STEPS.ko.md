# 이후 연구 방향

## 현재 위치

사용자가 제공한 기록에 따르면 결정론적 명세 시험, 실제 LLM 연결, 실패 관찰 및 유형 분리, primitive 진단 실행을 거쳐 **v046에서 교환식과 실제 연결식의 구성요소 성공 기준선을 확보**했다. “primitive 분해 실험 설계 ← 지금 여기”라는 표시는 더 오래된 상태다.

현재 실험은 하나의 불리언 식에 대한 실행 경로의 성공이다. 입력 a/b는 이전 모델이 반환했던 값에서 가져오며 새로 자연어에서 추출하지 않는다. 호스트가 NOT→AND 연결을 제공한다. 이 경계를 그대로 유지하며 다음 단계로 진행한다.

## 권장 순서

```text
v046 성공 원문과 소스 동결
    ↓
v047 같은 배치의 원식·교환식·연결식 대조 및 동일조건 반복
    ↓
관측 패턴 판별
    ↓
미리 고른 다른 표현·입력 표현·연산 구조의 일반화 검사
    ├─ sampling이 실제로 변하는 설정이면 seed 반복
    └─ temperature=0이면 먼저 표현·문제·별도 실행 재현에 집중
    ↓
원래 실패하던 전체 판단 작업에 연결 경로 재통합
    ↓
고정 문제·고정 목표에서 A/D/M 축별 조작과 실제 경로 측정
    ↓
다른 소형 계열 → 더 큰 모델의 동일 과제·예산별 비교
```

비용 기록과 비교 예산의 정의는 맨 마지막이 아니라 지금부터 시작한다. 모델 규모 비교는 A/D/M 최소 본 실험을 시작하기 위한 필수 선행조건이 아니다. 구성요소 대조만 계속 확대하여 본 가설로 복귀하지 못하는 상황을 피한다.

## v047 결과에 따른 다음 작업

| 같은 배치에서 관측한 결과 | 현재 가능한 결론 | 다음 작업 |
|---|---|---|
| 원식이 반복해서 틀리고 교환식·연결식이 안정적으로 맞음 | 표현에 따른 차이가 동시 대조에서도 재현됐다. 분해는 유효한 경로지만 유일하지 않다. | 원식·개선된 직접식·연결식을 모두 유지한 채 미리 정한 다른 표현/문제로 넓힌다. |
| 세 경로가 모두 안정적으로 맞음 | 현재 조건에서는 과거 실패가 재현되지 않았다. 과거 기록을 취소할 이유는 아니다. | 실패를 만들기 위해 설정을 튜닝하지 말고 과거 조건 차이를 기록한다. 이미 성공한 현재 구성에서 더 넓은 문제 또는 원래 전체 작업으로 이동한다. |
| 직접 경로들이 흔들리고 연결식이 상대적으로 안정적임 | 해당 과제/설정에서 실행 구성의 이점이 관측됐다. | 식의 형태와 문제를 확장하고, 일반적인 단계화·추가 호출 자체의 이점과 비교하는 대조군을 준비한다. |
| NOT가 틀렸는데 최종값만 맞음 | 최종값 성공과 전체 경로 성공이 갈라졌다. | NOT 실패와 공급값 기준 AND 실패를 분리해 기록한다. 정답을 호스트가 채워 넣지 않는다. |
| JSON/종료/채널 오류가 증가함 | 의미 연산 오답과 다른 프로토콜 실패가 관측됐다. | 두 실패율을 분리한다. 출력 형식 변경은 기존 데이터를 고치는 것이 아니라 별도 실험군으로 실행한다. |
| 통신 중단 또는 모델/서버 식별 변경 | 대응 실험을 완결하지 못했다. | 부분 자료를 보존하고 원인을 기록한다. 환경이 정리되면 새 이름으로 사전 계획부터 시작한다. |

특정 식에서 낮은 비용의 교환식이 안정적으로 성공하면 그 식의 운영 경로로 쓸 이유가 있다. 이것은 분해 연구를 폐기해야 한다는 의미가 아니다. 연구 질문은 성공한 한 표현을 찾는 것에서, 다양한 표현·문제에 대해 어떤 통제 방식이 재현 가능하게 작동하는지로 확장된다.

## seed 반복의 위치

원래 temperature가 0이면 우선 그것을 바꾸지 않는다. 이 단계의 동일 seed 반복은 재현 안정성과 실행 순서 대조다. 다음에 sampling 강도를 바꾸려면 별도 실험으로 동결하고 모든 경로에 같은 변경을 적용한다. seed 숫자만 여러 개 지정했다고 일반화 표본이 늘었다고 계산하지 않는다.

같은 seed를 경로별로 맞추는 것은 설정의 대응을 맞춘다는 뜻이지 서로 다른 요청의 생성 과정에서 같은 무작위 사건이 발생한다는 뜻은 아니다. 비교의 단위는 지정한 입력·반복·seed 블록이며, 모집단 일반화를 위해서는 별도의 표현 및 문제 집합이 필요하다.

## 표현·문제 일반화

첫 결과를 본 뒤 유리한 표기만 골라서는 안 된다. 다음 평가 집합을 실행 전에 정하고, 성공한 개선 직접식도 대조군에 남긴다. 바깥 괄호, 피연산자 위치, 입력 변수 표기, 부정의 위치, 더 많은 변수와 다른 함수처럼 무엇을 바꾸는지 각각 기록한다. 새 형태가 현 모듈의 한 식 전용 계약을 벗어나면 새 실험 버전으로 구현한다.

표현상의 괄호 중첩이나 NOT 추가를 곧바로 A/D/M의 D 조작이라고 이름 붙이지 않는다. 진단용 연산식 난이도와 실제 결론의 지지 의존 깊이는 서로 다른 측정 대상이다.

## A/D/M 본 실험으로 복귀

저장소 연구자료의 정의를 유지한다.

| 축 | 현재 연구자료의 정의 | 본 실험에서 필요한 관측 |
|---|---|---|
| A | 표상의 구체성·일반화 수준 | 실제 표현이 인스턴스 수준인지 일반화된 스키마인지, 의미가 보존되는지 |
| D | 현재 결론의 실제 지지 의존 구조 및 기록된 논증 깊이 | 전제·규칙·부모 연결을 재생했을 때 측정되는 실제 깊이 |
| M | 검토 대상의 수준 | 개별 논증 검토인지 수용 기준 검토인지, 기록된 검토와 증거가 일치하는지 |

사용자의 원래 아이디어대로 문제와 목표를 고정한 상태에서 역할을 바꾼다. 역할 이름이나 요청한 A/D/M 라벨을 측정값으로 읽지 않는다. 목표 문자열이 맞더라도 실제로 유효한 지지 경로가 없으면 실패다. 성공한 경로만 추려 축 준수율을 계산하여 실패를 감추지 않고 전체 할당 중 유효 완료율, 유효 경로의 축 측정값, 조건별 위반 유형을 나란히 보고한다.

먼저 기존 전체 판단 작업에 이번 연결 방식을 다시 붙인다. 이전 자연어/관측 추출 → 실제 a/b → primitive 호출 → 필요한 전체 판단 필드 → 기존 전체 검증의 흐름을 다시 실행한다. 지금의 단일 gap 식만 맞았다는 이유로 다른 판단 필드나 A/D/M 전체 경로까지 맞았다고 표시하지 않는다.

축별 최소 대조에서는 한 축을 바꾸고 나머지 축과 문제·목표·허용 자원을 가능한 한 고정한다. 다음에는 축 사이의 상호작용을 조사한다. 대조군은 기본 생성, 일반적인 단계 분해, A/D/M 계약을 적용한 제어를 포함하도록 설계한다. 그래야 단순히 일을 잘게 나눈 효과와 A/D/M에 특유한 효과를 구분할 수 있다.

## 다른 모델·큰 모델·계산량 비교

모델을 바꿀 때는 동일 문제 집합과 평가기를 유지하고 모델명뿐 아니라 체크포인트·양자화·thinking 모드·템플릿·서버 조건을 기록한다. 다른 소형 계열에서 재현한 뒤 더 큰 모델을 비교하면 특수한 체크포인트에만 맞춘 효과인지 확인하는 데 도움이 된다.

원하는 최종 주장에 맞게 비교 기준을 먼저 정한다. 같은 과제에서 실제 비용과 정확도를 함께 보고, 고정 지연시간·입출력 토큰 예산·금전 예산 등의 한도에서 각 방식이 낼 수 있는 품질을 비교할 수 있다. 같은 토큰 수가 서로 다른 크기의 모델에서 같은 FLOPs를 뜻하지는 않는다. 이번 v047은 토큰/시간 계측을 제공하지만 FLOPs 동등성 측정이나 전력량 계측은 구현하지 않는다.

“작은 모델과 큰 모델의 차이가 거의 없다”를 평가하려면 허용 가능한 품질 차이와 비용 조건을 사전에 정한다. 차이를 발견하지 못했다는 것만으로 동등하다고 결론 내리지 않고, 정한 차이 범위 안에 들어오는지를 검토한다. 모든 모델이 이미 100%인 매우 쉬운 한 식만으로는 원하는 고성능 대체 주장을 평가하기 어렵다. 전체 문제 집합과 실제 경로 정확성, 예산별 결과를 함께 사용한다.
