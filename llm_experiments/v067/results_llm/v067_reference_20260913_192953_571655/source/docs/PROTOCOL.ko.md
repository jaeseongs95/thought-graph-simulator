# v067 정상 참조 계획 재구성 양성 대조

## 결정과 남은 질문

v066은 direct12회와 planner12회→constructor12회, 총36회의 실험이었다. planner 출력은12개 모두 형식은 맞지만 유효 경로가 아니었고, constructor의 strict 증명도0/12였다. 모델 원계획 전달은12/12 일치했다. 따라서 v066의 사전 규정에 따라 **그 두 호출 구조의 실험 분기는 종료**한다. 같은 문구를 바꿔 다시 계획시켜 성공할 때까지 반복하지 않는다.

이 자료에는 **정상적인 완전 계획을 입력받은 constructor의 관측이 한 개도 없다.** 따라서 종단 실패는 확정되지만, 정상 입력에서조차 그 생성기가 증명을 구성할 수 없는지는 측정되지 않았다. 새 v067은 이 빈칸만 검사하는 한 번의 양성 대조다. 원래 D 제어 실험을 통과시키기 위한 답안 수선이나 성공 기준 완화가 아니다.

## 명시적으로 제공하는 정답 입력

**실험자가 올바른 규칙 경로 전체를 제공한다.** 이는 정답 경로를 준 재구성 과제이며 자율적 경로 선택 검증이 아니다. 임의의 모델 원응답을 고쳐 모델이 맞힌 계획처럼 가장하지 않는다. 요청의 `provided_route_plan.origin`과 고정 계획 모두 `experimenter_verified_reference`를 명시한다.

|문제|reference_short|reference_long|참조 경로 깊이|
|---|---|---|---|
|T02|r83|r21, r57, r04, r69|1 / 4|
|E01_shared_fork|n52|n08, n91, n37|1 / 2|
|E02_two_vs_four|m18, m76|m33, m05, m84, m41|2 / 4|

경로는 이전 실제 응답의 성공한 부분을 편집해 만든 것이 아니라 문제 명세에서 사전 정의했다. prepare 단계에서 등록 규칙·앞선 전제·목표 도달·불필요 규칙 부재와 깊이를 검사한다. 별도 검산기는 같은 명세를 다른 코드로 재확인한다. 두 코드는 검토된 문제 명세를 공유한다.

완성된 출력 DAG, 노드 ID, 부모 ID, 노드 배열, final_node_id의 정답은 제공하지 않는다. 모델이 작성한 graph는 원문 그대로 검사하며, 부모·목표 참조·오타를 고치거나 불필요 노드를 지우지 않는다. 답안 참조의 규칙 ID 목록만 복사한 응답은 graph schema를 만족하지 않아 성공이 아니다.

## 실험 배정과 비용

3문제 × 2seed × 2참조 경로 = **12회**. planner 모델 호출은0회다. 문제별 두 seed에서 short→long과 long→short 순서를 반전한다. 각 참조의 위치가 문제별로 균형이다. 문제 간 모든 순서/실행 이력/캐시를 통제하는 설계는 아니다.

원 v066의 모델 이름·digest·서버/template·옵션·seed와 facts/rules/goal/규칙 순서 및 기존 graph schema를 보존한다. 기존 graph 작성 지시의 자유 shallow/deep 요구는 제거하고, 제공된 계획을 그대로 사용하는 지시로 바꾼다. 참조 입력에 실험자 제공이라는 설명을 추가한다. 따라서 v066 constructor와 요청 바이트가 같거나, 같은 배치의 원인 하나만 바꾼 대조라고 하지 않는다.

기본 num_predict4096으로 설정 생성 상한은49,152이다. 입력 토큰·실제 생성 토큰·시간·비용 보장이 아니다. metadata는6블록의 전후12묶음, 각 version/tags/show3조회이며 추론과 별도다. warmup·성공에 따른 조기 선택·자동 재시도·모델 갱신·서버 시작 없음.

기준선은 `v066_staged_20260913_185054_745451_evidence.zip`, SHA-256 `9ad2cf76455d5b10584183b0123be96a9211586210732af7e9ffb649aac9f90e`다. 이전 전체 원문을 핀 고정 v066 검산기로 다시 감사한 뒤 요청 설정을 가져온다.

## 측정과 판정

- 기본 논리와 strict 완전 증명은 v064/v065/v066과 같은 `measure.py` 바이트로 평가한다.
- 모델이 출력한 비사실 노드의 규칙 순서가 제공 참조와 정확히 같은지 별도 평가한다. 독립 가지의 순서를 바꾼 동등한 graph는 논리·strict 성과를 인정할 수 있지만 이 순서 지정 과제의 성공으로는 세지 않는다.
- 실제 D는 strict 유효 graph에서만 측정한다. `reference_input_D`는 이미 제공한 입력의 속성이지 모델 선택의 성과가 아니다.
- 재구성 성공은 strict graph + 전체 참조 규칙 순서 이행 + 실제 D가 참조 깊이와 일치하는 경우다.
- 모든 단계가 관측·측정된12개 모두 성공이면 양성 대조 기준을 통과한다. `D_instruction_control_success`는null, A/M gate도null로 유지한다.
- 파싱 불가·미실행은 논리 오답이나 D=0으로 바꾸지 않는다. 불필요 노드/순서 위반과 실제 논리 오류는 별도 집계한다.

## 사전 종료와 다음 결정

12/12 성공: 이 인터페이스에 올바른 경로를 공급했을 때 재구성이 가능하다는 제한된 기준선만 확보한다. v066에서 계획기만이 유일한 원인이었다고 단정하지 않는다. 새로운 계획기/모델/표현을 선택할 때 쓸 생성기 기준선이지 v066의 재승인이나 A/M 진입권이 아니다.

12건이 모두 측정되고0/12: 정상 입력을 줘도 현재 전체-DAG 출력 계약을 수행한 증거가 없다는 범위로 이 과제 분기를 종료한다. 같은 전체-DAG 문구의 추가 변형을 기본 후속으로 만들지 않는다. 다른 모델·더 간단한 출력 계약·독립된 A/M 질문은 별도 연구 결정이다.

부분 성공: 해당 문제·참조 경로·seed의 범위를 보존한다. 성공만 남겨 전체 성공률을 재구성하거나 신규 문제의 성공으로 확대하지 않는다. 완료하지 못했거나 미측정이 있으면 전체 기준을null로 두고 기술적 수집 문제와 과제 실패를 분리한다.

어떤 경우에도 이 프로그램이 후속 실험을 자동 생성·실행하지 않는다. 새 분기에는 새로운 질문·조작·대조·예산·종료 기준이 필요하다.

## 이 대조가 입증하지 않는 것

새 문제 일반화, D의 자율적 선택, A/D/M 전체 이론, 내부 hidden layer 제어, 모델 크기 비교, 비용 절감은 측정하지 않는다. 동일한 세 문제와 두 seed를 이미 보았으므로 holdout이 아니다. 정답 경로 제공에 따른 성과는 새로운 실험 과제의 성과이며 기존 모델 원계획의 오류를 지우지 않는다.
