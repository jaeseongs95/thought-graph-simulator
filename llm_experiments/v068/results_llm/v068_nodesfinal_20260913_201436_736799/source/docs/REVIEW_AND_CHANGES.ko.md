# 대안 비교와 구현 검토

## 대안의 처분

v067 원응답의 final_node_id를 호스트가 고치기: 기존 실패를 성공으로 바꾸므로 기각한다.

v067 실패를 계속 분석만 하기: 4/12와 세 개의 고립된 최종 참조 오류를 보존하는 데는 필요하지만 원래 연구로 돌아갈 생성기 기준선을 직접 만들지 못한다.

증명 노드를 하나씩 append-only로 출력하기: 전체 DAG 출력을 여러 작은 호출로 바꾸는 타당한 별도 후보지만 이번 관찰에서 가장 좁게 확인할 수 있는 최종 ID 연결보다 조작 범위와 호출 수가 커 우선 채택하지 않는다.

JSON 키 이름/설명 문구를 반복 바꾸기: 강제 디코더의 정렬이나 내부 사고 순서가 실제 원인임을 현재 원문만으로 확인할 수 없고 성공할 때까지 튜닝하는 진단 연장을 만들 수 있어 채택하지 않는다.

nodes 생성 뒤 모델이 final ID를 지정하기: 기존 원문을 수선하지 않는 새 출력 계약으로 채택한다. 전 문제/경로/seed를 유지하고 같은 배치 direct를 둔다. 두 단계가 한 단계보다 많은 호출/생성 예산을 쓰는 점은 명시한다. 성공해도 내부 원인이 최종 필드 위치였다고 단정하지 않는다.

## 검토 후 반영한 사항

초기 배정식은 참조 순서를 뒤집는 조작과 arm 순서 조작이 상쇄되어 일부 문제/참조에서 같은 arm이 늘 먼저 오게 했다. 실제 모델 호출 전에 배정식을 바꾸어 모든 문제/참조의 두 seed에서 direct/staged 선후가 반전되도록 했다. 최종 단위시험이 이 조건을 직접 확인한다.

요청 크기 제한 등으로 final 호출을 전송하기 전에 중단될 수 있다. 요청 바이트가 아직 기록되지 않은 pending도 보존하도록 검산기를 확장했다. 이때 시작 표지 수와 합성 서버 수신 수가 다른 반례를 시험한다. 이를 실추론 완료로 세지 않는다.

기준선 판단은 staged만 보지 않는다. direct만 12/12, staged만 12/12, 양쪽 12/12를 구분한다. 오래된 v067 4/12는 어떤 경우에도 변경하지 않는다.

## 시험 범위

전체 synthetic HTTP 왕복, wrong parent·final·extra unused node·cycle·중복 ID·형식 추가 필드·불완전 응답·잘못된 원문 전달, 누락 사용량, HTTP/transport/identity/예산 중단, 요청 전 pending과 응답 후 pending, 해시/이벤트를 다시 작성한 변조, 한국어 보고서와 summary 변조, 원응답→후속 요청 drift, 출처/스키마 변조를 검사한다.

독립 검산기는 생산 채점 결과를 재사용하지 않고 원문 노드와 전달값에서 재계산한다. 동등한 독립 가지의 순서 변경은 strict 증명 성과와 참조 순서 준수를 따로 판단한다. 여러 반례를 포함한 시험 개수는 실제 모델의 성능 증거가 아니다.

Windows PowerShell native 시험은 Windows에서만 실행한다. Linux에서는 명시적으로 제외되며 대신 실제 Python 하위프로세스·한글/공백 경로·표준오류/종료코드 시험을 실행한다. 배포 파일의 최종 시험 수, 제외 항목, 해시는 별도 VALIDATION_RESULT.json과 원문 로그에 기록한다.
