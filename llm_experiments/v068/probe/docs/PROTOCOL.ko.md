# v068 동결 실험 계약

## 1. 선택 근거와 연구 범위

v067은 참조 경로를 제공한 양성 대조에서 4/12 성공했다. T02 짧은 경로와 E01 짧은 경로가 각 2/2이며 나머지는 0/2다. T02 긴 경로 두 개와 E02 짧은 경로 seed 64001002는 실제 노드 관계와 참조 규칙 순서는 맞지만 존재하지 않는 final_node_id를 출력했다. 노드 배열은 바꾸지 않고 관찰했으며 이 세 실패를 성공으로 재채점하지 않았다.

12개 원응답 모두 final_node_id 필드가 nodes보다 앞에 있었고, 그 값은 문제의 규칙 목록에서 첫 번째로 goal을 도출하는 규칙 ID와 같았다. 이것은 **출력 문자열의 관찰**이지 모델 내부 사고 순서나 강제 디코더의 원인에 대한 증명이 아니다. 올바른 참조 경로가 있어도 노드 배열 작성과 최종 ID 연결이 분리되어 실패할 수 있음을 보여 주는 자료다.

인계 문서의 partial 분기에서 허용한 '다음 결정을 바꾸는 한 번의 제한된 진단'으로, 최종 ID 지정 시점을 출력 계약상 분리한다. 문구를 반복 강조하거나 v067 오답을 보정하는 방식은 사용하지 않는다. v068 뒤에는 같은 분리 진단을 문구·seed만 바꾸어 반복하지 않는다.

## 2. 실험 질문

같은 정답 참조 경로가 주어졌을 때, 한 번에 전체 graph를 작성하는 방식과 'nodes 작성 → 그 실제 원문에 대한 최종 ID 지정' 방식의 엄격한 재구성 성공 범위가 다른가?

이는 출력 인터페이스와 호출 구조의 묶음 비교다. 최종 필드 위치 하나만 바꾼 인과 절제 실험이 아니며, 양쪽 토큰 예산도 같지 않다. 후속 선택 모듈과 결합할 수 있는 생성기 기준선이 생기는지를 판단하기 위한 제한된 실험이다.

## 3. 배정

T02, E01_shared_fork, E02_two_vs_four, seed 64001001/64001002, reference_short/reference_long를 그대로 쓴다. 이미 본 문제·seed이며 독립 holdout이 아니다. 문제·초기 사실·규칙·목표·규칙 순서·참조 경로·모델 identity·생성 옵션을 유지한다. 참조 깊이는 각각 1/4, 1/2, 2/4다. E01 긴 경로는 규칙 세 개라도 두 독립 가지가 합쳐지는 구조이므로 D=2다.

각 문제/참조의 두 seed에서 direct/staged 선후를 반전한다. 짧고 긴 참조의 선후도 두 seed에서 반전한다. 문제 간 모든 실행 이력이나 캐시를 통제하지는 않는다.

12개 짝의 direct 12회, nodes 12회, final 12회로 최대 36회 추론한다. 6개 블록 전후의 metadata는 별도의 12묶음이고 version/tags/show 각 조회를 보존한다. 자동 warmup, 재시도, 모델 변경, server 시작, 결과에 따른 조기 성공 선택은 없다. HTTP/transport/identity/예산 초과는 전체 배치를 멈추고 보존한다.

## 4. 사전 계약과 무보정 경계

직접 출력의 JSON schema와 요청 바이트는 같은 seed/참조의 v067 wire 요청과 동일하다. 현재 배치에서 재측정하므로 과거 4/12를 대조군 수치로 대체하지 않는다.

nodes 단계는 기존 노드 schema만 받으며 final_node_id 필드는 없다. 모델이 초기 사실 노드, 노드 ID, rule, parents, 목표 도출 노드 모두 직접 쓴다. final 단계는 문제와 참조 경로 및 직전 응답 원문 문자열을 받으며 final_node_id 문자열 하나만 쓴다. 모델 출력에서 유효한 목표 후보를 호스트가 추출하거나 enum으로 제공하지 않는다.

원문 message.content는 공백·개행·틀린 내용까지 보존한다. 전달 패키지는 원응답 SHA-256 및 source slot ID도 포함하고 독립 검산기가 원응답 바이트에서 재구성하여 대조한다. 파싱 불가인 노드 내용도 문자열이 있으면 전달한다. 원응답이 transport/identity 오류인 경우는 그 시점에서 중단한다.

채점 시 `nodes = 첫 모델 payload.nodes`, `final_node_id = 둘째 모델 payload.final_node_id`만 결합한다. 노드 추가·삭제·가지치기·재정렬·부모 치환·ID 추측 없음. 첫 단계에서 사전 schema 이외의 필드가 나와도 조용히 제거하지 않고 형식 미측정으로 둔다. 같은 방식으로 잘못된 마지막 ID를 존재하는 ID로 수선하지 않는다.

## 5. 측정

전체 증명 채점기는 v067 measure.py와 바이트 동일하다. 모든 사실, 등록 rule, 전제 다중집합, parent 존재, cycle, goal, final 존재, ancestry, 불필요 노드, 위상 순서를 검사한다. D는 strict 유효 graph에서만 계산한다. 규칙 목록 순서가 참조와 같고 실제 D가 참조 깊이와 같아야 참조 재구성 성공이다.

staged 성공은 두 단계가 모두 정상 관측·형식 유효이고 무보정 결합 결과가 위 기준을 만족해야 한다. 형식상 맞지만 논리적으로 틀린 앞 단계는 최종 ID가 맞아도 성공이 아니다. 파싱 불가·길이 종료·미실행은 논리 오답이나 D=0으로 채우지 않는다. 초과 생성은 별도 상태로 분리한다.

24개 종단 trial을 direct/staged 각각 12개로 보고한다. 문제/참조/seed와 짝별 both_success/staged_only/direct_only/both_failure/unmeasured를 모두 보존한다. 같은 문제 반복을 독립 표본으로 확대해 유의성이나 일반화 신뢰구간을 주장하지 않는다. usage는 단계별로 보존하고 누락은 null이다.

## 6. 사전 종료와 다음 결정

- 모든 36회가 완료되고 해당 arm의 12개 종단 trial이 모두 측정되어 12/12인 경우에만 그 arm의 참조 입력 생성기 기준선이 확보된다. 두 arm 모두 성공하면 양쪽 기준선을 표시한다.
- staged 0/12면 이 두 호출 계약은 종료한다. direct가 12/12이면 그 기준선은 별도로 유지한다. 두 방식의 실패를 같은 내부 원인으로 단정하지 않는다.
- 일부 성공이면 성공 문제/경로/seed만 그대로 표시한다. 이번 제한 진단은 종료하며 문구 변경·새 seed로 자동 연장하지 않는다.
- 미완료·미측정이 있으면 전체 비교는 미판정이고 각 arm gate도 정해진 완결 기준을 적용한다. 기술적 오류를 모델 논리 오류로 바꾸지 않는다.

기준선이 확보된 후에야 별도 사전 설계로 D 요구→모델의 경로 선택→검증된 출력 계약의 연결을 검토할 수 있다. 이 코드는 해당 다음 실험을 자동 생성하거나 실행하지 않는다. 이번 결과는 A/M 제어, hidden-layer 조작, 자율 D 제어, 비용 우월성, 새로운 문제 일반화를 입증하지 않는다.

## 7. 증거와 검산 한계

실제 v067 ZIP 해시, 원 계획 해시, 원 v067 소스 배포 ZIP 해시를 고정한다. 증거 안의 v067 source snapshot으로 결정적 ZIP을 재구성했고 인계 문서의 원 배포 해시 39844126...와 동일함을 확인했다. 그 고정 배포본으로 v067 전체 evidence를 실행 전에 다시 검산한다.

독립 검산기는 생산 measure/report/design/run/stages 모듈을 import하지 않는다. 문제·계약·바이트/JSON 도구는 공유한다. 생산 증명 계산은 재귀/조상 탐색, 별도 증명 계산은 독립 구현으로 대조한다. 별도 외부 심사자나 외부 LLM을 호출한 검증은 아니다. 재계산은 같은 증거를 재검산한 것이며 독립한 실제 실험을 추가한 것이 아니다.

manifest/hash는 번들 내부 일관성을 확인할 뿐 외부 모델 실행 자체를 서명 인증하지 않는다. pending의 inference_calls는 시작 표지 기준으로 기록되므로 서버 수신/완료와 다를 수 있다. 원응답이 남아도 commit event가 없으면 채점에 넣지 않는다.
