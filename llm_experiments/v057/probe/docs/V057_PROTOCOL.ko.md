# v057 사전 고정 프로토콜

## 질문과 식별 범위

전체 증명 DAG의 동시 작성 요구를 제거하고 마지막 규칙 ID 하나만 요청했을 때 방향 선택이 달라지는지 검사한다. 축소 과제는 완전한 증명 생성보다 요구가 다르므로 선택 성공을 논문 핵심의 직접 입증으로 세지 않는다. 내용과 schema를 함께 바꾸는 과제 대조이지 출력 길이만의 조작이 아니다.

## 고정과 조작

v056 원 증거를 생산 감사기로 전부 재감사하고 두 모델 merged 240요청을 동결한다. 과거 계획을 중첩 JSON으로 복제하지 않고 원 ZIP을 한 바이트 파일로 보존한다. 두 모델·2문제·2순서·3방향·10seed를 전부 유지한다. graph는 원 요청과 바이트 동일하며 choice는 마지막 규칙 ID 선택 지시와 schema만 해당 과제에 맞춰 바꾼다. 원래 방향 문장과 problem 문자열은 그대로다.

원 문제의 facts/rules/goal 외에 정답 경로·규칙·깊이를 입력하지 않는다. choice schema에 답 후보 enum/const를 넣지 않는다. 요청 생성 모듈은 채점 모듈을 import하지 않는다.

## 일정

480추론. seed마다 모델당 24회 블록이며 모델 선후는 5:5다. 블록 내 12조건별 graph/choice 선후를 6:6으로 교차시킨다. 블록 전후 metadata 검사 총 40회이며 각 검사는 서버/태그/show 3 HTTP 요청이다. 이 조회는 모델 추론 수에 포함하지 않는다. warmup, 자동 재시도는 0이다.

## 판정

형식, 유효성, 방향 이행, 대응쌍, 두 규칙순서 모두의 성공, 중립 대비 차이를 분리한다. 통계 단위는 고정 문제·순서·seed의 대응 기술통계다. 같은 seed를 서로 다른 모델의 동일 난수 상태로 해석하지 않는다. 하나의 중립 응답을 두 방향에서 재평가해도 두 독립 응답으로 세지 않는다.

choice의 선택값은 동일한 문제에서 마지막 규칙별 가능한 깊이가 유일할 때만 대응 깊이를 보고한다. proof_valid/strict_valid/D는 null로 유지한다. 잘못된 ID, 목표에 도달하지 않는 규칙, 오답 방향을 자동 교정하지 않는다. 미실행/파싱 미측정/선택 오류/증명 오류를 분리한다.

두 과제의 대응쌍이 모두 관측되지 않으면 과제 간 승패를 미관측으로 둔다. 전체 실행 미완료에서는 비교율을 null로 둔다. HTTP/identity 실패는 즉시 중단한다. 정상 HTTP로 받은 형식·논리 오류는 결과로 기록하고 예정된 나머지 실험을 수행한다.

## 다음 결정

choice만 성공하면 실제 선택 ID를 다음 생성에 무보정 전달하는 후속 실험의 근거가 된다. 현재 v057에는 그 연결 실험을 섞지 않는다. graph만 성공하면 축소 과제가 항상 쉽다는 가정을 폐기한다. 둘 다 실패하면 DAG 작성 부담만의 설명을 버리고 지시 해석/경로 판별 전제를 재검토한다.
