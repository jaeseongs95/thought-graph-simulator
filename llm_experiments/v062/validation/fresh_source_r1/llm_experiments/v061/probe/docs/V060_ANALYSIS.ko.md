# v060 실행 결과: 독립 관점 분석과 교차검토

## 1. Executive Verdict

v060에서는 앞에 놓인 목표 도출 규칙을 40회 모두 선택했다. `[k17,k03,k10]`에서는 긴 경로의 끝 규칙인 `k17`, `[k03,k17,k10]`에서는 짧은 경로의 끝 규칙인 `k03`을 각각 20회 골랐다. 두 조건 모두 짧은 경로를 선택하라는 지시를 받았다. 따라서 형식과 목표 도달 가능성은 모두 통과했지만, 짧은 경로 지시는 앞의 조건에서 0/20, 뒤의 조건에서 20/20 이행했다.

쉽게 말하면, 답안의 순서를 바꾸자 고른 답도 바뀌었다. 이전에는 ‘두 번째 답을 고른다’와 ‘목표를 만드는 규칙 중 맨 앞을 고른다’가 같은 예측이었다. 이번에는 두 예측이 갈라졌고, 결과는 후자와 맞았다. 다만 이번 배열에서는 첫 목표 도출 규칙이 전체 목록의 첫 항목이기도 하다. 이 결과만으로 모델 내부의 선택 방법까지 알아냈다고 할 수는 없다.

원문·계획·측정 882개 항목과 기준선 1,649개 항목의 독립 검산에서 차이는 없었다. 이는 보존된 기록의 일관성 판정이다. 실제 외부 서버 실행의 인증, 캐시 영향의 부재, 생성 증명의 깊이를 증명하는 검사는 아니다.

## 2. Consensus Proposal

다음 v061은 규칙 순서를 `[k03,k17,k10]`으로 고정하고 깊이 지시의 `작은`을 `큰`으로 바꾸는 실험으로 정했다. A는 shallow, B는 deep이다. 나머지 요청 바이트, 모델 설정, 문제, 규칙과 출력 형식은 조건 사이에서 같게 유지한다. 10개 seed마다 두 조건을 두 번씩 관측하는 40회 일정이며, ABBA/BAAB를 다섯 블록씩 배정한다.

지시를 따르는 선택이라면 A에서 `k03`, B에서 `k17`이 나와야 한다. 첫 목표 도출 규칙이나 얕은 규칙을 고정적으로 고르는 패턴이라면 둘 다 `k03`이다. 이 두 관측 예측을 우선 비교한다. 세부 사양은 [v061 사전 프로토콜](V061_PROTOCOL.ko.md)에 고정했다.

## 3. Strong Consensus

측정, 인과·통계, 증거 무결성을 맡은 세 검토자가 서로의 초기 의견을 받기 전에 원자료를 확인했다. 다음 사실과 한계에는 모두 동의했다.

|항목|확인 결과|
|---|---|
|실행 기록|40/40 호출, metadata 20개, event 60개|
|deep_first|`k17` 20/20, 전체 위치 0, terminal 순위 0, implied_depth 2|
|shallow_first|`k03` 20/20, 전체 위치 0, terminal 순위 0, implied_depth 1|
|형식·목표 도달 가능성|두 조건 모두 20/20|
|shallow 지시 이행|deep_first 0/20, shallow_first 20/20|
|조건 사이 선택 변화|20/20 대응 비교; 10개 seed 블록에 중첩|
|같은 조건 반복 불일치|각 조건 0/10|
|seed별 B−A|10개 모두 +1.0; shallow 지시 이행의 관측 차이|
|증명 측정|ID 하나만 출력했으므로 actual_D, D, proof_valid, strict_valid는 null|

ABBA/BAAB와 period, 직전 조건, 반복 간격으로 나눠도 이 선택 패턴에 예외가 없었다. 그러나 동일 문제의 seed 반복을 독립 문제 표본으로 세지 않는다. 독립 문제는 K01 하나다. 모집단 성능이나 일반적인 모델 행동의 유의확률·신뢰구간을 이 40회로 계산하지 않았다.

## 4. Material Disagreements

다음 실험의 우선순위에서는 초기 제안이 달랐다. 인과 관점은 `k10`의 위치와 terminal 순서를 함께 바꾸는 4조건 동시 비교를 제안했다. 서로 다른 버전의 실행을 합치지 않고 위치 예측을 분리할 수 있다는 장점이 있다. 측정 관점은 먼저 놓인 `k17`의 전제가 도달 불가능해지도록 바꾸는 2조건을 제안했다. 모델의 선택이 규칙의 실제 도달 가능성을 반영하는지 더 직접적으로 물을 수 있다.

교차검토에서는 지시 반전이라는 세 번째 안을 함께 비교했다. v059와 v060은 위치 패턴에 대한 별도 관측을 이미 제공하지만, 같은 배열에서 깊이 지시 자체를 반전한 비교는 제공하지 않는다. 이번 질문을 그 지시 민감도로 좁히면 변화량이 작고 결과 해석도 명확해진다는 이유로 측정·인과 검토자 모두 v061의 우선순위에 동의했다. 위치와 도달성 대안은 폐기하지 않고 후속 질문으로 남겼다.

증거 검토자는 이전 소스의 판본 감사 공백을 지적했다. 사전 독립 감사는 v060 source r1 ZIP을 대상으로 했고, 현재 r2 ZIP은 README 한 파일이 달랐다. 두 판본의 Python 소스는 같으며 현재 실행 계획의 소스 지문 287개도 현재 소스와 일치했다. Python 지문만으로 두 ZIP 판본 중 무엇을 사용했는지 구별할 수는 없다. 따라서 이것은 이번 원응답 계산의 불일치가 아니라, 변경된 r2 ZIP 전체에 대해 이전 감사 승인을 그대로 적용할 수 없다는 절차상의 한계다. 새 v061은 최종 ZIP을 만든 뒤 별도 검토자가 그 판본을 검사한다.

## 5. Decision by Axis

|판정 축|제3자 의견과 교차검토 후 판정|
|---|---|
|측정 타당성|선택 ID와 외부 규칙 계산으로 도달 가능성과 implied_depth를 측정할 수 있다. 모델이 실제 증명을 구성했는지는 알 수 없다.|
|경쟁 예측|v060은 first-terminal과 40/40 일치하며 absolute-second와 0/40 일치한다. 이번 배열만으로 first-terminal과 first-overall을 구분하지 못한다.|
|단일 전방 적용 설명|deep_first의 `k17`은 뒤에 있는 `k10`으로 전제를 만들어야 한다. 사실에서 즉시 적용 가능한 규칙만 한 번 앞에서부터 훑는다는 엄격한 설명에는 반례다.|
|역사적 일관성|v059도 두 배열에서 first-terminal 예측과 각각 20/20 일치했다. 버전별로 따로 검산한 서술적 재현 근거이며, 합산한 인과 효과량은 아니다.|
|이력·캐시|원응답에 cached count 0/28/280이 기록돼 있다. 반복 간격과 캐시가 연관돼 있고, 결과가 같다는 이유로 캐시 영향이 없다고 결론 내리지 않는다.|
|증거·출처|해시·계획·이벤트·원문·측정은 일치한다. 로컬 기록은 독립 외부 실행 인증을 대신하지 않는다. r1 감사의 r2 적용 공백은 별도로 공개한다.|
|후속 개발|v061에서는 순서를 고정하고 지시만 반전한다. shallow 선택 여부와 direction별 지시 이행을 분리해 채점한다.|

## 7. Required Actions

v061 소스에는 요청의 한 단어 차이 검증, 고정 일정과 해시, 원문·metadata·이벤트·소스 스냅샷 보존, 부분 실행과 미측정의 null 처리를 넣는다. 깊은 지시에서 `k17`을 고르면 shallow_success는 false지만 instruction_fulfilled는 true여야 한다. 양 조건 지시 이행과 선택 전환을 함께 보고, B−A 하나로 성공을 판정하지 않는다.

모의 실행으로 정상·오류·누락·변조를 검사하고, 최종 소스 ZIP을 새 폴더에 풀어 다시 시험한다. 구현에 참여하지 않은 검토자가 봉인된 ZIP과 검증 근거를 확인한 뒤 최종 감사 결과를 별도 validation 문서에 기록한다. 이 분석을 위한 실제 모델 호출은 하지 않는다.

## 8. Optional Optimizations

v061 결과가 나온 뒤 질문에 맞춰 지시×terminal 순서의 동시 비교나 도달성 조작을 선택할 수 있다. 앞선 결과를 보고 조건을 추가한다면 별도 버전과 별도 사전 프로토콜로 남긴다. 현재 소스에 사후 선택할 실험 조건을 숨겨 두지 않는다.

## 9. Unresolved

첫 terminal과 연관된 선택의 내부 원인, 캐시·과거 실행의 기여, 다른 문제·모델·지시 문구로의 일반화는 미확인이다. v061에서 `k03/k17`이 나와도 ‘큰’이라는 단어와 ID·위치의 단순 연상일 수 있고, `k03/k03`이 나와도 모델이 어떤 상황에서도 깊은 경로를 선택하지 못한다는 뜻은 아니다. 실제 증명 DAG의 유효성과 깊이는 별도 출력과 검증이 필요하다.

## 10. Method / Run Summary

MEDIUM 수준의 패널로 측정·구성 타당성, 인과·통계·실행 이력, 증거·소스 무결성의 실패 가능성을 나눴다. 세 검토자는 `fork_turns:none`으로 중립적인 자료 위치와 요청을 받고 초기 검토를 수행했다. 그 뒤 후속 설계의 정보가치와 판본 감사 공백을 주장 단위로 교차검토했다. 조정자는 원자료를 따로 재계산하고 결론을 통합했다. 다수결로 사실을 판정하지 않았다.

요청 모델은 gpt-5.6-sol, 추론 수준은 high였다. 생성 도구가 작업 식별자만 반환했으므로 실제 내부 모델 설정은 미검증으로 기록한다. 재위임은 요청하지 않았고 관측된 재위임도 없다. 이 분석의 통합자는 구현에도 참여하므로 분석 통합을 새 소스의 독립 최종 감사로 대신하지 않는다. 최종 소스 감사는 별도 검토자와 봉인된 산출물을 사용한다. 사용자에게 보여 주는 한국어 문서는 humanizer-ko 절차로 사실과 조건을 보존하며 다듬었다.
