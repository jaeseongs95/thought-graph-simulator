# 다각도 검토와 연구 핵심 대응

별도 외부 심사자나 독립 에이전트 호출 결과가 아니라, 상충하는 심사 관점을 원문·구현·반례로 대조한 기록이다. 기술적 검산기는 생산 채점기를 import하지 않는다.

|관점|질문|결정/시험|
|---|---|---|
|측정|규칙 선택만 맞으면 사고 깊이를 실제 생성한 것인가?|아니다. choice는 proof_valid/strict_valid/D를 null로 유지하고 implied_depth만 보고한다.|
|구현|정답 규칙이나 경로를 호스트가 넣었는가?|요청 생성은 원 문제와 방향 문장을 보존하고 채점기를 호출하지 않는다. 정답 enum, 후보 증명, 예시 깊이를 추가하지 않는다.|
|구성타당성|마지막 규칙만으로 경로 깊이를 알 수 있는가?|현재 두 문제에서는 가능하다. 같은 마지막 규칙이 여러 깊이에 대응하는 문제는 거부하는 반례가 있다.|
|비교|Gemma만 유리한 배치로 바꿨는가?|두 모델 모두 merged 고정이며 graph 대조는 동일 배치의 실제 이전 요청과 바이트 동일하다. 원 v056 split 자료도 그대로 보존한다.|
|인과|choice만 맞으면 지시는 이해했지만 생성 때 잊은 것인가?|그 내부 설명은 입증하지 않는다. 서로 다른 호출의 과제별 수행 격차다. 실제 선택값 전달은 후속 실험이다.|
|실패|항상 먼저 나온 경로도 성공으로 보이는가?|first-branch 반례는 두 과제 모두 유효할 수 있으나 선택적 성공은 0으로 판정한다.|
|집계|아직 호출하지 않은 조건을 패배로 세는가?|미관측 별도, 전체 비교율 null. 첫 HTTP 실패 및 두 번째 모델 실패를 시험한다.|
|보존|과거 원문·코드·모델이 덮어써지는가?|별도 v057 폴더, 기존 소스 전 바이트 검사, 원문 ZIP/계획 보존, 모델 pull 없음.|

## 초안에서 실제 발견한 실행 결함

실제 v056 ZIP 내부의 v055 기준선 ZIP이 8 MiB를 넘는데 새 수입 함수가 그 파일명을 큰 archive 예외로 허용하지 않아 prepare가 실패했다. v055/v056의 두 정확한 기준선 경로만 허용하도록 고쳤다. 일반 응답 8 MiB, 계획 32 MiB, 전체 archive 상한과 경로/목록/해시 검사는 유지했다. 허용되지 않은 다른 ZIP에 같은 예외를 적용하지 않는 시험을 넣었다.

이 교정은 준비 단계 I/O 결함이며 v056 실험의 채점을 변경하지 않는다. 테스트가 처음부터 통과한 것을 수정 전 실패로 꾸미지 않는다. 실제 검증 로그와 최종 결과는 별도 분석·검증 묶음에 제공한다.
