# v062 사전 프로토콜: 지정한 마지막 규칙으로 최소 증명 구성

상태: 실제 v062 결과를 보기 전에 작성한 실험 계약. 이번 소스 제작은 오프라인 검증이며 새로운 LLM 추론을 포함하지 않는다.

## 질문과 범위

Gemma가 K01에서 마지막 규칙을 명시적으로 지정받으면, 그 규칙으로 목표를 도출하는 유효한 최소 부모 연결 그래프를 구성하는가? 지정한 결과를 조건으로 한 구성 능력을 검사한다. 모델이 스스로 얕거나 깊은 경로를 선택하는지, 내부 사고가 깊어지는지, A/M을 제어하는지는 검사하지 않는다.

v061의 choice 형식에서 graph 형식으로 바뀌므로 버전 간 성공률 차이를 형식 하나의 인과 효과로 해석하지 않는다. v062 내부의 A/B는 마지막 규칙 ID 하나만 다르다.

## 고정값과 조작값

|항목|사전 고정|
|---|---|
|기준 자료|독립 검산된 v058_order_02 evidence의 candidate K01/original/shallow choice 요청 10개|
|실제 모델|기준선의 동결 identity에 기록된 `gemma3:4b`와 digest. 설명용 config 이름으로 대체하지 않는다.|
|문제|동일 facts·규칙 내용·goal, 규칙 배열 `k03,k17,k10`|
|공통 새 과제|마지막 규칙을 지정한 최소 `nodes`/`final_node_id` 증명 생성|
|A / B|`target_k03` / `target_k17`; 지시문에서 지정 ID 한 곳만 변경|
|원래 옵션|10개 seed 및 temperature/top_p/top_k/num_ctx 등 원요청 옵션 유지|
|스케줄|SHA256 순위, schedule_seed=6202026, seed별 ABBA 또는 BAAB, 각 5블록|
|예산|10 seed × 4회 = 40회, 블록 전후 metadata 20개, warmup 없음|

정답 DAG·기대 깊이 숫자·정답 노드 ID는 프롬프트에 주지 않는다. 마지막 규칙의 지정은 조건부 구성 과제의 독립변수이며, 자유 선택 과제의 성공으로 집계하지 않는다. 기준 reference의 과거 mode=choice는 출처 설명으로 보존하고 새 실행 slot의 mode/stage는 graph, task는 conditional_construction, direction은 neutral로 둔다.

## 출력과 측정

출력은 정확히 `nodes`, `final_node_id`만 갖는 JSON 객체다. 노드는 1~16개이며 각 노드는 정확히 `id`, `atom`, `rule_id`, `parents`를 가진다. 문자열은 길이 1~128, 부모는 최대 8개다. `rule_id=null`은 사실, 문자열이면 적용 규칙 ID다. 출력 순서와 부모 배열 순서는 의미가 없고 앞쪽 노드를 나중 노드에서 참조해도 된다.

- 노드 ID는 유일하고 부모 ID는 존재해야 하며 같은 부모를 중복 참조할 수 없다.
- 사실 노드는 부모가 없고 입력 facts에 있는 atom이어야 한다.
- 파생 노드는 등록된 규칙을 적용하며 atom이 그 결론과 같아야 한다. 부모 atom의 다중집합은 전제의 다중집합과 정확히 같아야 한다.
- 모든 노드의 논리와 비순환성을 검사하고, 최종 노드는 존재하며 goal을 도출해야 `proof_valid=true`다.
- 모든 노드가 최종 노드의 조상 또는 최종 노드여야 `strict_valid=true`다. 임의로 사용하지 않은 노드를 삭제하여 보정하지 않는다.
- 실제 D는 유효한 증명의 최종 parents에서 사실 0, 파생 `1+max(부모 D)`로 계산한다. 논리적으로 유효하지만 사용하지 않은 노드가 있으면 D는 측정하되 strict는 실패한다. 논리 오류·형식 오류의 D는 null이다.
- `target_rule_match`는 유효한 증명이 지정된 마지막 규칙으로 끝나는지, `instruction_fulfilled`는 strict 유효성과 target 일치를 모두 충족하는지 검사한다.

format·proof·strict·goal·target·instruction, 선택 규칙 ID/위치, 실제 D, 노드 수와 오류를 따로 기록한다. 형식/파싱 실패의 의미 지표는 null이며, 관측되지 않은 호출을 실패나 0으로 채우지 않는다. 완전한 분모와 측정이 확보됐을 때만 전체 성공률을 제시한다.

seed별 네 응답의 ID·D·strict·instruction과 양 조건 반복을 함께 본다. 반복 안정성은 네 응답 모두 strict일 때 계산한다. 노드 이름이나 배열 순서의 문자 단위 동일성을 요구하는 지표는 아니다.

## 결과를 보기 전에 정한 결정

**다음 단계 준비도 통과:** 40회 전부 strict 유효, 지정 규칙 일치, target_k03의 실제 D=1 및 target_k17의 실제 D=2, 10개 seed 모두 조건 내 반복 안정. 이는 한 문제의 조건부 구성 계약에 대한 공학적 준비 기준이다.

통과하면 별도 실험에서 마지막 규칙을 지정하지 않고 shallow/deep 지시만 주는 최소 DAG 대조를 설계할 수 있다. 자동 실행하지 않으며, 통과 자체를 자유로운 D 제어나 A/M 성공으로 표현하지 않는다.

통과하지 못하면 K01 choice 진단을 더 늘리지 않고 실패 층위를 보고한다. JSON 형식, 부모·규칙 논리, 불필요 노드, 목표 도달, 지정 규칙 이행을 구분하고 동일 자료에 맞춘 자동 프롬프트 튜닝을 하지 않는다. 부분 실행이면 준비도 판정은 미완료이며 실패율로 바꾸지 않는다.

## 실행·보존·검산

모델 identity·transport 오류는 중단한다. 자동 retry·repair·resume·모델 다운로드가 없다. metadata 조회를 상태나 캐시 초기화로 해석하지 않는다. 호출 전후 이력, 원문 wire 요청·응답, 동결 계획, 소스 지문, event chain을 보존한다.

생산 요청 생성은 정답·측정 모듈을 참조하지 않는다. 독립 검산기는 생산 요청·측정·집계를 import하지 않고 원자료와 명세에서 재구성한다. 두 구현이 공유하는 명세 자체의 오류 가능성은 남으므로 실제 DAG 반례와 별도 최종 소스 감사를 함께 사용한다. 소스 스냅샷은 증거로 읽기만 한다.

새 배포 ZIP을 빈 폴더에 풀어 manifest 검사와 자체시험을 실행한다. 합성 HTTP fixture와 자체시험은 실제 모델 결과에 합산하지 않는다. 소스 감사와 실제 실행 후 증거 검산의 결론을 구분한다.
