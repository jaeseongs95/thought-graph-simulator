# v061 원자료 검증과 연구 방향 판정

## 1. 최종 판정

**v061 기록은 독립 검산을 통과했다. 현재 조건에서는 깊이 지시가 선택을 바꾸지 못했다. 선택 ID만 반복 측정하는 단계는 종료하고, 실제 부모 연결을 갖는 작은 증명 생성으로 조건부 전환한다.**

중학생 눈높이로 말하면, 지금까지는 학생에게 풀이 전체를 쓰게 하지 않고 ‘어느 마지막 공식을 쓸래?’라고 물었다. 이번에는 ‘짧게 풀어라’와 ‘길게 풀어라’를 바꿔 말해도 같은 공식을 골랐다. 답안 기록이 잘 보관됐다는 것과 학생이 지시를 따랐다는 것은 다른 문제다. 다음에는 마지막 공식을 정해 주고, 거기까지 이어지는 풀이를 실제로 쓰게 한다. 성공해도 혼자 짧고 긴 풀이를 선택했다는 뜻은 아니다.

K01의 시작 사실은 `Ca`, 목표는 `Cc`다. 짧은 풀이는 `Ca —k03→ Cc`로 규칙 적용 한 단계다. 긴 풀이는 `Ca —k10→ Cb —k17→ Cc`로 두 단계다. v061은 마지막 규칙 이름만 받았지만, v062는 이 연결을 모델이 직접 노드와 부모 참조로 쓰게 한다. 이 설명용 풀이 도식은 모델 프롬프트에 넣지 않는다.

## 2. 합의된 제안과 채택안

독립 검토자들은 K01 한 문제의 choice 결과를 실제 D나 A/M 능력으로 확장해서는 안 된다는 점, 같은 선택 실험을 끝없이 이어서는 안 된다는 점에 합의했다. 다음 실험의 우선순위에는 이견이 있었다.

조정자는 v062에 **마지막 규칙 지정 + 최소 증명 DAG 생성**을 채택했다. 두 조건은 같은 문제·규칙 순서·출력 형식·옵션을 사용하고, 지정하는 마지막 규칙 ID만 `k03`/`k17`로 바꾼다. 이미 정해진 결론까지 유효한 부모 연결을 만들 수 있는지 확인한다. 자유로운 깊이 선택, A·M, 내부 사고의 검사는 아니다.

## 3. 강한 합의

- 완료·무결성 통과와 연구 가설 지지는 별개다.
- v061의 모든 원응답은 `{"final_rule_id":"k03"}`였다. 깊게 고르라는 지시는 이 조건에서 이행되지 않았다.
- 같은 seed의 네 번 호출과 같은 K01의 10개 seed를 40개의 독립 문제로 세면 안 된다.
- 선택 ID의 `implied_depth=1`은 생성된 증명 DAG의 실제 D가 아니다.
- 규칙 순서·지시·실행 이력·캐시를 하나의 내부 원인으로 묶어 단정할 수 없다.

## 7. 필수 조치

v062 사전 프로토콜에 조건부 구성 질문, 실제 parents 기반 D 계산, 실패 층위, 40회 예산과 종료 기준을 고정한다. 생산 채점기와 독립 검산기를 분리한다. 정상·변조·누락·부분 실행 반례 및 배포본 새 추출 자체시험 후, 구현에 참여하지 않은 새 검토자가 최종 ZIP을 감사한다. 실제 v062 모델 호출은 소스 검증과 구분하며 이번 제작에서 실행하지 않는다.

## 8. 선택적 후속 작업

v062의 사전 준비도 기준을 충족했을 때만, 별도 계획으로 자유 shallow/deep 최소 DAG 생성 대조를 설계할 수 있다. 이후 문제 수와 표현·규칙 ID·순서를 바꾼 일반화 검사가 필요하다. 이번 소스는 그 실험이나 A/M 조작을 자동 실행하지 않는다.

## 9. 미해결 사항

깊이 문구의 해석, 명시 규칙 지시와 위치 선호의 경쟁, 복잡한 출력 계약 부담, 세션 이력·캐시 및 문제 특이성은 완전히 분리되지 않았다. v062도 한 문제의 조건부 구성 준비도만 측정한다. 40/40이라는 문턱은 다음 단계 착수를 위한 공학적 기준이며 통계적 유의성이나 일반 능력의 증명이 아니다.

## 10. 검토 방법과 실행 요약

MEDIUM 패널로 구성타당성과 연구전략 두 검토자가 같은 중립 입력을 독립 검토했다. 각 초기 의견 후 조정자가 구체적인 반례를 주고 한 차례 조건부 재검토를 받았다. 두 검토자는 원자료 40개를 직접 확인했고, 조정자는 별도로 ZIP·독립 검산·층별 집계를 확인했다. 모델 요청 설정은 `gpt-5.6-terra`, `xhigh`, 새 문맥이었으며, 도구가 실제 모델 설정을 반환하지 않아 실제 적용 여부는 미확인으로 기록했다. 추가 적응형 패널은 사용하지 않았다.

분석 종료 후 두 검토자가 각각 v062 생산 구현과 독립 검산 구현을 맡았다. 따라서 이들의 구현 검토를 새 참여자의 최종 소스 감사로 부르지 않는다. 최종 배포 감사 결과는 ZIP 밖 `validation/FINAL_REVIEW.ko.md`에 따로 기록한다.
