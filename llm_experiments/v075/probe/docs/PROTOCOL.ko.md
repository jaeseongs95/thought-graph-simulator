# v075 — 공유 선택 기반 초기 사실 스키마 종단 대조 r1

## 목적과 배치 경계

원래의 ‘같은 문제/목표에서 D 요구 → 모델 경로 선택 → 유효 증명 생성 → 실제 목표 지지 DAG의 D 측정’ 흐름을 유지한다. v074에서 생성 실패 25건 중 22건이 facts-only 단계에서 규칙 노드를 작성한 데서 시작했다. 이를 근거로 첫 단계의 출력 스키마 제약을 새 종단 배치에서 비교한다. 숫자·공백 진단이나 더 많은 모델 탐색은 하지 않는다.

현재 상태: 소스 작성, 실제 Qwen v075 실행 전. 합성 HTTP·단위시험은 연구 성과가 아니다.

## 고정 요소

모델 `qwen3:4b-instruct`, digest/네이티브 정보/서버 버전/명시 옵션/seed/3문제/후보 카드/선택 지시는 v074 그대로다. 값은 `data/protocol.json`에 고정돼 있다. 참조 입력은 v074 evidence ZIP이며 해시가 다르면 실행하지 않는다.

선택 요청 24개는 v074와 바이트 동일하다. 실제 이번 선택 원응답 하나를 두 생성기가 공유하며 과거 선택을 본실험 입력으로 재사용하지 않는다. 기본 3문제×2seed×2후보순서×shallow/deep 24조건과 참조 12조건은 모두 실행한다. 알려진 실패를 제외하지 않는다.

## 유일한 생성 처치: 첫 facts 스키마

|필드|legacy|fact_only|
|---|---|---|
|nodes 개수|일반 graph 계약 1~16|초기 problem.facts 개수와 동일|
|각 rule|문자열 또는 null|null만 허용|
|각 parents|일반 부모 배열|빈 배열만 허용|
|각 atom/id|일반 문자열|동일한 일반 문자열|

스키마의 제약은 API `format`과 프롬프트의 스키마 설명 양쪽에 일관되게 들어간다. 자연어 지시는 변경하지 않는다. 실험 처치는 세 형태 제약을 함께 적용한 첫 단계 계약이며, 각 제약의 독립적인 효과를 분리하지 않는다. 실제 HTTP 호출의 디코딩 내부 원인도 분리하지 않는다.

atom/id에 정답 enum·const를 넣지 않는다. 호스트가 facts 노드를 써 주거나 model 출력에서 사실만 필터링하지 않는다. 구조 제약 안에서도 잘못된 원자, 중복 ID, 전제 오류는 가능하며 기존 채점기가 실패로 남긴다. 선택된 규칙의 노드와 최종 노드 ID도 모델이 직접 작성한다.

## 같은 선택, 서로 분리된 생성 이력

각 원조건에는 `unit_id`가 있다. 그 아래 `legacy`, `fact_only` 생성 trial을 둔다. 선택 호출은 unit당 1회뿐이다. 참조군은 동일한 실험자 지정 candidate_id를 두 생성기에 제공한다.

프롬프트에 variant 이름이나 정답 D를 주지 않는다. `selection_original`은 두 생성기에서 정확히 동일한 실제 원문·원응답 해시를 가진다. 생성 history는 같은 variant 안에서만 이어진다. `history.source_slot_id`는 `logical_id`이며 두 variant에서 같은 논리 연산 이름을 사용한다. 해당 원문은 `(trial_id, logical_id)`로 같은 variant의 실제 wire record에 유일하게 대응하며 독립 검산기가 이 대응을 검증한다. 이는 원문 내용을 바꾸는 것이 아니라 대응 단계의 식별자를 균형화한 것이다.

동일한 history를 넣으면 rule/final 요청은 두 variant에서 바이트 동일하다. 실제 실행에서는 이전 모델 원응답과 응답 해시가 달라지므로 후속 요청도 그 차이를 그대로 포함한다. 이것을 사후에 일치시키거나 다른 군의 성공한 노드로 교체하지 않는다.

오선택도 고정 후보 표로 그대로 실행한다. candidate_id를 읽을 수 없으면 두 생성기 모두 전달 불가로 미실행을 기록한다. 정답 경로를 대신 선택하지 않는다. 종단 성공의 상한은 이번 실제 선택 성공 범위에 묶인다.

## 일정과 호출 수

- 선택: 24회(공유). 48개 독립 선택으로 세지 않는다.
- 본실험 생성: 두 variant 각각 24건, 최대 136회씩, 합계 최대 272회.
- 참조 생성: 두 variant 각각 12건, 54회씩, 합계 108회.
- 총 최대 추론 404회. 모든 모델 선택이 요구 경로에 맞으면 348회. 모두 짧은 경로면 292회, 모두 긴 경로면 404회. 선택을 전부 매핑할 수 없으면 선택 24회+참조 108회만 기록된다.
- 진행 슬롯은 metadata 12개를 포함해 416개. 선택한 경로 밖의 규칙 슬롯은 skip이며 호출 수에 포함하지 않는다. metadata 한 action은 version/tags/show HTTP 조회이며 모델 추론이 아니다.

실행 순서는 사전 고정 균형 배치다. 각 원조건의 두 variant 선후는 문제/seed/후보 순서/요구에 따라 반전하며 본실험에서는 variant별 12회 먼저, 참조에서는 6회 먼저 배치된다. 무작위 표집이나 GPU 병렬 실행이 아니다.

## 동일한 과학적 채점

`measure.py`와 `stages.py`는 v074/v069과 바이트 동일하게 유지한다. 양쪽 응답을 같은 일반 노드 문법으로 읽고 동일한 facts-only·규칙 적용·부모·goal·불필요 노드 기준으로 판정한다. fact_only의 스키마 제약을 위반하는 응답이 실제로 왔다면 해당 원문을 보존하고 같은 단계 의미 기준으로 실패 처리한다. 예전 실패 응답을 새 문법에 맞게 복구하거나 공백을 정규화하지 않는다.

별도 기록: 공유 선택24/양방향12, 각 군의 초기 사실36, 본실험 생성충실24, 목표D구조24, 종단24/양방향12, 참조12. 같은 원조건의 두 생성기를 짝지어 둘 다 성공/legacy만 성공/fact_only만 성공/둘 다 실패/미측정을 기록한다. 실패 앞 단계 뒤 우연한 최종 정답은 종단 성공이 아니다.

파싱 실패, 의미 오류, 미실행, HTTP/transport/identity, 길이 종료, 생성상한 초과, pending을 분리한다. 미측정은 0이나 D=0으로 대체하지 않는다. 없는 usage 값은 null로 보존하며 합계는 관측된 값의 합임을 표시한다.

## 사전 판정과 종료

각 variant의 종단 공학적 기준은 본실험24/24·양방향12/12·참조12/12와 전체 측정 완료다. 각 variant의 생성 기준은 본실험 선택경로 충실24/24·참조12/12이며 종단과 별도다. 생성만 통과해도 모델 선택 실패를 종단 통과로 바꾸지 않는다.

두 variant 모두 종단 통과하면 기존 계약 보존 원칙에 따라 legacy를 미래 계약 참조 후보로 남긴다. fact_only만 통과하면 사실 전용 출력제약 포함 시스템이라는 범위를 명시해 참조 후보로 남긴다. legacy만 통과하면 새 제한이 유리하다고 주장하지 않는다. 어떤 경우도 P03를 자동 실행하지 않는다.

미완료·미측정이 하나라도 있으면 전체 gate null이다. 두 variant 모두 기준 미달이면 부분 성과와 조건별 오류를 보존하고 이 배치를 종료한다. 결과가 좋아질 때까지 사실/부모/선택/공백/seed 진단을 계속 추가하지 않는다. 다음 프로토콜은 사용자와의 별도 결과 판단 대상이다.

## 해석 한계

같은 선택을 공유한 짝비교이므로 두 생성 결과를 독립 모델 표본으로 합산하지 않는다. 실제 숫자쌍 과제가 아니라 세 기존 개발 문제의 후보 선택·생성이다. 규칙 수와 D의 대소가 일치하는 개발 세트이므로 깊이 개념과 목록 길이 휴리스틱 구분은 미측정이다. 내부 은닉층 제어, A/M 또는 세 축 독립성, 새 문제 일반화, 동일 비용 우월성은 이번 결과로 주장하지 않는다.

이전 v074 baseline 8/24·3/12쌍·참조3/12는 동결한다. 과거 실행과 새 한 군의 차이만으로 효과를 주장하지 않고, 새 배치 안의 두 군과 개별 성공/실패를 비교한다. 선택 요청·스키마 설명·모델 식별·원문 전달·생략·계수·한국어 보고서까지 독립 재구현으로 검산한다. 증거의 내부 일관성 검산이지 외부 실행 인증은 아니다.
