## 1. 결론

성공한 실제 종단 쌍은 `p0_s0_o1`, `p0_s1_o0`, `p0_s1_o1`이다. 각 쌍의 shallow D=1, deep D=4이며 최종 증명·단계 계약 모두 유효하다. 한 문제 T02의 후보/seed/순서 변형이지 서로 다른 세 문제에서 일반화한 결과가 아니다. 현재 세 개발 문제에서는 규칙 수와 D의 대소가 일치하므로, 모델이 의존 깊이 개념 자체를 사용했는지까지 분리하지 않는다.

E02는 후보 순서와 무관하게 두 규칙의 짧은 경로를 선택했다. 따라서 작은 D 4/4, 큰 D 0/4다. v075에서는 이 선택기를 그대로 유지하므로 생성 개선만으로 이 선택 오류가 해결된다고 가정하지 않는다.

178회는 중단이 아니다. 선택된 경로 밖의 규칙 슬롯 36개가 계획대로 생략됐다. 214 최대 추론 슬롯에서 36개를 뺀 값이 178이며 action 226은 생략/metadata를 포함한 진행 슬롯이다.

‘첫 사실 단계 실패’ 22건 모두 실제 원응답에 rule이 null이 아닌 규칙 노드가 포함됐다. 요청은 초기 사실만 작성하라고 했지만, 일부 응답은 그 시점에 전체 또는 여러 규칙의 graph까지 작성했다. 이후 고정 순서대로 규칙 노드를 추가하는 과정에서 노드 ID 중복이나 사용되지 않는 노드가 남았다.

예: `t003_facts`는 Lp, Ls 두 사실뿐 아니라 r21, r57, r04, r69의 결과까지 출력했다. 이어지는 규칙 호출은 그 사실 배열을 삭제/필터링하지 않고 그대로 받았다. 최종 graph는 중복 ID를 포함해 실패했다. ‘첫 응답에서 사실만 골라 남기면 된다’는 방식은 현재 무보정 원칙에 어긋나므로 수행하지 않았다.

초기 사실이 정상이었던 실패 3건은 모두 E01의 n37 전제 연결에 있다. 모델군 `t016`, `t019`는 Ax와 Ay만 연결하고 필요한 Ab를 누락했다. 참조군 `t022`는 Ax, Ay, Ab가 아니라 초기 Aa, Ab에 직접 연결했다. 첫 사실 스키마 제약이 이 오류까지 해결한다는 근거는 없다.

## 5. 관찰과 원인 가설의 구분

확인된 것은 단계 지시와 실제 산출물이 어긋났다는 사실이다. v074의 첫 facts 출력 JSON Schema는 일반 graph 노드 스키마를 재사용하므로 rule에 문자열과 null을 모두 허용하고, parents도 비어 있지 않은 배열을 허용한다. 따라서 형식상 합법적인 ‘성급한 규칙 적용’이 가능하다. 이는 기존 채점 버그나 호스트의 오답 수정이 아니다. 자연어로만 제시한 단계 경계를 API 출력 계약으로도 제한할 수 있는 설계 지점이다.

왜 모델이 첫 단계부터 graph를 작성했는지, 새 prompt의 어떤 토큰이나 서버 내부 처리가 그 행동을 만들었는지는 이번 자료로 특정하지 않는다. v069의 12/12를 새로운 입력 계약으로 자동 이전하지 않는다. v074의 생성 결과는 별도 계약에서 관측한 11/36이며 그 범위를 그대로 남긴다.

## 6. 다음 선택: v075 한 배치의 종단 대조

v074의 선택 요청은 그대로 보존한다. 각 조건에서 선택을 한 번만 새로 호출하고, 그 실제 원응답을 두 생성기가 공유한다.

- legacy: 기존 facts 스키마.
- fact_only: 첫 facts 스키마의 rule을 null, parents를 빈 배열, nodes 수를 problem.facts의 개수로 제한.

atom과 id의 정답은 스키마에 enum/const로 주지 않는다. 모델이 사실 원자와 모든 노드 ID를 직접 작성한다. 후속 규칙과 최종 노드 단계는 기존 계약 그대로이며 실제 각 생성기의 history를 무보정 전달한다. 구조 제약을 추가하는 사전 개입이지 이미 나온 응답의 보정이 아니다.

두 생성기는 같은 선택과 같은 명시 옵션을 사용하므로 선택 차이를 생성 효과로 오인하지 않는다. 각 단위의 선후를 균형 배치한다. 첫 요청의 스키마(프롬프트에 표시되는 설명과 API format)가 처치이며, 그 뒤에는 서로 다르게 생성된 원응답의 영향도 포함된다. 개별 제약(rule/parents/수량) 중 어느 하나만의 효과나 grammar와 프롬프트 중 하나만의 효과를 분리하는 실험은 아니다.

범위: 모델 선택 24회, 각 생성기 본실험 24건·참조 12건, 총 72개 graph. 최대 404회 추론/416 action, 모두 요구 경로를 선택하면 348회. 두 생성기를 병렬 실행하지 않고 동결된 순서로 순차 실행한다. 새 모델 추론은 소스 개발 중 하지 않는다.

v075는 수치 진단으로 되돌아가지 않으며, 첫 사실 제약이 실제 종단 성공에 얼마나 영향을 주는지 직접 측정한다. 개선·악화·동일·미측정을 모두 보고하고 한 배치 뒤 종료한다. v074는 원래 기준 미달로 닫고 기존 점수는 변경하지 않는다. 세부 사전 기준은 새 장부 r3 및 `PROTOCOL.ko.md`에 둔다.
