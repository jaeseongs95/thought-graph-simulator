# v071 원문 재검산과 v072 의사결정

대상: `v071_depthcompare_20260913_221758_352826_evidence.zip` 및 같은 실행의 independent JSON.

## 결론

v071은 **깊이 계산 2/20, 정답 깊이 입력 선택 28/40, 모델 계산값 기반 실제 경로 선택 24/40, 계산→선택 전체 2/40**이다. 비교 쌍은 각각 정답 입력 10/20, 모델 입력 실제 경로 10/20, 계산→선택 전체 0/20이다. 원래 실패를 보정하거나 성공으로 재채점하지 않았다.

동결 규칙의 `numeric_positive_control_failed_close_contract`에 따라 **이 Qwen 수치 분해 계약은 종료**한다. v072는 같은 모델의 프롬프트·예시·seed 변형을 이어가는 대신, v071의 설치 모델 목록에 기록된 `gemma3:4b`에서 **동일한 계약**을 한 번 검사하는 별도 모델 분기다.

100개 응답은 모두 정해진 payload 스키마에 맞았다. 미실행, HTTP 오류, identity 오류, JSON 파싱 실패, 길이 종료를 오답으로 채워 만든 결과가 아니다.

### 깊이 계산 오류는 실제 원문에 있다

예를 들어 후보 순서가 짧은 경로→긴 경로일 때 T02의 참값 `[1,4]`에 모델은 두 seed 모두 `[2,3]`을 출력했다. E02의 `[2,4]`에도 `[2,3]`, C01의 `[2,3]`에는 `[3,4]`가 나왔다. C02의 같은 순서에서는 `[0,0]`이 나왔다.

정확했던 두 응답은 E01의 후보 순서를 뒤집은 조건으로, 참값과 보고값이 모두 `[2,1]`이었다. 그러나 해당 조건에서 큰 D를 요구한 후속 응답은 인덱스 1을 골랐다. 작은 D 선택만 맞아 전체 성공은 두 건이며, 두 방향 모두 맞은 전체 비교 쌍은 없다.

### 정답 깊이 입력군에서도 수치 선택이 완전하지 않다

|참값의 배열 순서|정답 깊이 입력군|모델 원문군의 실제 경로 선택|
|---|---:|---:|
|작은 D가 앞, 큰 D가 뒤|20/20|20/20|
|큰 D가 앞, 작은 D가 뒤|8/20|4/20|

정답 깊이 입력군의 **큰 D 요청 20건은 모두 `candidate_index=1`**이었다. 실제 큰 값이 첫 번째에 있는 10건은 따라서 모두 틀렸다. 단, 작은 D 요청 일부는 배열을 뒤집었을 때 올바르게 인덱스 1을 선택하므로, 전체를 “항상 0/1만 기계적으로 출력한다”는 단일 규칙으로 단정하지 않는다.

모델 입력군에서 **제공된 숫자 자체에 대한 비교**는 판정 가능한 36건 중 32건이 맞았다. `[0,0]`에서 파생된 4건은 strict min/max가 없으므로 해당 수치 비교 항목이 null이다. 이 사실은 실제 경로의 참 깊이를 맞혔다는 뜻이 아니다. 최종 경로 선택 24/40 및 정확한 계산을 포함한 전체 2/40을 각각 보존한다.

## 3. 관찰 / 설명 후보 / 구분 증거 / 현재 결론

**관찰:** 경로 깊이 계산이 18/20 틀렸다. 정답 숫자를 준 선택에서도 12/40 틀렸다. raw 중간값 전달은 동일 문자열로 이루어졌다. 성공한 최종 선택이 틀린 중간 계산을 덮지 않았다.

**가능한 설명:** 현재 Qwen 모델 패키지와 이 입력·출력 계약 사이의 부적합, 경로 의미 계산의 실패, 수치와 인덱스를 연결하는 선택 실패 등이 후보이다. 가중치, 한국어 지시, 네이티브 채팅 템플릿, 구조화 출력의 상호작용 가운데 실제 내부 원인은 이 evidence만으로 분리되지 않는다.

**구분되는 것:** 전달 과정의 보정·치환을 주원인으로 설명할 증거는 발견되지 않았다. 숫자를 제공해도 실패가 남아 있어 “깊이만 올바르게 계산하면 무조건 해결”이라는 설명은 맞지 않는다. 동시에 수치 선택 실패가 깊이 계산 18건의 오류를 없애 주지도 않는다.

**현재 결론:** 이 Qwen 수치 분해 계약은 필요한 구성요소 기준선을 확보하지 못했다. A/D/M 전체 가설의 반증으로 확대하지 않는다. v069 Qwen의 안내된 증명 구성 12/12도 취소하지 않는다.

## 4. 표본과 반복을 세는 기준

깊이 계산은 20번이다. 각 계산을 shallow/deep 두 선택이 공유한다. 40개 선택을 40개의 독립 깊이 계산으로 세지 않는다.

실제 요청 바이트를 기준으로 보면 계산 요청은 20개가 서로 다르고, 정답 깊이 선택은 40회 중 32개, 모델 원문 선택은 40회 중 16개의 고유 요청이다. 서로 다른 문제에서 같은 숫자 보고가 나오면 선택 인터페이스의 입력도 반복된다. 이 반복은 배정된 실행으로 보존하되 독립 과제의 확대나 새로운 일반화 증거로 해석하지 않는다. 성공률에 독립 표본 가정의 유의성 주장을 붙이지 않았다.

## 5. v072 설계 결정

v071의 동결 명세는 실패 후 동일 모델의 문구/seed 반복을 종료하고, 다른 모델·다른 축·다른 출력 계약은 별도 설계로 진행하도록 한다. 여기서는 **동일 계약을 다른 설치 모델로 검사**하는 한 분기를 선택했다.

v071 `metadata/b00_before/1.response.raw.json`의 설치 목록에는 다음 모델이 실제로 있다.

```text
gemma3:4b
SHA-256 digest a2af6cc3eb7fa8be8504abaf9b04e88f17a119ec3f04a3addf55f92841195f5a
```

Gemma가 더 잘할 것이라는 실험 결과는 아직 없다. 과거 Gemma의 전체 graph 구성 실패와, 이번에 검사하는 깊이 계산/수치 선택도 같은 능력으로 묶지 않는다.

v072는 5문제 × 2seed × 2후보 순서의 같은 20개 block 및 100개 호출을 유지한다. 깊이 계산 20회, 자신의 계산 원문을 이용한 선택 40회, 정답 숫자 양성 대조 40회이다. 생성기 호출은 없다.

문제, 규칙/후보 순서, 지시문, JSON 스키마, sampling/토큰 옵션, 실행 선후를 유지한다. 고정 입력 60건은 v071과 비교하면 API 요청의 `model` 필드만 달라진다. 중간값 의존 선택 40건은 **현 배치의 Gemma 원응답**을 쓰므로 실제 입력 문자열은 달라질 수 있다. 같은 원문을 주었을 때 동일한 요청 생성 함수인지 별도로 회귀시험한다. 실제 실행에 Qwen의 이전 응답이나 정답 숫자를 몰래 대입하지 않는다.

이는 과거 Qwen과 새 Gemma 실행의 비동시 비교이며, 모델마다 네이티브 템플릿·내재 기본값이 함께 달라진다. 성공률 차이가 있더라도 가중치만의 인과 효과로 해석하지 않는다. 후보 목록 내 능력 확인이지 graph 종단 D 제어 성공도 아니다.

## 6. 모델 identity와 실행 보존

모델 이름/digest/tag details와 Ollama 버전은 v071 evidence에 묶는다. 첫 추론 전에 b00_before metadata에서 Gemma의 네이티브 template/system/parameters/model_info/details/capabilities/projector_info를 실제로 읽고, 이후 모든 metadata 확인에서 동일성을 검사한다. 첨부에 없던 Gemma template을 Qwen 값으로 채우거나 관측했다고 가장하지 않는다. 파라미터 문자열의 줄 순서만 사전에 명시한 방식으로 정규화한다.

누락·변경·오류가 있으면 모델 다운로드/갱신/서버 시작/다른 모델 대체 없이 중단한다. 실패 후 새 RunName으로 자동 반복하지 않는다. 실제 중간 응답과 오류는 보존한다.

## 7. 사전 판정

완료·측정 가능할 때 깊이 20/20, 정답 깊이 선택 40/40 및 20/20쌍, Gemma 계산→선택 40/40 및 20/20쌍이면 해당 모델/계약의 기준선이다. 미완료·미측정은 전체 gate null이다. 정답 숫자 대조, 깊이 계산, 자신의 원문을 이용한 선택을 각각 보고하며 하나의 원인으로 압축하지 않는다.

성공해도 Qwen의 v069 구성 결과를 Gemma 구성 성공으로 옮기지 않는다. Gemma 구성 양성 대조 또는 별도 모델 간 연결 실험이 필요하다. 그 작업을 현재 실행에 추가하지 않는다. 실패/부분 성공은 범위를 보존하고 이번 모델 분기를 종료한다.

## 8. 검증 자료

`raw_recalculation.json`에 100개 실제 message.content와 재계산 판정, 20개 단위의 참값/보고값/선택을 보존했다. `production_recalculation.json`은 생산 계산과 기존 보고 일치 여부, `independent_rerun.json`은 별도 검산기 재실행 결과다.

변조 시험과 v072 배포본 시험은 별도 결과 파일에 기록한다. 이 보고서의 v071 실측 결과와 v072 코드/합성 시험을 혼동하지 않는다. v072 실제 Gemma 추론은 여기서 수행하지 않았다.
