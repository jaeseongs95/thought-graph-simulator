# v061 소스 검증 결과

분석과 소스 제작·검증을 완료했다. 봉인된 ZIP에 대한 별도 검토자의 최종 판정은 PASS이며, 7개 감사축을 모두 통과했다. 해결되지 않은 차단 결함은 없다.

## 분석과 구현

v060의 원요청·원응답을 재계산하고 측정, 인과·통계, 증거 무결성의 세 관점에서 독립 검토와 교차검토를 수행했다. v060은 앞의 목표 도출 규칙 선택과 40/40 일치했다. v061은 `[k03,k17,k10]`을 고정하고 지시의 `작은`을 `큰`으로 바꿔 선택 ID의 전환을 검사한다.

조건별 direction과 role_id, 원문 바이트, schedule_seed=6102026, 40호출·20metadata 계획을 고정했다. shallow 선택과 direction별 지시 이행을 분리하고, 두 지시 공동 성공과 선택 변화도 집계한다. 실제 D와 증명 유효성은 null로 둔다. 누락·형식 오류·잘못된 선택을 구분하며 추론 자동 재시도와 응답 수정은 하지 않는다.

## 봉인 대상

파일은 `../releases/v061_direction_choice_source_r1.zip`, SHA-256은 `ee0e877ec0dd80b2210c0530e50f12aad0d55af8fd6b83a3086f32b48167e760`이다. manifest에 336개 파일을 담았으며 연구 증거 ZIP·모델 가중치·검증 로그는 배포 ZIP에 넣지 않았다. 새 압축해제 위치는 `fresh_r1/`다.

독립 감사 대상은 이 ZIP의 정확한 바이트다. 감사 결과와 완료 기록은 ZIP 밖 validation에 남긴다. 그 뒤 ZIP 안의 코드·시험·문서를 바꾸면 기존 판정의 적용 대상에서 벗어나므로 새 판본과 영향받은 검증이 필요하다.

## 독립 최종 판정

분석·설계·구현에 참여하지 않은 검토자가 `source_audit_r1.json`과 `SOURCE_AUDIT_R1.ko.md`에 PASS를 기록했다. 질문·해석 범위, 요청 바이트 격리, 일정·이력·반복, 측정·누락·공동 성공, 증거·독립 재계산, 실행기·manifest·새 압축해제, 보존·문서 판본의 7개 축을 모두 통과했다. 초기 role_id 오류는 해결된 항목으로 남겼고, 실제 모델 실행 미관측과 공유 사양·유틸리티의 한계도 별도로 기록했다.

검토자는 v060과 v059의 보존된 증거를 다시 계산해 `v060_reanalysis_final.json`과 전체 객체가 같음을 확인했다. 최종 판정은 위 SHA-256의 소스 ZIP에 한정된다.

## 보존과 한계

v060 evidence ZIP과 independent JSON의 SHA-256은 작업 시작 때와 같다. 기존 312개 의존 파일도 이전 배포 ZIP과 바이트가 같다. 작업 중 저장소 지침과 Git 상태가 별도로 바뀌어 현재 AGENTS.md와 STRUCTURE.md를 다시 읽었다. 현재 지침은 이 소스 계약과 충돌하지 않는다. 초기 Git 상태의 행 수를 변경 범위 보존의 근거로 사용하지 않았다. 범위 밖 상태를 되돌리거나 변경하지 않았다.

실제 v061 모델 추론은 실행하지 않았다. 이 검증은 소스와 증거 처리의 작동을 확인하며 v061의 연구 결과를 제공하지 않는다. 향후 선택이 지시에 맞아도 일반적인 깊이 제어나 모델 내부 기제를 입증하지 않는다. 해시 검산은 로컬 기록의 내부 일관성 확인이며 외부 실행 인증은 아니다. 독립 검산기와 생산 코드가 공유하는 사양·이전 유틸리티의 공통 오류 가능성도 남는다.
