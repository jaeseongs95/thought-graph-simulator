# 검증 기록과 적용 범위

v057 원문 분석과 v058 소스 시험을 분리했다. 실제 LLM을 새로 호출하지 않았으므로 v058의 연구 성과나 선후 효과를 확인한 것은 아니다.

| 검사 | 실행 결과 | 근거·한계 |
|---|---|---|
| 제출한 v057 다섯 파일 결합 | 통과 | 외부 계획·별도 기준선의 ZIP 내부 바이트 일치, preflight 계획·identity 일치 |
| v057 생산 재감사 | 통과 | 원문에서 재계산한 전체 summary가 저장 summary와 동일 |
| v057 독립 재계산 | 통과 | 480호출, metadata 40개, 비교 4,361필드 불일치 0; 내장 v056 3,738필드 |
| 별도 서술통계 도구 | 통과 | 480개 원문 재계산, 82/5 유효 graph, 33/7 선택 대응쌍, 13/0 양 규칙순서 성공 재현 |

| v057 빠른 회귀시험 | 64통과, 1건 건너뜀 | 65개 시험, UTF-8 모드. symlink 생성 시험은 운영체제 권한 제한으로 건너뜀 |

`v058_selftest_reaudit.log`, `input_validation.json`, `v057_analysis.json`, `v057_regression_utf8.log`는 `llm_experiments/v058/validation/pre_migration/`에 있다. 이 파일들은 구조 이전 전 검증 기록이므로 내용을 변경하지 않았다. 새 경로에서 다시 만든 계획, release와 검증 기록은 기존 이름을 덮어쓰지 않고 각각 `experiments/`, `releases/`, `validation/`에 새 이름으로 둔다. 배포 ZIP 밖 검증 자료는 소스 자체의 구성요소가 아니다.

## 시험이 실제로 확인한 것

- 두 모델의 지정 경계 조건, seed 10개 전체, 동일 seed의 양 순서가 80개 호출·120개 action으로 구성된다.
- 각 요청은 원래 v057 요청 바이트와 같다. 요청 생성은 정답 계산이나 채점 모듈을 import하지 않는다.
- 실제 graph D, choice implied_depth, 선택 ID 변화, 방향 이행, 미실행·미측정이 분리된다. 부분 실행 비교율은 null이다.
- 가짜 HTTP 서버의 완료 80회와 실패 1회 실행을 결과 ZIP으로 만들고 생산 채점기를 import하지 않는 검산기로 다시 계산했다.
- HTTP·metadata·응답 identity·중간 identity 실패 시 정해진 지점에서 멈추고 추론을 자동 재시도하지 않는다.
- 원문 누락·변조, event 중복, 추가 호출, source 누락, ZIP 경로 이탈·중복·해시 오류를 거부한다.
- manifest 해시를 다시 계산한 뒤에도 pair/trial 중복, 선택 ID·변화 횟수 위조, 응답·status 누락, 요청 변조, 추가 파일을 거부한다.

가짜 HTTP 통합시험에서는 **이전 v057 전체 기준선 감사만 mock**했다. 이 부분은 별도의 실제 제출 자료 검사와 실제 계획 준비로 확인한다. 가짜 응답을 새 모델 관측으로 표시하지 않으며, 그 결과를 v057 성과와 합산하지 않는다. 독립 계산도 같은 측정 명세와 과거 독립 도구를 공유하므로 공통 명세 오류 가능성은 남는다.

## 검증 과정에서 발생한 실패와 처리

최초 v057 독립 검산 호출은 입력 상대 경로를 한 단계 잘못 지정해 파일을 찾지 못했다. 경로를 바로잡은 뒤 제출 ZIP 검산이 통과했다. 원자료를 수정하지 않았다.

v058 시험 작성 중 소스가 바뀌어 전체 fake 실행의 최종 감사가 소스 지문 불일치로 중단됐다. 의도된 동결 검사였다. 모든 Python 파일을 고정한 뒤 전체 36개 시험을 다시 실행해 통과했다. 중간 실패를 통과로 합산하지 않았다.

v057 회귀시험의 첫 실행은 기본 `cp949`로 UTF-8 파일을 읽는 기존 시험 3개에서 `UnicodeDecodeError`가 났다. 기존 증거 소스는 보존하고 `PYTHONUTF8=1`과 `python -X utf8`로 다시 실행했다. 결과는 64통과·symlink 1건 건너뜀이다. Windows에서 같은 과거 회귀시험을 실행할 때도 UTF-8 모드를 사용한다.

독립 해석 검토는 “실행 이력에 따라 수행이 달라진다”는 보고서 표현이 현재 증거보다 강하다고 지적했다. 이를 실행 이력·성패의 연관성이 관측됐다는 표현으로 고쳤다. 선택 ID 변화 누락도 소스 검토에서 발견해 두 ID·변화 여부·비교 가능 분모·완료 시 변화율을 추가했다.

36개 시험 통과 후 독립 코드 감사에서 검산기의 거짓 통과 두 건을 재현했다. 이전 기준선 검산이 미완료·불일치를 반환해도 진행했고, 실행 manifest의 endpoint를 바꾼 뒤 ZIP manifest를 재해시해도 통과했다. 기준선 완료·불일치·호출 수 검사와 endpoint 결합 검사를 추가했다. 같은 구간의 버전·자료형·필드 집합·소스 목록 검사도 보강했다. 기준선 오류·타입 위장 6종, endpoint 변조, control 필드 오류 3종을 포함해 전체 39개 시험이 통과했다. 수정 후 독립 소스·해석 검토에서 미해결 지적이 없음을 확인했다.

검산기와 시험 변경 전 만든 `v058_order_01.plan.json`은 당시 준비가 통과한 기록으로 보존한다. 구조 이전 후 최종 소스에서는 새 이름 `v058_order_layout.plan.json`으로 다시 준비한다. 이전 계획은 최신 소스 지문과 다르므로 실행에 사용하지 않는다.

## 아직 확인하지 않은 것

실제 v058 Ollama 추론, 모델 다운로드·갱신, 서버·캐시 초기화, 다른 모델·새 문제 일반화, 캐시의 단독 인과 효과는 검사하지 않았다. 검사되지 않은 항목은 source PASS와 구별한다. 결과 ZIP의 해시는 파일 일관성 근거이며 외부 실행을 인증하는 전자서명이 아니다.
