# v061 사전 프로토콜: 고정 배열에서 깊이 지시 반전

## 질문과 적용 범위

v060은 앞에 제시된 목표 도출 규칙을 선택하는 패턴과 일치했다. v061은 `[k03,k17,k10]`이라는 한 배열에서 깊이 지시를 반전하면 선택 ID도 바뀌는지 묻는다. 대상은 감사 가능한 v058 원요청의 Gemma 후보 모델, K01, original 문제, choice 출력 방식이다. v060 결과는 후속 질문의 근거이며 새 관측값으로 복사하지 않는다.

관측 대상은 규칙 ID 선택이다. `k03`은 깊이 1, `k17`은 `k10`을 전제로 하는 깊이 2의 유효 경로 끝 규칙이다. 이 깊이는 외부 규칙 계산의 implied_depth다. 모델이 생성한 증명 DAG가 없으므로 actual_D, D, proof_valid, strict_valid와 selective_D_control은 null이다.

## 고정 사항과 조작

두 조건의 배열은 모두 `[k03,k17,k10]`이다. facts, rules의 내용과 ID, goal, JSON Schema, 모델, 옵션과 seed를 고정한다. source 요청은 감사된 v058의 shallow 조건으로, 원래 배열 `[k10,k17,k03]`을 두 조건 모두 같은 고정 배열로 변환한다. 이후 두 조건 사이의 유일한 바이트 차이는 아래 문장의 `작은`과 `큰`이다.

|조건|깊이 지시|지시를 충족하는 선택|
|---|---|---|
|A: shallow|허용된 유효한 증명 중 최종 지지 깊이가 가장 작은 경로를 선택한다.|`k03`|
|B: deep|허용된 유효한 증명 중 최종 지지 깊이가 가장 큰 경로를 선택한다.|`k17`|

전체 지시의 첫 문장에는 이미 비순환 증명 경로라는 조건이 있다. B에만 추가 수식어를 넣지 않는다. 입력 지시가 없거나 여러 번 있거나 원래 배열이 다르면 요청 변환을 거부한다. 독립 검산기는 기준선 원문에서 기대 요청을 다시 구성하고 실제 wire 바이트와 대조한다.

기준선은 v058 evidence ZIP이다. 준비 단계에서 생산 감사와 독립 검산으로 기준선을 확인한 뒤 원요청·seed·identity를 가져온다. 이전 응답을 새 호출 결과로 쓰지 않는다. 소스와 계획을 수정한 뒤 예전 계획으로 실행하지 않는다. 소스 지문이 맞지 않으면 중단한다.

## 일정과 실행 예산

기존 10개 seed를 모두 사용한다. `schedule_seed=6102026`과 SHA-256 순위를 이용해 다섯 블록에 ABBA, 다섯 블록에 BAAB를 배정하고 블록 순서도 고정한다. 각 조건은 seed마다 두 번, 전체 20번 관측된다. 추론은 총 40회, 블록 전후 metadata는 총 20개다. warmup은 없다.

같은 seed·조건의 두 요청은 바이트가 같아야 한다. 같은 seed의 A/B 요청은 지시 단어만 달라야 한다. 각 호출에 period, sequence, previous_variant, previous_call_id, 이전 같은 조건 호출, repeat_distance를 남긴다. 반복 간격은 1 또는 3이다. 공유 서버·캐시·실행 전 이력을 초기화했다고 가정하지 않는다.

이 일정은 무작위 모집단 표본을 만들지 않는다. 40호출은 K01 한 문제의 10개 seed 블록이며 20개 조건 대응쌍은 블록 안에 중첩된다. p값이나 모집단 신뢰구간을 산출하지 않는다. 시간·캐시·순서별 결과는 기술적으로 살피며 인과 기제를 확정하지 않는다.

## 측정과 사전 판정

형식 유효성, 실제 등록 규칙 선택 여부, 목표 도달 가능한 선택, shallow 선택 여부, direction별 지시 이행을 구분한다. `shallow_success`는 조건과 관계없이 최소 깊이 선택 여부다. `instruction_fulfilled`는 A에서 최소, B에서 최대 깊이 선택 여부이고 `role_match`는 이를 집계에 전달하는 같은 값이다. 따라서 B에서 `k17`을 선택하면 shallow_success=false, instruction_fulfilled=true가 맞다.

형식이 맞지만 `k10`처럼 목표를 도출하지 않는 규칙이나 미등록 ID를 고르면 측정 가능한 실패다. 형식을 읽지 못한 응답과 미실행은 성공 0으로 바꾸지 않고 해당 측정값을 null로 둔다. 실제로 관측한 형식 오류 건수는 별도로 집계한다. 전체 비율은 실행이 완료되고 해당 분모가 모두 측정 가능할 때만 계산한다.

|안정적인 A/B 선택|관측 판정|확정하지 못하는 것|
|---|---|---|
|`k03/k17`|방향 지시 예측과 일치; 두 지시 모두 충족하며 선택 전환|깊이의 내부 계산, 일반적 D 제어, 위치 영향 제거|
|`k03/k03`|첫 terminal 또는 고정 shallow 예측과 양립; B 지시 불충족|위치 기제의 확정, 모든 상황의 deep 선택 불가능|
|`k17/k17`|고정 deep 선택 패턴; A 지시 불충족|깊은 경로 선호의 원인|
|`k17/k03`|방향 지시와 반대인 선택 패턴|반전의 내부 원인|
|그 밖의 ID·오류·반복 불일치|별도 관측으로 공개; 안정 프로필에 편입하지 않음|사후 새 가설을 사전 예측으로 취급|

완전 일치는 해당 조건의 20회 모두가 예측 ID와 같을 때만 말한다. seed별 안정 프로필은 A0=A1, B0=B1이고 네 선택이 모두 측정 가능할 때 판정한다. 누락이나 반복 불일치를 제외하고 분모를 줄여 완전 일치라고 부르지 않는다.

주요 결과는 조건별 ID 분포와 지시 이행, seed별 A0/A1/B0/B1, 조건 내 반복 불일치, 조건 사이 선택 전환, 두 조건 지시의 공동 성공이다. `seed_mean_B_minus_A`는 direction별 지시 이행의 차이로 유지한다. 두 조건 모두 성공해도 모두 실패해도 0이 될 수 있으므로 이 숫자만으로 결론 내리지 않는다. sequence/period/직전 조건/반복 간격별 표와 원응답의 cache count를 함께 확인한다. 같은 결과가 여러 캐시 값에서 나와도 캐시 영향이 없다는 증거로 단정하지 않는다.

## 실행 실패와 증거

실제 추론을 시작한 뒤 자동 재시도·재개·응답 수정·정답 대체를 하지 않는다. transport와 identity 오류는 중단한다. 모델을 자동 다운로드하지 않는다. 부분 실행도 원문과 실패 위치를 보존해 감사하고 별도 evidence ZIP으로 묶을 수 있다. 기존 계획·결과·배포 ZIP을 덮어쓰지 않는다.

외부 계획, 계획 스냅샷, 요청 wire JSON, 응답 raw JSON, metadata, 이벤트 해시 체인, 상태, 소스 스냅샷과 집계를 보존한다. 독립 검산기는 생산 요청·채점·집계 모듈을 import하지 않고 기준선·계획·요청·원응답에서 값과 한국어 요약을 재계산한다. 이전 버전의 독립 검산 유틸리티를 재사용하므로 공유 사양·도구 결함 가능성까지 제거한 것은 아니다. 해시 검산은 내부 일관성을 검사하며 외부 실행을 인증하지 않는다.

## 소스 수용 기준

요청 단어 외 차이, direction 채점 오류, 미측정의 0 변환, 잘못된 source fingerprint와 재해시한 증거 변조를 시험한다. 정상 모의 실행, 부분 실행, 응답 형식·identity·transport 오류와 원문 기반 독립 검산을 확인한다. 모의 출력은 연구 결과로 보고하지 않는다.

최종 소스와 문서를 ZIP으로 묶어 manifest와 SHA-256을 고정하고 새 위치에서 자체시험을 실행한다. 구현에 참여하지 않은 감사자가 최종 ZIP을 검토한다. 감사 후 ZIP 내부 파일이 바뀌면 새 판본을 만들고 영향받은 검증과 감사를 다시 수행한다. 감사 기록은 ZIP 밖 `validation`에 보존해 기록을 추가할 때 감사 대상 ZIP을 바꾸지 않는다.
