# 사전 실험 계약

## 고정과 조작

동결 기준선은 사용자가 첨부한 v055_model_02_evidence.zip 전체다. 성공한 모델·응답·seed만 골라오지 않는다. 완료와 무결성만 수입 조건으로 사용한다. 두 모델 모두 v055에서 사용한 digest, show의 의미 해시, template, server 및 상세정보를 유지한다.

split은 system(전체 지시문) + user(problem)의 원래 요청 바이트다. merged는 user(원 system 내용 + \n\n + 원 user 내용)다. 추가 풀이 지시, 정답 깊이, 정답 예제, 경로 이름, 번역, 스키마 강화 없이 배치만 바꾼다. 역할 태그와 턴 경계가 함께 바뀌므로 효과는 이 묶음의 효과다.

각 seed마다 모델당 24요청 블록을 만든다. 두 모델의 선후는 10seed에서 5:5로 교차한다. 각 블록 12조건의 split/merged 선후는 6:6이다. metadata는 블록 전후 40회이며 각 record는 version/tags/show 3개 HTTP 응답을 보존한다. 자동화 사전검사도 두 모델 각각 같은 metadata를 별도 보존한다. 이것들은 추론 횟수에 포함하지 않는다. 워밍업 추론은 0이다.

## 판정

- 응답을 읽을 수 없는 경우 증명 유효성은 null이다. 읽은 증명에 잘못된 규칙·부모·사실이 있으면 false다.
- 최종 노드 ID 존재 여부와 증명의 논리 유효성은 분리한다. 이름 자동 보정, 누락 사실 추가, 경로 삭제, 원하는 경로 선택을 하지 않는다.
- 각 모델·배치의 주 판정은 방향쌍 40개다. 두 순서 모두에서 성공하는 20묶음과 순서 비교 60쌍은 같은 120응답을 재집계하는 것이지 새 표본이 아니다.
- 새 480회가 미완료라면 전체 비교율은 null로 둔다. 미관측을 어느 배치의 패배로 세지 않는다. HTTP 요청 시도·관측 응답·유효 증명을 서로 구별한다.
- 유효성 개선은 별도의 진단 결과다. 한 고정 경로를 유효하게 반복한 모델을 D 제어 성공으로 인정하지 않는다.

## 결과별 해석

1. 병합에서 증명 유효성·선택적 D 제어가 함께 개선: 현재 모델의 외부 기록 제어가 배치에 의존한다는 증거. 개선 범위와 모델·문제·순서를 따로 보고한다.
2. 유효성만 개선: 입력/증명 작성 경계가 개선됐지만 D 제어 문제는 남는다. 다음에는 지시 이해·경로 선택과 실제 생성의 분리를 검토한다.
3. 두 배치에서 실패: 이 병합 개입은 효과를 보이지 않았다. 원인을 '학습된 자기 사고 우선'으로 확정하지 않고 다른 원인 분리 또는 operationalization 재검토로 진행한다.
4. split에서도 새 성공: 이전 결과와 새 반복의 변동을 먼저 분석한다. 병합만의 효과로 몰아가지 않는다.

현재 모델·고정 문제 2개의 결과다. 파라미터 수, 일반지능 순위, 모든 프롬프트/모델 또는 내부 사고 제어의 결론으로 확대하지 않는다.
