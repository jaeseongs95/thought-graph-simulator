# v059 결과의 다각도 분석과 후속 설계

## 1. Executive Verdict

v059에서는 배열을 바꾸자 선택한 규칙이 `k17`에서 `k03`으로 일관되게 바뀌었다. 원래 배열의 shallow 지시 이행은 0/20, 교환 배열은 20/20이다. 40회 모두 전체 규칙 배열의 두 번째 항목을 골랐으며, 같은 조건의 반복 20쌍에서는 선택이 바뀌지 않았다.

이 결과는 **해당 K01 choice 요청의 배열 순열 민감성**을 지지한다. 현재 두 배열에서는 첫 목표 도출 규칙과 전체 배열의 두 번째 규칙이 같으므로, 어느 기준으로 선택했는지는 구분할 수 없다. 선택 ID를 경로에 대응시켜 계산한 `implied_depth`를 실제 생성한 증명의 D로 해석해서도 안 된다.

A의 표현 수준이나 M의 검토 수준을 조작한 실험도 아니다. 따라서 A/D/M 전체 제어 능력에 대한 판정으로 확장하지 않는다.

## 2. Consensus Proposal

분석 범위의 합의 상태는 `conditional_consensus`다. 수치와 관측 범위에는 합의했으며, 후속 설계의 해석에는 아래 조건을 붙인다.

v060에서는 `k10`을 마지막에 고정하고 A=`[k17,k03,k10]`, B=`[k03,k17,k10]`을 비교한다. 모델·문제·규칙 ID와 의미·지시·옵션을 유지하고 같은 10개 seed를 조건마다 두 번 관측한다. 40회는 반복 안정성 검사를 포함한 예산이다. 단순한 두 예측의 비교만 한다면 20회도 가능하지만 조건 내 반복 정보를 잃는다.

|관측 예측|A: deep_first|B: shallow_first|
|---|---|---|
|첫 목표 도출 규칙|k17|k03|
|전체 배열의 두 번째 규칙|k03|k17|
|항상 얕은 규칙|k03|k03|
|항상 깊은 규칙|k17|k17|

이 표의 행은 모델 내부 기제가 확인됐다는 뜻이 아니다. 첫 행은 첫 전체 항목 선택과도 같고, 둘째 행은 마지막 목표 도출 규칙 선택과도 같다. 항상 `k03`을 고르는 패턴은 shallow 지시 이행 외에 앞에서부터 한 번만 읽는 전략과도 양립할 수 있다.

## 3. Strong Consensus

생산 채점기를 import하지 않는 기존 독립 계산기로 ZIP을 재검산했고, 새 재분석 도구에서도 원요청·원응답의 선택을 다시 계산했다. v059 비교 802개 필드와 기준선 비교 1,649개 필드에서 차이가 없었다.

|지표|original|terminal_swap|
|---|---:|---:|
|계획/관측|20/20|20/20|
|형식 유효|20|20|
|목표를 도출할 수 있는 규칙 선택|20|20|
|선택 ID|k17 20회|k03 20회|
|선택 위치, 0기준|1 20회|1 20회|
|선택에 대응하는 implied_depth|2|1|
|shallow 지시 이행|0|20|
|같은 조건 반복의 ID 불일치|0/10쌍|0/10쌍|

10개 seed 모두 A0=A1=`k17`, B0=B1=`k03`이다. seed별 평균 B−A는 모두 1이고, 그 평균도 1이다. 조건 간 20쌍은 seed 10개에 중첩되며 독립 문제는 하나다. ABBA/BAAB 각 5블록, 각 period에서 조건별 5회라는 배치에서도 동일한 패턴을 관측했다.

## 4. Material Disagreements

|쟁점|초기 주장 또는 가능한 해석|교차검증과 최종 처리|
|---|---|---|
|완전한 선택 전환이 원인을 특정하는가|40/40이므로 두 번째 항목을 고르는 기제가 확인됐다|첫 목표 도출 규칙과 두 번째 항목의 예측이 현재 자료에서 같다. 관측 패턴은 채택하고 내부 기제의 확정은 기각했다.|
|순서와 이력이 배제됐는가|각 period에서 패턴이 같으므로 순서 설명이 반박됐다|단일 period·seed·sequence·직전 조건만으로 설명하기 어렵다는 범위로 좁혔다. sequence×period는 variant를 결정하므로 상호작용과 고차 이력은 배제하지 못한다.|
|후속에서 여섯 순열이 필요한가|가능한 위치를 전부 조사해야 한다|현재 동치인 두 예측을 가르는 데에는 두 새 배열이면 충분하다. 모든 위치 전략의 식별은 후속 범위에서 제외했다.|
|k10 후치가 실험을 무효화하는가|전제 생산 규칙이 뒤에 오므로 비교가 불가능하다|v060의 A/B 안에서는 k10 위치가 같아 대비를 유지한다. 다만 v059의 기제가 새 배열에도 그대로 적용된다는 전제는 두지 않는다.|
|선택 유효성이 전체 과제 성공인가|v059의 task_valid=true면 지시까지 이행했다|k17도 목표 도출 규칙으로 유효하지만 shallow 지시에는 실패한다. v060은 goal_reachable_choice와 instruction_fulfilled를 분리한다.|
|여러 문제와 외부 환경 봉인이 필요한가|증거 검토자는 일반화와 장기 재현성을 위해 여러 문제·직교 배치·실행 환경 봉인을 제안했다|이번 목표인 두 관측 예측의 최소 비교와 분리했다. 일반화·외부 인증은 현재 수용 조건에 포함하지 않고 미해결 한계로 남겼다.|

측정 검토자는 D의 구성타당성과 지표 명칭을, 인과 검토자는 관측적으로 동치인 설명과 후속 조작의 최소성을 서로 반박했다. 다수의 동의보다 각 주장이 원응답과 반례를 견디는지를 기준으로 범위를 정했다.

## 5. Decision by Axis

관점은 역할 이름을 먼저 정해 채운 것이 아니라, 이 결과를 잘못 해석할 수 있는 실패 방식에서 도출했다.

|분석 관점|잘못될 수 있는 판단|직접 확인할 근거|제3자 판단과 소스 요구|
|---|---|---|---|
|측정 정의|ID 선택을 생성 증명의 깊이로 바꿈|원응답, 선택 채점기, D 필드|choice의 implied_depth만 관측했다. actual_D와 proof_valid는 null을 유지한다.|
|과제 이행|형식·선택 유효성을 shallow 성공으로 합침|k17과 k03의 전제·결론 및 지시|형식, 목표 도달 가능 선택, shallow 지시 이행을 따로 집계한다.|

## 7. Required Actions

v060 구현은 두 배열의 원요청 바이트 차이를 규칙 배열 구간으로 제한하고, 실행 전에 모든 요청 해시를 고정해야 한다. 누락·파싱 불가·유효하지 않은 ID·유효하지만 shallow를 어긴 선택을 서로 다른 상태로 보존한다. 요약에는 전체 선택 위치와 terminal 순위를 추가한다.

실제 호출 전에 최종 소스에서 새 계획을 만들고 자체시험을 통과해야 한다. 실제 실행은 사용자의 별도 명시 요청으로 수행한다. 이번 작업의 소스 제작·검증에는 실제 모델 추론을 포함하지 않는다. 최종 배포본과 소스 검증의 결과는 v060 `validation/FINAL_REVIEW.ko.md`에서 별도로 보고한다.

## 9. Unresolved

캐시의 인과적 영향, 서버의 외부 이력, 모델 내부의 실제 계산 경로는 이 자료에서 관측하지 못했다. 규칙 ID와 내용의 상호작용도 완전히 분리하지 않았다. 해시와 독립 검산은 서로 맞는 기록임을 확인하지만, 기록자가 원문·해시·계획을 함께 재작성하는 위협까지 막는 외부 인증은 아니다. 두 구현이 같은 문제 명세를 오해할 위험도 남는다.

`production_imports=false`는 v059 생산 모듈을 import하지 않는다는 제한된 뜻이다. 독립 계산기도 v058 검산기와 v057의 독립 유틸리티를 사용한다. 현재 소스 지문의 일치는 당시 Python 파일이 보존됐음을 확인하지만, Python/Ollama 실행파일·하드웨어·backend·캐시까지 봉인하거나 같은 출력을 보증하지 않는다. metadata identity 검사는 선택한 필드와 parameter 줄 순서 정규화를 기준으로 하므로 미추적 필드 변화 가능성도 남는다.

## 10. Method / Run Summary

로컬 자료에 대한 MEDIUM 패널로 측정·구성타당성, 인과·통계·최소 설계, 증거·재현성의 세 검토자를 별도 컨텍스트에서 시작했다. 초기 판단을 받은 뒤 주장 단위로 교차검증했고 메인이 원자료와 재계산 결과로 통합했다. 별도 전문 검토자 추가나 전체 재투표는 하지 않았다. 이 분석 단계에는 fresh Judge를 두지 않았으며, 최종 소스에는 구현에 참여하지 않은 별도 감사자를 배정한다.

세 검토자 생성에는 `gpt-5.6-sol`·`high`를 요청했다. 도구 응답이 작업 식별자만 반환하므로 실제 모델·추론 적용 상태는 `unverified`다. 별도 컨텍스트는 관찰 가능한 생성 방식에 대한 기록이며 서로 다른 공급자·학습 전제·사람 전문가의 독립성을 뜻하지 않는다. 초기 검토와 교차검증을 분리해 기록했다.
