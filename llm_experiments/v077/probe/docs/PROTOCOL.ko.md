# v077 프로토콜

공식 계획은 `PLAN_LEDGER.ko.md`, 실행 가능한 동결 데이터는 `../data/protocol.json`이다.

질문: 같은 선택에 대해, 모델이 전제→부모 ID 대응표와 node를 같이 작성하는 계약이 실제 유효 규칙·종단 graph를 늘리는가?

base 규칙 응답은 `{"node":...}`다. premise_binding 규칙 응답은 `{"bindings":[{"premise":"...","parent_id":"..."}],"node":...}`다. 대응표는 모델이 직접 작성하며 호스트는 전제-부모 정답을 생성하지 않는다. 부모 수 제한은 채택하지 않는다. 첫 사실·선택·규칙 본문·최종 ID 계약은 기존 base를 유지한다.

`bindings.py`는 실행 후 오프라인 채점에서만 사용한다. `audit_bindings.py`는 별도 구현이다. 고정 투영은 원응답의 node 값을 그대로 기존 증명 채점기에 전달하는 것이며, 대응표를 이용한 부모의 생성·수정·정렬·노드 삭제가 아니다. 틀린 표 뒤 맞은 graph는 graph-only 결과와 계약 실패를 각각 보존한다.

최대404회, 416슬롯, 공유 선택24개, 각 군 본실험24개·참조12개. 실제 호출 수는 경로 선택에 따라 달라진다. 기존 실패의 보정·반복실행·자동 모델 교체·자동 서버 시작·후속 단계 실행은 없다.
