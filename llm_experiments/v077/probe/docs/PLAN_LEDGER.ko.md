## 3. 이번 설계 판단 — 새 결정이며 효과는 아직 미측정

부모 수 강제와 존재하는 ID 강제만으로는 실제 전제 대응 오류가 제거되지 않았다. 이번에는 모델이 이미 제공된 규칙과 자기 이전 원응답에서 **전제 원자 → 실제 부모 노드 ID**를 직접 명시하게 한다. 정확한 부모를 호스트가 찾아 주거나 스키마 enum에 넣지 않는다.

`base`는 v076의 base 계약을 유지한다. `premise_binding`은 규칙 호출 한 번 안에서 `bindings`와 기존 `node`를 함께 출력한다. bindings를 실행 중 채점한 뒤 node를 고치는 단계는 없다. 추가 숫자 퀴즈·규칙 선택 호출·별도 매핑 호출도 없다.

두 군 모두 초기 사실 전용 스키마와 content-only 이력을 유지한다. **부모 수 제한은 두 군 모두 적용하지 않는다.** 선택기는 v076 요청과 동일하다. E02 경로 선택을 이번 생성 변경이 고친다고 가정하지 않는다.

## 4. 새 출력 계약과 무보정 경계

규칙 호출의 새 형식은 `{"bindings":[{"premise":"모델 작성 전제","parent_id":"모델 작성 부모 ID"}],"node":{...}}`다.

- bindings 길이는 일반 상한 0~16만 사용하며 현재 규칙의 정답 개수로 고정하지 않는다.
- premise와 parent_id는 일반 문자열이다. 정답 전제·부모 ID의 const/enum은 제공하지 않는다.
- node 스키마는 base와 바이트 동일하다. 호스트가 부모를 표에서 만들어 넣지 않는다.
- 최종 graph 구성에서는 모델의 node 필드만 고정 투영한다. bindings는 별도 의무 검사한다. 값 수정·정렬·노드 삭제는 없다.
- 실제 bindings와 node가 담긴 전체 `message.content`를 다음 호출로 그대로 전달한다. 잘못된 표도 보정하지 않는다.
- 전체 HTTP 응답·해시·dispatch·시각·토큰 계수는 evidence에 보존하되 모델 입력에는 감사 해시를 넣지 않는다.
- 생성기는 요청한 작은/큰 D를 다시 받지 않고 실제 선택 경로만 구성한다. 잘못된 선택도 정정하지 않는다.

## 5. 대응표 검사의 의미

실행 후 두 검산 구현이 별도로 확인한다.

1. 대응표의 전제 다중집합이 현재 지정 규칙의 전제와 같은가?
2. 각 parent_id가 이전 원응답의 유일한 노드이며, 그 노드의 atom이 표의 premise와 같은가?
3. 표의 parent_id 다중집합이 실제 node.parents와 같은가?
4. 기존 단계·전체 graph 검증에서 사실·규칙·부모·최종 목표·ancestry·불필요 노드·실제 D가 유효한가?

잘못된 부모에 맞춰 거짓 전제를 적어 일관되게 보여도 1번 또는 2번에서 실패한다. 정답 표와 잘못된 node를 함께 내면 3번과 기존 graph 검사에서 실패한다. node가 맞고 표만 틀린 경우에는 **node 기반 종단 성공을 별도로 보존하되 새 대응표 계약 전체 성공은 실패**다.

이는 대응표를 A/D/M 전체의 필수조건으로 승격하는 것이 아니다. 새로운 생성 인터페이스를 시험하기 위해 해당 군에만 부과한 조건이다. 동일한 산출물 수준의 비교를 위해 `model_graph_only_trace`, `model_target_structure`, 규칙 유효성도 함께 보고한다. 표 스키마를 충족하지 못하면 새 계약은 미측정이며 기존 값으로 보충하지 않는다. 단, 동일 원응답의 node가 정상적으로 읽히면 graph-only 관측은 유지한다. 전체 응답 JSON 자체가 깨져 node도 읽히지 않으면 graph 역시 미측정이다.
