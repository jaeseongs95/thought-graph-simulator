## 4. 부모 수와 실제 전제 연결은 다른 지표다

base에서 부모 수가 잘못된 규칙은 5개였고, parent_count에서는 다섯 개 모두 개수가 맞았다. 그러나 그중 의미적 규칙 적용까지 바로잡힌 것은 2개뿐이다. 나머지 3개는 개수는 맞지만 잘못된 부모를 골랐다. 기존에 의미적으로 맞았던 다른 규칙 3개도 새 군에서 틀렸다.

parent_count의 규칙 오류 10개는 모두 `premise_counter_mismatch`다. 부모 ID가 중복되거나 존재하지 않는 경우가 아니라, **존재하는 노드를 선택했지만 그 노드의 원자가 필요한 전제와 다르다.** 최종 노드 ID는 72개 graph 모두 존재하는 목표 노드를 가리켰고, 규칙 출력 순서도 선택 경로와 일치했다. 마지막 문자열과 목록 형식만 확인했으면 이러한 실패를 놓쳤을 것이다.

### 개선 사례 — E01 t016

규칙 `n37`: `Ax AND Ay AND Ab → Ag`.

기존 이력에서 `n01=Aa`, `n02=Ab`, `n03=Ax`, `n04=Ay`다.

```text
base:         parents = [n03, n04]       → Ax, Ay       → Ab 누락, 실패
parent_count: parents = [n03, n04, n02]  → Ax, Ay, Ab   → 유효한 D=2 증명
```

`t020`에서도 최종 규칙이 올바른 세 부모를 연결하면서 전체 성공으로 바뀌었다. 두 개선 모두 해당 규칙 직전의 원문 이력이 동일하고, 요청 차이는 부모 길이 제약 및 그 스키마 설명뿐이었다.

### 악화 사례 — E01 t022

```text
base:         parents = [n03, n04, n02] → Ax, Ay, Ab → 성공
parent_count: parents = [n01, n02, n03] → Aa, Ab, Ax → Ay 대신 Aa, 실패
```

두 응답은 모두 부모 세 개다. 동일한 이전 이력에서 새 제약군이 필요한 전제를 잘못 골랐다. 따라서 ‘부모 수가 맞으면 전제 연결도 해결된다’는 설명은 이 원문과 맞지 않는다.

### 악화 사례 — E02 t025

규칙 `m05`: `Pu AND Pb → Pv`.

```text
base:         [node_pu, node_pb] → Pu, Pb → 성공
parent_count: [node_pa, node_pb] → Pa, Pb → Pu 대신 Pa, 실패
```

이 사례도 이전 이력은 동일하고 부모 수는 둘 다 2개다. 파생 사실 Pu와 그보다 앞선 초기 사실 Pa의 노드를 구분하지 못한 출력이 관측됐다. 이를 모델 내부의 특정 메커니즘으로 확정하지는 않는다.

### E01

### E02

선택 요청과 선택 원응답은 v075와 동일하다. 큰 D를 요구해도 짧은 `m18 → m76`을 선택한다. 두 생성기는 선택된 짧은 경로를 각각 8/8 정확하게 구성했지만, 그중 큰 D 요구 4개는 유효 D=2이므로 종단 실패다. 생성에 실패한 것과 요구에 맞지 않는 경로를 충실히 실행한 것을 구분한다.

긴 경로는 본실험에서 선택되지 않았다. 별도 참조에서 base는 긴 경로 2/2를 구성했고, parent_count는 1/2였다. 이 참조 성공을 자율적인 큰 D 선택 성공으로 옮기지 않는다.

- E02 선택 오류 4건: 짧은 경로를 정확하게 구성했지만 요구 D와 다름.

사전 장부는 초기 사실을 공유하지 않고 별도 호출하도록 정했으며, 동일 요청에서 반드시 동일 응답이 나온다고 가정하지 않았다. 따라서 설계 위반은 아니다. 그러나 전체 종단 차이를 전부 특정 한 규칙의 길이 제한 때문이라고 단정하는 데에는 주의가 필요하다.

## 7. 사전 기준에 따른 결정과 연구 방향

r4는 본실험24/24·양방향12/12·참조12/12를 종단 기준으로, 선택 경로 구성24/24·참조12/12를 생성 기준으로 정했다. 두 군 모두 미달이고 미측정은 없으므로 gate는 null이 아닌 false다. P02-C/v076 배치를 종료하며 P03은 실행·승인된 상태가 아니다. 기존 장부 원문은 수정하지 않는다.

**이번 결과만으로 parent_count를 기본 생성기로 전면 채택할 것을 권하지 않는다.** E01 두 조건의 개선은 실제이고 보존할 가치가 있지만, 참조군 세 조건의 악화와 전체 규칙 정확성 73/82→72/82도 함께 있다. 형식 제약을 더 강하게 넣으면 증명 의미가 단조롭게 좋아진다는 결론은 지지되지 않는다.

다음 설계 판단의 초점은 단순 배열 길이가 아니라 실제 필요한 전제와 노드 ID를 연결하는 동작, 그리고 E02의 경로 선택이다. 존재하는 노드 ID만 쓰도록 하는 검사만으로는 이번 parent_count의 10개 오류를 해결할 수 없다. 그 오류들은 이미 존재하는 노드를 잘못 골랐기 때문이다. 정답 부모를 호스트가 선택해 스키마에 고정하면 현재 모델 연결 능력 검증과 다른 시스템이 되므로 구분해야 한다.

이는 다음 진단이나 새 소스를 자동 승인하는 결론이 아니다. 현재 요청에 따라 결과 분석만 수행했다. 원래의 종단 D 평가, 실패 원문 보존, 무보정, 문제·seed 반복 구분을 유지한다.

세 개발 문제에서 부분적인 종단 D 제어는 실제로 존재한다. 그러나 안정적인 전체 생성기나 확인 세트 일반화는 확보되지 않았다. 이번 결과를 A/D/M 전체 실패로 확대하거나 기존 성공을 삭제하지 않는다.
