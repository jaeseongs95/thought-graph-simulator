## 이번 설계의 선택과 한계

모델 작성 대응표는 한 번의 규칙 호출 안에서 기존 node와 함께 생성한다. 호스트가 정답 전제를 맞는 ID에 연결하는 표를 제공하지 않으므로 모델의 연결 능력을 그대로 측정한다. 선택기를 고정하므로 E02 선택 오류의 해결을 주장할 수 없다. 정확한 수치 깊이 보고를 필요조건으로 추가하는 하위 진단이 아니다.

대응표의 추가 요구가 오히려 오류·토큰량을 늘릴 수 있다. 그래서 기존 base와 같은 배치에 짝지어 실행하고 node 기반 성공과 표를 포함한 전체 성공을 나눠 보고한다. 첫 사실은 각 군 별도 생성되며 이전 이력도 달라질 수 있다. API schema·문구·추가 출력·후속 이력을 하나의 생성 계약으로 비교한다. 효과의 내부 원인은 이 비교로 식별하지 않는다.

parent_count를 함께 쓰지 않는다. 대응표로부터 graph.parents를 호스트가 구성하지 않는다. 잘못된 대응표를 validator가 보고 실행 요청을 바꾸지 않는다. 실패하는 표도 다음 호출에 원문 그대로 전달한다.

## 필수 반례

정답 node+틀린 표, 정답 표+틀린 node, 잘못된 노드와 일치하도록 거짓 전제를 적은 표, 누락/중복 전제, 존재하지 않는/현재/모호한 부모 ID, 순서만 다른 유효 표, 잘못된 선택 뒤 맞은 생성, 파싱불가 중간값, 중단·HTTP·identity·예산 오류, 표를 일관되게 후속 요청에 전달한 뒤 옛 성공 집계를 붙인 변조를 검사한다.

실제 모델 추론은 코드 시험과 별개다. 전체 graph·단계 채점 파일은 v076 원문과 동일하게 유지한다.
