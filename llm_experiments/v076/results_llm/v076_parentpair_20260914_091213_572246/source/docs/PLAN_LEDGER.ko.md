## 4. 이번에 내린 설계 결정

v075 분석은 부모 누락과 잘못된 부모 선택을 구분했고, 감사용 전체 응답 해시가 프롬프트에 노출됨을 확인했다. 이번 변경은 그에 근거한 **새 설계 결정**이며, 과거에 이미 효과가 확인된 사실이 아니다.

1. 두 군 모두 초기 사실 전용 스키마를 유지한다. fact_only의 기존 개선을 버리지 않는다.
2. 두 군 모두 `message.content` 원문은 유지하되 전체 응답 해시는 모델 입력에서 제외한다. 전체 HTTP 응답·해시·시간·dispatch 기록은 evidence에 보존한다. 해시 제거의 인과 효과를 따로 측정하는 군은 없다.
3. `base`와 `parent_count`를 같은 선택 원응답에 연결한다. **유일한 군 간 처치는 규칙 단계의 부모 배열 길이 제한**이다.
4. `parent_count`에서 현재 지정 규칙의 전제 수만으로 `parents.minItems/maxItems`를 정한다. 정답 부모 ID, 원자, 노드 ID, 규칙 ID를 스키마로 강제하거나 과거 출력에서 추출해 주지 않는다.
5. 선택기는 v075의 요청을 그대로 유지한다. E02 선택 오류를 이 생성 변경이 고친다고 전제하지 않는다.

부모 수가 맞아도 부모가 잘못됐거나 중복됐다면 실패다. `Ax,Ay,Ab` 대신 `Ax,Ay,Ax`를 연결하는 것은 전제 세 개를 충족한 것이 아니다. 노드 중복·없는 부모·잘못된 규칙·불필요 노드·최종 참조 오류도 기존 채점 그대로 실패한다.

- 실제 선택 성공 수는 두 군의 종단 상한이다. 선택 오류가 유지되면 생성기만으로 상한을 넘을 수 없다.

## 8. 비교 해석의 경계

이번 `base`는 **v075 fact_only에서 모델에 보이는 감사 해시를 뺀 새 입력 계약**이다. v07517/24와 v076 한 군의 차이만으로 부모 수 제약 효과를 판단하지 않는다. 주된 비교는 같은 v076 배치의 base 대 parent_count다.

부모 수를 제한하는 스키마는 API `format`과 프롬프트 내 스키마 설명에 함께 반영된다. 둘의 개별 효과를 분리하지 않는다. 해시 제거의 효과도 이번 두 군 비교로는 식별하지 않는다. 기존 점수를 새 계약으로 소급 수정하지 않는다.

3개 개발 문제·두 seed·후보 순서 반복이다. 규칙 수와 D를 독립 분리하거나 새 구조 일반화·A/M·내부 은닉층·비용 우월성을 입증한 실험이 아니다. 호스트의 사전 출력 형태 제약을 포함한 시스템 실험이며, 모델이 모든 형식을 자율 설계하는 실험과 구분한다.
