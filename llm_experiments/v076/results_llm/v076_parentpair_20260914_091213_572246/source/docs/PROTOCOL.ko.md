# v076 실행 계약 — 부모 수 제약 종단 대조

이 문서는 실행 전 계획이다. 실제 모델 결과는 아직 없다. 정밀한 상수·모델 identity·요청 문구는 `data/protocol.json`, 전체 연구 장부는 `docs/PLAN_LEDGER.ko.md`가 기준이다.

## 질문

동일 경로 선택 원응답에서 시작할 때, 규칙 parents 배열 길이를 현재 규칙의 전제 개수로 제한하면 실제 유효한 최종 증명과 D 제어가 개선되는가?

## 두 생성군

`base`: v075 fact_only의 첫 사실 스키마를 사용한다. 후속 parents는 기존 범위0~16이다.

`parent_count`: 첫 사실은 base와 같다. 규칙 단계에서만 `parents.minItems = parents.maxItems = len(current_rule.premises)`를 요청한다. ID 문자열과 전제에 해당하는 실제 부모의 선택은 모델이 수행한다.

선택 요청, problem, candidate, 옵션, first-facts, final 계약은 같다. 같은 이력을 넣으면 rule 요청은 parents의 두 길이 값과 그 스키마를 보여주는 텍스트만 다르다.

두 군 모두 과제와 무관한 전체 응답 해시를 모델에 보여주지 않는다. 기록상 실제 원응답 `message.content`는 공백·개행·잘못된 값까지 보존한다. response.raw.json, record의 SHA-256, base64, 이벤트 체인, MANIFEST는 기존처럼 보존·검산한다.

## 무보정 경계

호스트는 모델의 candidate_id를 사전 후보표에 대응시키고, 그 경로의 현재 규칙 전제 수를 센다. 기대 D를 보고 경로를 바꾸거나, 이전 node 중 정답 부모를 찾거나, 누락 부모 추가·노드 삭제·정답 atom 고정·이력 정규화를 하지 않는다.

부모 수 일치는 의미적 성공의 충분조건이 아니다. 3개 전제가 필요한 규칙에서 부모3개를 냈어도 ID/원자 대응이 틀리면 실패다. 부모 중복·missing·선후 위반·자기 참조·잘못된 최종 노드도 원래 채점기로 확인한다.

## 오류·예산

24개의 공유 선택, 각 군 본실험24/참조12. 최대404회 추론과 metadata12·조건부skip을 포함한416개 action. 선택 불가 시 생성은 전달 불가로 기록한다. 짧은 경로 뒤 남은 슬롯은 outside_selected_route로 기록하고 추론하지 않는다. 모든 목표 경로 선택이면348회, 모두 짧게 고르면292회, 모두 길게 고르면404회. 선택24개가 모두 형식 불가이면 참조108회와 선택24회인132회만 수행한다.

HTTP·transport·identity·생성 상한 위반 시 중단한다. JSON/스키마 실패, 길이 종료, 미실행, pending을 구분한다. 선택이나 중간 content가 유효한 JSON이 아니어도 형식상 원문 전달이 가능하면 그대로 전송하며 측정은 별도 null/오류로 유지한다. 실패 후 재시도·새 RunName·모델 갱신·서버 시작은 없다.

## 판정

종단 gate: 군별 본실험24/24·양방향12/12·참조12/12 및 측정 완료. 생성 gate: 본실험 선택경로 구성24/24·참조12/12. 관찰된 부분 개선·악화는 gate와 따로 보존. 어떤 결과든 한 배치 종료. 정확한 숫자 보고 실험이나 공백 탐색으로 복귀하지 않는다.

## 재현·해석 한계

content-only는 두 군 공통으로 도입한 새로운 모델 입력 경계다. 이번 비교는 그 제거 효과를 따로 추정하지 않는다. v075와의 비동시 비교보다 같은 배치의 짝비교를 사용한다. 네이티브 모델 추론 결과는 아직 없으며, 이 코드의 합성 응답은 모델 성능을 증명하지 않는다.
