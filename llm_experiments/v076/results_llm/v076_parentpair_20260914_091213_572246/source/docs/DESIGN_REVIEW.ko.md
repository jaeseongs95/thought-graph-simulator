# v076 설계 점검 기록

이 문서는 독립된 사람이나 다른 모델의 심사를 받았다는 주장이 아니다. 작성 과정에서 적용한 반례·비교 기준을 기록한다. 코드의 실제 시험 결과는 배포 외부 검증 자료에서 확인한다.

## 확인한 설계 경계

|쟁점|이번 처리|
|---|---|
|부모 수를 알려주는 것이 정답을 대신 주는가?|현재 규칙 본문에 이미 존재하는 전제 개수를 배열 길이로 반영한다. 부모 ID나 원자 대응을 풀거나 제공하지 않는다. 외부 출력 제약의 기여는 명시한다.|
|부모 수만 맞아도 성공으로 바뀌는가?|아니다. 같은 개수의 잘못된 부모·중복 부모·없는 부모를 별도 반례로 시험하고 기존 의미 채점기를 유지한다.|
|이전 17/24를 새로운 기준으로 고치는가?|아니다. 실제 v075 fact_only 원문을 두 새 채점 경로에 재생해도17/24·5쌍·참조9/12가 유지되는 회귀를 수행한다. 새 입력 계약의 실제 모델 실행을 대신하는 시험은 아니다.|
|스키마와 해시 제거 효과가 섞이는가?|해시 제거는 두 군 공통 조건이고 부모 수 스키마만 군 간 처치다. v075와 새 군의 단순 비교로 효과를 판단하지 않는다. 해시 제거의 별도 효과는 미측정이다.|
|E02 선택 오류를 해결한다고 오해할 수 있는가?|선택기 요청24개는 v075와 동일하다. 실제 선택의 정답률과 상한을 두 생성군과 별도로 보고한다.|
|부모 개수 제한 후 무한히 제약을 추가하는가?|한 배치 후 종료한다. 자동 재시도·모델 교체·새 수치 진단·다음 코드 실행이 없다.|
|감사 증거가 약화되는가?|전체 응답, base64, 응답 SHA, dispatch, 사건 체인, 소스 스냅샷은 계속 보존·대조한다. 해시는 모델 입력에서만 제외한다. 외부 실행을 인증하는 기능이라고 주장하지 않는다.|
|선택을 공유하면 모든 생성 입력도 동일한가?|아니다. 같은 선택은 공유하되 각 생성군에서 실제 원응답을 순차 생성한다. 사실 첫 요청은 동일하지만 별도 호출이며 이후 결과가 다를 수 있다. 같은 원문을 주었을 때의 요청 차이는 별도 시험한다.|
|미측정과 오답을 섞는가?|원래 JSON·스키마·length·transport·identity·pending 구분과 null gate를 유지한다. 부모 수 진단도 미측정을0으로 채우지 않는다.|

## 새 실행 전 판단

v075에서 사실 단계의 개선은 나타났고, 남은 오류 중 부모 누락이 직접 관측됐다. 이 제한된 개수 제약 비교를 실제 증명 생성까지 연결하는 것은 그 관찰을 시험하는 새 설계다. 잘못된 부모의 정체성이나 선택 경로 오류까지 해결될 것으로 미리 판정하지 않는다. 3개 개발 문제의 결과를새 구조 또는4B급 모델 일반의 성과로 확대하지 않는다.
