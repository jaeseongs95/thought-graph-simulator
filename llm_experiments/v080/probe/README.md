# v080 — D/W 구별 및 후보 위치×ID 교차 진단

이 버전은 점수를 높이기 위한 새 프롬프트 탐색이 아니다. v079의 `explicit_rule` 생성기를 유지하고, 선택 결과가 **의존 깊이 D / 전체 규칙 수 W / 후보 위치 / 후보 ID** 가운데 어떤 요구·표시에 따라 달라지는지 한 동결 배치에서 검사한다.

현재 상태는 **실험 소스 및 오프라인 시험**이다. 배포 과정에서 실제 Qwen을 호출하지 않는다. 합성 시험 성과를 실제 모델 결과에 합산하지 않는다.

## 연구 범위

원 연구의 D=Decomposition 전체를 새로 정의하지 않는다. 여기서 사용하는 조작적 지표는 `D_DAG`, 즉 고정 규칙 체계에서 실제 출력한 유효 proof DAG의 목표 의존 깊이다. 초기 사실 깊이는 0이고, 규칙 결과 깊이는 `1 + max(전제 깊이)`다. W는 목표를 지지하는 규칙 노드 수다. D와 W 모두 심리적 난이도, 실제 GPU 계산량, 모델 내부 사고의 깊이를 직접 측정하지 않는다.

고정된 문제의 최소 필요 깊이와 실제 선택·작성한 증명의 깊이는 다르다. 이 실험은 문제·목표를 바꾸지 않고 후자를 제어하는지를 검사한다. 후보 경로는 실험자가 제공하며, 호스트는 선택된 ID를 그 후보의 규칙 순서에 무보정 대응시킨다. 모델은 선택 및 실제 노드·부모 연결을 작성한다. 자율적인 경로 발견 전체를 모델이 수행했다고 보고하지 않는다.

## 배정

| 구분 | 조건 | 양방향 쌍 | 위치×ID 전 조건 묶음 |
|---|---:|---:|---:|
| D 본실험, H01~H04 | 64 | 32 | 문제×seed 8묶음 |
| W 구별 대조, H03/H04 | 32 | 16 | 문제×seed 4묶음 |
| 실험자 지정 경로 참조 | 16 | 해당 없음 | 해당 없음 |

D 본실험은 문제 4개 × seed 2개 × 후보 순서 2개 × ID 배정 2개 × 작은/큰 요구 2개다. W는 같은 배정 중 H03/H04만 사용한다. H01/H02는 W가 동률이므로 어느 한 후보를 정답으로 강제하는 W 시험을 만들지 않는다.

H01~H04는 v078/v079에서 이미 본 진단 문제다. **독립 구조 수는 4이며 새 구조 수는 0**이다. 반복·ID 변경·W 대조를 새로운 문제 수로 세지 않는다.

총 선택 호출 96개, 증명 112개. 모두 요구 경로를 고르면 추론 요청 748개, 선택 결과에 따른 상한 780개다. 슬롯은 metadata 16개를 포함해 796개다. Metadata 슬롯 한 개는 최대 세 HTTP 조회를 하므로 슬롯 수와 총 HTTP 수는 다르다.

## 무엇을 바꾸고 무엇을 유지하는가

D 조건의 선택 지시문·출력 스키마·모델 identity·API 설정·두 seed·문제·규칙·후보 경로는 v079에서 유지한다. 기존 ID 배정에 해당하는 선택 요청 32개는 v079 원요청과 바이트 단위로 비교할 수 있다. 추가 조작은 후보 표시 위치와 `route_0/route_1` ID의 연결을 독립적으로 바꾸는 것이다. 출력 JSON Schema의 enum 순서는 두 ID 배정에서 동일하게 유지한다.

W 대조에서는 요청하는 양을 전체 규칙 수로 바꾼다. 헤더와 `requested_rule_count`라는 입력 키로 이를 명시한다. 따라서 D/W 대조를 한 토큰의 순수한 인과 효과라고 해석하지 않는다. 같은 문제·후보·seed·배치에서 의미가 다른 요구를 구별할 수 있는지를 검사한다.

생성은 `explicit_rule` 한 군을 사용한다. 기존 현재 규칙 재표시 이외에 정답 부모 ID·완성 graph·후보 D/W 숫자를 제공하지 않는다. 선택 오류·중간 오류를 그대로 전달한다. 숫자 계산 보고나 설명을 새 성공 조건으로 만들지 않는다.

## 결과 해석

주평가지표는 D 양방향 종단 성공이다. 기존의 단일 표시 조건 성공은 그대로 보존하고, 추가로 같은 문제×seed에서 **위치2×ID2의 네 비교 쌍 전부**가 성공하는지를 별도로 표시한다. 네 쌍 전수 기준이 실패해도 부분 성공을 지우지 않는다.

H03/H04에서는 D를 작게/크게 요구할 때와 W를 적게/많게 요구할 때 정답 후보가 반대다. 네 요구를 모두 맞추는지를 구별 대조 지표로 기록한다. 단순히 선택을 바꿨다는 것만으로 성공 처리하지 않는다. W 성공을 D 성공 분모에 더하지 않는다.

`summary.json`에 개별 선택, 실제 D/W, graph·단계 판정, 방향별 쌍, 위치×ID 묶음, D/W 네 요구 대조, 사용량의 미기록 수가 남는다. 첫 위치와 `route_0` 선택 빈도도 분리한다. 이는 관찰된 행동 패턴이며 내부 심리 원인의 확정은 아니다.

## 오프라인 측정 교정

```powershell
python -X utf8 -B .\calibrate080.py --out .\calibration_result.json
```

기호 전단사 재명명, 규칙 사전 나열, 허용된 위상적 순서 변경에서 D가 유지되는지 검사한다. 규칙 수 동일/D 상이, 규칙 수-D 역전, 미사용 노드 거부, 부모 누락 거부도 포함한다.

별도 합성 예제에서는 `A→B→G`를 등록된 macro `A→G`로 묶으면 원시 깊이가 2에서 1로 달라지는 것을 보인다. 고정된 primitive 체계로 **명시적으로 인증된 전개**를 하면 다시 2가 된다. 외부 입·출력 인터페이스의 비교이며 두 이론의 모든 내부 명제를 동일시하지 않는다. 임의 macro의 의미 깊이를 자동 추측하거나 실제 모델 실패 graph를 전개해 성공으로 재채점하지 않는다.

이는 측정 도구의 검사이지, 재명명에 대한 실제 모델 강건성이나 인간의 사고 깊이를 검증한 결과가 아니다. 라이브 v080에는 규칙 분할·압축을 섞지 않는다.

## Windows 실행

배포된 `Run-v080-Auto.ps1`을 Downloads에 둔 뒤 사용한다. 소스 ZIP이 내장되어 있다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v080-Auto.ps1" -CheckOnly -AllTests
```

위 명령은 설치·자체시험·오프라인 교정·v079 재감사·계획 동결까지만 수행한다. Ollama 조회/추론/서버 시작/모델 다운로드는 하지 않는다.

실제 한 배치 실행:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v080-Auto.ps1"
```

기존 Ollama와 `qwen3:4b-instruct`가 준비되어 있어야 한다. v079 evidence ZIP은 Downloads 또는 기존 `v079\results_llm`에 둔다. 자동화는 파일명 뒤 `(1)`과 관계없이 SHA-256으로 확인한다.

자동 탐색이 맞지 않을 때 명시할 인수는 `-RepoRoot`, `-Baseline`, `-PythonPath`다. 원래 저장소 우선 경로는 `D:\codex\AI논문\thought-graph-simulator`다.

기존 시작 상태만 읽기:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v080-Auto.ps1" -InspectOnly
```

가드는 첫 추론 전에 생성될 수 있다. 가드를 지워 재실행하지 않는다. 부분 실행은 원문·로그를 보존하고 상태를 먼저 판정한다. `-CheckOnly`는 실제 실행 가드를 만들지 않는다.

## 검산과 구현 경계

`legacy/measure.py`, `legacy/stages.py`, `legacy/audit_graph.py` 등은 v079의 원 파일을 바이트 그대로 보존한다. `audit080.py`는 생산 `design080`, `report080`, `measure`, `stages`를 import하지 않고 배정·요청·단계·graph·D/W·집계를 재구성한다.

한국어 표를 출력하는 `render080.py`는 양쪽에서 공유하는 표시 전용 코드다. 따라서 숫자 집계의 독립 검산과 표시 코드의 재사용을 구분한다. 독립 검산은 번들 내부 일관성을 확인하며 외부에서 실제 로컬 추론 사실을 인증하는 것은 아니다.

한 동결 배치 후 종료한다. 같은 결과를 여러 번 검산한 것을 새 실험 표본으로 세지 않는다. 소스 작성·합성 시험·실제 Qwen 추론·실험 해석은 별도 단계다.
