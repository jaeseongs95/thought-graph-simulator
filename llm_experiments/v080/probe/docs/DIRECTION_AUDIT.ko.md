# ADM 연구 방향 다각도 점검 — v079 이후

작성일: 2026-09-14 KST

## 1. 결론

**현재 연구는 ‘고정된 문제·목표에서 실제로 출력한 유효 증명의 의존 깊이를 제어할 수 있는가’라는 범위에서는 타당한 방향으로 진행되고 있다.** D 계산식이나 기존 부분 성공을 폐기할 이유는 없다. 다만 이 측정을 Decomposition 축 전체나 일반적인 사고의 깊이로 바꾸어 부르면 측정 범위를 넘어선다.

다음 실험의 우선순위는 새로운 부모 제약이나 규칙 세분화가 아니라 **요구한 지표(D와 규칙 수)를 구별하는지, 후보 위치와 ID를 바꾸어도 그 반응이 유지되는지**다. 이에 맞추어 v080을 작성했다. 이는 프롬프트 성능 개선을 보장하는 실험이 아니라, 현재 관찰을 더 정확하게 분류하는 제한된 진단이다.

검토 기반은 첨부 인계서, v078/v079 분석보고서, v079 evidence의 동결 protocol·소스·원요청·원응답·기존 독립 검산기다. 외부 1차 자료는 깊이 측정의 의미와 근접 선행 연구를 확인하는 데 사용했다. 아래의 방향 평가는 이 자료들에 대한 분석이며 원 논문 전체의 신규성 판정을 완료했다는 뜻은 아니다.

## 2. 원래 D 축과 이번 지표를 구분한다

원 연구의 축 이름은 **D=Decomposition**이다. 이 상위 개념을 임의로 `Inferential Dependency Depth`로 대체할 필요는 없다. 대신 이번 실험에서 사용하는 조작적 지표를 다음처럼 둔다.

```text
D 축: Decomposition
이번 실험의 지표 D_DAG:
  초기 사실 깊이 = 0
  규칙 결과 깊이 = 1 + max(전제 깊이)
  최종값 = 실제 goal을 지지하는 유효 proof DAG의 깊이
```

분해에는 분할 방식, 가지 수, 공유 중간 결과, 순차적 의존 관계 등이 관련될 수 있다. 이 중 최장 의존 경로 하나를 측정했다는 사실로 나머지까지 측정한 것은 아니다. 반대로 이것이 상위 개념의 일부라는 이유로 실험 가치가 사라지는 것도 아니다.

컴퓨팅의 work/depth 모델은 총 연산 수와 최장 순차 의존 경로를 구별한다. 따라서 이 형식적 깊이 정의는 근거가 있다. 그러나 어떤 지표가 명확히 정의돼 있다는 것과 그 지표가 넓은 심리적 개념 전체를 대표한다는 것은 다른 문제다. 구성타당도 연구에서도 현상·과제·지표·결론 사이의 연결을 따로 점검한다. [외부 1, 2]

## 3. 출력 증명의 깊이와 문제 자체의 깊이는 다르다

같은 문제 P에 여러 유효 증명이 있을 때 다음 두 양을 구별한다.

```text
D_min(P) = 그 문제를 증명할 수 있는 최소 의존 깊이
D(G)     = 이번에 실제로 출력한 증명 G의 의존 깊이
```

현재 실험은 P와 목표를 고정하고 D(G)를 바꾸는 것이다. 깊이 2와 깊이 3의 증명이 모두 가능한 문제에서 모델이 깊이 3을 택했다고 해서 문제 자체의 최소 필요 깊이가 3으로 바뀌지는 않는다.

이는 원래 고정 목표·경로 비교 질문에 맞는다. 다만 ‘더 어려운 문제를 풀었다’ 또는 ‘더 깊이 생각해야만 알 수 있는 정답을 알아냈다’는 실험으로 기술하면 달라진다. 목표가 미리 제공돼 있다는 것도 이 증명 구성 과제의 설정이다. 완성된 증명의 타당성과 목표 의존 구조를 검사하므로 목표 문자열을 안다고 곧바로 성공하는 것은 아니다.

## 4. 측정 단위 문제는 중요하지만 현재 쌍대조의 직접 혼란은 아니다

규칙을 하나로 묶거나 여러 개로 쪼개면 원시 graph 깊이는 바뀔 수 있다. 하지만 현재 shallow/deep 쌍 안에서는 facts·rules·goal을 고정한다. 따라서 한쪽에만 새 macro 규칙을 허용해서 D가 달라진 대조는 아니다.

직전 설명에서 제안한 `A→B→C`와 `A→B, B+X→C`의 비교를 ‘단순 분할 대 진짜 의존’의 순수 대조로 사용할 수는 없다. X라는 전제가 추가돼 문제 조건도 달라진다. 또 두 그래프 모두 형식적으로 실제 의존 경로다. 외부 의미 기준 없이 어느 쪽이 더 진짜 사고인지 판정할 수 없다.

이번에는 이 불완전한 예제를 라이브 실험으로 추가하지 않았다. 대신 별도 오프라인 합성 예제에서 다음을 검산했다.

```text
고정 primitive 체계: A→B→G     원시 D=2
등록된 macro 표현:  A→G        원시 D=1
인증된 전개를 primitive 체계로 환원: D=2
```

이는 지정된 입·출력 인터페이스와 명시적 전개 계약 아래의 비교다. B를 포함한 모든 내부 명제까지 두 이론이 같다고 선언하는 것이 아니다. 임의의 추상 규칙에 가중치를 추측해서 붙이지도 않는다.

향후 A 축에서 추상화로 규칙을 묶는 실험을 한다면, 규칙 단위 변화와 D 변화의 관계를 사전에 정의해야 한다. 현재의 고정 규칙 비교를 버릴 문제가 아니라 다른 축으로 확장할 때 지켜야 할 조건이다.

## 5. 모델과 호스트가 하는 일을 구분한다

현재 파이프라인은 다음과 같다.

```text
실험자가 두 유효 후보의 규칙 경로 제공
→ 모델이 요구에 따라 후보 ID 선택
→ 호스트가 실제 선택 ID를 해당 경로에 단순 대응
→ 호스트가 규칙 단위 호출을 순서대로 배정
→ 모델이 사실·규칙 노드·부모·최종 ID 작성
→ 별도 채점기가 graph/단계/D 검사
```

따라서 관찰된 것은 **이 지원 구조를 사용하는 모델 시스템의 선택·구성 성과**다. 모델이 아무 후보 없이 경로 전체를 새로 발견했다거나 내부 hidden state의 순차 계산 깊이를 직접 조작했다고 해석하지 않는다.

이 지원 구조는 현재 연구 목적에 사용할 수 있다. 선택 오류가 나도 호스트가 정답 경로로 교체하지 않고, 모델이 잘못 작성한 부모도 고치지 않으므로 종단 성공이 자동 보장되는 것은 아니다. v078/v079의 유효한 역방향 graph가 그 차이를 보여 준다.

이와 별도로 자연어 증명을 단계별로 생성하는 접근 자체는 ProofWriter 같은 선행 연구에도 있다. 따라서 단계별 생성이나 graph 사용만을 신규성의 핵심으로 삼는 것은 적절하지 않다. 현재 연구의 구체적인 검증 대상은 고정 목표에서의 요구별 구조 선택, 실제 D 재측정, 규칙 수와의 분리, 표시 변경에 대한 유지 여부다. 이 조합의 신규성에 대한 전수 문헌조사는 이번 점검에서 수행하지 않았다. [외부 3]

출력된 설명을 내부 사고의 충실한 기록으로 읽는 문제는 CoT faithfulness 연구에서도 별도 검증 대상으로 다뤄진다. 본 실험은 실제로 외부에 작성한 노드 연결을 검사한다는 장점이 있지만, 그 사실만으로 내부 계산 전체가 드러나지는 않는다. [외부 4]

## 6. 지금까지의 결과는 무엇을 지지하는가

v079의 **동일 배치 내부** 비교를 사용한다.

| 지표 | base | explicit_rule |
|---|---:|---:|
| 선택 경로 생성 | 9/32 | 27/32 |
| 요구 D 종단 | 4/32 | 14/32 |
| 양방향 종단 | 0/16 | 2/16 |
| 지정 경로 참조 | 4/16 | 13/16 |

현재 규칙의 본문을 다시 표시하는 입력 변경이 실제 부모 연결과 전체 증명 구성을 개선했다. 입력 계약의 공학적 효과에 대한 근거다. 이 증가를 곧바로 D 이론 전체의 검증 수치로 사용하지 않는다.

D 제어에 더 직접적인 근거는 H01이다. 같은 사실·목표·규칙 수 3개에서 실제 D=2와 D=3의 유효 증명을 요구에 맞게 생성했다. 두 seed에서 관찰됐지만 한 구조의 특정 후보 순서다. 이것은 부분 효과이며 두 독립 문제 또는 새로운 holdout 성공이 아니다.

v079의 선택 프롬프트에는 이미 정확한 재귀식과 ‘규칙 개수나 글자 수로 대신하지 말라’는 지시가 있다. 따라서 단순히 정의가 빠져서 선택을 실패했다는 설명은 소스와 맞지 않는다. 새 소스에서는 기존 D 문구를 다시 최적화하지 않았다.

## 7. 현재 주된 병목은 선택의 구별성과 표시 강건성이다

v079에서 32번 중 28번 첫 후보/route_0을 선택했다. 하지만 첫 후보와 route_0이 항상 붙어 있었으므로 어느 속성을 따랐는지 분리할 수 없다.

공유 선택은 16/32, 양방향 2/16이었다. 같은 선택 원응답을 고정하면 생성기가 완벽해도 종단은 최대 16/32, 양방향은 최대 2/16이다. 명시군이 14/32와 2/16을 얻었으므로 생성기의 세부 제약만 더 추가하는 것은 다음 양방향 연구의 우선순위가 아니다.

규칙 수-D 역전 문제에서 나타난 역방향 선택은 규칙 수를 따르는 행동과 일치하지만, 모든 오류의 원인이라고 확정할 수는 없다. 지금 필요한 것은 이 대체 해석들이 서로 다른 예측을 내는 대조다.

## 8. 규칙 수를 분리했지만 모든 부담을 분리한 것은 아니다

같은 규칙 수에서 D가 달라지는 대조는 총 규칙 수 설명을 배제하는 데 중요하다. 다만 graph의 가지 너비, 공유 구조, 전제 수, rule/atom 이름, 노드 ID 검색 부담까지 모두 같은 것은 아니다.

요구에 맞는 D의 출력 구조를 만들 수 있는가라는 질문에는 이런 구조 변화를 허용할 수 있다. 그러나 성공률 변화가 오직 D 하나의 난이도 효과라고 추정하려면 추가 설계가 필요하다. 지금은 구조 제어의 유무와 난이도의 인과 추정을 같은 결과로 쓰지 않는다.

이번 교정 기록은 D·W와 함께 최대 파생 층 너비·최대 규칙 전제 수·직렬 생성 호출 수를 기록한다. 이 보조 지표들을 새 성공 조건으로 강제하지는 않는다.

## 9. 깊이가 작다고 실제 실행 시간이 짧아지는 실험은 아니다

실행기는 graph에서 병렬 가능한 가지도 한 규칙씩 순차 호출한다. H01의 D=2와 D=3 증명은 모두 규칙 3개이고 사실·final을 포함한 생성 호출 수는 둘 다 5개다.

따라서 graph의 최장 의존 경로는 실제 API 호출 횟수·직렬 실행 시간·모델 내부 연산량과 구별해야 한다. work/span 모델의 깊이를 실제 실행 시간으로 연결하려면 연산 비용과 스케줄링 가정이 필요하다. [외부 1]

현재 지표를 검증하기 위해 큰 모델 비교나 하드웨어 업그레이드부터 할 이유는 없다. 우선 선택과 구조 제어의 기준을 안정적으로 구별해야 이후 비용 비교가 무엇을 비교하는지 명확해진다.

## 10. 표본·일반화·검산

96개 증명이나 수백 개 규칙 단계는 서로 독립적인 문제 수가 아니다. 현재 반복에 사용한 독립 구조는 4개이고, 이미 결과를 본 진단 문제다. 구조별 결과와 동일 조건의 짝비교를 우선한다. 이 작은 구조 집합에서 모든 반복을 독립으로 취급한 모집단 유의확률을 산출하지 않았다.

기존의 무보정, 미실행과 실패의 구분, 원응답 보존, 생산/독립 채점 대조는 유지할 가치가 있다. 다만 같은 evidence를 여러 구현으로 재검산한 것은 판정 일관성을 확인한 것이지 새 실험 표본이나 넓은 구성타당도를 입증한 것은 아니다.

v080은 노출된 진단 세트라는 지위를 유지한다. 이후 일반화 검증은 controller·지표를 먼저 동결하고 다른 문제를 사용해야 한다. 이번 배치의 불리한 결과를 지우거나 같은 문제를 holdout으로 재명명하지 않는다.

## 11. 추가 실험 v080

두 후보가 다음과 같은 H03 형태의 문제를 생각하면 된다.

| 후보 | D | W |
|---|---:|---:|
| A | 2 | 4 |
| B | 3 | 3 |

D를 작게 요구하면 A, 크게 요구하면 B다. 반면 W를 적게 요구하면 B, 많이 요구하면 A다. 정답 방향이 반대이므로 요구 지표를 구별하는지 확인할 수 있다. 실제 모델 입력에는 이 숫자 표를 주지 않고 원래 후보 규칙만 준다.

여기에 후보 위치와 ID를 독립적으로 교차한다. A가 첫 위치에 있는 경우와 둘째 위치에 있는 경우, A의 ID가 route_0인 경우와 route_1인 경우를 모두 검사한다. 기존 출력 enum 순서는 고정해 표시 위치와 enum 순서를 함께 바꾸지 않는다.

D 본실험 64조건/32쌍, W 대조 32조건/16쌍, 지정 경로 참조 16조건이다. 네 표시 조합이 모두 성공한 문제×seed 묶음도 별도 보고한다. W 성공을 D 성공에 더하지 않는다. 새 구조는 0개다.

생성기는 v079 explicit_rule로 고정한다. 추가 숫자 보고, 정답 부모 제공, binding, 사후 보정은 없다. 최대 추론 780회, 모든 요구 경로 선택 시 748회, metadata 포함 796슬롯이다.

## 12. 사전 판정과 종료

D/W 네 요구가 각각 맞고 표시 변경에도 유지된다면, 해당 진단 문제에서 의존 깊이와 규칙 수를 구별하는 요구 기반 구조 제어를 관찰한 것이다. 단순히 네 선택이 서로 다르다는 것만으로는 충분하지 않다.

위치나 특정 ID를 고정 선택하면 해당 표시 의존 패턴을 기록한다. W는 맞지만 D에서 역전하면 D/W 구별 실패와 일치하는 결과로 기록한다. 정답 선택 뒤에 graph가 실패하면 생성 병목을 별도로 남긴다.

어떤 결과이든 한 배치로 종료한다. 점수가 낮다고 자동으로 문구·seed·제약을 추가하지 않는다. 이번 실험의 목적은 성능이 오를 때까지 탐색하는 것이 아니라 무엇을 통제하고 있는지 구별하는 것이다.

## 13. 수행과 미수행

v079의 소스·계약·원요청을 열람했고, 기존 독립 검산기로 evidence를 다시 감사하는 경로를 시험했다. v080 소스, 계획장부, 오프라인 교정, 독립 검산, 합성 행동 대조, 단일 배치 실행·보존 기능을 구현했다. 최종 배포본의 실제 시험 수와 해시는 동봉한 `v080_검증결과.md` 및 `VALIDATION_RESULT.json`에 기록한다.

실제 Qwen 추론과 v080 연구 결과는 아직 없다. Windows PowerShell 네이티브 실행 여부도 실제 수행 범위대로 검증 기록에 별도 표시한다.
