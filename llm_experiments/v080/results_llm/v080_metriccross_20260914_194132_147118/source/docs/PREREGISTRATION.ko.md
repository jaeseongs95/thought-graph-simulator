# ADM 연구 계획장부 — v080 / r1

작성일: 2026-09-14 KST. 상태: 소스·오프라인 검증 단계. 실제 Qwen 결과 없음.

## 출발 근거

v079 내부 짝비교에서 base 대비 explicit_rule의 생성 충실성은 9/32→27/32, 요구 D 종단은 4/32→14/32, 양방향은 0/16→2/16이었다. 참조는 4/16→13/16이다. v078의 참조 5/16을 v079 base로 대체하지 않는다.

v079의 선택은 16/32 및 양방향 2/16으로, 명시군은 고정된 선택 결과에서 가능한 양방향 상한을 모두 실현했다. 첫 후보와 route_0은 붙어 있었으므로 이전 자료만으로 위치와 ID를 구별할 수 없다.

기준 plan SHA-256: `fbbf7605ebaae1be37ab2d8fc52126197bec530e69fd57f61ad5fb3a6da88007`

## 평가할 질문

1. 같은 문제·목표에서 의존 깊이 D의 작음/큼 요구에 맞는 유효한 증명을 출력하는가?
2. 그 반응은 후보 위치·ID를 서로 독립적으로 바꾸어도 유지되는가?
3. D와 전체 규칙 수 W의 정답이 반대인 문제에서 두 종류의 요구를 구별하는가?

질문 3은 질문 1의 성공 조건을 바꾸지 않는 별도 구별 대조다. W를 새로운 ADM 축으로 선언하지 않는다.

## 고정 계약

H01~H04, Qwen identity, API 옵션, 두 seed, 기존 D 선택 프롬프트, 생성 프롬프트 및 스키마 유지. 생성기는 v079 explicit_rule이다. D 선택 64개, W 선택 32개, 참조 16개. D 쌍 32개·W 쌍 16개. 최대 780 추론, 전부 요구 후보 선택 시 748 추론, 진행 슬롯 796개.

정답 후보의 깊이/규칙 수를 숫자로 주지 않는다. 정답 부모나 완성 graph를 주지 않는다. 실제 선택 원응답을 사전 후보표에 대응하는 것 외의 호스트 선택·보정은 없다. 생성 성공·요구 지표 종단·역방향 유효 graph를 구분한다.

두 후보 순서×두 ID 배정을 교차하지만 출력 스키마의 enum 순서는 고정한다. 기존 ID 배정의 D 요청 32개는 v079의 원 요청 bytes와 회귀 비교한다.

## 관측에 따른 판정 범위

| 관측 | 허용되는 해석 | 허용하지 않는 해석 |
|---|---|---|
| D 성공이 네 표시 조건에서 유지 | 이 진단 구조의 위치/ID 변경에 견디는 D 제어 관찰 | 모든 표현·문제·모델 일반화 |
| 특정 위치나 ID를 고정 선택 | 해당 대체 행동과 일치하는 선택 패턴 | 모델 내부의 정확한 원인 확정 |
| W는 맞는데 D는 규칙 수 순서로 선택 | D/W 구별 실패와 일치 | graph를 만들 수 없다는 결론 |
| D/W 네 요구를 모두 맞춤 | 해당 조건에서 두 지표의 요구를 구별 | 일반적인 사고 깊이 전체의 타당도 확보 |
| 올바른 선택 후 생성 실패 | 선택과 생성 병목을 분리 | 선택 성공을 종단 성공으로 계산 |
| 유효한 역방향 graph | 생성 성공·요구 지표 실패 | 앞선 실패를 마지막 정답으로 덮기 |
| 부분 실행/전송 오류 | 미관측·중단으로 보존 | 오답 또는 D=0으로 채우기 |

네 요구의 반응이 서로 반대라는 조건만으로 충분하지 않다. 네 응답이 각각 요구한 지표에서 맞는지도 확인한다.

## 측정 타당도와 중단 규칙

오프라인 교정으로 정의 자체의 기호/나열 불변성과 규칙 단위 의존성을 확인한다. 이 교정 결과를 모델의 새 실제 실험으로 세지 않는다. 라이브 실험에는 macro/primitive 혼합이나 규칙 분할을 도입하지 않는다.

단일 배치 종료 후 결과와 가드를 보존한다. 결과에 따라 자동으로 seed·표현·부모 제약을 추가하거나 다음 버전을 실행하지 않는다. 현재 배치가 유리하더라도 H01~H04를 holdout으로 부르지 않는다. 새로운 확인 세트는 별도의 사전 동결 문제로 설계해야 하며 이 소스는 그것을 자동 생성·실행하지 않는다.
