# v064 동결 프로토콜: 직접 유효 증명의 D 대조

기계 판독 원본은 `data/protocol.json`이다. 실제 모델 결과를 보기 전에 고정한다. 기존 v062의 40/40 기준을 수정하는 판본이 아니다.

## 질문과 조작

v058에서 얕은 증명을 구성한 `qwen3:4b-instruct`의 같은 digest를 사용한다. 세 조건의 차이는 깊이 지시 한 문장뿐이다. shallow는 가능한 유효 증명 중 최소 깊이, deep은 최대 깊이, neutral은 유효 증명 하나를 요청한다. 문제·목표·규칙 순서·schema·샘플링 옵션은 비교쌍 안에서 고정한다. 기대 D와 정답 DAG·지정 마지막 규칙은 요청에 넣지 않는다.

|문제|분류|구조 차이|최소/최대 D|
|---|---|---|---|
|T02|이미 사용한 개발 회귀|두 사실의 직접 결합 대 중간 결합을 포함한 긴 사슬|1 / 4|
|E01_shared_fork|새 prospective 평가|하나의 사실을 공유하는 두 분기와 다중 전제 결합, 무관 규칙|1 / 2|
|E02_two_vs_four|새 prospective 평가|세 사실, 최소도 두 단계인 결합 대 네 단계의 연속 결합|2 / 4|

새 두 문제는 모델 응답을 아직 관측하지 않은 설계자 선정 구조이다. 독립 생성자·외부 평가자가 보관한 미사용 구조 holdout이라고 부르지 않는다. 과거 T02는 새 문제로 세지 않는다. 준비 단계에서 가능한 경로 깊이를 재계산하고 표와 다르면 무추론 중단한다.

## 표본·순서·예산

각 문제에서 사전 지정 seed 64001001, 64001002를 사용한다. 과거 성공 seed를 선별하지 않고 새 고정 두 값을 사용한다. 각 seed에서 세 조건을 한 번씩 실행한다. 조건별 같은 seed 반복은 없으며 seed 두 개는 문제 표본 두 개가 아니다.

문제별 두 조건열은 역순이며, 세 문제 전체에서는 세 조건의 여섯 순열이 한 번씩 등장한다. T02: SND/DNS, E01: NDS/SDN, E02: DSN/NSD. 블록은 문제 순서·seed 순서로 고정한다. period와 직전 호출·직전 조건을 기록한다. 문제별 완전한 순서 균형, cold start, 캐시 초기화는 주장하지 않는다.

최대 **18개 추론**, 블록 전후 **12개 metadata 묶음**(각 version/tags/show 3조회), warmup 0, 자동 재시도 0이다. 모든 슬롯을 사전 배정하고 성공/실패에 따라 추가하지 않는다. `num_predict=4096`의 총 생성 설정 상한은 **73,728 tokens**이다. `num_ctx=8192` 등 옵션은 v058 원요청 그대로다. 요청당 UTF-8 16,000 bytes 제한과 응답 1 MiB 운영 제한을 별도로 둔다. 입력 토큰의 사전 정확값은 토크나이저로 계산하지 않았으며 실제 `prompt_eval_count`를 기록한다. 토큰·cache·시간 누락값은 0으로 채우지 않는다. 설정 상한과 실제 소비량을 구분한다.

## 판정·분모

|관측|처리|
|---|---|
|정상 형식의 논리 오답|관측된 proof/strict 실패, actual_D=null. 다음 예정 슬롯 계속|
|유효 증명이지만 요구와 다른 D|증명은 성공, directed 이행은 실패. 다음 슬롯 계속|
|모든 조건에서 같은 유효 D|선택적 D 불승인. 같은 D만으로 그래프 자체가 동일하다고 단정하지 않음|
|JSON/스키마/정상 완료 파싱 불가|형식 상태 따로 기록, 의미 지표 미측정. 다음 예정 슬롯 계속|
|완료 관측 기록 없음|not_observed, 의미 지표 null; 논리 오답으로 합산하지 않음. 호출 미발생을 인증하는 값은 아님|
|HTTP/전송/identity/운영 예산 실패|즉시 중단, 이미 관측한 원문과 성과를 유지하고 뒤 슬롯 미관측|
|중단·프로세스 예외|started marker와 부분 자료 보존; 자동 재개 없음|

사실의 깊이는 0, 규칙 적용은 실제 parents의 `1+max`로 재계산한다. 모든 노드의 사실·규칙 결론·전제 multiset·참조를 검사한다. 전체 증명과 최종 goal이 논리적으로 유효해야 proof_valid이며, 최종 조상 폐쇄와 전체 노드가 일치하고 원요청의 위상순서(부모가 자식보다 먼저 등장)도 지켜야 strict_valid다. actual_D는 strict 유효할 때만 산출한다. 오류 노드 제거·누락 사실 추가·참조 수선·노드 재정렬은 하지 않는다. 비용 계수가 음수·불리언·비정수이면 측정 불가 null로 두며, 유효한 0과 구분한다.

주 단위는 **문제×seed의 shallow/deep 대응쌍 6개**(T02 2개, 새 구조 4개)이다. 양쪽 strict 유효이며 실제 D가 각각 사전 최소·최대와 같을 때만 쌍 성공이다. neutral 6개는 주 분모에 넣지 않는다. 미관측/파싱 불가 쌍은 미측정이며 전체 비율을 산출하지 않는다. 관측 가능한 실패와 미측정을 별도로 센다. 모든 계획이 완료되고 여섯 directed 쌍을 측정할 수 있을 때만 다음 진입 판정을 계산한다.

## 다음 결정

- 여섯 쌍 모두 유효 min/max: 이번 좁은 D feasibility 통과. D-only 검사를 끝내고 별도 A 또는 M 대조 설계로 이동한다. A/M 성공이나 외부 일반화로 올리지 않는다.
- 유효하지만 같은 D 또는 반대 D: 이 계약의 선택적 대응 불충족. 깊은 유효 증명도 실제 관측됐는지 별도로 본다. 원인은 단정하지 않는다.
- 깊은 출력이 무효이고 어느 조건에서도 깊은 유효 구성을 보지 못함: 구성/선택 미분리. 다음 결정을 바꿀 경우에만 별도 최소 구성 질문을 제안한다.
- neutral에서 깊은 유효 증명은 있지만 directed 이행이 실패: 해당 조건에서 깊은 구성은 관측됐으나 지시 대응은 실패다. neutral로 성공을 대체하거나 반복 튜닝하지 않는다.
- 미완료·미측정: 전체 진입 판정 보류. 이미 관측한 결과를 유지한다. 자동 재시도나 새 RunName 우회 실행은 없다.

|주장 또는 경계|조작/고정|측정|시험 대응|
|---|---|---|---|

실제 테스트 로그와 발견·교정 내역은 ZIP 밖 validation에 남긴다. 시험 건수·합성 서버의 정답은 연구 가설의 증거가 아니다. 생산 계산과 독립 계산이 공유하는 명세 오류 가능성은 수동 경로·반례와 별도 소스 감사로 검토한다.

## 운영 중단 기록의 경계

시작했으나 완료 event에 결속되지 않은 한 action의 request/response 저장 순서상 prefix와 미확정 record는 원문으로 보존한다. 요청은 동결 요청의 byte prefix와 대조하고, 응답과 record는 크기를 제한한 미확정 자료로 취급한다. 독립 receipt의 pending_action에 경로를 표시하되 의미 지표·관측 완료 호출에 합치지 않는다. 이후 action의 파일은 허용하지 않는다. 중단 사유를 관측한 완료 action 뒤에 다음 action을 시작한 기록은 거부한다. 오류 event 직후 프로세스 중단으로 crashed인 경우에도 뒤 action이 없어야 한다. 제공자가 num_predict 초과 계수를 보고하면 그 초과 관측을 지우지 않고 즉시 중단한다. 이는 설정 상한 위반을 성공으로 승인하는 것이 아니라 위반·중단 자료의 일관성만 검산하는 것이다.
