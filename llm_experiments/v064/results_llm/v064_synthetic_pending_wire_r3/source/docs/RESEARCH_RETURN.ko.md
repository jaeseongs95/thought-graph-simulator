# A/D/M 연구 복귀 결정서

## 1. Executive Verdict — 결정

**Qwen 기준선에서 실제 유효 증명의 D를 비교하는 직접 생성 18호출 묶음을 채택한다.** 개발 중 실제 모델을 실행하지 않는다. `data/protocol.json`과 [프로토콜](PROTOCOL.ko.md)을 먼저 고정하고 실행·측정·독립 검산 소스를 제공한다. Gemma/K01의 v063 진단 분기는 재개하지 않는다.

이 검사는 같은 문제·목표에서 shallow/deep 지시가 실제 최소·최대 깊이의 유효 증명으로 대응하는지 묻는다. 모델 내부 사고나 hidden layer 제어, A/M 성공, 큰 모델과의 동등 성능, 비용 절감을 주장하지 않는다.

## 2. Consensus Proposal — 채택 범위

직접 생성과 무보정 측정에는 공통 동의가 있지만 **지정 구성 선행 게이트에는 이견이 남았다**. `conditional_consensus`는 전원 동의나 사실의 증거가 아니다. 메인이 아래 근거로 직접 검사를 선택했다.

1. v058에서 Qwen이 실제 유효 그래프를 20/20 구성했으므로 직접 D 조작을 시험할 출발 근거는 있다.
2. T02의 지정 구성 12/12도 새 문제의 구성 가능성을 보장하지 않는다. 선행 실패 시 직접 질문의 원자료를 얻지 못한다.
3. 직접 검사 성공은 제한된 D 질문에 답한다. 실패에서는 구성/선택 원인을 미분리로 남길 수 있으며, neutral의 실제 깊은 증명 여부가 후속 구성 검사의 정보 가치를 바꾼다.

## 6. Evidence — 핵심 근거

원자료 해시·판본 대조는 ZIP 밖 `validation/baseline.json`, `EVIDENCE_MAP.ko.md`, `raw_crosscheck_corrected.json`, `staged_transfer_check.json`에 있다. 과거 AI 답변이나 감사 PASS를 새 실험 관측으로 더하지 않았다.

이전 `v046_composition_01`의 4개 NOT 반환값과 후속 AND 요청 b를 직접 대조해 모두 일치함을 확인했다. 코드가 의미상 틀린 bool도 교체하지 않는 경계와 국소/종단 채점을 분리하는 점은 재사용 가능한 선례다. 다만 이전 입력을 재사용한 boolean 게이트이며 신규 추출부터 수행한 A/D/M 종단 성공은 아니다. 따라서 단일 호출만 허용한다는 원칙을 만든 것이 아니라 이번 질문에 직접 생성이 더 적합하다고 선택했다.

## 7. Required Actions — 이번 소스의 범위

프로토콜·계획 동결 → 무추론 준비 검사 → 사용자의 명시적 실행 → 원문·부분 실행 보존 → 생산 감사 → 증거 ZIP → 독립 재계산으로 연결한다. 개발 중에는 합성 HTTP만 사용한다. 과거 자료와 소스를 보존하고, v058 기준선은 고정 해시의 외부 입력으로 사용한다. 새 소스 ZIP에는 과거 소스 체인을 복제하지 않는다.

최종 ZIP은 새 빈 폴더에서 검사하고, 구현에 참여하지 않은 감사자가 동일 해시를 확인한다. 실제 검증 결과는 `validation/FINAL_REVIEW.ko.md`에 기록하며 승인 ZIP을 감사 문서 추가 때문에 다시 만들지 않는다.

## 8. Optional Optimizations — 연구 복귀의 다음 단계

여섯 directed 대응쌍이 모두 strict 유효 최소/최대 D로 분리되면 D 단독 준비 검사를 종료한다. 다음은 A 또는 M 하나를 조작하는 제한된 새 계약이다. A는 사례 관계와 역할 치환 스키마를 구분하고 의미 보존 바인딩을 검사한다. M은 실제 논증 근거 검토와 평가 기준 검토를 구분하고, 검토 수준과 판정의 정오를 별도 채점한다. 처음부터 A/D/M을 동시에 바꿔 독립 효과라고 주장하지 않는다.

그 후 설계·프롬프트 튜닝에 사용하지 않은 문제 생성자와 구조 계보를 별도 동결하고 평가 담당을 분리한다. 공유 전제, 다중 전제 결합, 서로 다른 최소 깊이, 대안 규칙 수 등 구조 단위를 분할한다. 현재 E01/E02와 T02는 그 최종 독립 평가에 다시 넣지 않는다. 비용 비교는 동일 모델·출발 문맥·기회 예산의 직접/중립 대조와 실제 입력·출력 토큰·시간을 사용하며, 같은 기록 재집계를 비용으로 중복 합산하지 않는다.

## 9. Unresolved — 한계와 중단

두 seed는 동일 출력 보장 장치가 아니며 조건별 같은 seed 재실행은 없다. 세 문제 중 새 구조는 두 개이고, 모집단 표본 추출이나 문제별 완전 순서 균형은 아니다. 이 규모로 통계적 일반화나 내부 원인을 확정하지 않는다. 여섯 쌍 완전 이행은 큰 성과의 증명이 아니라 제한된 A/M 후속 설계에 들어갈 보수적 공학 기준이다.

같은 유효 D 반복, 방향 반전, 한쪽 무효, 파싱/미관측은 별도로 보고한다. neutral에서 깊은 증명이 나와도 directed 실패를 성공으로 바꾸지 않는다. 단일 모델의 실패는 연구 전체를 끝내지 않는다. 현재 직접 묶음은 종료하고, 새로운 구성 질문이나 다른 검증된 모델 경로의 정보 가치가 있을 때만 별도 동결한다. 자동 재시도·모델 변경·문구 튜닝은 하지 않는다.

## 10. Method / Run Summary — 절차

MEDIUM 패널의 연구·측정, 인과·실험설계, 구현·증거 검토자를 각각 새 문맥으로 시작해 동일 원자료와 질문을 제공했다. 초기 결론을 서로 전달하지 않았으며 초기 의견 뒤 각자 한 차례 교차검토했다. 슬롯 한도로 공학 검토를 순차 배정했다. 메인이 증거를 대조해 통합했으므로 보증 표현은 partially_independent이다. 별도 설계 Judge는 요청되지 않았으며, 최종 소스 감사자와 구분한다.

세 검토에 도구가 지원하는 `gpt-5.6-terra`/`xhigh`를 실제 인자로 전달했으나 반환값은 task_name뿐이라 적용 설정은 unverified로 남긴다. 적응형 specialist나 재위임은 사용하지 않았다. 모델명·다수결·합의 자체로 주장을 채택하지 않았다. 구현 참여자와 최종 감사자는 별도로 기록한다.
