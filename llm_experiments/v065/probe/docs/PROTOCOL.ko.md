# v065: 지정 마지막 규칙의 최소 구성 검사

## 결정

v064의 기존 D 진입 기준은 0/6쌍으로 불통과다. 중립 포함 18개 응답 모두 국소 논리는 유효했으나, E01/E02의 12개는 최종 답의 조상이 아닌 노드를 포함해 strict 실패했다. 모든 문제에서 실제 선택된 최종 규칙은 짧은 경로에 속했다. A/M 대조로 진입하지 않는다.

다음은 **마지막 규칙을 지정했을 때도 전체 증명을 완결하지 못하는가**를 확인하는 단 한 번의 12회 구성 검사다. 원래 v064의 실패를 재채점하는 도구도, D 지시만으로 경로를 선택하는 성공 실험도 아니다.

## 세 후보 비교와 처분

|후보|얻는 정보|한계·처분|
|---|---|---|
|불필요 노드를 사후 제거|원래 응답에 어떤 목표 지지 부분이 있는지|오프라인 진단만 허용. 삭제한 결과로 기존 성공을 올리지 않는다. 삭제만 해도 최종 경로는 모두 짧으므로 D 실패는 남는다.|
|지정 마지막 규칙 구성|경로 선택을 명시 입력으로 바꾸면 긴 목표 증명을 구성하고 불필요 노드를 억제할 수 있는지|채택. 단, 지정 구성 성공은 D 지시 해석의 성공이 아니다.|
|즉시 단계형 증명 시스템|호출 분해/상태 연결이 전체 구성에 도움이 되는지|이번에는 미채택. 중간 단계·호스트 상태·추가 호출의 효과가 함께 바뀌기 전에 마지막 규칙 구성의 최소 근거를 얻는다. 이후 필요 시 새 직접/단계형 대조 계약.|

v062의 Gemma/K01 지정 규칙 진단을 재개한 것이 아니다. 이번 대상은 실제 v064에서 모든 노드의 국소 논리가 맞았던 Qwen과 T02/E01/E02다. 새로운 조건의 정보 가치가 없으면 같은 문구 변형을 계속하지 않는다.

## 입력·출력

기준선은 `v064_direct_20260913_172703_019_evidence.zip`, SHA-256 `7a20b2b6bfc3a9d185b9049e2a67bb4ee344b7a8353312f90e202c752d02126e`다. 원 v064의 3문제, 2seed, 모델 digest/server/template/옵션/schema/facts/rules/goal/규칙 제시 순서를 보존한다.

|문제|짧은 지정 경로의 마지막 규칙|긴 지정 경로의 마지막 규칙|대응 깊이|
|---|---|---|---|
|T02|r83|r69|1 / 4|
|E01_shared_fork|n52|n37|1 / 2|
|E02_two_vs_four|m76|m41|2 / 4|

이 표의 **규칙 ID는 모델에게 명시적으로 제공한다**. 그것이 이번 과제의 조건이다. 전체 정답 DAG, 부모 ID, 중간 노드, 수정한 원응답은 제공하지 않는다. 요청 생성은 깊이 채점기를 호출하지 않는다. 입력의 기존 shallow/deep 경로 지시 한 문장만 지정 규칙 구성 문장으로 바꾸며 나머지 텍스트와 요청 옵션은 유지한다. 조건명이나 목표 깊이 숫자는 새로 프롬프트에 넣지 않는다.

반환된 원본 DAG를 기존 `measure.py`와 같은 바이트의 평가기로 검사한다. 지정한 규칙과 반환된 마지막 규칙의 일치, 국소 논리, 전체 strict 계약, 실제 유효 D를 각각 기록한다. 지정 규칙이 맞아도 전제가 틀리거나 무관 노드가 남으면 지정 구성 성공이 아니다. 오타·참조·노드·규칙·경로를 자동 보정하지 않는다.

## 배정·예산

3문제 × 2seed × 2지정 규칙 = **12회**. 각 문제의 첫 seed는 짧은→긴 지정, 두 번째는 긴→짧은 지정으로 배치한다. 두 조건의 위치는 전체와 문제별로 균형이다. 문제 순서 자체는 고정이며 완전한 실행이력 통제를 주장하지 않는다.

metadata는 6블록의 전후 12묶음이고, 각각 version/tags/show 3 HTTP 요청이다. 추론 호출과 구분한다. warmup·자동 재시도는 0. 생성 설정 상한은 12×4096=49,152토큰이며 실제 사용량/입력 토큰을 보장하는 수치가 아니다. 실제 비용은 원응답 계수로 기록한다.

중립은 재실행하지 않는다. v064의 6개 중립 자료는 원 ZIP에 보존하며, 이번 과제는 D 문장 개입이 아니라 지정된 경로 구성 능력 확인이다. 과거18회와 새12회의 차이를 같은 시점의 단일 원인 효과나 유의한 성능 개선으로 계산하지 않는다.

## 진입·종료

12개 모두 strict 유효·지정 규칙 일치·기대 D이면 **고정 경로 구성 기준선만** 통과한다. 이것으로 A/M 진입이나 원 D 실패의 취소를 결정하지 않는다. 이후 D로 실제 규칙을 고르고 원출력을 다음 단계에 그대로 전달하는 구조가 필요한지, 직접 생성과 비교하는 별도 계약을 검토한다.

깊은 지정 경로의 strict 구성이 하나도 없다면 현재 모델·인터페이스의 이 구성 분기는 종료한다. 이름만 맞음/국소 논리만 맞음/무관 노드 위반은 그대로 기록한다. 문구를 바꾸며 자동 반복하지 않는다. 일부 성공이면 조건별 성공과 실패를 함께 보존하고 전체 성공으로 바꾸지 않는다.

미완료 또는 파싱/응답 불완전으로 측정 불가이면 전체 진입 판정은 null이다. 원문, 호출 시도 표지, 보존된 pending 파일과 실제 확정 관측을 구별한다. 모델·전송·예산 오류 뒤 후속 호출이 있으면 감사기가 거부한다.

## 주장 범위

이 세 문제는 이미 결과를 본 문제다. 독립 holdout도 모집단 평가도 아니다. 지정된 두 경로를 구성한 것은 모델이 D 명령으로 경로를 스스로 선택한 것과 다르다. `D_instruction_control_success` 및 A/M 진입 표시는 null로 둔다. 내부 사고, 학습 우선순위, 비용 우월성, 큰 모델 동등 성능은 이번 검사에서 측정하지 않는다.
