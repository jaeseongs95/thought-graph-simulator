# 설계 검토와 반례

이 문서는 검토 기준과 구현 결정을 적은 것이며 실험 성공 보고서가 아니다. 실제 검증 횟수/성패는 별도 배포 검증 결과 파일을 따른다.

## 연구 질문과 분리

고정 목표·동일 problem에서 작은/큰 D 요구만 바뀌는 selector 요청을 짝비교한다. D는 graph ancestry 깊이이며 규칙 수는 별도 지표다. 후보 제시는 이미 v077 계약에 포함되었던 외부 scaffolding이다. 호스트가 정답 경로를 골라 주는 본실험이 아니지만 무제약 자율 증명 생성/내부 추론 제어 실험도 아니다.

## 반례와 필요한 검증

규칙 수 휴리스틱은 H01/H02의 동률을 D 정보 없이 구별하지 못하며 H03/H04에서는 방향이 반대다. 합성 count-only 선택기가 깊이를 계산하지 않고 수만 비교하게 하여 양방향 성공으로 통과하지 못하는지 검사한다. 이 합성 대조는 모델 행동의 실제 원인 검사가 아니라 설계가 대체 설명을 구별할 수 있는지의 소프트웨어 시험이다.

전제가 빠진 연결, 기존 다른 원자의 node ID, 중복/순환/미사용 노드, 잘못된 final, 요청 규칙 순서를 어겼으나 수학적으로 유효한 graph, 사후 변경된 원문, 누락된 usage, length 종료, HTTP/identity 불일치, dispatch 후 중단을 구분한다. 올바른 graph가 잘못된 단계 계약을 지우지 못하도록 한다.

## 한계와 설계상의 선택

4개 수작업 새 구조이며 두 계층당2개다. 같은 문제의 seed/후보순서 반복은 독립 문제 수가 아니다. 새 이름/ID/전체 규칙 나열을 함께 바꾸었으므로 특정 이름/순서의 순수 효과를 식별하지 않는다. 추가 표현 교차를 늘리지 않고 먼저 고정된 구조 전이를 검사한다. 문제 난도와 분기 수가 같다는 가정을 하지 않으며 문제별 참조 생성 결과를 함께 판독한다.

미관측 숫자는 null이다. 파싱 불가 결과도 실행 성공이 아니지만 논리 깊이를 억지로 수치화하지 않는다. 보고서에는 배정/실패/미측정을 함께 적어 미측정을 분모에서 숨기지 않는다. 정상 응답의 잘못된 선택은 논리 실패이며 생성 결과는 그 선택을 그대로 따라 평가한다.

## 증거·운영

원시 요청/HTTP 응답, dispatch/action 시작, 완료 event hash chain, 모델 native identity, source/plan hash, summary를 함께 보존한다. 독립 검산기는 생산 design/report/measure/stages를 import하지 않는다. 두 검산 경로의 일치는 같은 evidence의 일관성 확인이며 외부 인증이 아니다. 가드는 추론보다 먼저 생길 수 있어 읽기 전용 상태 판독을 별도로 제공한다.
