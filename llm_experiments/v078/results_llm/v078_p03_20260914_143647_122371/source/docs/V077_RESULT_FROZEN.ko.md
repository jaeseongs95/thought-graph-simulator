## 6. 원응답에서 확인되는 핵심 패턴

### 6.1 실제 graph는 맞는데 대응표가 틀린 사례

`wire/t007_premise_binding_rule_01/response.raw.json`의 모델 content 발췌:

```json
{
  "bindings": [
    {"parent_id": "node_Lp", "premise": "Lq"},
    {"parent_id": "node_Ls", "premise": "Ls"}
  ],
  "node": {
    "atom": "Lr",
    "id": "node_Lr",
    "parents": ["node_Lq", "node_Ls"],
    "rule": "r57"
  }
}
```

규칙은 `Lq AND Ls → Lr`다. 대응표는 Lq를 `node_Lp`에 연결했지만 실제 node의 부모는 올바른 `node_Lq`, `node_Ls`다. 이 시행의 전체 graph는 D=4로 유효하다. **graph 성공, 대응표 실패**로 분리해야 한다.

이 발췌는 가독성을 위한 들여쓰기 재배치이며 값은 바꾸지 않았다. 검산은 `message.content` 원문을 사용했다.

새 군의 증명 단위(본실험 24건 + 참조 12건) 분포:

|선택 경로의 증명 구성|대응표 전체|건수|
|---|---|---:|
|유효|유효|13|
|유효|실패|13|
|실패|유효|0|
|실패|실패|10|

여기서 유효한 선택 경로 구성 26건은 요구 D 종단 26건이라는 뜻이 아니다. 잘못 선택한 E02 짧은 경로도 생성 충실성 자체는 성공일 수 있다. 증명 유효·표 실패 13건은 본실험 10건과 참조 3건이다. 그중 요구 D까지 맞은 것은 본실험 6건과 참조 3건이다.

규칙 단계 단위에서는 node/단계와 표 모두 유효 48/82, node/단계만 유효 22/82, 둘 다 실패 12/82였다. 하나의 증명에 여러 규칙 단계가 있으므로 22를 22개 독립 증명으로 세지 않는다.

### 6.2 표의 오류가 실제 node의 오류와 항상 같지 않다

E02 `m76: Ps AND Pc → Pg`는 새 군에서 실제 node/단계 10/10이 유효하지만 대응표는 0/10이었다. `t026_premise_binding_rule_01`에서는 표에 `Pb, Pc`를 쓰면서 실제 node.parents에는 올바른 `Ps, Pc` 노드 ID를 썼다.

현재 관찰은 **두 출력 필드 사이의 일관성 실패**다. 대응표를 출력했다고 해서 그 표가 node를 결정한 실제 내부 추론의 충실한 기록이라고 볼 근거는 확보되지 않았다. 표가 틀렸다는 이유로 맞은 node를 틀린 node로 재분류할 수도 없다.

### 6.3 오류는 일부 규칙에서 줄고 다른 규칙에서 늘었다

본실험과 참조를 합친, 동일 규칙의 로컬 단계 유효성:

|규칙|base|premise_binding|
|---|---:|---:|
|r21|6/6|3/6|
|r57|2/6|6/6|
|r69|4/6|6/6|
|n91|6/6|0/6|
|n37|2/6|4/6|
|m84|2/2|1/2|

T02 `r57: Lq AND Ls → Lr`는 2/6 → 6/6, E01 `n37: Ax AND Ay AND Ab → Ag`는 2/6 → 4/6으로 개선됐다. 그러나 `r21: Lp → Lq`는 6/6 → 3/6, `n91: Aa → Ay`는 6/6 → 0/6으로 악화됐다.

따라서 “아무 단계도 좋아지지 않았다”가 아니라, **국소 개선이 앞 단계 오류 증가 때문에 유효한 종단 개선으로 이어지지 않았다**가 정확하다. 로컬 단계 유효성은 부모 노드의 atom과 현재 규칙의 일치를 검사한 결과다. 그 부모 자체가 앞에서 잘못 유도됐다면 전체 graph는 계속 실패다.

특히 단일 전제인 `n91`에서도 오류가 반복됐으므로, 현재 남은 문제를 다중 전제 개수나 복잡성 하나로 설명할 수 없다. 이 비교만으로 특정 모델 내부 원인을 식별한 것은 아니다.

## 8. 소스와 보고에서 확인한 점

### 채점 계산

검토한 범위에서는 잘못된 graph를 성공으로 세거나 누락된 결과를 임의로 채우는 오류를 발견하지 못했다. 생산 재계산, 번들 독립 검산, 별도 원응답 검산이 일치했다. 대응표를 이용해 node를 자동 생성·수정하는 경로도 확인되지 않았고, 후속 요청의 이력과 선택 원문이 보존된 응답과 일치했다.

### 보고상 주의할 부분

`summary.ko.md`는 “노드·단계 기준 종단(대응표 별도)” 14/24 대 14/24를 보여 주지만, 이어지는 “선택부터 종단까지”, “양방향 종단 쌍”, “별도 참조 구성”에는 새 대응표 계약이 포함된다. 표시된 숫자가 계산상 틀린 것은 아니다. 그러나 **같은 표 안에서 기준이 바뀌므로 graph 성능 하락으로 오독하기 쉽다.**

`summary.json`의 `pairs`도 `trace_success`를 이용한 계약 pair다. 기존 연구 기준의 graph-only pair 2/12 대 2/12는 `graph_only_trace_success`에서 별도로 계산해야 한다. 이 분석에서는 원본을 수정하지 않고 두 기준을 나누어 제시했다.

`decision = close_batch_partial_no_automatic_followup`의 partial은 부분 연구 성과에 대한 결정 문구다. `status.state=complete`이므로 “실행이 partial이었다”는 뜻으로 읽으면 안 된다.

## 9. 재현성 관련 추가 관찰

ZIP 안에 포함된 v076 evidence와 v077을 직접 비교했다. 선택 요청 24개는 요청 bytes와 응답 content가 모두 동일했다. base 생성 요청 154개 중 140개는 v076과 요청 bytes가 동일했으며, 그중 8개는 응답 content가 달랐다. 4개는 JSON 값도 달랐고 4개는 JSON 값은 같고 공백·개행 형식만 달랐다.

이는 이 자료에서 **동일한 요청·seed만으로 응답 bytes의 완전 동일성이 관찰되지는 않았다**는 뜻이다. 실제 차이의 원인을 GPU, 캐시, 서버 등 특정 요인으로 단정하지 않는다. v076과 v077의 base 종단 합계가 같다고 원응답까지 같았다고 쓰지 않으며, v077 내 짝비교를 우선한다. 이런 반복은 새로운 독립 문제를 추가한 것도 아니다.

## 10. 연구상 판단과 다음 단계의 경계

이번 결과가 직접 지지하는 것은 다음이다.

1. 기존 기준의 D 종단 부분 성공은 유지된다. 두 생성군 모두 14/24와 양방향 2/12가 관찰됐다.
2. **이번 premise_binding 계약이 실제 증명 생성과 D 종단을 전체적으로 개선한다는 가설은 지지되지 않았다.** 일부 규칙과 T02에서의 개선은 보존하되 전체 개선으로 확대하지 않는다.
3. 대응표는 현재 신뢰할 수 있는 node의 대체 표현이 아니다. 맞은 graph를 설명하는 표가 틀린 현상을 별도 결과로 보존해야 한다.
4. E02 선택과 T02/E01의 실제 premise 연결 문제는 구분해서 남긴다. 이번 생성기 변경으로 E02 선택 문제까지 시험했다고 쓰지 않는다.

전체 공학적 24/24·12/12·참조12/12 gate는 통과하지 못했다. 따라서 안정적 기준선 확보라고 보고하지 않는다. 반대로 그 gate 실패를 실제 부분 효과의 부재로 바꾸지도 않는다.

내 판단은 **v077 분기를 종료하고 base를 계속 비교 기준으로 보존하는 쪽**이다. 이 결과만으로 대응표에 더 세부 제약을 연속 추가하는 것은 원 연구보다 인터페이스 진단을 앞세울 위험이 있다. 후속 설계를 한다면, 새 구조에서 규칙 수와 D를 분리해 기존 관찰의 범위를 확인하는 연구 질문을 먼저 결정해야 한다. 현재 T02/E01/E02를 holdout으로 재명명하지 않으며 P03나 v078을 자동 실행하지 않는다.

이 분석에서는 새 실험 버전, 모델 재요청, 가드 삭제, 실행 재개를 수행하지 않았다. 생성한 Python 파일은 **기존 증거의 읽기 전용 오프라인 검산 도구**이며 v078 실험 소스가 아니다.
