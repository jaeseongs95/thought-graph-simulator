# v066 동결 실험 계약

## 1. 종료한 분기와 새 질문

v065의 종료 기준은 깊은 지정 경로 구성 성공이 하나도 없으면 같은 모델·인터페이스의 지정 규칙 단일 호출 분기를 종료한다는 것이다. 실제 결과는 지정 구성0/12, 깊은 지정 성공0/6으로 이 기준을 충족했다. 새 지정 규칙 문구를 추가하지 않는다.

동시에 짧은 r83을 요구한 T02 응답 한 개는 strict 유효한 깊이4/r69 증명이었다. 따라서 모든 긴 증명을 못 만든다는 전제는 이 원문과 맞지 않는다. 명시적 요구와 경로 산출의 연결이 불안정하고 최종 참조·규칙 연결 오류가 함께 관측됐다.

새 질문: **모델이 먼저 전체 규칙 경로를 출력한 뒤, 그 실제 문자열을 다음 호출에 보존 전달하는 실행 구조가 D 지시의 종단 이행을 바꾸는가?** 이전 단일 호출 분기의 종료를 취소하지 않고, 다른 인터페이스/호출 구조를 직접 대조군과 비교한다. 사후 삭제·선택·답안 보정은 하지 않는다.

## 2. 조건과 비교

Qwen의 실제 v065 identity, v064부터 사용한 T02/E01/E02, 두 seed64001001/64001002, 모델 옵션을 고정한다. 세 문제는 이미 본 구조이고 holdout이 아니다. direct12회는 실제 v064 shallow/deep 요청 바이트를 복원한다. 이전 모델 응답을 신규 대조군으로 복사하지 않고 재실행한다.

staged24회는 조건별 planner와 constructor 두 호출이다. planner는 facts/rules/goal과 원래 D 문장을 보고 사용할 전체 규칙 ID 목록만 출력한다. 후보별 정답 깊이·정답경로·특정 규칙 지정은 하지 않는다. constructor에는 원래 증명 계약과 D 지시 및 planner 원응답을 보낸다.

바뀌는 것은 호출 수, 계획 출력 요구와 전달 문맥이라는 시스템 묶음이다. 추가 토큰과 계산 기회를 동등화하지 않았으므로 개선이 관측돼도 동등 비용 우월성이나 특정 내부 메커니즘의 단독 효과로 주장하지 않는다.

## 3. 실행·연결

6개의 문제×seed 블록을 사용하고 각 블록은 shallow/deep의 direct·plan·construct 총6호출이다. 방향 선후는 seed별로 반전하고 direct/staged 선후는 블록과 방향에 따라 반전한다. planner와 construct는 인접하되 모델 원응답 파일을 먼저 확정·보존한다. 문제 순서 자체는 고정이며 완전한 실행 이력 제거를 주장하지 않는다.

`route_plan_response`는 source_slot_id, 원 envelope SHA-256, message.content 문자열이다. 문자열은 JSON을 파싱해 재직렬화하지 않고 받은 내용 그대로 보낸다. 인용 경계에서 JSON escaping을 사용할 뿐 의미 값을 바꾸지 않는다. 서버 응답의 content가 없으면 null이며 가짜 계획을 만들지 않는다. 내용이 JSON으로 파싱되지 않거나 의미상 틀려도 정상 HTTP 관측이면 다음 생성 단계로 그대로 전달한다. 올바르게 고쳐서 보내지 않는다.

HTTP/identity 오류는 전체 실행을 중단한다. 정상 HTTP의 형식/논리 오류는 관측으로 남기고 미리 배정한 호출을 계속한다. 같은 호출 재시도, 중간값 성공 선별, warmup, 모델 갱신, 서버 자동 시작은 없다. 정상 실행 최대36회, 각 최대4096 출력 설정, 합계147,456은 생성 설정 상한이지 실제 사용량 보장이 아니다.

## 4. 평가

계획의 형식과 규칙 도달가능성, 계획 깊이는 사후 채점한다. 모든 규칙은 등록돼 있고 전제가 앞선 단계 또는 초기 사실에 있어야 하며, 중복·불필요 규칙 없이 마지막 규칙이 goal을 도출해야 한다. planned_D는 이 계획의 규칙 관계에서 계산한 진단값이다. 이를 생성된 완전 증명 깊이로 보고하지 않는다.

증명은 v064/v065와 동일한 measure.py 바이트로 평가한다. fact·rule·부모·goal·cycle·추가노드·위상순서 기준은 변경하지 않는다. 모델이 명시한 final_node_id를 기준으로 평가하며 마지막 배열 원소나 다른 goal 노드로 바꾸지 않는다.

staged의 각 종단 성공에는 아래를 모두 요구한다.
- planner가 유효하고 shallow/deep의 기대 깊이를 충족할 것.
- 실제 응답 문자열 전달이 요청 원문과 결속될 것.
- 생성 그래프의 사실이 아닌 규칙 ID 순서가 원계획과 정확히 같을 것.
- 전체 strict 증명이 유효하고 actual_D가 요구 깊이일 것.

모델이 동등한 그래프를 다른 독립 노드 순서로 작성해 원계획 순서를 어기면 graph의 국소 타당성은 인정해도 이 엄격한 전달 계약은 실패다. 이는 논리 오류가 아니라 계획 준수 실패이며 별도로 보고한다. 틀린 계획 이후의 우연한 정답도 국소 최종 성공만 보존한다. 양쪽 단계가 미관측/파싱불가이면 종단 판정은 null이다.

방식별12조건을 문제×seed6쌍으로 묶어 shallow와 deep 모두 이행했는지 판정한다. 같은 경로 반복은0쌍이다. direct와 staged 같은 조건 대응을 보고하되 각 단계와 같은 결과의 재집계를 별도 표본/추가 비용으로 합치지 않는다.

## 5. 사전 다음 결정

staged6/6이면 현재 고정 문제의 외부 실행 구조 D 기준선만 확보한다. 새로운 문제·구조로 재현과 A/M 복귀 설계를 별도 검토하며 이전 D/지정구성 실패를 취소하지 않는다. 일부만 성공하면 범위를 보존하고 사후 성공조건만 골라 전체 성과로 바꾸지 않는다.

staged 종단 성공이 하나도 없다면 이 두 호출 구조도 종료한다. 같은 문구를 변형하며 추가 호출을 자동 수행하지 않는다. direct가 새로 성공했다면 그 반복 변동도 별도 인정하고 staged만의 개선으로 귀속하지 않는다. 미완료/파싱 미측정이면 전체 진입 판단은 보류한다.
