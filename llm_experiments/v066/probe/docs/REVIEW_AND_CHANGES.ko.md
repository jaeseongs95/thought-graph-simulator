# 제3자 관점 검토·작성 후 반례 검사

외부 심사자나 다른 에이전트를 호출한 결과가 아니다. 상충하는 심사 기준을 원자료·별도 의미 구현·반례로 대조했다. 생산 코드와 독립 검산기는 바이트/JSON/동결 명세/이전 증거 감사기를 공유하지만 새 요청 재구성, 그래프 의미, 계획 의미, 집계는 별도 구현한다. 한국어 표 표현 명세는 동일하며 독립적으로 재계산한 결과로 출력한다.

## 후보 비교

|후보|판정|
|---|---|
|마지막 규칙 강조 문구를 다시 변형|거부. v065에서 정한 해당 분기 종료를 따르지 않는 반복이 된다.|
|생성된 응답의 final 참조/부모를 정답으로 고치기|거부. 원래 실패를 호스트의 성공으로 바꾼다.|
|오프라인 오류 분석만|이번 실제 결과 분석에서는 수행한다. 이것만으로 외부 실행 구조가 D 제어를 바꿀 수 있는지는 알 수 없다.|
|직접 생성 대 모델 원계획 전달|채택. 현재 모델의 단일 호출 실패를 보존하면서 원값 연결이라는 별도 실행 구조의 효용과 한계를 제한된 예산으로 비교한다.|

## 호스트와 모델 기여

호스트는 호출 순서, 같은 문제·목표·방향 배정, 원문 저장, 모델 원content의 다음 입력 이동만 수행한다. 규칙 선택은 첫 모델이 하고 노드/부모/최종 참조는 두 번째 모델이 작성한다. host가 계획의 도달가능성이나 깊이를 계산하는 코드는 사후 보고에만 참여한다. request_for에서 채점기를 호출하지 않는 경계를 검사한다.

실행은 원문 그대로 전달하지만 그것만으로 성공하지 않는다. 모델이 잘못된 중간값을 무시하고 최종 정답을 만들어도 pipeline 성공은 거부한다. 잘못된 첫 단계가 뒤 단계의 국소 성공을 지우지 않으며, 뒤 단계 실패가 첫 단계의 국소 성공을 지우지도 않는다.

## 작성 후 검토

원래 v065 배포 manifest 외부 입력명이 남아 있던 초안 문구를 v065 실제 기준선 이름으로 교정했다. 정적 검토에서 고친 것이며 수정 전 실행 실패를 재현했다고 주장하지 않는다. 최초 긴 시험 명령은 도구 시간 제한으로 종료돼 완료 시험으로 세지 않았다. 최종 동결 ZIP을 별도 폴더에서 전수 재검사하고 실제 완료 횟수는 ZIP 밖 검증 기록에 둔다.

각각 성공/실패하게 만드는 합성 서버, 잘못된 계획을 보존한 최종 성공, 잘못된 계획을 모델이 고쳐 만든 최종 성공, 중간 파싱 실패, 응답 누락, 원문·계획·요청·한국어 요약 변조, pending 원문, HTTP/identity 중단을 시험한다. 실제 실행한 목록/종료코드/시간은 분석 ZIP에 있다. 모든 가능한 물리적 crash나 제공자 장애를 열거했다고 주장하지 않는다.

이전 measure.py는 바이트 보존한다. 새 평가의 planned_D와 실제 actual_D를 구분하고, 단계별 성과·종단성공·비용을 별도로 기록한다. 이 구조가 성공해도 호출 추가/문맥 증가를 통제한 순수한 인과효과, hidden state 제어, 일반적 A/D/M 성공, 계산비용 절감을 자동 주장하지 않는다.
