# v086 구현 검토

## 변경한 부분

신규 cases086의 결정적 구조 생성과 기존/신규 개별 경로·쌍의 동형 배제, 독립 audit086의 비동형 재검산, 신규 구조를 표시하는 report/render, v085 기준 evidence·검산기 앵커, v086 배포 경로를 추가했다. 선택·비교·조회·생성의 요청 로직은 동일 입력에서 v085 원응답 요청을 재구성하도록 유지했다. 기존 legacy 디렉터리와 v085 배포 ZIP 바이트는 변경하지 않는다. v085 ZIP이 포함한 이전 검산기 체인을 재사용하므로 중복된 옛 ZIP의 최상위 사본은 따로 넣지 않는다.

byte_diagnostics086은 원문 요청 유일성, oracle 동일 요청, 같은 경로의 생성 입력 차이, metric-only 조회, 실패 단계·사용량을 보고한다. 두 채점기는 각각 자체 의미 판정을 수행하고, 보조 바이트 집계/표시만 공유한다. 보조 보고서도 manifest와 독립 검산에 포함된다.

## 결과 해석상 남는 범위

D는 외부 proof DAG의 의존 깊이다. 새 구조는 primitive 규칙 유형과 규칙 수 층화를 유지하되 3개에서 새 깊이 조합과 D=5까지의 범위를 포함한다. 기존 조합 5개와 분리 보고한다. 신규 topology가 과제 난이도까지 일치한다는 뜻은 아니다. 신규 8쌍은 명시된 절차로 고정된 집합이며 무작위 IID 모집단 표본이 아니다. 모형 내부 사고/hidden layer, A/M 축, 자력 깊이 계산은 이번 실험의 직접 측정 대상이 아니다.

개발 테스트에서 사용하는 합성 정답 생성 함수는 tests/calibration에서만 호출한다. live 요청 경로는 모델 결과를 보정하거나 synthetic proof를 정답으로 삽입하지 않는다. Python CLI는 synthetic 계획의 실제 서버 실행을 거부한다.

## 실제 검증 기록

정확한 테스트 개수·플랫폼·경과·성공/실패/skip·배포 SHA-256은 함께 전달한 VALIDATION_RESULT_v086.json 및 개별 테스트 결과를 기준으로 한다. 자체시험·합성 전체 실행은 실제 Qwen 연구 실행이 아니다. PowerShell 네이티브 파서가 없는 환경에서는 그 검증을 했다고 주장하지 않는다.
