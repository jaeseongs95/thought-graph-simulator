# v050 다각도 검토와 수정 기록

## 검토 방식

실제 외부 심사자 또는 별도 에이전트를 호출하지 않았다. 서로 다른 심사 관점의 반론을 적용하고, 코드·원문·수동 표·공격성 회귀시험으로 확인했다. 이전 자기평가를 독립적인 성공 증거로 사용하지 않았다.

## 연구 방향 논쟁

| 관점 | 대립하는 선택 | 검토 결과 |
|---|---|---|
| 연구 연속성 | 괄호/변수명 실험을 계속 추가 vs 원래 판정 과제로 복귀 | v049에서 두 괄호 조건 모두 성공하는 직접 경로를 확보했다. 원래 criterion_witness 재통합을 선택했다. |
| 효율 | pipeline만 사용 vs 개선된 oneshot도 유지 | v049에서 직접 교환식이 같은 정확도를 더 적은 비용으로 달성했다. 개선된 oneshot을 반드시 유지한다. |
| 인과 해석 | 단계 수만 늘린 효과라고 주장 vs 설계 묶음 비교 | 출력 schema와 지시도 달라지므로 oneshot 대 staged는 묶음 비교다. 순수 호출 수 효과는 판정하지 않는다. |
| 공통 추출 | 두 staged 경로마다 추출 재실행 vs 실제 추출값 공유 | 하위 경로를 같은 추출값에서 비교하려고 공유한다. 독립 표본·실제 총비용으로 중복 계산하지 않는다. |
| 호스트 역할 | a를 answer_only에 연결하면 호스트가 답을 만든 것인가? | 계산/정답 보정 없이 실제 모델 필드를 그대로 라우팅한다. 이 역할을 명시하고 해당 값도 원래 입력에 대해 검사한다. |
| 의미 유지 | A/D/M을 이 과제의 bool로 재정의 vs 원래 의미 보존 | 재정의하지 않는다. 현재는 원래 전체 실험에 필요한 기준 판정 구성요소의 재통합이다. |

## 작성 후 실제로 재현된 문제

초기 기능 시험 64개는 통과했다. 그다음 오류 위치 심사에서 **후행 오류가 앞선 성공을 지우는 집계 결함 한 가지**를 발견했다. 다음 네 반례로 실제 재현했다.

| 반례 | 수정 전 | 수정 후 |
|---|---|---|
| proof 응답만 형식 오류, extract는 정답 | observed/primitives까지 False | 실제 성공한 observed/primitives는 True 유지 |
| proof 응답만 형식 오류, gap 응답은 정답 | gap 정답까지 False | gap은 True, 세 finding/전체 경로는 False |
| 추출·proof는 완료, gap은 미실행 | 완료된 입력 읽기까지 null | 완료된 층은 실제 결과 유지, gap·전체 경로만 null |
| NOT 형식 오류, 입력 읽기·primitives는 정답 | 입력 읽기 실패처럼 집계 | 앞 단계 정답 유지, 최초 출력상 오류는 NOT_format |

`REVIEW_BEFORE_FIX.log`에서 네 시험이 모두 실패했고, 같은 `test_review_regressions.py`를 수정 후 실행한 `REVIEW_AFTER_FIX.log`에서는 네 시험이 모두 통과했다.

이는 전체 성공 기준을 완화한 수정이 아니다. 원래 입력·원자 판정·최종 finding·필요한 NOT 중간값이 모두 맞아야 전체 성공한다는 기준은 유지된다. 부분 실패와 부분 성공을 실제 관측 위치에 맞게 보고하도록 고친 것이다.

작업 초안에서 과거 fixture의 규칙 배열 순서를 대조하여 `k10, k17, k03` 순서로 고정했다. 네 목표 동일성/소속 사례의 의미는 같지만, 입력을 고정한다는 계약을 지키기 위한 정리였다.

## 추가 반례 검사

실제 NOT 응답을 뒤집은 뒤 해시 연결까지 다시 계산하더라도, 자식 요청이 원래 정답을 계속 사용하면 거부했다. 부모 ID만 바꾸어 전체 event 해시를 다시 계산한 경우도 거부했다. 형식 오류를 정답으로 대체하지 않았으며 숫자·문자열 bool, 중복 키, thinking/잘린 응답 등은 통과시키지 않았다.

완료 보고서에서 오답은 실패로 집계하지만 통신/모델 식별 오류는 실행 미완료로 구분했다. 미완료는 자동 재시도하지 않는다. 무결성을 잃은 재감사는 과거 PASS 파생 요약을 무효화하고 요청·응답 원문은 보존한다.

ZIP은 실제로 담을 바이트를 임시 폴더에 고정한 후 다시 감사한다. 외부 계획의 snapshot/하드링크 대체, 미등록 호출 파일, source_snapshot 변경, 기존 파일 덮어쓰기 등도 시험했다.

## 합의

v050의 방향은 타당하다. 이미 확인한 계산 성공 경로를 원래 입력·출력 계약에 다시 붙여 보며, 직접 경로를 대조군에서 제외하지 않고, 호스트가 담당한 연결과 실제 모델 출력을 구분한다. 수정된 부분 결과 집계는 실패의 실제 위치를 찾는 목적에도 맞는다.

실제 사용자 LLM의 v050 성공 여부는 아직 관측하지 않았다. 제공된 실행·형식·반례 시험 결과와 이후 사용자가 실행할 모델 성능을 혼합하지 않는다.
