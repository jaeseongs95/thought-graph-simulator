# v079 동결 연구 계약

## 연구 근거와 새 설계 결정

v078은 완료된 배치다. 선택16/32, 선택 경로 생성9/32, 요구 D 종단4/32,
양방향 종단0/16, 지정 경로 참조5/16이었다. 초기 사실48/48·final 목표 지목48/48이지만
실패한 규칙50개는 실제 전제 연결 오류였다. 이 자료는 내부 원인이나 개선 방법의 효과를 확정하지 않는다.

**이번 구현의 설계 선택**은 선택기를 유지하고 현재 적용 규칙의 입력 중복 표시만 대조하는 것이다.
생성기가 기존 전체 규칙 목록과 요청 규칙 ID를 함께 받는 상태에서, 해당 규칙을 국소적으로 다시 보여주는
입력 계약이 전체 증명 구성에 미치는 관측 변화를 측정한다. 정보를 찾기 어려운 것이 실제 원인이라고 가정하지 않는다.

## 변경·불변 경계

기존 base 규칙 입력:

```json
{"operation":{"stage":"rule","index":2,"requested_rule_id":"u70"}}
```

새 explicit_rule의 같은 부분:

```json
{"operation":{"stage":"rule","index":2,"requested_rule_id":"u70","requested_rule":{"id":"u70","premises":["J20","J96"],"conclusion":"J54"}}}
```

전체 problem·provided_route_plan·원문 history·selection_original은 유지한다.
facts/final은 바꾸지 않는다. rule 출력은 기존 node 객체 하나이고 부모 수/ID enum 제약은 추가하지 않는다.
두 군은 같은 선택을 공유하지만 각 군이 실제 작성한 history는 별도로 유지한다.
이후 원응답이 달라지면 history도 달라지는 것이 정상이며, 어느 군의 정답으로 다른 군을 보정하지 않는다.

## 배정과 예산

H01~H04는 v078에서 이미 노출된4개 진단 문제다. 새 독립 구조는0개다.
같은 문제·seed·후보순서 안에서 shallow/deep 지시만 다른 쌍을 유지한다.
선택은 조건당1회로 두 생성군이 공유한다. 실험자가 경로를 지정하는 참조는 별도이며 선택 성공에 넣지 않는다.

- 두 seed:64001001,64001002. 후보순서2개, 방향2개.
- 공유 모델 선택32회, 군당 본실험32·참조16·양방향16쌍.
- 총 증명96건; 최대 추론600, 정답 경로 선택 시584, 매핑된 선택 최소568.
- metadata16슬롯 포함 진행616슬롯. 출력 토큰 이론적 상한2,457,600(600×4096).

전수 기준은 군별 모델 종단32/32·양방향16/16·참조16/16이다.
주 진단 비교는 전체 선택 경로 생성과 참조 구성의 각각 짝비교이며 서로 합치지 않는다.
종단 D 성공 정의는 이전과 동일하고 대응표 등의 신규 성공 조건은 없다.
유효하지만 역방향으로 바뀐 D 쌍은 reversed로 보존하며 성공으로 바꾸지 않는다.

## 해석·종료

명시군에서 생성이 늘어도 선택기 개선이나 새 문제 일반화를 주장하지 않는다.
전체 합계와 문제별 개선·악화를 함께 보고한다. 같은 seed라도 원응답의 완전 재현을 가정하지 않는다.
비교는 현재 배치의 짝자료를 우선하고 v078 과거 점수와 단순 차이를 인과 효과로 쓰지 않는다.
순증은 관측 짝의 수치이며 통계적 유의성/모집단 효과의 보장이 아니다.

이 한 배치 뒤 진단 분기를 닫는다. 성과가 좋거나 나빠도 자동 반복·추가 제약·다음 버전을 만들지 않는다.
다음 연구 결정은 결과를 본 뒤 원 D 연구의 종단 질문에 비추어 별도로 내린다.
