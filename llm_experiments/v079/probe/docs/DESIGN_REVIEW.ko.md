# v079 설계 검토

## 주요 위험과 대응

1. 원인 미확인: 현재 규칙 추가 표시는 가능한 개입이다. 전제 연결 실패의 원인이 검색 부담이라고 단정하지 않는다.
2. 선택 병목: 공유 선택은 unchanged. 생성기가 좋아져도 오선택의 요구 D 실패는 그대로 유지한다.
3. 정답 누출: 원래 problem.rules 객체의 재표시만 허용. 정답 부모 ID·완성 node·binding·깊이표 금지.
4. 사후 보정: 실제 history 원문을 그대로 전달. parse로 노드를 추려 전달하거나 실패 단계 교체 없음.
5. 재사용 문제: H01~H04는 진단용 노출 문제. 개선 후 일반화 주장은 새로운 확인 절차 없이는 하지 않는다.
6. 불공정 분모: 선택32회 공유를64회로 부풀리지 않음. 참조16은 군별 자율선택 성과에 합산하지 않음.
7. 독립성: 독립 요청/graph/단계/집계는 별도 구현. 공통 프로토콜·보고서 서식 일치만으로 정확성을 보장하지 않음.
8. 출력 부담: 원문·출력 토큰·서버시간 계측을 보존. 시간 합은 전체 wall-clock이나 보편 비용 우월성이 아님.
9. 실행 순서: 두 군이 먼저 실행되는 단위를24/24로 배정. 작은 반복 수로 캐시/하드웨어 원인을 추정하지 않음.
10. 끝없는 진단: 한 배치 종료를 고정. 개선 여부와 관계없이 자동 제약 추가·후속 버전 없음.

## 시험할 반례

선택 오류+정확 생성, 정답 선택+오류 생성, 유효한 역방향 쌍,
부모 개수는 같으나 전제가 다름, 부모 누락/중복/미존재, 잘못된 final,
앞 단계 실패 이후 우연한 최종 정답, 명시군만 악화/개선, 한 군 미관측,
해시를 다시 계산한 현재 규칙/프롬프트/점수 변조, 실제 base 요청306개 원바이트 호환성.

독립 검산은 번들 내부 일관성 검사이며 외부 실제 실행 사실의 인증은 아니다.
