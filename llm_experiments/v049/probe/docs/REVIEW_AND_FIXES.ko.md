# v049 다각도 검토와 교정 기록

## 검토 방식

외부 에이전트나 실제 외부 심사자를 호출하지 않았다. 연구 설계, 인과 해석, 비교 공정성, 통계, 실행 오류, 자료 보존, Windows 호환성의 서로 다른 기준으로 주장을 대조했다. 코드 검증은 단위/통합/명령행/합성 HTTP/오류 주입 시험으로 수행했다. 역할별 의견의 개수는 채택 기준이 아니다.

## 설계 논쟁

**더 많은 seed인가, 표현 확장인가?** v048은 발견 seed 밖 10개에서 두 성공 경로를 확인했고 같은 요청의 불안정성을 보이지 않았다. 현재 미확인 조건은 표현의 구성 요소다. 따라서 seed를 더 추가하지 않고, 전체 10개를 유지한 대응 표현 실험을 채택했다. 이미 관측한 seed라는 사실을 표시하고 새로운 seed 검증이라고 부르지 않는다.

**NOT 괄호·바깥 괄호·변수 이름을 한꺼번에 바꿀 것인가?** 그 경우 성공 차이를 어느 변경과 연결해야 하는지 흐려진다. 이번에는 순서와 바깥 괄호의 2×2만 사용한다. NOT b 자체의 괄호는 유지해 scope 표지를 제거하지 않는다. 변수 이름 변경은 시스템 지시도 바꾸므로 제외했다.

**pipeline을 빼도 되는가?** 현재 목표식 최종값만 얻는 데는 더 비싼 경로다. 하지만 원문 반환값 연결과 중간값 검증의 anchor이고, 직접식 모두가 흔들리는 경우를 관측할 대조군이다. retained comparator로 유지하되 비용 절감·추가 정확도를 선험적으로 주장하지 않는다.

**6회에서 2회로 줄여도 되는가?** 같은 seed의 반복은 새로운 문제 표본이 아니다. v048의 동일 요청 재현 관측에 근거해 반복 예산을 줄였다. 대신 전체 seed에 걸쳐 5조건 위치와 블록 내부 직전 조건을 균형화했다. 한 seed 안의 모든 순서를 통제했다고 쓰지 않는다. 중복 요청 불안정성은 새 결과에서도 계속 측정한다.

**이것으로 A/D/M 본 가설을 검증하는가?** 아니다. 본 작업으로 돌아가기 위한 실패 민감도·실행 계약의 기반 검사다. 이 작은 식에서의 성공을 본 가설 입증으로 확장하지 않는다. v049 이후 원래 전체 판단 작업으로 재통합하는 출구를 명시했다.

## 구현 후 실제 재현한 문제 3개

1. **최초 감사 뒤, ZIP으로 읽기 전 원문이 변경되는 간격.** 초기 구현은 감사한 시점의 PASS를 유지한 채 그 후 바뀐 바이트를 묶을 수 있었다. 시험은 첫 감사 직후 응답 한 파일을 바꿨고 오류가 발생하지 않아 실패했다. 수정 후 수집한 바이트와 외부 계획을 임시 폴더에 동결해 다시 감사한 뒤 그 바이트만 ZIP으로 기록한다. 실패 시 새 ZIP은 생성되지 않는다.

2. **calls 아래 미등록 응답 파일이 있는 완결 실행.** 초기 감사는 호출 하위 폴더 목록만 대조해, calls 바로 아래 추가 응답 파일을 검출하지 못했다. 수정 후 완료 실행의 실제 요청·응답 파일 전체 목록이 event에서 도출한 목록과 정확히 일치해야 한다. 누락·추가·숨겨진 파일을 거부한다. 링크 포함 원문도 거부한다.

3. **Windows 예약 파일명.** 초기 ZIP 경로 검사는 상위 디렉터리 이탈·중복·링크는 막았지만 `CON.json` 같은 Windows 장치 예약명을 명시적으로 거부하지 않았다. 수정 후 예약명, 끝의 점/공백, Windows 특수문자, 제어문자를 거부한다.

수정 전 동일한 세 시험이 모두 실패했고, 수정 후 모두 통과했다. 로그는 `validation/REVIEW_BEFORE_FIX.log`와 `validation/REVIEW_AFTER_FIX.log`에 있다. 이러한 경계 문제는 새 코드에서 실제 반례로 확인한 사항이다. 사용자 v048 점수가 틀렸다는 뜻으로 해석하지 않는다.

## 유지한 경계

Python subprocess 출력의 Windows 인코딩 수정은 기존 `test_support`를 그대로 유지했다. 실험 runner는 subprocess로 모델을 호출하지 않으며 HTTP 원문은 bytes로 보존한다. JSON/MD 저장은 UTF-8이다. CP949/UTF-8/ASCII/불완전 바이트 시험도 기존 회귀에 포함된다.

실행 중에는 정답 계산기로 부모값을 보정하지 않는다. 실제 잘못된 NOT bool도 다음 AND에 전달한다. bool을 얻지 못하면 해당 child만 blocked가 된다. 전체 마지막 값이 우연히 맞아도 중간값이 틀리면 trace는 실패다. 이미 보존된 PASS 요약은 재감사 실패시 명시적인 실패 요약으로 갱신하며 원문을 지우지 않는다.

## 최종 합의

현재 연구 질문에는 v049의 좁은 2×2 대조가 적절하다. 생성 조건·목표·모델을 유지하고 표현 요소만 계획적으로 바꾼다. 기존 성공 경로를 보존하며, 비용과 경로 검증을 구분한다. 교정 후에도 미시험 모델, Windows 실기 실행, 내부 모델 메커니즘까지 검증했다고 보고하지 않는다. 실제 시험 범위는 `validation/VALIDATION.ko.md`에 별도로 기재한다.
