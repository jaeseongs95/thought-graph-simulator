# v058 사전 고정 프로토콜: 같은 seed의 과제 선후 재현

## 질문

v057에서 선후와 성패가 함께 움직인 두 경계 조건을 대상으로, 같은 seed의 choice 출력이 graph→choice와 choice→graph 순서에서 달라지는지 확인한다. 조건은 v057 결과를 본 뒤 선정했으므로 탐색적 재현이다. v058 새 결과를 보기 전에 이 명세와 실행 계획을 동결한다.

## 고정값과 실행표

| 항목 | 고정 내용 |
|---|---|
| reference | `qwen3:4b-instruct`, `T02/original/shallow` |
| candidate | `gemma3:4b`, `K01/original/shallow` |
| seed | v057의 서로 다른 10개 seed 전체 |
| 순서 | 각 모델·seed에 `graph_first`와 `choice_first` 모두 |
| 요청 | 해당 v057 graph/choice 요청 바이트 그대로. facts/rules/goal, 지시, schema, 옵션, seed 보존 |
| 모델 | digest, server, details, template, parameters, model_info 보존. 다운로드·갱신 없음 |
| 일정 | 모델×seed 20블록, 블록마다 4추론. 순서 묶음의 선후와 모델 선후는 seed index별 교차 |
| 기록 | 블록 전후 metadata 40개, 추론 80개, 합계 120 action. 원문과 직전 추론 ID를 보존 |

metadata 호출은 모델 추론 수에 포함하지 않는다. warmup과 자동 재시도는 0이다. Ollama 0.34의 `/api/show`는 같은 `parameters` 항목을 다른 줄 순서로 반환할 수 있다. 이에 따라 줄 순서만 정규화하며, 줄의 값과 중복·누락 여부는 그대로 비교한다. 모델 digest, 서버 버전, details, template, model_info도 정확히 일치해야 한다. 원문 metadata와 `show_sha256`은 증거에 보존한다. 모델 내부 상태·캐시를 초기화하지 않으므로 각 순서 묶음의 첫 호출도 앞선 호출 이력에서 독립인 cold start로 해석하지 않는다. `previous_call_id`와 요청·응답의 시간·cache 관련 수치를 보존하되 캐시 인과 실험이라고 부르지 않는다.

선택 ID를 전달하거나 정답을 추가하지 않는다. 기존 graph/choice 과제 문구 차이는 그대로 유지한다. 모델별 문제가 다르므로 두 모델 간 격차를 순수한 모델 효과로 비교하지 않는다.

## 평가 단위와 성공·실패

주 평가 단위는 모델·고정 문제·seed 10개다. 각 seed에서 두 순서의 choice를 대응시켜 다음을 별도로 보고한다.

1. 선택 ID가 달라졌는가. 두 ID를 측정할 수 없으면 null이다.
2. 얕은 방향 이행이 `둘 다 성공`, `graph_first만 성공`, `choice_first만 성공`, `둘 다 실패`, `미관측/미측정` 중 어디에 해당하는가.
3. 형식과 choice 유효성은 어떠한가. graph는 별도로 실제 유효 D와 방향 이행을 기록한다.

choice의 `D`, `proof_valid`, `strict_valid`는 null이다. 무효 graph에는 실제 D를 부여하지 않는다. 미실행을 실패나 0으로 합산하지 않으며 비교율은 전체 완료 시에만 계산한다. 원문 payload 오류와 무효 논리 결과는 기록하고 다음 예정 호출을 수행한다. HTTP·transport·identity 실패는 즉시 중단하고 부분 실행을 보존한다. 실행을 시작한 결과는 자동 재개·새 이름 재시도로 이어가지 않는다.

이번 설계는 shallow만 검사한다. shallow/deep 대응 성공이나 A/D/M 전체 제어 성공은 보고하지 않는다. 같은 seed에서 반복한 네 호출은 새 문제 네 개가 아니다. 가설검정의 일반화 p값보다 10개 seed의 대응표와 관측 분모를 우선한다.

## 결과 이후의 결정

- 같은 seed에서 선택 또는 방향 이행 변화가 재현되면 실행 선후·이력 민감성의 근거로 기록한다. 다음에는 직전 요청 또는 상태를 하나씩 고정하는 별도 진단을 검토한다. 캐시를 단독 원인으로 선언하지 않는다.
- 변화가 재현되지 않으면 v057의 선후 연관성을 원인 설명으로 채택할 근거가 약해졌다고 기록한다. 유한한 두 조건·10seed에서 차이를 관측하지 못했다는 범위이며 순서 효과의 부재를 증명하지 않는다.
- 두 순서 모두 선택을 안정적으로 이행하면 실제 선택 ID를 무보정 전달하는 후속 생성 대조를 검토한다. 성공 seed만 사후 선별해 후속 모집단을 만들지 않는다.
- 두 순서 모두 선택이 실패하면 선택 전제·규칙 위치·지시 해석을 먼저 진단한다. 형식 실패가 많으면 선택 변화와 출력 계약 실패를 분리한다.
- 일부만 완료되면 누락·실패 원인을 보고하고 전체 비교 결론을 보류한다. 새 실험 실행은 별도 사용자 요청으로 한다.

## 소스·증거 계약

준비 단계에서 v057 전체 증거를 생산 감사기와 생산 채점기를 import하지 않는 검산기로 확인한다. 첨부 snapshot은 실행하지 않는다. 계획에 기준선 해시·선택한 원문 요청·모델·일정·소스 해시를 동결한다. 실행·감사는 요청 바이트, event chain, identity, 원문·snapshot 파일 목록, 상태의 일관성을 검사한다. 결과 ZIP은 별도 독립 검산기로 다시 계산한다.

완료된 v057 소스·증거를 수정하지 않고 v058은 새 경로에 쓴다. Python 3.10 이상과 표준 라이브러리를 사용한다. 검증에는 mock·fixture를 사용하고 이를 실제 LLM 성과로 세지 않는다. 최종 소스 ZIP은 새 위치에 풀어 manifest와 자체시험을 다시 검사한다.
