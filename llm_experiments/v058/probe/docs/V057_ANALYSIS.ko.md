# v057 결과 분석과 v058 설계 판단

v057에서 Qwen은 마지막 규칙을 고르는 과제와 전체 증명을 작성하는 과제 사이에 큰 수행 차이를 보였다. Gemma의 규칙 선택은 제시 순서를 바꾸면 안정성이 사라졌다. 두 모델 모두 전체 증명의 shallow/deep 대응 제어에는 성공하지 못했다. 이 결과를 논문 전체의 성공·실패로 판정할 수는 없다.

이번 검토에서 새로 확인한 쟁점은 **seed와 graph/choice 실행 선후가 얽혀 있다는 점**이다. 따라서 다음 실험은 선택 ID 전달보다 같은 seed의 양 실행 순서를 재현하는 진단을 우선한다. v058은 이 판단을 구현한 80회 탐색 실험이다. 이 문서는 v057 관측 결과와 아직 실행하지 않은 v058 설계를 구별한다.

## 분석 관점은 어떻게 도출했는가

논문의 주장에 필요한 증거와 실험에서 실제 얻은 자료 사이의 연결을 나눠 관점을 도출했다. 논문은 관측 좌표, 연산 선택, 실행, 결과 수용, 추가 효용을 구분한다. 실험 자료도 출력 형식, 증명 유효성, 방향 이행, 대응 성공, 증거 무결성을 따로 기록한다. 이 두 구분이 만나는 지점과 서로 연결되지 않는 지점을 검토했다.

| 관점 | 출발 질문과 근거 | 확인할 자료 | 반례·대안 설명 |
|---|---|---|---|
| 측정 | 논문 §3.3의 D를 실제 측정했는가? | 원응답의 `parents`, `final_node_id`, 사실·규칙 | 마지막 규칙만 맞아도 부모가 틀릴 수 있다. |
| 구성타당성 | 축소 과제 성공이 같은 능력의 성공인가? | graph/choice 지시·schema 차이, 논문 §5.3 | 선택값에 대응하는 깊이는 생성된 DAG의 깊이가 아니다. |
| 수행 병목 | 선택·구성·참조 연결 중 어디서 실패하는가? | 유효성, 최종 규칙, 부모·원자·ID 오류 | 유효하지만 방향이 틀린 증명과 무효 증명은 원인이 다를 수 있다. |
| 표면 단서 | 규칙 위치가 답 선택과 함께 움직이는가? | 두 규칙 순서, 첫 goal 규칙과 출력의 일치 | 위치 휴리스틱과 양립해도 내부 알고리즘을 입증하지 않는다. |
| 통계·실행 이력 | 관측 차이를 seed나 선후로 설명할 수 있는가? | 같은 seed, 실행 위치, 직전 요청, cache 관련 원문 수치 | 교차 배정만으로 같은 seed의 두 선후를 관측한 것은 아니다. |
| 구현·증거 | 저장 요약을 신뢰할 수 있는가? | 계획·원문·event chain·identity·snapshot·ZIP 해시 | 검산 일치는 무결성 근거이며 가설 지지나 외부 실행 인증과 다르다. |
| 논문 기여 | 어느 가설의 어떤 부분을 검사했는가? | 논문 §9–10, 부록 D | A/M, 인간 주석 신뢰도, CTA·TTS 추가 효용은 별도 대조가 필요하다. |

이론 담당과 실증 담당은 먼저 각자 논문 또는 원문을 읽고 의견을 냈다. 조정자는 입력 결합과 생산·독립 감사를 맡았다. 이후 원문에서 얻은 반례를 서로 전달해 후속 설계를 다시 판단했다. 이는 별도 에이전트의 독립 검토이며 외부 인간 심사나 독립 연구기관의 재현은 아니다. 같은 모델 계열·명세를 공유하는 검토의 공통 오류 가능성도 남는다.

## 원문에서 확인한 결과

| 모델·과제 | 과제 유효 | 방향 지정 이행 | shallow/deep 대응 성공 | 두 규칙순서 모두 대응 성공 |
|---|---:|---:|---:|---:|
| Qwen `qwen3:4b-instruct` graph | 82/120 | 30/80 | 0/40 | 0/20 |
| Qwen choice | 120/120 | 73/80 | 33/40 | 13/20 |
| Gemma `gemma3:4b` graph | 5/120 | 5/80 | 0/40 | 0/20 |
| Gemma choice | 120/120 | 47/80 | 7/40 | 0/20 |

120회에는 중립 40회가 포함된다. 40쌍은 문제 2개 × 규칙순서 2개 × seed 10개에서 shallow와 deep을 함께 평가한 단위다. 20단위는 같은 문제·seed에서 두 규칙순서를 모두 통과해야 성공이다. choice의 유효성은 도달 가능한 마지막 규칙 선택을 뜻한다. `proof_valid`, `strict_valid`, 실제 `D`는 null이며, 표의 choice 방향 이행은 `implied_depth`로 평가한다.

480개 출력은 모두 형식 계약을 통과했다. 모든 응답의 `done=true`, `done_reason="stop"`도 확인됐다. 현재 관측은 생성 상한에 걸려 응답이 잘렸다는 설명을 뒷받침하지 않는다. 다만 이것만으로 내부 계산이 충분했는지는 알 수 없다.

독립 재계산에서 v057의 4,361개 비교 필드와 내장 v056의 3,738개 비교 필드는 불일치가 없었다. v057 ZIP manifest 대상은 1,124파일, 관측 추론은 480회, metadata 기록은 40개다. 다섯 입력 사이의 바이트·계획·identity 결합과 생산 재감사는 `tools/validate_inputs.py`로 다시 검사한다. 검사 결과는 별도 검증 자료에 둔다.

### 규칙 선택과 그래프 연결의 차이

Qwen의 방향 지정 graph 80개는 모두 제시 순서상 첫 goal 도출 규칙을 최종 노드의 `rule`로 기록했다. 무효 그래프도 포함한 원문 표지 비교이므로 이를 80개의 유효 D 선택으로 세지 않는다. Gemma choice는 방향 지정 73/80, 중립 포함 103/120에서 첫 goal 규칙을 골랐다. 두 패턴은 위치 단서 의존성과 양립한다.

Qwen의 `T02/swapped` graph 30개는 모두 마지막 `r69`의 전제 `Lt` 대신 초기 사실 `Lp`, `Ls`의 노드를 부모로 연결했다. 마지막 규칙을 맞히는 것과 그 규칙을 지지하는 DAG를 구성하는 것은 분리된다. `graph__merged__reference__s00_T02_swapped_deep`이 대표 사례다.

`graph__merged__reference__s00_K01_original_shallow`는 유효한 `Ca → Cb → Cc`, D=2를 작성했다. 이 사례는 방향 이행 실패다. 반면 `graph__merged__candidate__s00_K01_original_deep`는 사실·규칙·도출 노드의 역할을 혼동한다. 두 실패를 하나의 “추론 부족”으로 묶으면 다음에 무엇을 바꿀지 결정하기 어렵다.

Qwen graph에서 최종 조상이 아닌 추가 노드 37회, 규칙 전제 불일치 30회가 독립 진단됐다. Gemma는 각각 96회와 93회이며, 규칙 결론 불일치 53회, 없거나 뒤에 나오는 부모 참조 55회도 관측됐다. 오류는 중복 집계이고 생산 오류 코드와 일대일 대응하지 않는다.

### seed와 실행 선후의 교락

Gemma `K01/original/shallow` choice 성공은 `s00,s02,s04,s06,s08`에서 5/5, 나머지 seed에서 0/5다. 전자는 graph→choice, 후자는 choice→graph 순서였다. 응답의 `prompt_eval_cached_count`도 각각 31과 70으로 갈렸다. Qwen `T02/original/shallow`의 성공 seed `s05,s07,s09` 역시 모두 choice-first였다.

이것은 실행 선후와 성패의 연관성이다. 각 seed가 두 선후에서 모두 관측된 것이 아니므로 seed 차이, 직전 요청, 캐시, 시간 또는 모델 상태 가운데 하나를 원인으로 확정할 수 없다. 특히 cache 수치가 다르다는 이유만으로 캐시가 정답을 바꿨다고 결론 내리지 않는다.

통계의 범위도 두 고정 문제의 반복 측정에 한정한다. 480호출이나 40쌍을 서로 독립인 새 문제 표본으로 취급하지 않는다. 이 자료로 모든 문제·모델의 성공률을 추정하거나 작은 p값을 일반화의 증거로 제시하지 않는다.

## 제3자 의견과 교차검증에서 바뀐 판단

| 제안·주장 | 독립 반론 | 교차검증 후 판단 |
|---|---|---|
| Qwen은 선택을 할 수 있으니 ID를 다음 생성에 넘겨 보자. | 부모 연결 오류가 남을 수 있고 선택 안정성에도 선후 교락이 있다. | 유효한 후속 질문이지만 현재 원인 진단의 첫 순위에서는 내린다. |
| 두 모델의 실패는 긴 DAG 작성 부담 때문이다. | Gemma는 choice도 두 순서 안정성 0/20이고, 과제 지시와 schema가 함께 바뀐다. | 출력 과제별 격차는 인정하되 길이만의 원인 설명은 채택하지 않는다. |
| graph/choice 선후를 seed별로 교차했으니 순서 문제를 통제했다. | 같은 seed는 한 선후만 경험했다. 특정 셀에서 parity와 성패가 정확히 겹친다. | 같은 seed의 양 선후 재현이 필요하다. |
| 모든 선택을 사용한 960회 전달 실험으로 순서 문제까지 해결하자. | 새 전달 비교의 민감도는 검사해도 과거 choice 교락은 풀리지 않는다. | 비용과 질문의 직접성을 고려해 80회 순서 진단을 먼저 구현한다. |
| 검산 PASS이면 논문 가설도 지지된다. | 무결성·채점 일치와 연구 가설의 지지는 다른 판단이다. | 기각한다. 검산은 보고 수치의 근거로만 사용한다. |

채택한 설명은 “외부 출력 과제·규칙 위치별 수행 차이와 실행 이력·성패의 연관성이 관측되며, 전체 D 제어는 아직 관측되지 않았다”이다. “선택을 이해했는데 생성 때 잊었다”는 내부 설명은 보류한다. 다수결 대신 원문 반례와 현재 대조의 식별 범위로 판단했다.

## 논문에 대해 말할 수 있는 범위

논문 §3.3의 기록된 의존 깊이를 계산하는 측정 명세와, 같은 문제에서 다른 외부 기록을 요구하는 진단의 일부를 구현했다. 그러나 v057의 choice 성공을 A/D/M 전체 제어로 승격할 수는 없다. 논문 §9–10의 인간 주석 신뢰도, 활성값 개입, 추가 예측력, 동등 예산 효용, 학습 효율, CTA 중재, 내부 연산 기여, TTS 결합의 추가 가치, 재사용 가설은 이 실험으로 입증되지 않는다.

제3자의 권고는 논문 결론을 확대하기보다 결과를 외부 기록의 선택·생성 진단으로 추가하는 것이다. 모델 일반 능력 차이라는 표현도 선후 재현 결과가 나오기 전에는 제한해야 한다.

## 선택한 후속 소스

v058은 Qwen `T02/original/shallow`와 Gemma `K01/original/shallow`에서 기존 seed 10개를 모두 사용한다. 각 seed마다 graph→choice와 choice→graph를 새로 실행한다. 두 순서 묶음의 선후와 모델 블록 선후를 교차한다. 총 80회이며 모든 요청은 해당 v057 원문과 바이트가 같다.

문제·모델별 경계 조건은 결과를 본 뒤 골랐다. 따라서 탐색적 재현이며 두 모델의 일반적인 성능 비교도, shallow/deep 선택적 성공 검사도 아니다. 첫 번째 과제 앞에도 이전 호출 이력이 남는다. 서버·모델 재시작이나 캐시 초기화를 하지 않으므로 구체적인 캐시 원인을 분리하지 않는다.

같은 seed의 선택 ID 변화, 얕은 방향 이행의 변화, 형식·유효성, 원문 비용·cache 수치를 따로 보고한다. 변화가 재현되면 고정 seed만으로 결과를 설명하기 어렵다는 근거가 된다. 변화가 없으면 기존 선후 연관성의 재현 근거가 약해진다. 두 경우 모두 시간·상태·캐시의 구체적 원인은 남는다. 자세한 고정값과 다음 결정은 `V058_PROTOCOL.ko.md`에 기록한다.
