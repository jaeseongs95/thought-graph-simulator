## 1. 결론

**공백 하나에 따라 선택 결과가 달라지는 현상은 이번 제한된 교차 검사에서 다시 관측됐다. 그러나 공백을 넣어도 후보 순서와 요구 방향 전체에서 정상 선택이 확보되지는 않았다. 두 형식 모두 사전 공학적 기준에 미달하므로 P01은 종료한다.**

정확한 표현은 ‘Gemma가 숫자 비교를 전혀 못 한다’도, ‘공백을 넣으면 해결된다’도 아니다. **이번 입력·출력 계약에서 공백이 있으면 큰 값 선택은 후보 순서와 무관하게 16/16이지만, 작은 값 선택은 16회 모두 첫 후보에 고정됐다.**

실험 소스나 동결 계획을 수정하지 않았다. 이 분석에 포함된 Python 파일은 제출 원문을 읽는 오프라인 검산용이며 새 모델 추론을 수행하는 실험 소스가 아니다.

## 2. 원응답 재계산 결과

### 2.1 형식별 집계

|형식|선택 성공|작은·큰 요구를 모두 맞힌 쌍|사전 기준|
|---|---:|---:|---|
|공백 없음 `compact`|16/32 (50%)|0/16|미달|
|쉼표 뒤 공백 `comma_space`|24/32 (75%)|8/16|미달|

전체 선택 40/64, 전체 방향 쌍 8/32다. 전체를 합친 수치로 어느 한 형식이 통과한 것처럼 판정하지 않는다. 형식별 기준은 선택 32/32 및 방향 쌍 16/16이다.

### 2.2 순서와 요구를 나눈 결과

|형식|숫자 순서|작은 값 요구|큰 값 요구|모델 원응답 패턴|
|---|---|---:|---:|---|
|공백 없음|작은 값 먼저|8/8|0/8|둘 다 인덱스 0|
|공백 없음|큰 값 먼저|0/8|8/8|둘 다 인덱스 0|
|공백 있음|작은 값 먼저|8/8|8/8|작은 값은 0, 큰 값은 1|
|공백 있음|큰 값 먼저|0/8|8/8|둘 다 인덱스 0|

각 8건은 서로 다른 숫자쌍 4개 × seed 2개다. 숫자쌍 `[1,2]`, `[1,4]`, `[2,4]`, `[2,3]` 모두 동일한 패턴이며, 두 seed 사이에서도 대응하는 32개 조건의 선택 인덱스가 모두 일치했다.

### 2.3 원문 예시

`0`은 첫 번째 후보, `1`은 두 번째 후보다. 아래 선택은 두 seed에서 동일하다.

|입력 원문|작은 값 요구의 응답|큰 값 요구의 응답|
|---|---|---|
|`{"depths":[1,2]}`|`{"candidate_index":0}` — 정답|`{"candidate_index":0}` — 오답|
|`{"depths":[1, 2]}`|인덱스 0 — 정답|인덱스 1 — 정답|
|`{"depths":[2,1]}`|인덱스 0 — 오답|인덱스 0 — 정답|
|`{"depths":[2, 1]}`|인덱스 0 — 오답|인덱스 0 — 정답|

표의 일부는 응답의 선택 값만 표시했다. 공백과 개행을 포함한 실제 응답 문자열은 `RAW_RESPONSES.csv`와 `RAW_REAUDIT.json`에 보존했다.

## 3. 공백 대조가 말해 주는 것

값·순서·요구·model·seed·options·출력 Schema를 같게 유지한 32개 대조를 실제 요청 바이트로 비교했다. 각 대조는 정확히 ASCII 공백 한 글자만 다르다.

|공백만 다른 짝비교|건수|
|---|---:|
|둘 다 정답|16|
|둘 다 오답|8|
|공백 있을 때만 정답|8|
|공백 없을 때만 정답|0|
|미측정|0|

공백의 이득은 **작은 값이 먼저 있고 큰 값을 요구한 8건**에 전부 집중된다. 따라서 전체 50%→75% 차이는 모든 조건에서 균등한 개선이 아니라, 특정 순서·요구 조합에서의 변화다.

v072와 API 요청 바이트가 완전히 동일한 이번 조건은 36개였고, 대응하는 과거 응답들의 선택 인덱스와 모두 일치했다. 이 중 공백 없는 조건은 32개다. 과거 중복 호출을 새로운 독립 문제로 가산하지 않았다.

이는 기존 사후 관찰을, 사전에 고정한 공백·순서·요구 교차 설계에서 확인한 결과다. 네 숫자쌍과 두 seed의 범위에서 패턴이 일관됐다고 판단할 수 있다. 무작위 표집이나 광범위한 새 문제 일반화를 검증한 것은 아니다.

## 4. 관찰·추론·원인 가설의 구분

**관찰:** 공백 없는 32회는 모두 인덱스 0이다. 공백 있는 32회 중 큰 값 요구는 16/16으로 맞고, 작은 값 요구는 첫 후보를 16회 모두 선택해 8/16이다. 응답 형식과 실행 상태는 모두 정상이다.

**자료가 지지하는 해석:** 현재 수치 선택 인터페이스는 의미가 같은 입력 표현과 후보 위치에 안정적이지 않다. 특히 작은 값 선택과 큰 값 선택의 수행 양상이 비대칭이다. ‘큰 값 선택조차 수행하지 못한다’는 설명은 이번 성공 16/16과 맞지 않는다. ‘작은 모델 전체의 수치 비교 한계’라는 확대 해석도 하지 않는다.

**현재 구별하지 못하는 내부 원인:** 토큰화, 모델 학습 패턴, 출력 문법 제약, 기타 실행 조건 중 무엇이 이 행동을 만들었는지는 확인하지 않았다. 이번에는 출력 Schema를 바꾸지 않았으므로 그 영향을 독립적으로 판정하지 않는다. 출력 패턴과 맞는 설명을 모델 내부 알고리즘을 발견한 것처럼 쓰지 않는다.

**연구 범위:** 이번 과제의 숫자는 실험자가 제공했다. 모델의 깊이 계산, 경로 선택, 증명 생성, 실제 목표 지지 DAG의 D 변화는 이번에 측정하지 않았다. 따라서 숫자 대조의 부분 성공을 종단 D 제어 성공으로 옮기지 않는다.

다음 의사결정 대상은 **원래의 D 경로 선택 프로토콜을 재정의할 것인지**다. 정확한 수치 보고/수치 비교를 반드시 통과해야 하는 선행 단계로 고정하지 않고, 원래 목표인 ‘D 요구 → 모델의 경로 선택 → 원값 무보정 전달 → 유효 graph와 실제 D’로 복귀할 설계를 판단한다. 이 판단은 자동 P02 실행 승인이나 준비 완료가 아니다. 이전 v070과 무엇이 다르고 어떤 관측이 본래 가설을 구분할지 먼저 명시해야 한다.

동결 장부 r1과 evidence 안의 계획 파일은 변경하지 않았다. 이 문서는 그 계획에 대한 실제 결과 기록과 판단이며 새로운 실험 승인서가 아니다.
