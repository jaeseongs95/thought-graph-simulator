## 1. 연구의 목표와 이번 계획의 경계

같은 문제·목표를 고정하고 구조 요구를 바꿨을 때, **실제 유효한 최종 산출물의 구조가 요구에 맞게 달라지는지**를 검증한다. D는 최종 goal을 지지하는 DAG의 의존 깊이다. 초기 사실은 0, 규칙 결과는 `1 + max(전제 깊이)`로 측정한다. 규칙 수·설명 길이·모델 내부 연산 깊이와 동일시하지 않는다.

이번 재정렬은 다음 세 가지를 구분한다.

- **증거·코드 검증:** 원문과 채점, 요청 구성, 중단·미측정 처리가 계약에 맞는가.
- **인터페이스 양성 대조:** 정해진 숫자쌍을 주었을 때 공백·후보 순서에 따라 선택이 어떻게 달라지는가.
- **본래 연구:** D 요구에 따라 경로를 선택하고 실제로 유효한 최종 증명을 생성하는가.

정확한 깊이 숫자를 설명하는 능력을 마지막 항목의 새로운 필수조건으로 추가하지 않는다. 수치 대조 실패를 A/D/M 전체의 실패로 확대하지 않는다. 반대로 수치 대조 성공을 그래프 제어 성공으로 세지 않는다.

## 4. P01 — v073의 동결된 질문과 설계

### 4.1 질문

같은 숫자 값·순서·요구·모델·seed·출력 스키마·옵션을 유지하면서, `depth_report` 문자열의 **쉼표 뒤 공백 하나만** 바꾸면 선택 결과가 달라지는가? 그 결과가 후보 순서를 뒤집어도 유지되는가?

이 질문은 앞선 검토의 사후 관찰을 제한된 교차 검사로 옮긴다. 공백을 넣으면 해결된다는 결론을 미리 정하지 않는다.

### 4.2 고정 요소와 조작 요소

| 구분 | 동결 내용 |
|---|---|
| 모델 | `gemma3:4b`, v072에 기록된 digest 및 네이티브 템플릿/설정. 모델 변경 없음. |
| 숫자쌍 | `[1,2]`, `[1,4]`, `[2,4]`, `[2,3]`. 기존 5문제의 서로 다른 범위 4개만 사용. C01/C02의 중복 `[2,3]`을 새 과제로 중복 실행하지 않는다. |
| 표현 조작 | compact: `{"depths":[1,2]}` / comma_space: `{"depths":[1, 2]}`. 쉼표 뒤 1개 ASCII 공백 이외의 차이 없음. |
| 순서 조작 | 작은 값 먼저 / 큰 값 먼저. |
| 요구 조작 | v072의 작은 D 선택 문장 / 큰 D 선택 문장을 그대로 사용. |
| seed | v072와 같은 `64001001`, `64001002`. 반복 seed는 독립 문제 수가 아니다. |
| 출력 계약 | v072와 동일한 `{"candidate_index":0 또는 1}` JSON Schema. 입력 표현과 출력 제약을 동시에 바꾸지 않는다. |
| 샘플링·예산 | 실제 v072 수치 선택 요청을 복제하고 seed와 실험 입력만 대입. temperature 0.7 등 명시 옵션은 유지. |
| 모델 이력 | 사용하지 않는다. 숫자는 실험자가 사전 지정한 양성 대조 입력이다. 기존/새 모델 응답을 보정하는 단계가 없다. |

총 **4숫자쌍 × 2seed × 2후보 순서 × 2표현 × 2요구 = 64회 추론**이다. 16개 block에서 각 4회를 실행하고 block 전후에 모델 정보를 확인하므로 **96개 action**이다. metadata action 한 개는 version/tags/show 세 HTTP 조회이며 추론 1회로 세지 않는다.

동일한 공백 비교 32쌍, 각 형식의 shallow/deep 비교 16쌍을 같은 응답에서 계산한다. 두 집계를 별도 독립 표본으로 합산하지 않는다. seed를 제외한 고유 입력 조건은 32개, 서로 다른 숫자쌍은 4개다.

### 4.3 호출 선후 통제

각 block의 4개 처치는 compact/shallow, compact/deep, comma_space/shallow, comma_space/deep다. 숫자쌍과 후보 순서로 순환 이동하고 두 번째 seed에서 선후를 반전한다. 16개 block 전체에서 각 처치는 네 순번에 각각 4회 배치된다.

이는 **사전 고정 균형 배치**이지 무작위 표집·새 문제 일반화 실험이 아니다. 문제·값을 추가하거나 결과를 보고 좋은 실행 순서만 선택하지 않는다.

### 4.4 측정 및 결과 장부

| 기록 | 정의 |
|---|---|
| 원응답 상태 | 정상, JSON/스키마 오류, HTTP/transport, identity, length 종료, 생성 상한 초과, 미실행, pending 분리 |
| 개별 선택 | 원응답 인덱스가 실제 제공된 두 숫자의 작은/큰 값에 맞는가 |
| 방향 쌍 | 동일 숫자쌍·순서·seed·표현에서 shallow와 deep가 모두 맞는가 |
| 표현 짝비교 | 같은 숫자쌍·순서·seed·요구에서 공백만 바뀌었을 때 인덱스/정오가 바뀌는가 |
| 비용 기록 | 원응답의 토큰·시간 계수. 없는 계수는 null. 반복 샘플의 평균/비용 우월성은 자동 주장하지 않음 |

형식 오류를 수치 오답으로 채우지 않는다. 출력이 파싱되지 않은 경우 수치 비교는 미측정이며 별도 형식 실패로 보존한다. 마지막 결과가 좋다고 일부 요청을 삭제하지 않는다.

| 결과 | 공학적 판정 | 다음 결정 |

64/64 또는 형식별 32/32는 **다음 공학적 단계에 사용할 수 있는지의 기준**이다. 기존 지표를 소급 변경하지 않으며, 부분 성공·표현 효과는 gate와 별도로 보고한다. 낮은 기준으로 몰래 통과시키지 않는다.

통과한 형식을 새 프로토콜에 사용할 수는 있지만, 모델이 이미 출력한 원문을 그 형식으로 조용히 정규화하는 권한은 주지 않는다. 원응답 전달 계약은 그대로 지킨다. 수치 입력에서 확인한 조건을 실제 경로 이해 능력으로 자동 이전하지 않는다.

### 4.6 진단 확장 제한

**이번 장부가 승인하는 새 진단은 v073 한 배치, 최대 64회뿐이다.** 정답률을 보고 예시·토큰·모델·seed·숫자·스키마를 늘리지 않는다. 출력 제약의 효과는 이번에는 미측정으로 남긴다. v073.1, 추가 formatting sweep, 더 큰 모델 자동 투입은 승인된 계획에 없다.

## 5. P02 — 원래의 종단 D 실험으로 돌아간다

핵심 흐름:

```text
같은 문제·목표·후보 경로
  → 작은 D / 큰 D 요구
  → 모델이 경로 선택
  → 실제 선택 원값을 무보정 전달
  → 단계별 증명 graph 생성
  → goal·규칙·premise·parent·ancestry·불필요 노드 및 실제 D 재측정
```

**주지표:** shallow/deep 요구에 맞는 실제 유효한 최종 graph와 짝지은 구조 변화. 정확한 D 숫자 보고는 별도 진단 항목이며 자동으로 선행 필수 단계가 되지 않는다.

다음 프로토콜 작성 전에 아래를 동결해야 한다.

| 항목 | 이번에 유지할 원칙 / 남은 결정 |
|---|---|
| 대상 | v069에서 구성 이력이 있는 3개 개발 문제에서 시작. 후보 순서를 균형 배치하고 동일 문제의 두 요구를 짝짓는다. 문제 수·seed·호출 상한은 P02 프로토콜에서 실행 전에 동결한다. |
| 모델 구성 | 선택기와 생성기 모델을 명시한다. Gemma 선택기→Qwen 생성기라면 혼합 시스템으로 표시한다. 같은 모델로 바꾸면 그 생성 계약의 검증 상태를 별도 기록한다. |
| v069 성공 범위 | Qwen, 3문제×2경로×2seed의 안내된 구성 12/12만 보존한다. Gemma의 생성 성공이나 새로운 입력 계약의 보편적 성공으로 이전하지 않는다. |
| 선택 출력 | 원래 후보 경로와의 대응을 사전 고정한다. host가 shallow/deep에 맞는 정답 경로를 대신 선택하지 않는다. 후보 매핑과 정답 선택을 구분한다. |
| 전달 | 잘못된 선택도 계약상 전달 가능하면 그대로 전달. 경로/규칙/부모 보정, 정답 치환, 사후 실패 삭제 금지. 전달 불가면 해당 단계와 종단을 미측정/실패 유형에 맞게 기록한다. |
| 전체 채점 | 선택의 요구 충족, 생성의 유효성, 실제 최종 D, 두 단계 정합성을 따로 기록한다. 잘못된 중간값 뒤 우연한 정답은 해당 종단 계약의 전체 성공으로 세지 않는다. |
| 예산 | 경로 길이별 호출 상한을 사전 계산한다. 예산이 미동결인 지금은 실행하지 않는다. |
| 금지 | P02 전에 또 다른 숫자 추정 하위 과제를 무기한 추가하지 않는다. v073 성공만으로 P02 실행/성공을 자동 표기하지 않는다. |

현재 배포의 실행기는 **P02를 자동 실행하지 않는다.** P01 결과를 읽은 후 별도 프로토콜과 소스를 검토한다.

## 6. P03 — 확인용 문제와 일반화

개발 세트에서 실험 계약을 결정한 뒤 새 구조·명칭·규칙 순서의 확인 세트를 결과 관측 전에 고정한다. 기존 C01/C02와 이번 숫자쌍은 이미 진단에 사용했으므로 독립 holdout으로 이름을 바꾸지 않는다.

확인 세트에서는 목표·문제 의미·기본 예산을 유지한 shallow/deep 비교, 형식 실패율, 종단 유효성, 실제 D 분포와 방향 쌍을 함께 기록한다. 문제 수준 반복과 seed 수준 반복을 구분한다. 비용 또는 더 큰 모델과의 비교를 추가하려면 별도 동일 예산 설계를 정한다.

A/M 및 축 간 분리는 후속 명시 실험이다. 현재 D 파일럿 성공만으로 세 축 독립성·내부 은닉층 제어·작은 모델의 일반적인 비용 우월성을 주장하지 않는다.

## 7. 별도 선택지 — 외부 제어 시스템 연구

외부 제어기가 D를 계산·선택하고 모델이 증명을 작성하는 연구는 가능하지만, **현재 모델 선택 연구와 별도 분기**다. 이 경우의 주장은 외부 제어를 포함한 시스템의 구조 제어이며 모델의 자율 선택 성공이 아니다. 사전 설계한 외부 제어와 오답 사후 수정을 구분한다. 현재 소스에는 이 분기를 넣지 않는다.
