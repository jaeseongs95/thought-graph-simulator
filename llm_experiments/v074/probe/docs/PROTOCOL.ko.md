# v074 — 후보 규칙 카드 선택 → 원응답 전달 → 단계별 증명 생성

계약: `v074-candidate-card-end-to-end-r1`  
상태: 실행 전 동결. 개발 중 실제 모델 추론 없음.  
근거: v073 분석의 P01 종료 판단과 기존 장부의 P02 재정의. 아래의 후보 카드, 대조군 규모, 호출 상한은 **이번에 내린 설계 결정**이며 v073에서 관찰된 사실이 아니다.

## 1. 질문과 v070과의 차이

같은 문제·목표·두 후보를 유지하고 작은 D/큰 D 요구만 바꾸었을 때, 모델이 선택한 후보 경로를 따라 생성한 **실제 유효 증명 graph의 깊이가 요구와 함께 달라지는가?**

v070은 문제 전체와 두 `rule_ids` 목록을 보여 주고 규칙 목록을 복사하는 선택 전용 검사였다. v074는 각 후보에 포함된 **원래 규칙의 본문**을 사전 대응표에 따라 묶어 보여 주고 `candidate_id` 하나를 반환하게 한다. 깊이 숫자를 보고하거나 숫자 목록을 비교하는 중간 과제는 없다. 반환된 후보 ID와 실제 원응답을 단계별 생성에 연결한다.

입력 표현, 선택 출력 계약, 생성 연결이 함께 달라졌다. v070과 동일 배치의 단일 요인 비교가 아니므로 성패 차이를 한 변경의 인과 효과로 해석하지 않는다. 이 버전은 단순한 문구 재시도가 아니라 **새 입력·출력·연결 계약의 종단 개발 파일럿**이다. 성공을 보장하지 않으며 한 배치 후 종료한다.

## 2. 고정 요소

선택기와 생성기는 모두 기존 `qwen3:4b-instruct`다. digest는 `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`이다. v073 모델 목록에서 이 설치 항목을 확인했고, 네이티브 template/model_info는 내장된 과거 v069 기록에 근거한다. 실행 전후 version/tags/show를 확인하며 변하면 중단한다. 모델 설치·갱신·서버 시작·대체 모델 선택은 하지 않는다.

문제는 v069의 T02, E01_shared_fork, E02_two_vs_four와 해당 short/long 규칙 경로를 그대로 사용한다. seed는 64001001, 64001002다. 명시 옵션은 temperature 0.7, top_p 0.8, top_k 20, min_p 0, repeat_penalty 1, num_ctx 8192, num_predict 4096, num_thread 6, num_batch 256이다. 원문 API 기본 옵션을 유지한다.

|문제|짧은 참조 경로|긴 참조 경로|측정용 D 범위|
|---|---|---|---|
|T02|r83|r21 → r57 → r04 → r69|1 / 4|
|E01_shared_fork|n52|n08 → n91 → n37|1 / 2|
|E02_two_vs_four|m18 → m76|m33 → m05 → m84 → m41|2 / 4|

위 D 값은 준비 검사·사후 채점용이며 선택기 입력에 제공하지 않는다. 규칙 ID, 규칙 본문, 사실과 목표 자체는 문제 입력이다. 후보 경로는 실험자가 제공하므로 임의의 경로 발견 능력은 측정하지 않는다.

## 3. 본실험과 참조 구성 점검

### 모델 선택→생성: 24건

3문제 × 2seed × 2후보 순서 × 2요구 = 24건. 같은 문제·seed·후보 순서의 shallow/deep가 12쌍이다. 후보 위치와 `route_0`/`route_1`의 의미 대응은 후보 순서를 뒤집어 균형 배치한다.

선택 입력은 `problem`, `candidates`, `requested_depth` 세 항목이다. `candidates`는 각 후보의 ID와 기존 규칙 본문 목록만 담는다. 정답 D, short/long 라벨, 올바른 후보 ID, 완성 graph, 노드/parent ID는 제공하지 않는다. 출력은 `{"candidate_id":"route_0"}` 또는 `route_1`이다.

### 별도 참조 구성 점검: 12건

3문제 × 2seed × 2참조 경로 = 12건. 선택 모델을 호출하지 않고, 실험자가 사전 고정한 후보 ID를 **참조 입력**으로 제공한다. 이후 생성 계약은 본실험과 같은 노드 단위 생성이다. 새 연결 계약의 구성 가능성을 같은 배치에서 확인한다. v069 12/12를 새 계약의 성공으로 가져오지 않는다.

참조 입력의 provenance는 `experimenter_reference`이고 모델 입력은 `model`이다. 참조 선택 문자열은 사전 고정한 JSON이고 모델 선택 문자열은 실제 원문이므로 표현이 달라질 수 있다. 이 점검은 **선택 정확성만의 인과 효과를 고립하는 대조가 아니다.** 참조 성공이 모델 원문의 모든 표현에 대한 생성 성공을 보증하지 않는다. 각 실제 종단 graph를 직접 채점한다. 참조 실패라도 본실험에서 관측한 성공을 삭제하지 않는다.

각 문제/seed block에 본실험 4건과 참조 2건을 넣고 두 번째 seed에서 실행 선후를 반전한다. 참조의 후보 순서도 두 seed 사이에 뒤집는다. 무작위 표집이나 독립 holdout 설계는 아니다.

## 4. 연결 계약과 무보정 경계

```text
선택 모델: candidate_id 반환
  → JSON 문법 및 등록 ID 여부만으로 고정 후보표에 대응
  → 실제 선택 원문 + 대응된 규칙 목록 전달
  → 모든 초기 사실 노드 작성
  → 선택된 경로의 규칙 하나당 노드 하나 작성
  → 실제 최종 노드 ID 지정
  → 단계 계약, 전체 graph, 실제 D를 사후 검산
```

호스트의 후보 ID→규칙 목록 대응은 정답 판단이 아니다. 모델이 요구와 반대인 후보를 골라도 **그 후보를 그대로** 생성한다. 호스트는 D를 비교해 후보를 바꾸거나, 규칙 순서를 복구하거나, 누락 사실/부모를 추가하거나, 최종 노드를 고르지 않는다.

생성 입력에는 원래 shallow/deep 요구나 정답 D를 재전달하지 않는다. 생성기가 틀린 선택을 몰래 다시 선택해 덮는 것을 요구하지 않기 위해서다. 모델 선택 원문 문자열, 외부 응답 SHA-256, 모든 이전 생성 원문을 보존·전달한다. 선행 graph 응답의 문법/논리 오류도 고치지 않는다.

선택 원문에서 후보 ID를 문법적으로 읽을 수 없으면 해당 생성 슬롯은 `unmappable_selection`로 기록하고 모델을 부르지 않는다. 등록된 후보로 대응 가능하면 선택의 정오로 실행을 차단하지 않는다. 길이 종료 등 정상 완료가 아닌 선택에서도 ID가 형식상 읽히면 원문은 전달할 수 있지만, 앞 단계는 미측정으로 남아 종단 성공으로 승격되지 않는다.

## 5. 호출·중단·증거

본실험 선택은 24회, 별도 참조 생성은 54회다. 본실험 생성은 실제 선택 경로 길이에 따라 달라진다.

|시나리오|모델 선택|본실험 생성|참조 생성|합계|
|---|---:|---:|---:|---:|
|모든 요구에 올바른 경로를 선택|24|108|54|186|
|모든 본실험에서 긴 경로 선택 — 상한|24|136|54|214|
|모든 본실험에서 짧은 경로 선택|24|80|54|158|
|모든 선택의 ID가 대응 불가|24|0|54|78|

214는 **최대값**이지 반드시 채워야 할 호출 수가 아니다. 전체 계획에는 214개 가능한 추론 슬롯과 12개 모델 상태 점검 슬롯, 총 226개 진행 슬롯을 고정한다. 선택된 경로 밖 규칙 슬롯은 `outside_selected_route`로 생략하며 이를 추론으로 세지 않는다. 상태 점검 1슬롯은 version/tags/show의 세 HTTP 조회이고 모델 추론이 아니다.

기록에서 action 시작, 실제 dispatch 시작, HTTP 응답 관측, 생략을 구분한다. HTTP/transport/identity 오류 및 생성 token 상한 초과는 전체 배치를 중단한다. JSON·스키마 오류나 length 종료는 그대로 보존하며 자동 재시도하지 않는다. 초과 입력은 자르지 않고 중단한다. 충돌·인터럽트의 pending request/dispatch/response도 보존한다.

같은 결과 폴더의 배치 시작 표지로 새 RunName 재시도를 차단한다. `-CheckOnly`는 오프라인 준비만 하며 이 표지를 만들지 않는다. 다른 PC나 수동 복사로 모든 반복을 방지하는 중앙 통제 기능은 아니다.

## 6. 측정: 숫자 설명을 필요조건으로 만들지 않는다

- 모델 경로 선택: 원래 D 요구에 맞는 후보인가.
- 구성 충실성: 선택한 경로와 단계별 rule 계약을 지켰고 전체 graph가 유효한가.
- 목표 구조: 유효한 최종 graph의 실제 D가 요구에 맞는가.
- 종단 trace: 선택·각 단계·최종 graph와 실제 D가 모두 맞는가.
- 양방향 쌍: 같은 조건의 shallow/deep 종단 trace가 모두 맞고 실제 목표 깊이가 각각 맞는가.
- 참조 구성: 지정 참조 경로 12건의 구성 성공. 모델 선택 성과와 분리한다.

전체 graph가 유효해도 이전 단계의 지정 규칙을 어겼다면 trace 성공이 아니다. 반대로 전체 trace 실패라고 실제로 유효했던 graph나 선택 성공까지 지우지 않는다. 형식/미실행/HTTP/길이 종료는 수치 오답 또는 D=0으로 채우지 않는다. 토큰 계수가 없으면 관측합과 누락 건수를 별도로 기록한다.

## 7. 사전 기준과 종료

모든 슬롯 처리와 측정이 끝난 상태에서 본실험 24/24, 양방향 12/12, 참조 구성 12/12를 충족하면 **이 3개 개발 문제·6개 후보 경로·선택-생성 계약에서의 종단 기준선**으로 판정한다.

참조만 통과하면 선택 결과와 단계별 실패 위치를 기록하고 본실험 실패/부분 성공을 그대로 남긴다. 참조가 미달하면 새 구성 계약의 기준선도 미확보로 남긴다. 본실험이 일부 성공하면 조건별 성공과 실패를 보존한다. 하나라도 미측정이 있거나 실행이 미완료면 전체 gate는 null이다.

어느 결과든 **한 배치 후 종료**한다. 자동 추가 진단, 예시/문구/seed 변경, 모델 변경, 재시도, 다음 실험 실행은 없다. 성공하면 P03을 계획할 근거를 얻는 것이지 P03을 자동 수행하는 것은 아니다. 실패/부분 성공이면 종단 결과로 연구 주장과 후속 우선순위를 다시 판단하며 v071~v073 숫자 분기로 자동 회귀하지 않는다.

## 8. 해석의 범위

주지표는 실제 출력 graph의 D 제어다. 정확한 D 숫자 설명, 모델 내부 계산 깊이, A/M 축, 세 축 독립성, 비용 우월성은 측정하지 않는다. 규칙 본문 카드에 사용한 경로는 실험자가 제공했다. 모델의 경로 발견을 시험하지 않는다.

이 3개 개발 문제에서는 규칙 수가 많은 후보가 D도 더 크다. 따라서 v074 성공만으로 모델이 규칙 수가 아닌 의존 깊이 개념을 사용했다고 주장하지 않는다. 관측된 종단 구조 제어와 내부 선택 전략을 구별한다. P03의 확인용 문제에는 규칙 수 동률/역전과 새 구조·명칭·규칙 순서를 결과 관측 전에 동결해야 한다. 기존 C01/C02를 새로운 holdout으로 바꾸어 부르지 않는다.

후보 카드/ID 출력은 이번 설계의 변경이지 효과가 검증된 해결책이 아니다. 생성기 공통 입력에 선택 원문을 추가했으므로 v069과 바이트 동일 계약이 아니며, 별도 참조 구성 점검과 실제 종단 측정을 두는 이유다.
