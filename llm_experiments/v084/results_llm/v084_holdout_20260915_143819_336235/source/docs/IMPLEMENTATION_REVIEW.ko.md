# v084 구현 검토

## 연구 설계 결정

v083에서 남은 질문을 신규 구조 재현성으로 좁혔다. 선택기·생성기를 동시에 새로 고치지 않았다.
숫자군 선택은 실험자 지원 계약의 성과다. 같은 규칙 수 및 규칙 수 역전을 유지해 D를 W와 구분한다.
H02에 대한 사후 부모 수정, 특정 실패를 피하는 실행 중 경로 교체, 성공 구조만 고르는 후처리는 없다.

## 소스 변경 범위

- `cases084.py`: 8개 고정 구조쌍, SHA-256 기호 배정, 완전 구조 정규형, protocol 재구성.
- `audit084.py`: 별도 구조 동형 검사, 8개 구조 검증, 독립 schedule 및 구조 단위 집계.
- `report084.py`: 기존 원응답 채점에 구조 단위 동일 가중치 짝비교를 추가.
- `design084.py`: 두 군/신규 구조 배정. 선택용 카드에서 전체 protocol 깊은 복사를 제거했지만 반환 바이트 계약은 유지.
- `launch.py`: v084 전용 설치 경로, 기준 v083 해시, 신규 결과명. 이전 버전 migration/교체 기능은 없다.
- `selftest084.py`: 개별 test ID, 성공/실패/skip을 구조화해 저장.
- `legacy/`: v083에 포함된 파일을 바이트 그대로 유지.

## 계층 분리

요청 생성기와 실행기는 모델 응답의 정확성을 보고 경로를 보정하지 않는다.
전체 graph 채점은 모델 실행 후 독립적인 오프라인 경로에서 이루어진다.
참고 깊이는 사전 primitive 규칙에서 계산한 값이며 모델 계산값으로 표시하지 않는다.
생산 채점과 독립 채점은 별도 구현이며 JSON/해시와 한국어 렌더링 유틸리티는 공유할 수 있다.
동일 렌더러 일치만으로 독립 수치 검산을 대신하지 않는다.

## 시험 범위

계약/배정, v083 실제 요청 1,020건의 바이트 회귀, 기존 v083 verifier,
신규 구조 정규형과 별도 동형 검사, 계산표 반례, 부모/규칙/final 변조,
첫 후보·고정 ID·역방향·W-only·D-only 합성 응답, 미관측과 구조별 비교,
전체 합성 실행과 evidence 재검산, 이벤트·요청·응답·summary 변조,
HTTP 오류·identity 오류·dispatch 이후 중단·응답 저장 후 commit 이전 중단,
가드/무덮어쓰기, Python launcher 설치, 단일 PowerShell 내장 ZIP 일치를 검사한다.

시험의 실제 실행 결과·개수는 별도 검증 JSON과 원문 로그가 기준이다.
PowerShell native parser가 없는 환경에서는 해당 시험을 skip하며 통과로 세지 않는다.
Linux/Python launcher 시험은 Windows 11/PowerShell 5.1 실제 종단 실행과 구분한다.

## 남는 범위

구조집합은 모델 반응을 보지 않고 사전 지정했지만, 사람이 고른 유한 구조 8개다.
부분 모티프를 공유할 수 있고 IID 무작위 표본이 아니다. 정확 지원군 선택이 개선될지, 생성 병목이 반복될지는 실제 v084 결과로 판단한다.
사전 설계상 W는 선택만 실행하므로 W 종단이나 D/W 모든 요구의 종단은 주장하지 않는다.
원래 JSON/스키마 범위, 프롬프트, 모델 identity를 바꾸지 않았다. 새 기능을 이유로 과거 실패를 소급 성공 처리하지 않는다.
