# v084 사전 계획 — 2026-09-15

상태: v084 실제 모델 응답 관측 전 고정. 설계는 v083 결과를 본 이후 정했으며 이 선택 사실을 숨기지 않는다.

## 1. v083에서 이어지는 질문

v083 D 양방향 종단은 직접 2/32, 전체표 11/32, 정확한 숫자 15/32였다.
숫자군 H01은 모든 위치·ID 표시에서 두 seed 모두 성공했다. D 숫자 교환에서는 47/64쌍의 경로가 바뀌었다.
그러나 노출된 진단 구조는 H01~H04 네 개뿐이었다. 정확한 지원 아래에도 선택 및 전제–부모 연결 실패가 남았다.

따라서 이번 주질문은 다음이다.

> v083의 직접/정확숫자 선택기와 생성 계약을 고정하면, 새 구조에서도 정확한 수치 지원에 따른 양방향 D 종단 개선과 표시 강건성이 재현되는가?

전체표군과 교환군을 다시 최적화하지 않는다. H02의 부모 ID를 고치거나 생성 계약을 새로 추가하지 않는다.
이를 함께 변경하면 새 구조 효과와 새로운 인터페이스 효과를 구분하기 어렵기 때문이다.

## 2. 사전 신규 구조

T01~T08 8개는 코드에 명시된 구조쌍이다. 각 쌍은 같은 초기 사실 3개, 동일 목표 및 동일 primitive rule dictionary를 공유한다.
둘의 실제 의존 깊이는 다르다. T01~T04는 규칙 수가 같고 T05~T08은 얕은 경로의 규칙 수가 더 많다.
정확한 D/W는 README 및 `protocol.problem_metadata`에 고정한다.

신규성의 단위는 **공통 사실과 목표를 공유하는 두 DAG의 쌍**이다.
생산 측에서는 사실 전단사·내부 결과 전단사의 완전 열거에 따른 정규형을 계산한다.
독립 측에서는 두 쌍 사이에 공통 사실 매핑과 경로별 내부 결과 매핑이 존재하는지 별도로 열거한다.
신규 8개 간 중복과 기존 H01~H04의 단순 재명명을 제외한다. 각 후보의 모든 사실과 규칙은 최종 목표 ancestry에 속해야 한다.
부분 모티프 공유는 허용한다. 이 설계는 무작위 IID 문제 표본이 아니다.

문제 선정은 모델 응답에 의존하지 않는다. 기호·규칙 사전 순서는 SHA-256 기반 고정 순서다.
실행 시 결과를 보고 문제를 교체하거나, 성공할 때까지 seed·순서를 추가하지 않는다.

## 3. 조건

두 군: `candidate_id`와 `correct_values`.
D는 두 군 모두 선택과 실제 graph 생성까지 수행한다.
W는 T05~T08에서 선택만 수행하는 보조 대조다.
공통 경로 참조는 문제·seed·방향당 한 번이며 32건을 군별로 복제하지 않는다.

seed는 v083과 동일한 64001001/64001002다. API defaults, 모델 identity, JSON Schema, 프롬프트 헤더,
선택 원문·생성 이력 전달 규칙, `explicit_rule` 재명시 및 초기 사실 제약을 유지한다.
수치 지원은 선택기에만 제공한다. 생성기는 수치 계산표, 요구 방향이나 정답 부모 ID를 받지 않는다.
잘못 선택한 유효 후보를 다른 후보로 교체하지 않는다.

조건별 두 선택기는 순서를 교차하고 동일 모델 seed를 사용한다. 같은 문제의 seed·표시 반복은 묶음 내부 관측이다.

## 5. 주평가

구조 j에서 같은 seed·표시의 shallow와 deep이 모두 유효 graph를 만들고 실제 D가 각각 요구를 만족해야 pair 성공이다.
구조별 8쌍의 군간 짝비교를 먼저 계산한다.

```text
delta_j = (지원군에서만 성공한 pair 수 - 직접군에서만 성공한 pair 수) / 8
주요 관측값 = 8개 구조 delta_j의 동일 가중치 평균
```

구조의 8쌍 중 하나라도 비교 불가이면 해당 delta_j는 None이다. 전체 구조가 완전하지 않으면 전체 평균도 None이다.
이는 오답 보완이나 완료한 사례만 고른 결과를 방지하기 위함이다. 완료 구조의 상세 관측은 그대로 남긴다.
개선/악화/동일 구조 수, 같은규칙수/규칙수역전 가족별 평균도 보고한다.
사전 방향 가설은 수치 지원군이 직접군보다 높다는 것이다. 실제 결론에서는 총합과 구조별 분포를 함께 읽으며
100% gate 하나로 부분 효과를 지우거나, 총합 개선만으로 모든 구조 일반화를 주장하지 않는다.
p-value는 자동 산출하지 않는다. seed/표시를 독립 문제 표본으로 넣은 검정을 하지 않는다.

## 6. 부평가와 실패 분해

단방향 선택, 생성 성공, 실제 graph D/W, D 종단, 양방향, 네 표시 강건성,
한 구조에서 모든 seed·표시 통과, W 선택, D/W 네 요구 구별, 공통 참조 생성을 분리한다.
유효 graph의 정방향/역방향/동일 방향은 별도 보존한다.
선택은 틀렸으나 그 경로는 유효하게 생성한 결과를 D 성공으로 올려 세지 않는다.
최종 ID가 맞아도 앞서 무효 규칙 적용이 있으면 전체 종단 실패다.

정상 응답의 의미 실패, JSON/스키마 실패, 길이 종료, HTTP/transport/identity 오류,
미실행·중단, 설계상 미배정을 구분한다. 미관측을 D=0/오답으로 채우지 않는다.
기존 v083과 같은 길이 종료 계측을 유지하며 정상적인 의미 실패로 바꾸지 않는다.
