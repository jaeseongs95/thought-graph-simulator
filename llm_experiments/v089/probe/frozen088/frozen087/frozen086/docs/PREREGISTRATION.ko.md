# v086 사전등록 — 동결 절차의 구조 일반화

## 1. 근거와 결정

v085 원본 evidence에서 확인된 직접/수치 지원/두 단계 D 양방향 종단은 3/64, 31/64, 60/64다. 두 단계 D 선택은 128/128, 전표시 종단은 13/16이지만 T01~T08은 이미 관측된 구조다. 이에 프롬프트나 생성기를 추가 최적화하지 않고 새로운 구조쌍에서 동결 절차를 비교한다. 위 숫자를 v086 관측치나 표본으로 포함하지 않는다.

이번 파일은 개발 중 실제 v086 모델 호출 전에 고정한다. 문제 생성·선택은 모델 응답을 사용하지 않는다. 연구자가 v085 결과를 바탕으로 고른 비교 절차이므로 v085는 개발/진단 집합이며, v086 신규 구조는 이 다음 비교의 미관측 집합이다.

## 2. 연구 질문과 해석 범위

주질문: 정확한 외부 수치를 주는 절차에서 값 비교와 후보 ID 조회를 분리한 계약이 새로운 구조에서도 기존 수치 지원보다 실제 유효 proof DAG의 양방향 D 종단을 높이는가?

동시에 네 표시 전체의 D 선택·종단 유지 여부를 측정한다. 평균 효과와 전표시 성과를 하나로 합치지 않는다. W는 조회의 지표별 오류가 새 표에서도 나타나는지 보는 보조 대조이며 선택만 배정한다. 이번에는 W 전용 프롬프트나 생성 schema를 변경하지 않는다.

v085에서 두 단계 처치는 문맥·프롬프트·형식·호출 수가 함께 달라진 절차였다. v086은 그 묶음 절차를 그대로 재현한다. 두 호출 자체를 D=2로 세는 것이 아니라 별도로 생성된 goal proof DAG의 의존 깊이를 측정한다. 정확한 출발 D/W는 실험자 제공값이다.

## 3. 자극 생성 및 신규성

U01~U08의 (얕은 D,얕은 W,깊은 D,깊은 W)는 순서대로 다음과 같다.

```text
(2,4,3,4), (2,4,4,4), (3,5,5,5), (4,5,5,5),
(2,4,3,3), (3,5,4,4), (3,5,4,4), (3,5,4,4)
```

사실 3개, 원시 규칙 전제 1~3개, 모든 노드의 goal ancestry 포함을 요구한다. 두 경로는 같은 사실·목표를 사용하고 내부 원자는 겹치지 않는다. 원시 규칙 수와 D의 분리를 유지한다. 기존 D/W 조합의 새 구조 5개와 새 깊이 조합 3개(U02:2/4, U03:3/5, U04:4/5)를 분리한다. 수치 범위는 D=5까지 확장된다. 전제 개수 분포·기호·경로 내부 토폴로지는 바뀌므로 구조 난이도가 동일하다고 가정하지 않는다.

생성 seed는 `ADM-v086-structural-holdout-20260915-r1`이다. 각 규칙의 가능한 부모 부분집합을 정해진 순서로 열거하고 SHA-256으로 후보를 선택한다. 깊이/연결/신규성 조건을 통과한 첫 후보를 사용한다. 경로별 상한은 200,000후보이며 상한 초과 시 다른 seed로 자동 우회하지 않는다. 실패/성공 응답을 보고 문제를 선별하지 않는다. 실제 후보 검사 횟수는 protocol의 holdout_generation에 보존한다.

생산 완전 정규형과 독립 전단사 검사로 기존 H01~H04/T01~T08 12쌍에 대한 비동형 및 신규 쌍끼리 비동형을 확인한다. 신규 16경로는 기존 24경로와 다른 신규 경로에도 비동형이다. 부분 모티프는 공유할 수 있다. 기존 조합 5개에서는 수치 하위 과제가 중복될 수 있으며, 새 조합 3개도 seed/표시에 따라 반복된다. 신규 구조 성과를 전부 새로운 산술 문제의 성과로 표현하지 않는다.

## 4. 배정·고정

모델·native identity·API 설정·두 seed·프롬프트 헤더·schema·원문 전달·생성기는 v085에서 동결한다. 직접군, 수치군, 두 단계군, oracle 조회군 및 순서 교차를 유지한다. 동결한 모든 구조에 두 위치×두 ID×두 요구 방향을 배정하며 불리한 표시도 제외하지 않는다.

D는 군당 선택/조회 128건, 앞 세 군의 실제 graph 384건이다. W는 군당 선택 64건, oracle은 D/W 조회만 수행한다. 두 단계 비교 호출은 D128+W64=192다. 지정 경로 참조는 32 graph로 한 번만 실행하고 본실험에 합산하지 않는다. 예상 목표 경로 추론 3,612, 최대 3,708, 전체 action 3,740이다. 전체 배정을 종료한 뒤만 결과를 판단한다.

## 5. 주평가 및 부평가

주비교는 같은 배치의 two_stage_values−correct_values다. 과거 v085의 성과를 현재 주비교 분모로 대신하지 않는다.

각 구조 i의 지표는 2 seed×4표시의 양방향 종단 8쌍이다. `delta_i=(지원 절차 성공 쌍−기존 수치 성공 쌍)/8`, 주효과는 8개 구조에 같은 가중치를 준 `mean(delta_i)`다. 개선/악화/동일/미관측을 함께 보고한다. 미관측이 있는 구조의 delta는 계산하지 않으며, 하나라도 구조가 불완전하면 전체 mean을 산출하지 않는다. 표시는 구조 내부 반복이다. IID 표본 p값을 계산하지 않는다.

기존 D/W 조합의 새 구조 5개 및 새로운 수치 조합의 새 구조 3개를 별도 층으로 보고한다. 이 층화는 모델 응답 전에 고정하며 성공한 조건만 묶어 새로 만들지 않는다.

부평가는 단방향, 양방향 선택, 네 표시 전체 선택/종단, 모든 seed/표시 통과 구조 수, 위치×ID별 성과, 비교 정확도, 보고값 조회 준수, 선택 후 생성 성공, W 선택, 공통 참조, 고유 입력 수 및 사용량이다. 전표시 실패와 평균 개선을 서로 지우지 않는다. 모든 조건의 100%만을 유일한 연구 성공 기준으로 삼지 않는다.

## 6. 무보정 및 상태

모델 비교값을 고치지 않고 원문 문자열로 전달한다. 비교·조회 중 하나라도 틀리면 마지막 goal이 맞아도 두 단계 종단 성공은 아니다. 관측된 null은 기권이며 후속 graph를 실행하지 않고 별도 상태로 남긴다. graph 자체의 유효 목표 도달과 전체 선택 trace 성공은 별도 기록한다.

유효 graph는 사실, 규칙 전제 multiset, 부모, ID 유일성, 순환, goal ancestry 및 계획 충실성을 모두 검사한다. D는 fact 0, 규칙 노드 1+max(parent D)다. 누락 premise/parent/final을 보완하거나 잘못된 경로를 교체하지 않는다.

JSON/schema 오류, 논리 오류, HTTP/transport, identity, length, 중단/pending, 미배정, 경로 밖 여분 슬롯을 분리한다. 미관측을 실패나 D=0으로 채우지 않는다. unit test·합성 응답·독립 검산·원문 재검산은 모델 실행 표본으로 가산하지 않는다.

## 7. 원문·중복·생성 입력 진단

숫자 비교·조회의 고유 요청을 seed 포함/제외로 세되 연구 구조 수로 대신하지 않는다. 실제 비교가 맞을 때 oracle과 같은 조회 요청이 반복되는지 보고한다. 동일 경로에서 selection_original의 공백/개행이 다르면 생성기 코드가 같아도 실제 입력은 다르므로 바이트 일치를 따로 기록한다.

D/W 조회 비교는 metric 필드 외의 전체 요청이 같은 조건만 metric-only로 인정한다. 같은 비교 요청의 반복, oracle 중복, 같은 graph 여러 검산을 독립 표본으로 가산하지 않는다. 사용량은 D 본실험과 W/oracle/참조를 분리하고 누락 수를 보존한다.

## 8. 중단·보존·다음 결정

기존 v085 evidence를 변경하지 않는다. 원문·plan·source·state·event chain을 보존하고 생산 집계와 독립 재구성을 대조한다. identity/transport 등 실행 중단은 자동 재시도하지 않는다. started guard를 삭제하거나 다른 RunName으로 조용히 다시 시작하지 않는다. 모델 다운로드/업데이트/서버 자동 시작도 없다.

v086 종료 후 원문부터 검산하여 재현·실패·표시 차이·생성 병목을 판단한다. 새 버전 자동 작성이나 성공한 조건만 남기는 후속 실행은 하지 않는다. v086 결과에 따라 이후 독립 실험을 별도로 결정한다.

## r2 실행 전 구현 정정

연구 protocol·요청·문제·seed·배정·채점은 변경하지 않는다. 보조 graph 오류 필드와 HTTP 완결성/부분 본문 보존을 바로잡았다. `docs/REVIEW_FIXES_r2.ko.md` 및 배포 검증 기록을 참조한다. 실제 v086 모델 결과를 본 뒤 고른 조건 변경이 아니다.
