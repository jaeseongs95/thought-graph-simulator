# 구현 검토와 성과 해석 경계

## 실제 변경 지점

`design081.py`의 선택 출력 지시·스키마·정확한 후보 대응, 두 군 교차 배정과 중립적인 논리 ID, `report081.py`의 군별/짝별/매핑 판정이 신규 부분이다. `audit081.py`는 이를 독립 재구성한다. 생성 요청의 내용·초기 사실 제약·현재 규칙 객체 제공은 v080에서 유지했다.

`candidate_id`군 및 참조의 v080 실제 원요청 739개를 원응답을 그대로 사용해 재생하여 바이트 일치 여부를 시험한다. 이 회귀 시험은 과거 실제 성과를 소급 수정하는 것이 아니다. 실제 새 배치의 응답은 다시 관측해야 한다.

## 순수하게 한 개의 내부 원인을 판정하는 실험은 아니다

새 군은 출력 지시와 JSON 스키마가 함께 바뀐다. 후보 ID 대신 규칙 목록을 작성하므로 복사 부담과 출력 길이가 달라진다. 원문 무보정 전달 원칙 때문에 생성기가 받는 선택 원응답의 형태도 다르다. 따라서 전체 시스템의 개입 효과와 순수한 선택 정확도를 함께 보고한다.

`candidate_id` 응답을 호스트가 새로 만들어 모델 원응답인 것처럼 대체하지 않는다. 대신 model 원문과 `provided_route_plan`을 분리한다. 후자는 정확히 일치한 후보표의 경로만 나타낸다. 대응된 후보 ID는 사후 측정·기록용 식별에도 사용하지만 원문 자체는 수정하지 않는다.

## observed와 unmeasured의 구분

정상 응답으로 잘못된 목록을 받은 경우 관측된 선택 인터페이스 실패로 처리한다. 뒤따르는 생성의 skip은 생성 논리 실패가 아니다. `generator_success`와 실제 D/W를 null로 두고 end-to-end 계약의 실패만 기록한다. 정상 응답의 JSON/스키마 실패도 형식 실패로 분리한다. 전송·길이·중단은 그 상태를 유지하며 논리 실패와 합치지 않는다.

한국어 보고서에는 전체 배정의 선택 성공, 정확 매핑 성공, 매핑 가능한 경우의 조건부 선택 정오가 함께 있다. 그중 유리한 분모 하나로 전체 성과를 대체하지 않는다.

## 검산 구현 경계

핵심 graph 및 단계 판정은 이전에 검산한 v080 legacy 파일을 유지한다. 새로운 규칙 목록 매핑·요청 재구성·짝 집계는 생산/독립 경로에서 별도 구현한다. `render081.py`는 양쪽에서 공유하는 표시 전용 코드다. 모든 세부 구현이 완전히 독립적이라고 주장하지 않는다.

정상·반례·합성 정책·부분 실행·해시 재작성 변조·가드 거부를 시험한다. 입력과 seed가 같은 데도 실제 모델 응답이 달라질 수 있다는 기존 관찰은 유지한다. 테스트 PASS 자체를 실제 Qwen 효과나 독립 연구 표본으로 사용하지 않는다.

## 실행기 보강

응답 파일 저장 직후 프로세스가 중단되면 메모리의 카운터가 증가하기 전이라도 저장된 응답 수를 관측 수에 포함한다. 아직 event로 확정되지 않은 응답은 `pending_action`으로 남기고 연구 점수에 끼워 넣지 않는다. 이는 응답 보존·감사 보강이지 추론 재개나 재시도 기능이 아니다.
