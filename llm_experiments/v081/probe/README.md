# v081 — 후보 ID 선택과 규칙 목록 선택의 짝대조

상태: 실험 소스·오프라인 검증용 배포본. 작성일: 2026-09-15 KST. 이 소스의 작성·배포 검증에서 실제 Qwen 추론은 하지 않는다. 이전 실제 결과는 v080 evidence이며 새 합성 시험 결과와 합산하지 않는다.

## 1. 무엇을 검사하는가

v080의 D 본실험은 선택 30/64, 생성 51/64, 요구 D 종단 25/64, 양방향 2/32였다. 후보 위치×ID의 네 표시 모두에서 유지된 양방향 묶음은 0/8이다. D 요청의 첫 위치 선택은 58/64였고, 후보 ID만 바꿔도 H01의 기존 성공이 사라졌다. W 작은 값은 16/16 맞았지만 큰 값에서는 15/16회 `route_1`을 선택했다.

**새 가설:** 선택 답안을 후보 ID 하나가 아니라 선택한 후보의 규칙 ID 목록으로 표현하게 하면, 같은 문제·요구·표시에서 실제 경로 선택과 종단 D 제어가 달라지는가?

이 가설은 이전 자료에서 이미 입증된 사실이 아니다. 한 번의 동결된 짝대조로 검사할 후속 질문이다. 위치 영향까지 해결될 것이라고 가정하지 않는다.

## 2. 바꾸는 것과 그대로 두는 것

| 항목 | candidate_id 대조군 | rule_ids 실험군 |
|---|---|---|
| 문제·사실·규칙·목표·후보 내용 | v080 유지 | 같은 조건에서 동일 |
| 후보 위치와 ID 배정 | 위치 2 × ID 2 | 동일 |
| D/W 정의와 작은/큰 요구 | v080 유지 | 동일 |
| 모델 identity·seed·API 설정 | v080 유지 | 동일 |
| 선택 출력 | `{"candidate_id":"route_1"}` | `{"rule_ids":["u76","u70","u79"]}` |
| 변경되는 프롬프트 | 기존 선택 출력 안내 | 목록 출력 안내로 변경 |
| 선택 JSON 스키마 | 후보 ID 하나 | 문자열 목록 1~16개 |
| 증명 생성기 | explicit_rule | 같은 생성기 |

선택 입력의 후보 카드는 **두 군에서 바이트 내용이 같다.** 후보 ID도 두 군의 입력에 남아 있다. 제거하는 것은 출력에서의 `candidate_id` 응답 의무이지 입력의 모든 ID가 아니다. D/W 정의를 새로 가르치거나 정답 깊이를 제공하는 실험도 아니다.

출력 안내와 스키마를 함께 바꾼 **선택 인터페이스 전체의 효과**를 비교한다. 숫자 한 토큰이나 ID의 내부 원인만 분리한 실험으로 해석하지 않는다. 규칙 목록을 복사해야 하는 부담과 출력 토큰 증가 가능성도 해당 계약의 비용이다.

## 3. 정답으로 바꾸지 않는 경로 대응

`rule_ids`는 제공된 두 후보 중 한 후보의 규칙 ID 목록과 **원래 순서까지 정확히 일치할 때만** 실행된다. 정렬, 중복 제거, 누락 보충, 가까운 후보 선택, 다른 경로와의 합성, 재질문을 하지 않는다. 스키마는 정답 목록이나 정답 길이를 열거·강제하지 않는다.

매핑 후에도 모델의 선택 원문은 그대로 `selection_original.content`로 전달한다. `provided_route_plan`만 사전 후보표에서 유일하게 대응한 경로다. 이 과정은 D/W의 정답을 계산하지 않는다. 잘못 선택한 후보도 그대로 생성한다.

생성기에는 정답 부모 ID나 완성 노드를 주지 않는다. 현재 규칙 객체를 다시 표시하는 기존 `explicit_rule` 조건만 유지한다. 양쪽은 자기 군의 실제 이전 응답을 사용하며, 다른 군의 올바른 이력으로 교체하지 않는다.

기록용 물리 슬롯명은 evidence에서 두 군을 구분한다. 모델에게 전달되는 선택·이력의 논리명은 같은 조건에서 공통으로 사용하여 군 이름 자체가 불필요하게 입력되지 않게 했다. `candidate_id`군과 참조의 기존 물리명은 v080과 동일하여 기존 739개 요청을 실제 원응답으로 재구성·비교할 수 있다.

## 4. 성공과 실패의 구분

주평가지표는 **군별 D 양방향 종단 성공과 같은 조건의 군간 짝비교**다. 실제 초기 사실·모든 규칙 단계·전체 graph·경로 충실성·요구 D를 검사한다. 라벨, 규칙 수, 설명 길이만으로 D 성공을 세지 않는다.

다음 결과를 따로 저장한다.

1. 선택 출력 형식 및 정확한 경로 매핑 성공, 대응된 경로의 D/W 선택 정오.
2. 선택한 경로의 전체 증명 구성과 요구 지표 종단 성공.
3. 작은/큰 요구 쌍의 정방향·고정·역방향, 네 표시 모두에서의 유지.
4. H03/H04의 D 작게·크게 및 W 적게·많게 네 요구의 전체 정오.
5. 같은 조건에서 양쪽 성공 / ID군만 성공 / 목록군만 성공 / 양쪽 실패 / 비교 불가.
6. 선택·생성 호출 수와 입력·출력 토큰·서버 시간의 계측 합, 누락값 수.

**규칙 목록을 복사하다 틀린 것을 곧바로 D 이해 실패로 단정하지 않는다.** 전체 선택 계약의 성과와, 실제 후보에 대응된 응답에서의 조건부 선택 정오를 함께 보여 준다. 조건부 성공률만으로 전체 분모를 대체하지 않는다.

관측된 잘못된 목록은 `unmappable_selection`으로 기록하고 해당 증명 생성은 예정된 skip으로 남긴다. 이는 선택 인터페이스의 관측 실패이며 종단 성공은 false다. 하지만 실행하지 않은 생성 자체를 실패로 채우지 않고 `generator_success`, `actual_D`, `actual_W`는 null로 둔다. 목록의 원소는 같고 순서만 다른 경우도 보고용 진단에만 남기고 실제 실행에는 사용하지 않는다.

전송 오류·identity 오류·길이 종료·중단·미실행은 별도 상태다. D/W 미측정값을 0으로 대체하지 않는다. 한쪽 미관측을 상대 군의 승리로 세지 않는다. 정상 응답의 JSON/스키마 오류는 관측된 출력 형식 실패로 구분한다. 기존 v080 응답은 이 형식 오류가 모두 0이었으므로 과거 성공 점수를 소급 변경하지 않는다.

## 5. 배정과 모델 호출 수

| 항목 | 배정 |
|---|---:|
| D 본실험 | 군별 64조건, 32쌍, 네 표시 전수 8묶음 |
| W 구별 대조 | 군별 32조건, 16쌍, 네 표시 전수 4묶음 |
| 선택 호출 | 두 군 각각 96회, 합계 192회 |
| 본실험 증명 | 두 군 합계 192건 |
| 공통 생성기 지정 경로 참조 | 공유 16건, 두 군에 복제하지 않음 |
| 전체 증명 | 208건 |
| 모든 선택이 요구 후보를 고를 때 | 1,404회 추론 |
| 모든 선택이 매핑 가능한 경우의 최소 | 1,340회 추론 |
| 선택한 경로에 따른 최대 | 1,468회 추론 |
| metadata 16개를 포함한 진행 슬롯 | 1,484개 |

미매핑으로 생성이 생략되면 호출 수가 1,340보다 작을 수 있다. 이를 누락 응답이나 실패한 생성으로 채우지 않는다. metadata 슬롯 하나에는 최대 세 HTTP 조회가 있으므로 슬롯 수와 전체 HTTP 요청 수는 다르다.

H01~H04는 이미 결과를 본 **4개 진단 구조이며 신규 구조는 0개**다. W는 후보 규칙 수가 다른 H03/H04에만 배정한다. 동일 구조의 seed·위치·ID 반복을 독립 문제로 부풀리지 않는다.

선택 군의 호출 순서는 조건에 따라 균형 배정한다. 두 선택을 먼저 독립 호출한 다음 각 군의 선택·이력으로 생성한다. 같은 seed가 응답의 완전 동일성을 보장한다고 가정하지 않는다.

## 6. 유지하는 연구 범위

원 연구의 D=Decomposition 전체를 재정의하지 않는다. 이번 지표는 고정 규칙 체계에서 실제로 산출한 유효 proof DAG의 목표 의존 깊이 `D_DAG`다. W는 목표를 지지하는 규칙 노드 수이며 새 ADM 축이 아니다.

문제의 최소 필요 깊이와 이번에 작성한 증명의 깊이는 별개다. 후자를 요구에 맞게 바꾸는 시스템의 성과를 검사한다. 후보는 실험자가 제공하고 모델이 선택 및 실제 부모 연결을 작성한다. 후보 없는 자율 경로 발견, 내부 hidden-state 깊이, 사고의 모든 질적 측면, A/M 독립성, 큰 모델 대비 동등성은 이 배치의 측정 대상이 아니다.

후보 ID만큼 규칙 ID도 여전히 기호이며, 새 방식이 모든 기호 민감성을 제거했다고 주장할 수 없다. 실제 원응답이 후속 생성기에 전달되므로 두 선택 출력 형식의 차이가 후속 입력에 미치는 효과도 종단 비교에 포함된다.

## 7. Windows 실행

기존 v080 evidence를 Downloads 또는 기존 `v080\results_llm` 폴더에 둔다. 파일명 뒤 `(1)` 여부와 관계없이 내용 해시로 확인한다.

먼저 무추론 점검:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v081-Auto.ps1" -CheckOnly -AllTests
```

이 명령은 설치, 자체시험, 오프라인 교정, v080 재감사, v081 계획 동결까지 수행한다. 실제 Ollama 조회·추론·서버 시작·모델 다운로드를 하지 않는다. `-AllTests`는 기존 실행 방식과의 호환 인수이며 이 배포본은 기본 실행에서도 전체 자체시험을 수행한다.

실제 한 배치:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v081-Auto.ps1"
```

이미 사용 중인 Ollama와 `qwen3:4b-instruct`가 동결 identity와 일치해야 한다. 모델 및 서버 버전이 다르면 중단하며 자동으로 업데이트·다운로드하지 않는다. 저장소 우선 경로는 `D:\codex\AI논문\thought-graph-simulator`다. 자동 탐색이 맞지 않으면 `-RepoRoot`, `-Baseline`, `-PythonPath`로 이미 있는 경로를 명시할 수 있다.

완료 산출물:

```text
llm_experiments\v081\results_llm\v081_routepair_<시각>_evidence.zip
llm_experiments\v081\results_llm\v081_routepair_<시각>_independent.json
```

기존 v080 파일은 읽기만 하고 덮어쓰지 않는다. v081도 한 번 시작한 배치를 새 RunName으로 우회 실행하지 않는다. 중단하면 가드·원요청·원응답·로그를 보존한다. 가드는 첫 모델 요청 전에 생성될 수 있다.

기존 상태만 확인:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v081-Auto.ps1" -InspectOnly
```

## 8. 검산과 종료 기준

`legacy/`의 graph·단계·JSON 판정 모듈은 v080 원본을 유지한다. 새 `audit081.py`는 생산 선택 매핑·요청 생성·집계 모듈을 import하지 않고 독립 구현으로 대조한다. 한국어 렌더러는 두 경로가 공유하는 표시 코드이며 표시까지 독립 구현한 것으로 주장하지 않는다.

시험은 합성 응답과 기존 evidence를 사용한다. 현재 모델에 대한 새 실험 표본이 아니다. 독립 검산은 번들 내부 일관성을 검증하며 사용자 PC에서 일어난 일을 외부에서 인증하지 않는다.

결과가 좋든 나쁘든 한 배치 종료 후 원문 검산부터 수행한다. 목록 출력 계약의 개선이 없으면 이 변형을 성공으로 승격하지 않는다. 복사 오류만 많다면 이번 출력 계약의 제한으로 기록한다. 개선이 있어도 네 표시 유지·D/W 구별·참조와 생성 오류·계측 부담을 함께 확인한다. 자동으로 추가 문구·seed·부모 제약·다음 버전을 실행하지 않는다.
