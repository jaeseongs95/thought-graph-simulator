# v085 사전등록 — 값 비교와 후보 ID 조회를 분리한 절차의 D 종단 평가

작성일: 2026-09-15. 상태: v084 결과 관측 후 설계, v085 실제 Qwen 응답을 보기 전 동결. 기준선은 SHA-256이 고정된 v084 evidence다. 본문과 `data/protocol.json`이 함께 소스 manifest에 포함된다.

## 1. 연구 질문과 주장 단위

정확한 수치 지원의 기존 선택기보다, 수치 극값 선택과 후보 ID 조회를 명시적으로 분리한 절차가 **실제 유효한 proof DAG의 양방향 D 종단**을 개선하는가? 효과가 위치·ID를 바꾼 표시에서도 유지되는가?

D의 정의와 primitive rule 체계는 v084와 같다. 새 숫자 비교 과제는 이미 제공된 정수의 작은/큰 값을 고르는 것이며 DAG의 D를 스스로 계산하는 과제가 아니다. 기존 eight-case holdout은 이제 관측된 진단 집합이다. 같은 구조의 재사용을 새 holdout이나 새 독립 표본으로 부르지 않는다.

## 2. 동결 범위

T01~T08 전체, 원자·규칙·사실·goal·두 후보 경로, 모델 identity, 두 seed, 후보 ID, 위치×ID 네 표시, 기존 선택 두 군의 프롬프트/스키마/API 옵션, `explicit_rule` 생성기/초기 사실 제약을 그대로 유지한다. 같은 규칙 수 네 구조와 역전 규칙 수 네 구조를 모두 사용한다. 실패가 컸던 특정 구조만 선별하지 않는다.

새 군의 비교·조회 헤더, 스키마, 각 단계 입력 필드 및 호출 배정도 실행 전 고정한다. 숫자 비교 단계의 원응답은 원문 그대로 다음 단계로 전달한다. 대상 값의 수정·재시도·순서 재선택·모범 parent 제공은 금지한다. 모델 선택이 틀렸어도 실제 선택 경로를 생성한다.

## 3. 실험군과 처치

1. `candidate_id`: v084 직접 선택, D만 생성.
2. `correct_values`: v084 정확한 후보 D/W 지원, D만 생성.
3. `two_stage_values`: 후보 ID 없는 숫자 비교 → 요구 방향 없는 값-ID 조회 → D만 기존 생성.
4. `oracle_lookup`: 정확한 목표값을 실험자가 제공한 조회 대조. D/W 선택 진단만. graph 배정 없음.

세 번째 군의 첫 단계는 metric/direction/values를 받는다. 후보 값의 위치 순서는 원래 후보 배열과 동일하되 ID는 없다. 두 번째 단계는 기존 정확한 후보 측정표·metric·첫 단계 원응답을 받는다. first stage의 잘못된 값도 보정하지 않는다. null 출력이 허용된다. 두 단계군은 숫자 비교에 실패하면 전체 선택 실패이며, 조회가 잘못되어 우연히 목표 graph가 맞아도 전체 성공은 아니다.

`oracle_lookup`는 조회능력의 지원 대조이며 숫자 비교·D 계산·graph 생성의 성공 증거로 사용하지 않는다. 숫자 비교 원문이 정확하고 동일하게 직렬화된 경우 두 단계군의 조회 요청과 oracle 조회 요청이 같을 수 있다. 둘은 실제 반복 호출로 보존하되 별개의 독립 과제로 가산하지 않는다.

## 4. 배정 및 실행 수

8구조×2seed×4표시×2방향 = 군당 D 128조건. W는 마지막 네 구조에 같은 교차를 적용하여 군당 64조건. 총 선택/조회 768회, 비교 단계 192회. D 본실험 증명 384건과 공통 참조 32건, 총 416건. 각 증명은 facts 1회, 선택한 규칙 수만큼 rule, final 1회다.

군 순서는 조건에 따라 회전 배정하며 특정 군을 항상 첫째/마지막에 실행하지 않는다. 공통 참조는 중복하지 않는다. 최대 추론 3,708회, metadata 32개 포함 action 3,740개. 목표 경로가 모두 선택되면 3,612회다. 실패 또는 선택 경로 차이에 따른 실제 호출 수는 원문과 함께 보고한다. 추가 토큰/호출을 비용 기록에서 누락하지 않는다.

## 5. 주평가

각 구조의 같은 seed·표시에서 shallow/deep 두 요구에 대해 **선택 단계 모두 성공 + 유효 graph + 요구 D + 선택 경로 충실도**를 만족해야 한 쌍이 성공한다. 구조당 군별 8쌍의 성공률을 계산한다.

주효과는 `two_stage_values - correct_values`의 구조별 성공률 차이 8개의 동일 가중치 평균이다. 각 구조의 개선/악화/동일을 함께 보고한다. 어느 구조에 미관측 쌍이 있으면 그 구조 차이를 산출하지 않으며, 전체 8개가 완전하지 않으면 전체 평균도 미판정이다. seeds와 네 표시는 독립 구조가 아니다. 이 비무작위 진단 집합에 자동 유의확률/IID 신뢰구간을 적용하지 않는다.

## 6. 부평가와 단계 진단

- v084 두 비교군의 같은 배치 내 지원 효과, 새 군과 기존 지원군의 조건별 순증/소실.
- 단방향 선택·종단, 양방향 선택·종단, 네 표시 전체 통과, 위치×정답 ID별 성공.
- 숫자 비교 성공, 모델 보고값에 대한 ID 조회 준수, 비교 정답 조건에서의 조회 준수.
- 정확한 목표값 조회 양성 대조 및 두 단계군과의 차이.
- 비교가 틀린데 유효 목표 graph에 도달한 횟수: 우연 도달로 별도 보고, 전체 성공 제외.
- 선택이 맞은 뒤의 생성 실패, 모든 단계의 원문과 actual D/W. W는 선택만, D 종단에 합산하지 않음.
- usage 누락, 입력/출력 토큰, 호출 수를 비교/조회/생성별로 분리.

## 7. 가설별 판단 규칙

**P1 절차 효과:** 주효과가 양수이면 이 집합의 평균 개선을 보고하되 소실 조건과 전표시 통과를 별도로 보고한다. 0 또는 음수이면 두 단계군을 기본 선택기로 승격하지 않는다. 특정 표시의 최고 점수만 고르는 성공 기준은 금지한다.

**P2 비교 과제:** 숫자 비교가 정확하고 조회가 실패하면 관측된 실패 위치를 조회 단계로 좁힐 수 있다. 숫자 비교가 실패하면 그 실패와 이후 원문 추종을 따로 보고한다. 새 하위 과제의 성과는 v084가 내부에서 같은 하위 계산을 했다는 증거가 아니다.

**P3 ID 연결 대조:** 정답 목표값 조회에서도 위치/ID별 오류가 남으면 이 조회 계약 자체에도 표시 의존성이 남았다는 증거다. 조회가 좋아져도 문제 문맥·출력 형식·추가 호출 변경을 함께 적용했으므로 단일 내부 원인을 확정하지 않는다.

**P4 실제 종단:** 하위 과제가 좋아졌지만 D 종단이 개선되지 않으면 선택·생성·추가 단계 실패를 분리한다. 하위 과제만의 성공으로 연구 전체가 개선됐다고 쓰지 않는다.

## 8. 오류·중단·검산·종료

JSON/schema의 관측된 위반은 출력 계약 실패다. HTTP/identity/길이 종료/미실행은 그 상태대로 보존하며 D=0 또는 논리 오답으로 채우지 않는다. 비교 출력이 schema상 유효하지만 후보에 없는 정수이면 그대로 조회기에 전달한다. 유효한 null 응답 후 graph는 미배정 상태가 아니라 선택 결과로 미실행된 상태이며, 전체 파이프라인 실패와 생성 미관측을 구분한다.

dispatch와 응답 저장을 분리하고 응답은 record commit 전에 보존한다. 해시·원문·event chain·실제 requests/history·독립 graph 채점·집계와 한국어 보고서를 검산한다. synthetic/test/offline/실제 Qwen을 구분한다. 시작한 배치의 guard 제거·자동 재시도·새 RunName 우회·소급 보정은 하지 않는다.

이 배치 1회로 종료한다. 결과가 나온 후에만 다음 질문을 정한다. 새 구조·모델·지원 계약으로의 재현이나 생성기 변경은 별도 실험이다. v084와 이번 배치를 합쳐 신규 문제 수를 늘리지 않는다.
