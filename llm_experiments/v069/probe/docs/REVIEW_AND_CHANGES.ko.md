# v068 원문 검토와 v069 변경

## 확인된 관찰

v068은 36회 추론과 metadata를 포함한 48개 action이 완료된 번들이다. 원응답 36개, 종단 graph 24개, staged의 원문 전달 12개를 재확인했다. direct 4/12, staged 8/12가 생산 재계산·기존 독립 검산·새 원문 검산에서 일치했다. direct의 12개 요청 바이트와 응답 content는 v067 대응 기록과 모두 동일했다.

staged의 최종 ID 12개는 모두 출력된 목표 atom 노드를 가리켰다. 이것을 유효 증명 12/12로 세지 않는다. E01 short는 n08/n91의 불필요한 가지가 남고, E02 long은 참조에 없는 m18과 m05/m84의 전제 연결 오류가 남았다.

## 수정·새로 구현한 내용

기존 v068 파일을 덮어쓰지 않고 v069 경로에 추가한다. nodes→final 진단을 종료하고, 실험자 제공 참조 규칙을 한 노드씩 적용하는 새 positive control을 만든다. facts 12회 + rule 30회 + final 12회 = 최대 54회다. 모든 앞선 원응답을 전달하며 정답 노드/부모/후보를 호스트가 생성하지 않는다.

새 모듈은 배정(design), 형식/결합/단계 감사(stages), 12개 종단 집계(report), 별도 요청·순서·증명·단계 검산(verify)이다. measure.py는 v068과 바이트 동일하다. 실행·변조 검사·pending 보존의 기존 기반을 유지하고 history 계약에 맞춰 확장했다.

v068 run.py의 prepare 출력에는 실제 배정 36회와 달리 `max_inference_calls_when_executed: 12`라는 낡은 표시가 있었다. v068의 실제 실행 상한은 계획/실행기에서 36으로 적용되어 이번 결과를 바꾸지 않았다. v069는 계획의 `protocol.max_inference_calls`를 출력하므로 54와 일치한다. 이 수정은 새 prepare 명령을 실행하는 회귀 시험으로 검사한다.

최종 graph가 유효해도 앞 단계 계약 위반을 성공으로 덮지 않는 반례를 추가했다. 형식 오류/길이 종료/미관측은 null을 유지한다. 새 시험은 정답 enum 주입, 전달 history 생략/수정, 요청 rule/seed 변경, 최종 응답 변조, 보고서 변조를 포함한다.

## 선택하지 않은 해석과 다음 실행의 범위

8/12를 전체 생성기 확보로 바꾸지 않는다. T02의 4/4만 사후 추려 D 파이프라인 성공 기준을 충족했다고 하지 않는다. 최종 ID만 옮긴 인과 실험이라고 하지 않는다. v069는 단계별 정답 규칙 안내까지 추가된 단일 방식 양성 대조이며 v068 대비 우월성을 통제해 추정하는 실험이 아니다.

새 source의 단위·통합·합성 HTTP 시험과 실제 Qwen 추론을 구분한다. 개발 환경에서는 실제 Qwen v069 추론을 실행하지 않았다. Windows PowerShell 네이티브 실행은 Windows 환경에서 별도 시험 대상으로 남는다.
