# v069 동결 계약 — 지정 규칙 append-only 양성 대조

## 1. 결정 근거와 이전 분기의 종료

실제 v068 배치에서 direct는 4/12, nodes→final은 8/12였다. 짝별 결과는 양쪽 성공 2, staged만 성공 6, direct만 성공 2, 양쪽 실패 2다. T02의 짧고 긴 경로는 staged에서 각각 2/2였으나 E01 짧은 경로와 E02 긴 경로는 각각 0/2였다. 사전에 정한 12/12 gate는 양쪽 모두 불통과다. T02만 사후 선택해 전체 기준선을 통과했다고 바꾸지 않는다.

v068의 nodes→final 진단은 종료한다. 같은 문구·seed 변형이나 direct/staged 추가 배치를 반복하지 않는다. v069는 출력 단위를 규칙 적용 노드 하나로 바꾸고, 실험자가 제공한 경로의 다음 규칙을 단계별로 명시하는 **별도의 더 강한 안내 계약**이다. 새 요청에서 얻는 응답만 채점한다. v068 실패 graph의 가지치기·부모 교정·최종 ID 교정은 없다.

v068이 보여 준 것은 분리 방식의 성공 범위가 문제/참조 경로에 따라 달라졌다는 것이다. 최종 ID 선택만 좋아진 것은 아니다. 예컨대 E01 긴 경로는 실제 노드 구성까지 바뀌어 성공했고, E01 짧은 경로는 불필요한 가지가 생겨 실패했다. 내부 디코더·주의집중·은닉 사고의 원인을 특정한 결과가 아니다.

## 2. 질문과 설계 범위

같은 문제와 정상 참조 경로를 제공하고, 실행 순서를 facts → 지정 rule 노드 하나씩 → final로 고정하면 모델이 무보정으로 유효한 전체 증명을 작성할 수 있는가?

이것은 단일 방식의 구성 가능성 양성 대조다. v068과 동시 무작위 대조를 하지 않으므로 과거 성공률과의 차이를 이 방식의 인과 효과로 주장하지 않는다. 단계별 정답 rule ID 안내, 출력 schema, 호출 수, 문맥 전달 모두 달라진다. 동일 비용 비교도 아니다.

정상 경로뿐 아니라 매 단계에 적용할 rule ID까지 이미 제공한다. 그러므로 12/12여도 자율 D 선택이나 A/M 제어의 증거가 아니다. 이 계약으로 이미 본 문제에서 참조 증명을 구성하는 기준선만 확보한다.

## 3. 고정되는 입력

v068 evidence의 SHA-256은 `4206bfaacef17b811e232d05a458bbd9b90e8661d69dba3cd2feaf4f11790ad2`다. 당시 소스 ZIP은 `ee9734f552fc6405f3015922cc250f338bc9054447c57f09e22f4e21c6049d20`로 고정해 전체 이전 evidence를 별도 프로세스에서 재검산한다. 임의 evidence 속 소스를 실행하지 않는다.

모델은 기존 `qwen3:4b-instruct`, digest `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`다. 서버 버전·template·모델 정보·parameters도 v068 identity와 대조한다. 모델 다운로드, 변경, 갱신, 서버 시작은 없다.

T02 / E01_shared_fork / E02_two_vs_four, seed 64001001 / 64001002, 각 short/long 참조 경로를 그대로 사용한다. 문제·사실·규칙 순서·목표·모델 옵션은 유지한다. 독립 holdout이나 새 seed 일반화가 아니다. 각 문제의 두 seed에서 short/long의 선후를 반전한다. 서로 다른 문제의 모든 캐시/실행 이력을 통제했다는 주장은 하지 않는다.

참조 경로와 D:

|문제|short|D|long|D|
|---|---|---:|---|---:|
|T02|r83|1|r21 → r57 → r04 → r69|4|
|E01_shared_fork|n52|1|n08 → n91 → n37|2|
|E02_two_vs_four|m18 → m76|2|m33 → m05 → m84 → m41|4|

E01 긴 경로의 규칙은 세 개지만, 독립적인 두 가지가 합쳐지므로 지지 DAG의 깊이는 2다.

## 4. 호출 배정과 예산

12개 trial = 3문제 × 2seed × 2참조 경로다. 각 trial은 초기 사실 배열 1회 + 참조 경로의 규칙 수만큼 단일 노드 생성 + 최종 ID 지정 1회다.

|문제|short의 호출 수|long의 호출 수|두 seed 합계|
|---|---:|---:|---:|
|T02|3|6|18|
|E01_shared_fork|3|5|16|
|E02_two_vs_four|4|6|20|
|전체|||54|

facts 12회, rule 30회, final 12회다. 6개 block의 전후 metadata 12묶음을 합하면 66개 action이다. metadata 묶음은 version/tags/show를 별도로 기록하며 모델 추론으로 세지 않는다.

기존 옵션인 num_predict=4096, num_ctx=8192를 유지한다. 생성 토큰의 배정 상한은 54×4096=221184다. 실제 사용량은 원응답 계수로 별도 기록하며 누락은 null이다. 호출마다 UTF-8 요청 바이트 상한 32768을 검사한다. 이 바이트 제한을 정확한 tokenizer 기반 문맥 사용량 측정으로 간주하지 않는다. 상한을 넘는 원응답을 잘라 전달하지 않고 실행을 중단·보존한다.

## 5. 호스트와 모델의 경계

호스트는 고정 경로의 적용 순서를 배정하고 현재 requested_rule_id를 알려 준다. 이는 실험자가 제공하는 정답 안내임을 명시한다. 호스트가 노드 내용·전제 atom·부모 ID·최종 ID를 생성하지 않는다.

facts 호출은 초기 사실 노드 배열만 쓴다. 각 노드의 id/atom/rule/parents는 모델 출력이다. rule 호출은 현재 규칙의 새로운 노드 하나만 `node` 필드로 쓴다. final 호출은 실제 출력된 목표 노드의 `final_node_id`만 쓴다. 정답 enum이나 후보 목록으로 출력을 강제하지 않는다.

다음 호출에는 같은 trial의 이전 모든 response.message.content 문자열을 공백·개행·오류까지 원문 그대로 전달한다. 각 항목은 source slot ID와 원응답 envelope SHA-256을 동반한다. 호스트는 내부 JSON을 파싱해 정상 부분을 골라 전달하지 않는다. 외부 envelope 자체가 파싱 불가하면 content는 null로 남기되 전체 원응답 바이트와 해시는 보존한다. 형식상 틀린 내부 JSON 문자열은 그대로 전달한다.

실행 후 채점기에만 사실 배열과 각 단일 노드를 호출 순서대로 연결하고, 모델의 최종 ID를 그대로 붙인다. 노드 추가·삭제·재정렬·중복 제거·ID 변경·부모 교정·fact 보충·정답 경로 선택은 없다. 같은 입력에서 실패했다고 생성 요청을 반복하지 않는다.

## 6. 단계 감사와 종단 성공

단계별 형식 오류, 국소 계약 위반, 전체 증명 유효성을 분리한다.

facts의 모든 원자는 주어진 초기 사실과 다중집합이 같고, rule=null/parents=[]이며 ID가 중복되지 않아야 한다. rule은 배정된 requested_rule_id와 같고, 이미 출력된 실제 전제 ID를 사용하여 등록 규칙의 전제를 정확히 충족해야 한다. final은 실제 모델 출력의 목표 노드를 가리켜야 한다. 이러한 단계 감사는 실행 뒤에만 하며 후속 요청을 고치는 데 사용하지 않는다.

전체 graph는 기존 v068과 바이트 동일한 measure.py로 검사한다. 모든 fact/rule/전제 다중집합/부모 존재/순환/goal/final 존재/ancestry/불필요 노드/위상 순서를 검사한다. 실제 D는 strict 유효 graph에서만 정의한다.

종단 성공은 모든 배정 호출의 관측·형식 유효, 모든 단계 계약, 전체 strict graph, 참조 규칙 순서 일치, 참조 D 일치를 함께 요구한다. 최종 graph가 유효하더라도 앞선 단계 계약을 어기면 종단 실패다. 초기 facts 단계에서 규칙 노드를 몰래 만들고 뒤 단계에 fact를 출력하는 반례를 별도 검사한다.

JSON/schema 실패·미실행·generation length 종료는 논리 오답이나 D=0으로 채우지 않는다. 개별 단계 schema는 맞지만 결합 graph가 최종 schema 제한을 넘는 경우도 형식 미측정이다. HTTP/transport/identity/생성 예산 초과는 즉시 전체 배치를 멈춘다. 논리적 실패나 전달 가능한 형식 오류는 원문을 유지하며 사전 배정 순서를 계속 진행한다.

## 7. 사전 gate와 종료

54회 모두 완료되고 12개 trial이 모두 측정되어 12/12이면, 이 지정 경로·단계별 지시 계약에서 구성 기준선을 확보한다. 이후 D 요구를 모델이 선택한 경로로 변환해 같은 실행 계약에 무보정 전달하는 별도 실험을 설계할 수 있지만 여기서 자동 실행하지 않는다.

0/12면 이 계약을 종료한다. 1~11/12면 문제/short-long/seed별 범위를 보존하고 이번 배치를 종료한다. 이 코드가 문구·seed를 바꾸어 추가 진단을 자동 생성하지 않는다. 성공한 문제만 골라 전체 gate를 올리지 않는다. 일부 또는 전부 미측정/미완료이면 gate는 null이다.

v068의 4/12·8/12 및 불통과 판정은 모든 경우 그대로 유지한다. 성공과 실패 어느 쪽도 전체 A/D/M 이론이나 모델 내부 원인으로 확대하지 않는다.

## 8. 검산과 실행 보존

생산 코드와 별도 검산 구현은 본 버전의 design/measure/report/run/stages를 공유 import하지 않는다. 공유하는 것은 바이트·JSON·ZIP 도구, 동결 protocol과 이전 고정 버전의 감사 경로다. 생산 DAG 측정과 별도 DAG 측정을 대조하고, 실행 순서·원문 전달·요청 바이트·identity·status·usage·한국어 보고서까지 재계산한다.

각 action의 시작 표지, 원문 request/response, 완료 record, event hash chain을 보존한다. commit event가 없는 원응답은 pending으로 보존하고 채점하지 않는다. inference_calls는 시작 표지 수이므로 요청 생성 직전 중단된 경우 서버가 받은 호출 수와 다를 수 있다. observed_calls와 pending_action을 함께 보고한다.

hash와 manifest는 번들 내부 일관성 검산이며 외부 모델 실행을 서명 인증하지 않는다. 같은 evidence를 여러 검산기로 재계산한 것을 독립한 실제 실험 여러 번으로 세지 않는다.
