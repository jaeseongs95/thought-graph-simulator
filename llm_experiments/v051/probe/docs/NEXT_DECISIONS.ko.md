# v051 결과에 따른 다음 결정

## 1. 증명·A/D는 유효하지만 M2만 실패

A/D의 구조 조작 관측을 인정하고 M2의 평가 기준 판정 실패를 분리한다. 전체 A/D/M 성공이라고 쓰지 않는다. 후속 M 실험은 같은 생성 증명에서 검토를 별도 호출로 수행하는 조건과 단일 호출 조건을 비교할 수 있다. 그 실험은 호출 예산과 제공 정보를 별도로 통제한 새 계획으로 만든다. 이번 기록의 finding을 사후 교체하지 않는다.

## 2. 모든 기록은 유효하지만 요청한 축이 바뀌지 않음

모델이 문제를 해결했다고 해서 역할 조작도 성공한 것이 아니다. `strict_valid`와 `role_match` 차이를 보고한다. 어느 지시를 무시했는지 대응표를 확인한 다음 한 축 지시만 개선한 새 실험을 설계한다.

## 3. 요청한 축과 다른 축도 함께 바뀜

축 조작의 분리 가능성이 이 조건에서 유지되지 않은 관측이다. 성공처럼 합치지 않고 `unmanipulated_axes_changed` 및 개별 trace를 확인한다. 제어 자체의 결합인지 표현/검토 형식 오류인지 기록으로 구분한다.

## 4. 목표 문자열은 맞지만 증명·도식이 무효

고정 결과 성공이 아니다. 잘못된 전제·규칙·부모·도식 접지의 위치를 먼저 확인한다. 호스트가 증명을 정답으로 보정하는 대신, 동일 계약에서 출력 구조 지원이 필요한지를 별도 대조한다.

## 5. 모든12조건과 한 축 비교가 안정적으로 성공

그때 확보한 것이 단일 문제의 성공 기준선이다. 다음은 결과를 보기 전에 정한 다른 고정 문제들에서 같은12조건을 반복하는 외부 과제 재현이다. A/D/M 축을 동시에 조작하면서 큰 모델보다 낫다는 성능 주장으로 바로 건너뛰지 않는다. 다른 모델·효율 비교는 타당한 문제 집합과 예산별 기준이 마련된 뒤에 진행한다.

## 6. 통신·모델 식별·원문 감사 실패

자료 수집 문제를 모델의 축 조작 실패로 집계하지 않는다. 남은 원문을 보존하고 새 실행 이름으로 다시 계획한다. 완료된 일부 결과만 잘라 완결된 실험처럼 묶지 않는다.

모든 경우 v050와 v051의 정확도를 직접 개선율로 비교하지 않는다. 서로 다른 과제와 출력 계약이다. 사후 성공 seed만 남기지 않으며, 아직 호출하지 않은 실제 모델 결과를 합성 시험 성적에서 추정하지 않는다.
