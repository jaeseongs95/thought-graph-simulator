# v070 분석과 v071 변경 근거

## 관찰

실제 첨부 v070은 live/complete, 40회 추론, 60개 action, pending 없음이다. 원응답의 후보 경로는 40/40 유효하다. 올바른 D 방향 선택은 20/40이며, 두 방향을 모두 맞힌 비교 쌍은 0/20이다. 20쌍 모두 동일한 경로를 출력했다. 이 결과는 원응답을 다시 계산하고 생산 계산 및 기존 독립 검산과 대조했다.

T02와 E01은 후보 위치를 뒤집어도 항상 짧은 경로를 선택했다. E02, C01, C02는 위치 0의 첫 후보를 항상 선택했다. 따라서 모든 문제를 하나의 '항상 짧은 경로' 또는 '항상 첫 후보' 설명으로 묶을 수 없다. 첫 후보의 규칙 수가 더 많은 C02에서도 같은 위치 패턴이 나타났다.

형식·후보 복사는 정상이나 요구 방향에 맞는 선택은 없었다. 성공률 50%를 선택적 제어가 절반 성공한 것으로 해석하지 않는다. 각 쌍에서 같은 답을 반복해 한쪽만 맞았다. 자유로운 graph 생성이나 parent ID 정확성은 v070에서 측정하지 않았다.

## 확인되지 않은 원인

깊이 계산 실패, 크고 작은 수 비교/방향 지시 실패, 복합 선택 계약의 문제 중 어느 것이 실제 병목인지는 v070 원응답만으로 분리되지 않는다. 후보 순서에 따라 선택이 달라졌다는 관찰을 내부 메커니즘 발견으로 확대하지 않는다.

## 다음 결정

v070의 실패 종료 조건을 적용한다. 원문 실패는 보정하지 않는다. v071은 단일 후보 복사 지시를 재작성하는 대신 깊이 계산과 숫자 비교를 분리하고, 참값을 제공하는 양성 대조를 함께 실행한다. 20개 계산을 두 방향에서 공유하므로 이를 독립 계산 40개로 과장하지 않는다. 한 번의 100호출 배치 이후 이 계약도 종료한다.

정답입력군은 직접 생성 능력의 검사가 아니라 수치 비교 인터페이스의 양성 대조다. 두 팔 모두 전체 증명을 생성하지 않는다. v069의 생성기 성과와 v071 선택 성과를 더해 종단 제어 성공이라고 보고하지 않는다.

## 소스 변경

새 `depths.py`에 정수 배열·인덱스 채점과 원문 기반 경계 판정을 넣었다. `design.py`는 20block/100호출/140action, model/oracle 입력 provenance와 실제 원문 전달을 동결한다. `report.py`와 `verify.py`는 서로 다른 의미 계산으로 단계·쌍·보고서를 재현한다. 바이트/JSON/ZIP 계약과 고정 입력 명세는 공유한다.

run/launch는 이전 증거 수신, 원문 보존, 이벤트 체인, 중단, 실제 호출 상한, 기존 결과 보호를 유지한다. 이전 버전을 수정하지 않으며 새 v071 디렉터리만 추가한다. Windows PowerShell 래퍼에는 소스 ZIP을 내장하고 해시를 검증한다.
