# v062 결과 분석과 3자 교차토론

## 1. Executive Verdict — 최종 판단

**실행 기록은 독립 검산을 통과했지만, 조건부 증명 구성은 0/40으로 사전 진입 기준에 미달했다. 새 K01 추론 실험은 진행하지 않는다. v063은 기존 원자료를 분석하는 오프라인 도구 버전으로 만든다.**

쉽게 말하면, 학생이 답안 양식을 채우고 마지막에 써야 할 공식 이름도 대부분 적었지만, 풀이에 틀린 단계를 섞었다. 짧은 풀이에서는 정답까지의 연결 바깥에 틀린 단계를 붙인 경우가 많았고, 긴 풀이에서는 정답까지의 연결 자체도 틀렸다. 틀린 부분을 대신 지워서 성공으로 바꾸지 않고 오류 위치를 설명하는 단계다.

## 2. Consensus Proposal — 합의안

상태는 `conditional_consensus`다. 세 검토자는 최종 교차검토에서 새 LLM 호출·K01 선택 반복·결과 맞춤 프롬프트 튜닝·자유 깊이 실험을 하지 않는 데 합의했다. 사용자가 요청한 소스는 **v062 공식 결과를 보존하는 오프라인 진단·검산 CLI**로 제공한다.

v063이라는 번호는 소스 보존을 위한 도구 버전이다. v062의 다음 실험 진입 기준을 통과했다는 뜻도, 새 연구 조건을 승인했다는 뜻도 아니다. 도구는 원문 JSON의 규칙·목표 라벨, 기록된 최종 부모 연결의 안팎, 노드별 의미 오류만 추가한다. 노드 삭제, 보정 그래프, 조상만의 D, 새 성공률이나 새 진입 기준은 만들지 않는다.

## 3. Strong Consensus — 공통 판단

- 40개 응답은 모두 JSON Schema에 맞지만, 전체 출력의 규칙 의미론은 40개 모두 틀렸다.
- 원래 `proof_valid`, `strict_valid`, `instruction_fulfilled`는 0/40, `actual_D`는 40개 모두 null, 진입 판정은 false다.
- 최종 규칙 문자열을 맞춘 39/40과 유효한 지정 규칙 증명 0/40은 서로 다른 관측이다.
- 전체 증명이 실패했다고 해서 모든 최종 연결에 오류가 있다거나, 목표 문자열조차 출력하지 못했다고 말해서는 안 된다.
- 한 문제의 10개 seed와 각 조건 두 번의 관측을 독립 문제 40개로 세지 않는다.
- 기록의 무결성, 모델의 수행, 연구 방향의 타당성은 별도 판정이다.

## 4. Material Disagreements — 이견과 교차검토

|논점|초기 의견|교차검토 후 판단|
|---|---|---|
|다음 소스 자체를 만들 것인가|인과·통계 검토자는 다음 실행 소스 중단, 측정 검토자는 오프라인 보조 진단을 권고했다.|새 실제 추론 소스를 중단한다는 뜻으로 범위를 좁혔다. 공식 판정을 바꾸지 않는 진단 CLI는 사용자 요청과 사전 종료 약속을 함께 충족한다.|
|최종 조상만의 D를 추가할 것인가|측정 검토자의 초기 제안에는 `ancestor_only_D`가 포함됐다.|잘못된 노드를 제외한 사후 성공으로 오해될 위험을 지적했다. 제안을 철회하고 오류의 위치만 표시한다.|
|새 holdout 문제를 바로 만들 것인가|공학 검토자는 새 문제에서 단일 규칙/두 단계의 20회 진단 설계를 제안했다.|새 문제·새 계약·새 실행은 이번 최소 범위에서 제외했다. 이번 도구에 프롬프트나 실행 계획을 넣지 않는다.|
|‘최소’라는 표현의 범위|공학 검토자는 일반 DAG의 조상 폐쇄가 전역 최소 노드 수와 같지 않다고 지적했다.|일반 최소성 주장을 하지 않는다. 원래 고정 K01 계약은 보존하고, 새 도구는 최소성 점수를 만들지 않는다.|

교차 항목 X1은 인과 검토자의 실행 중단 주장과 측정 검토자의 보조 진단 제안을 서로 검토하게 했다. X2는 측정 검토자의 조상만의 D 제안을 인과 관점과 대조했다. X3은 공학 검토자의 새 holdout 및 보강 범위를 나머지 두 관점의 종료 조건과 대조했다. 각 검토자는 한 차례만 조건부 재검토했다.

`target_k17`에서 밖에만 오류가 있는 1개는 `b00_p0_target_k17_r0`이다. 이 응답은 지정한 `k17` 대신 `k03`으로 끝난다. 긴 조건의 부분 성공으로 표현하면 안 된다.

원래 goal/target 지표는 유효한 전체 증명을 전제로 정의돼 모두 0이다. 진단 도구는 이 정의를 바꾸지 않고 별도 이름의 표면 일치를 추가한다. 원래 `extra_unused_node` 오류는 proof가 유효할 때만 산출되므로, 40/40의 비조상 노드 존재를 설명하려면 별도 구조 진단이 필요하다.

## 6. Evidence — 직접 확인한 근거

입력: `llm_experiments/v062/results_llm/v062_construction_01_evidence.zip`.

- 입력 SHA256: `baea752ac1a55dc7a20b42b41ced69b3c8e126105f65deea8ebecc8dde3f09fd`
- 계획 SHA256: `071b17338d23e067297bbec0f60bc527a41100d0a1f274789b752767a3bbcbf3`
- event tip: `6a4f1aa93788b07d8068094a6b6fba777342cd80b8b4c4d2b75a2d9e0a50a457`
- 독립 검산: 40 calls, 20 metadata, 842 비교 필드, 기준선 1,649 필드, `differences=[]`.
- 실제 모델: 동결 요청·identity의 `gemma3:4b`. 과거 baseline config의 설명용 모델 이름을 실제 wire 모델로 대신하지 않는다.

K01의 사실은 `Ca`, 목표는 `Cc`다. 규칙은 `k03: Ca→Cc`, `k10: Ca→Cb`, `k17: Cb→Cc`다. 규칙 배열은 두 조건 모두 `k03,k17,k10`이다.

`b01_p0_target_k03_r0`은 `Ca→k03 Cc` 연결 외에 `Cb/k17/[Ca]` 노드를 낸다. 후자는 k17의 전제와 결론을 모두 위반한다. `b01_p1_target_k17_r0`의 최종 `Cc/k17/[]`에는 필요한 `Cb` 부모가 없다. `b00_p1_target_k03_r0`은 입력 사실이 아닌 `Cb`, `Cc`를 초기 사실처럼 추가했다.

호출별 오류는 중복 집계다. `wrong_atom`과 `premise_counter_mismatch`는 각각 40회, `unreachable_fact`는 23회다. 오류 개수를 서로 더해 독립 실패 호출 수로 쓰지 않는다.

동일 seed의 최종 규칙 라벨 반복은 9/10 seed에서 양 조건 모두 같았다. 그러나 strict 유효한 네 응답이 없으므로 공식 구성 안정성은 10개 seed 모두 측정 불가(null)다. 사전 기준을 충족한 안정 seed의 수 0과, 실제로 불안정함이 입증된 수를 혼동하지 않는다.

캐시 카운트는 각 조건에서 0이 1회, 402가 19회였다. 첫 두 호출 이후 카운트가 달라졌지만 호출 순서·직전 이력도 함께 변한다. 캐시가 실패를 일으켰다거나 영향이 없다는 결론은 낼 수 없다. 원문 재분석 JSON에 seed·sequence·period·직전 조건·반복 거리·캐시별 관측을 보존한다.

## 7. Required Actions — 이번 소스의 필수 범위

원자료 읽기→이전 독립 검산→추가 노드 진단→별도 구현의 진단 JSON 전체 대조→새 출력 폴더 보존만 제공한다. 기본 실행 입력의 SHA256을 고정하며 다른 입력을 지정하려면 기대 해시도 명시한다. 원자료는 새 증거 ZIP에 중첩하지 않는다.

이전 소스 감사의 D01은 파싱 오류 설명 문자열 일부가 독립적으로 결속되지 않는 한계였다. 이번 도구는 그 자유 텍스트를 근거로 사용하거나 출력하지 않고, 원문에서 `raw_parse_category`를 새로 계산해 독립 대조한다. 이는 v063 출력의 보강이며 v062의 옛 검산기를 소급 수정한 것은 아니다.

형식·논리·참조·순환·미관측·부분 실행과 보고서 변조 반례를 검사한다. 최종 소스 ZIP을 새 폴더에 풀어 자체시험하고, 작성·통합에 참여하지 않은 새 검토자가 마지막 소스 감사를 수행한다. 실제 완료 결과는 ZIP 밖 `validation/FINAL_REVIEW.ko.md`에 기록한다.

## 8. Optional Optimizations — 후속 판단으로 남긴 내용

연구를 재개하려면 새로운 holdout 문제에서 규칙 적용과 노드 생성 부담을 분리하는 별도 연구 질문을 정할 수 있다. 이번 자료만으로 그 설계의 표본 수·모델·성공 기준을 자동 결정하거나 실행하지 않는다. 이전 소스 사본은 보존 가치가 있고 evidence의 큰 부분은 기준선이므로, 이번에 버전 체인을 합치거나 소스 스냅샷을 제거하지 않는다.

## 9. Unresolved — 남은 한계

이 결과는 한 모델 digest, 한 문제, 한 출력 계약과 초기화하지 않은 실행 이력의 관측이다. 모델 능력, 프롬프트 부담, 경쟁 규칙, 캐시 중 무엇이 원인인지 분리되지 않았다. A/M 및 자유 D 제어는 입증하지 못했다. JSON Schema 제약 아래의 형식 성공을 자유 출력의 형식 준수 능력으로 일반화하지 않는다.

진단에서 부모 연결은 원응답에 기록된 참조만 따른다. 최종 조상 집합에는 최종 노드 자신도 포함한다. 오류가 밖에만 있다는 관측은 삭제 후 성공, 모델의 숨은 올바른 추론, 측정 가능한 보정 D를 뜻하지 않는다. 해시는 내부 일관성을 보일 뿐 외부 실행 인증이 아니다.

## 10. Method / Run Summary — 수행 방식

MEDIUM 패널에서 측정·구성타당성, 인과·통계·연구방향, 구현계약·재현성의 서로 다른 실패 관점을 맡은 세 검토자를 새 문맥으로 시작했다. 다른 검토자의 결론이나 조정자의 선호를 초기 입력에 넣지 않았다. 각자 원문을 확인한 뒤 한 차례 조건부 교차검토했고 조정자가 근거를 대조해 통합했다. 분석에 별도 fresh Judge는 요구되지 않아 사용하지 않았다. 보증 표현은 `partially_independent`이며, 독립 초기 검토와 조정자 통합을 구분한다.

각 초기 검토에는 `gpt-5.6-terra`와 `xhigh`를 요청했다. 생성 도구가 실제 적용값을 반환하지 않아 적용 여부는 미확인이다. 추가 specialist나 적응형 재숙고는 사용하지 않았다. 공개 가능한 주장·반박·근거만 이 문서에 요약했다.

토론이 끝난 뒤 측정 검토자는 시험, 인과 검토자는 별도 진단 검산기 구현을 맡았고 조정자는 분석기·실행 도구·문서를 작성했다. 이 구현 참여를 최종 소스 감사의 독립성으로 대신하지 않는다. 새 소스 감사자는 일반 검증과 ZIP 고정 이후 별도로 배정한다.
