# v058_order_02 다각도 분석과 v059 설계 판단

## 1. Executive Verdict

저장된 결과는 원문·계획·측정의 일관성 검사를 통과했다. 연구 해석은 **선정된 두 조건에서 관측한 출력 차이**까지가 적절하다. Qwen의 선택은 같은 seed의 두 일정에서 한 쌍이 달랐고, Gemma는 두 일정 모두 최소깊이가 아닌 규칙을 선택했다. 특정 캐시 상태, 순수한 과제 순서, 일반적인 모델 능력을 원인으로 확정할 자료는 없다.

v059는 Gemma의 `K01` choice에 한정해 두 terminal rule의 목록 순서를 바꾸는 진단으로 정했다. 분석에 필요한 코드는 새 버전에 두고, v058 원문과 완료된 소스는 보존한다.

## 2. Consensus Proposal

판정은 `conditional_consensus`다. 40회 후속 실험을 준비하되 결과의 범위를 규칙 배열 순열에 대한 탐색적 민감도로 제한한다. 실제 LLM 호출은 소스 제작·검증과 구분한다.

`K01`의 원래 rules 배열 `[k10,k17,k03]`과 교환 배열 `[k10,k03,k17]`을 비교한다. facts, 규칙 내용과 ID, goal, shallow 지시, 출력 형식, 모델 identity, 옵션과 generation seed는 고정한다. 기존 seed 10개 전체에서 조건당 두 번, 총 40번 관측한다. ABBA와 BAAB를 각각 다섯 블록에 배정하고, 배정과 블록 순서는 별도 schedule seed로 동결한다.

이 선택은 ‘Gemma가 순서를 따라 고른다’는 결론을 전제하지 않는다. 같은 조건의 반복에서도 선택이 달라지는지, 순열 간 차이가 실행 위치나 직전 조건에 따라 바뀌는지를 함께 확인하는 설계다.

## 4. Material Disagreements

**무엇을 먼저 조작할 것인가.** 인과 관점에서는 일정·직전 호출·상태를 분리하는 진단을 우선 후보로 제시했다. 측정 관점에서는 Gemma가 유효한 깊은 규칙을 20회 반복 선택한 점이 더 직접적인 병목이라고 보았다. v058을 한 번 더 순서 반전해도 기존의 안정된 오선택이 왜 생겼는지 구분하기 어렵다는 이유로, 규칙 순열 조작을 먼저 택했다. 상태 초기화와 고정 prelude는 후속 후보로 남긴다. 이 선택이 상태 원인 가설을 기각한다는 뜻은 아니다.

**반복 배치.** ABAB/BABA는 같은 조건의 인접 반복을 피하지만 블록 안에서 늘 반대 조건 뒤에 실행된다. ABBA/BAAB는 AA·BB와 AB·BA 전이를 모두 포함한다. 두 조건의 period와 반복 횟수, 블록 내부에서의 직전 같은·다른 조건 빈도가 대칭이라는 이유로 ABBA/BAAB를 채택했다. 같은 조건의 반복 간격은 1 또는 3이므로, 이를 별도 필드와 집계 축으로 남긴다. 블록 사이의 이력까지 완전 대칭은 아니다.

**인과 표현.** 한 검토 의견은 terminal 위치의 인과를 식별할 수 있다고 표현했으나, 원문 실행표와 다른 관점의 반박을 대조한 뒤 채택하지 않았다. 현재 조작은 두 규칙의 위치를 함께 바꾸며, 연속 실행 이력도 남는다. 관측 가능한 결론은 이 두 배열에서의 출력 민감도다. 캐시·내부 휴리스틱 또는 순수 위치 효과는 미확정이다.

**더 작은 실험.** 20회 AB/BA로도 두 배열의 차이를 관찰할 수 있다. 다만 같은 조건 재관측이 없어 반복 변동과 비교하기 어렵다. 40회를 택한 이유는 유의성을 높이기 위해 표본을 부풀리는 것이 아니라, 같은 조건의 반복 변동이라는 별도 질문을 측정하기 위해서다.

## 7. Required Actions

v059 실행 전에 최종 소스에서 새 계획을 준비한다. 준비 단계는 기준선 전체의 생산 감사와 독립 검산을 요구하며, 반대 과제 순서에서 같은 seed의 choice 요청 바이트가 동일했는지도 확인한다. 실제 모델 identity가 동결 값과 다르거나 transport가 실패하면 즉시 중단한다. 출력 형식·선택 오류는 원문 그대로 기록한다.

결과 해석 때는 조건 간 ID 변화뿐 아니라 조건별 반복 불일치, ABBA/BAAB·period·직전 조건·반복 간격별 분포를 함께 본다. 비교율의 분모와 미측정 수를 공개한다. 실패 seed만 빼거나 일부 호출을 새 문제 표본으로 합산하지 않는다.

## 8. Optional Optimizations

이번에는 적용하지 않는다. ID 재명명, prompt 재작성, 그래프 표현 교정, Qwen의 선택→생성 연결은 각각 다른 원인을 조작하므로 별도 실험으로 분리해야 한다.

## 9. Unresolved

원문만으로 모델 내부 계산, cache의 인과 역할, 실제 사고 깊이를 관찰할 수 없다. v059도 한 문제·한 모델에 대한 사후선정 탐색이다. 위치에 따라 선택이 변해도 다른 문제나 모델로 일반화하지 못하며, 변하지 않아도 모든 위치 효과가 없다는 뜻은 아니다.

생산 계산기와 독립 계산기는 코드가 분리돼 있어도 문제 명세를 공유한다. 두 계산의 일치만으로 명세의 구성타당성이 입증되지는 않는다. 실제 v059 LLM 수행 결과는 소스 제작과 오프라인 시험에서 얻을 수 없다.

## 10. Method / Run Summary

중요도는 MEDIUM으로 분류했다. 독립 초기 검토 3개를 새 컨텍스트에서 시작했고, 측정·구성타당성, 인과·통계, 증거·구현의 실패 기준을 나눴다. `fork_turns:none`으로 서로의 결론을 전달하지 않은 상태에서 초기 발견을 받았다. 이후 C1(후속 조작의 우선순위), C2(인과 주장의 경계와 증거 계약), C3(ABAB 대 ABBA)를 주장 단위로 교차검토했다. 다수결 대신 원문·실행표·계산 결과와 반례를 기준으로 통합했다.

초기 발견 뒤 구현 후보를 제시하고 재검토했으므로 후속 설계 합의는 맹검이 아니다. 보증 수준은 `partially_independent`로 제한한다. 별도의 fresh Judge가 연구 해석을 판정한 것은 아니며, 메인이 통합했다. 원자료 검증에는 독립 계산기를 실제 실행했다. 모델 출력 자체를 증거로 채택하지 않았다.

초기 reviewer 3개는 `gpt-5.6-terra`/`xhigh`, 구현 담당은 `gpt-5.6-sol`/`xhigh`를 생성 인자에 지정했다. 도구 응답은 작업 식별자만 반환했으므로 실제 모델·추론 설정 적용은 `unverified`다. specialty 추가 패널은 만들지 않았다. 소스의 최종 독립 감사와 실행 검증 결과는 [VALIDATION.ko.md](VALIDATION.ko.md)에 별도로 기록한다.
