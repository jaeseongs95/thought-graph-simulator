# v052_adm_02 실제 증거 분석·독립 검증

## 1. 결론

**실행은 440/440 완료됐다. D 단독은 유효 증명 40/40이지만, shallow/deep 요청에 따라 경로 깊이를 바꾼 대응쌍은 0/20이다. 현재 모델·프롬프트·실행 조건에서 D의 선택적 제어는 실패했다.**

이 결론은 증명 성공을 취소한 것이 아니다. 올바른 증명을 생성한 능력과 요청한 축을 조작한 성과를 구분한 결과다. 두 지시 중 한쪽과 맞는 응답 20/40은 문제별 고정 경로가 한쪽 지시와만 일치한 것이며, seed 일부에서 선택적 제어가 성공한 결과가 아니다.

A/D/M 통합에서는 T02에 한정해 유효 기록 35/120, 지정 역할 일치 17/120이 있었다. instance/shallow 조건의 M0↔M1 전환은 7/10 대응쌍에서 성공했다. 이 성과는 인정하지만 A·D의 선택적 제어 및 M2까지의 제어는 확인되지 않았다. K01 통합의 유효 기록과 역할 일치는 모두 0/120이다.

**소프트웨어 결함도 별도로 발견했다. 최종 ID가 실제로 존재하는데, 해당 노드의 논리가 틀렸다는 이유로 ‘참조 실패’로 집계한 진단 오류 117건이다. 이를 교정해도 기존 증명·A/D/M 성공 판정은 바뀌지 않는다.**

## 2. 자료와 검증 방식

요청 기준은 사용자가 제공한 `current_session_full_chat.md`의 원문이다. 관련 원문 위치는 다음과 같다.

- 197~213행: 다각도 제3자 심사 관점으로 결과를 판별하고 토론·합의 후 다음 방향, 프로세스, 구현·테스트 소스를 제공한다.
- 484~519행: 실행기와 정답표의 분리, 원문 보존, 반례 검사, 실제 실행과 합성 서버 시험의 구분.
- 809~839행: seed별 대응 비교, 미실행·전송 오류·모델 오답 구분, 현재 질문에 필요한 변수만 변경.
- 마지막 D 단독 논의: D 단독의 실제 결과를 먼저 보고, 유효 증명만이 아니라 shallow/deep 경로 선택을 판정한다.

이번 심사 관점들은 한 분석 과정 안에서 서로 다른 기준을 적용한 것이다. 외부 심사자나 별도 독립 에이전트를 호출한 결과가 아니다. 기술적 교차검증은 생산 평가기를 import하지 않는 별도 파서·증명 검사·깊이 계산기로 수행했다.

### 검사 대상과 순서

1. 원본 ZIP의 파일 목록·해시, 외부 동결 계획, 실행 상태, 원시 요청·응답, 이벤트 체인, 런타임 모델 identity와 source snapshot을 검사했다.
2. 원래 r2 생산 감사기로 전 보고서를 재생성했고 저장된 summary.json과 전체가 일치했다.
3. 별도 구현 `independent_review.py`로 응답 440개를 재검사했다. 기존 평가기·시험용 정답 생성기·첨부 source_snapshot을 실행하거나 import하지 않았다.
4. 응답별 10개 의미 필드, 총 4,400개 비교는 기존 결과와 일치했다. 최종 참조 진단 필드는 별도로 비교해 117건의 오류를 분리했다.
5. D 단독을 같은 문제·seed의 shallow/deep로 짝지어 재계산했다. 정답 복사 대조군과 통합 역할 실험은 별도 분모로 유지했다.
6. 확인된 코드 결함의 동일 반례를 원본과 수정본에 적용하고 전체 회귀·합성 HTTP 실행·오프라인 재감사를 수행했다. 시험 수와 종료 코드는 `VALIDATION.ko.md`와 원시 로그에 기록한다.

## 3. D 단독: 핵심 결과

|문제|요청|유효 증명|실제 깊이|요청 이행|
|---|---|---:|---|---:|
|K01|shallow: 가능한 최소 깊이 1|10/10|전부 2|0/10|
|K01|deep: 가능한 최대 깊이 2|10/10|전부 2|10/10|
|T02|shallow: 가능한 최소 깊이 1|10/10|전부 1|10/10|
|T02|deep: 가능한 최대 깊이 4|10/10|전부 1|0/10|

K01은 항상 `Ca → Cb → Cc`의 깊이 2 경로를 만들었다. 예시 원문은 `s08_K01_graph_only_instance_shallow_M0`와 `s04_K01_graph_only_instance_deep_M0`다. 노드 ID 표현은 달라도 규칙 경로는 같다.

T02는 항상 초기 사실 `Lp`, `Ls`에서 `r83`으로 `Lg`를 도출하는 깊이 1 경로를 만들었다. 예시 원문은 `s01_T02_graph_only_instance_shallow_M0`와 `s08_T02_graph_only_instance_deep_M0`다. 여러 전제가 있다고 깊이를 합산하지 않는다. 최종 깊이는 `1 + max(부모 깊이)`다.

**대응 비교:** K01 0/10, T02 0/10, 합계 0/20. 각 쌍에서 두 응답은 모두 유효하지만 둘 다 서로 다른 요청을 충족한 쌍이 없다. 쌍별 실제 깊이는 `D_pairs.csv`에 전부 기록했다.

따라서 “A/M과 동시에 요구해서만 D가 실패했다”는 단독 원인 설명은 이번 결과와 맞지 않는다. A/M 요구를 제거해도 실패했다. 반면 두 문제에서 깊이 방향이 서로 다르게 고정됐으므로, “무조건 짧은 경로를 선호했다”는 설명도 관측과 맞지 않는다.

### T02에서 실제로 성공한 범위

T02 통합 120개 중 proof_valid는 91개다. 이 91개는 모두 실제 깊이 1이다. 표현 유효 60개는 모두 instance였으며, 요청한 보편 도식(schema)을 유효하게 만든 성과는 없다. 세부 조건 전체가 유효한 것은 35개이고, 배정된 A/D/M 역할까지 맞은 것은 17개다.

역할 일치 17개는 instance_shallow_M0 10/10, instance_shallow_M1 7/10이다. 이 중 같은 seed에서 M0와 M1의 요청·출력 변화가 함께 맞고 증명 구조를 유지한 7쌍은 **제한된 M의 선택적 제어 성공**이다. A와 D의 대응 전환은 0쌍이다.

이 성과를 “A/D/M이 전부 안 된다”라고 지우지 않는다. 동시에 M 단독 격리 실험이나 M2까지 성공한 것으로 확대하지 않는다. A 단독·M 단독 격리 실험은 이번 증거에 포함되어 있지 않다.

### 정답 복사 대조: 유효 응답 20/20, 완전 복사 0/20

생산 보고서의 `copy_exact`는 K01 0/10, T02 0/10이다. 원문의 reference_record와 응답을 별도로 대조한 결과도 같다. 20건 모두 nodes, final_node_id, reviews는 같았지만 node_views의 universal_schema를 instance로 바꿨다. 그래서 반환 객체는 전체 계약상 유효해도 “값 변경 없이 복사”라는 지시는 이행하지 않았다.

**초기 분석 초안에서 이 20/20 유효성을 완전 복사 성공으로 잘못 읽었다. 생산 코드의 copy_exact는 처음부터 False를 기록하고 있었다. 이 부분은 평가기 결함이 아니라 분석 해석 오류이며, 원문 비교에 맞춰 완전 복사 0/20으로 고쳤다.** 최종 참조 진단 117건의 코드 결함과 혼동하지 않는다.

이것은 보편 도식 실패를 단순히 “도식을 새로 생성하기 어려웠다”로만 설명하기 어렵게 만든다. 정답 도식을 제공했을 때도 표현을 바꿨기 때문이다. 다만 A 단독 격리 실험은 아니므로 A 생성 능력 전체의 부재로 확대하지 않는다.

### 깊은 증명 생성과 깊이 선택 제어도 구분

T02 통합 중립의 `s04_T02_neutral_none`, `s09_T02_neutral_none`는 proof_valid=True, 실제 깊이 4다. 전체 응답은 검토 채널 오류 때문에 유효하지 않지만 긴 증명 자체는 유효했다. 따라서 “이 모델은 T02의 긴 증명 자체를 생성할 능력이 없다”는 설명은 관측과 맞지 않는다. 다른 조건에서 긴 경로가 나왔다는 사실이 D 단독의 deep 지시 이행 성공으로 바뀌는 것도 아니다.

M0↔M1의 7쌍도 별도 증명 구조 서명으로 동일 경로를 유지했는지 확인했다. 복사 비교와 깊은 중립 증명, M 대응 검사 결과는 `additional_raw_checks.json`, `M_pair_verification.json`에 기록했다.

### legacy 오류를 ‘미실행’이나 ‘잘림’으로 바꾸지 않음

58개의 legacy 응답은 정상 HTTP 응답이지만 JSON 객체 내 같은 키가 중복되어 엄격 파서가 거부했다. 마지막 키만 취하는 관대한 재파싱으로 점수를 올리지 않았다. 파싱되지 않은 응답의 증명 의미는 미측정이며, 형식 실패와 구분된다. 나머지 62개 파싱 가능한 legacy 응답은 `final: "Cc"`를 제시했지만 그 이름의 노드 ID가 없었다.

## 5. 발견한 진단 오류와 수정 범위

원본 `adm_diagnostic_v052/measure.py::local_diagnostics`는 논리 검증을 통과한 노드만 `lookup`에 넣고 `final in lookup`으로 최종 참조를 판정한다. 그래서 노드가 존재해도 그 결론이 규칙에 맞지 않으면 “참조 실패”가 된다.

|대상|원본 참조 유효 수|원문에서 ID가 유일하게 존재하는 수|교정|
|---|---:|---:|---:|
|K01 통합|10/120|120/120|110건|
|K01 통합 중립|3/10|10/10|7건|
|합계|13/130|130/130|117건|

새 기준은 다음과 같다.

- 최종 참조 존재: 최종 ID와 일치하는 노드가 정확히 하나인가?
- 증명 유효성: 그 노드까지의 사실·규칙·부모·목표·사용 노드가 논리 계약을 만족하는가?
- 축 조작 성공: 유효한 응답이 배정된 A/D/M 또는 D 방향을 만족하는가?

서로 다른 질문이다. 원문을 보정하거나 최종 ID를 대신 선택하지 않는다. 117건에서 참조 진단만 False→True로 달라지고, 기존 proof_valid/strict_valid/role_match 판정은 그대로다.

동일한 3개 반례(근거 없는 목표 사실, 잘못된 규칙 결론, 누락 부모)를 원본 r2에 적용해 3개 실패를 재현했다. 수정된 진단은 3개 모두 통과하면서 각 응답의 증명 실패를 유지했다. `reference_red.log`와 `reference_green.log`가 그 기록이다.

역사적 결과의 재현을 위해 기존 v047~v052 코어 59개 파일은 바이트 단위로 그대로 둔다. 교정된 진단은 독립 분석과 새 `depth_probe_v053/measure.py`에 구현했다. 따라서 **구버전 v052의 summary.json을 덮어써 교정한 것이 아니다.** 이후 구버전으로 재감사하면 당시 진단이 그대로 재현되며, 이 분석 보고서의 교정표와 구분해 읽는다.

또한 v052 Markdown 요약에는 D 단독의 유효성에 비해 요청 깊이 이행과 대응쌍 성공이 충분히 드러나지 않았다. 새 보고서에서는 실제 깊이 분포, 방향 이행, 선택적 대응쌍을 따로 출력한다.

|연구 설계|A/M 동시 요구가 유일한 실패 원인인가?|아니다. D 단독에서도 실패했다. 다만 통합 부하가 추가로 영향을 주는지까지 배제한 것은 아니다.|
|성과 해석|아무 성과도 없었는가?|아니다. 유효 증명 생성 40/40과 T02 제한적 M 전환 7쌍은 성과다. 복사 대조는 유효 응답 20/20이지만 완전 복사는 0/20이다.|
|이론·구현 대응|이 결과가 이론의 논리 모순을 보여주는가?|논리 모순이 검출된 결과는 아니다. 현재 프롬프트 제어 구현의 경험적 예측은 실패했다. 두 판단을 바꾸어 말하지 않는다.|
|원인 구별|정의가 빠진 것이 원인인가?|기존 지시문에 깊이의 계산식이 없는 것은 확인된다. 그 누락이 실패 원인인지는 대조 실험이 필요하다.|

**합의:** 기존 실패와 제한적 성공은 모두 보존한다. 통합 실험을 바로 확대하거나 큰 모델로 바꾸지 않고, D 단독에서 동일 조건의 원래 지시와 깊이 계산 정의를 명시한 지시를 비교한다. 성공 기준은 유효 증명만이 아니라 실제 방향의 대응 전환이다.

현재 고정된 두 경로는 각각 규칙 목록상 먼저 나오는 가지와도 일치한다. K01에서는 앞쪽 두 규칙이 긴 경로를, T02에서는 첫 규칙이 짧은 경로를 만든다. 따라서 규칙 순서의 영향도 원인 후보다. 다만 순서를 교환한 대응 실행은 없으므로 인과로 확정하지 않는다. v053은 규칙 순서를 보존한 채 정의 명시를 먼저 검사하는 단계이며, 이 실험 하나로 모든 원인 후보를 분리한다고 주장하지 않는다.

## 7. 다음 단계: v053, 120회

기존 문장은 “유효한 경로 중 최종 지지 깊이가 가장 작거나 가장 큰 경로를 선택”하라고만 한다. v053은 다음 정의 문단 하나를 추가하는 조건을 둔다.

> 사실 깊이 0, 규칙 노드 깊이 1+max(부모 깊이), 증명 깊이 d(final_node_id). 전체 노드 수·출력 순번·문장 수·부모 깊이의 합은 깊이가 아니다.

문제별 정답 깊이 1/2/4, 선택할 규칙, 정답 경로는 요청에 제공하지 않는다. 출력 스키마로 특정 깊이를 강제하지 않는다. 이 정의는 계산 규칙이며 모델 대신 증명을 선택하는 코드가 아니다.

2문제 × 2지시 조건(original/defined) × 3방향(shallow/deep/neutral) × 10seed = 120회다. 방향 지정 80회, 중립 40회를 분리한다. 기존 모델·digest·서버 identity·옵션·seed를 그대로 수입하고, 지정 방향 original 40회는 이번 실제 v052의 요청과 바이트 단위로 일치함을 확인했다. defined 60개 요청은 대응 original에서 정의 문단 하나만 다르다.

문제·조건별 10쌍에 대해 두 응답이 모두 유효하고 각각 최소/최대 깊이를 이행했는지를 본다. 중립 응답 하나를 두 역할로 재채점하는 값은 참고 비교이며 호출 수나 독립 표본 수를 늘리지 않는다.

|새 관측|판정|
|---|---|
|original 실패 유지, defined에서 대응 성공|정의 명시 조건의 개선. 길이·주의 효과와 내부 기전까지 분리한 결과는 아님.|
|둘 다 성공|원래 조건도 이번에는 성공. defined의 독점적 효과로 주장하지 않음.|
|둘 다 같은 경로 반복|정의 문단 명시만으로는 D 선택 제어가 해결되지 않음.|
|defined에서 증명 유효성 저하|정의 추가가 출력 과제 부담을 늘렸을 가능성 검토. 성공한 subset만 골라 보고하지 않음.|

지금 구현한 것은 이 한 단계다. A/M 통합 재실험, 더 큰 모델 비교, 학습·hidden layer 개입은 추가하지 않았다.
