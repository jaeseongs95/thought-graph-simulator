# 다각도 검토와 수정 기록

## 실제 발견한 결함

v052 `local_diagnostics`가 유효한 노드만 모은 lookup을 최종 참조 존재 판정에도 사용했다. 원문 K01 통합 110개 및 통합 중립 7개는 최종 ID가 있지만 증명 오류 때문에 참조 실패가 됐다. 독립 원문 재계산으로 총 117개를 확인했다.

기존 코드와 같은 반례 3개(근거 없는 목표 사실, 잘못된 규칙 결론, 누락 부모)를 적용했다. 기존 r2는 ‘존재하는 참조’를 True로 내야 하는 검사를 3개 모두 실패했다. v053의 진단은 3개 모두 통과했다. 두 버전 모두 증명은 실패로 유지했다. 기존 기준을 낮추지 않았다.

새 기준은 ID가 정확히 하나 존재하는지를 직접 검사한다. 파싱되지 않았거나 nodes를 관찰할 수 없으면 None, 없는 ID/형식이 잘못된 ID/중복 ID는 False다. 원문 값은 수정하지 않는다.

기존 59개 코어 파일은 그대로 보존했다. 독립 재분석과 새 모듈에서 진단을 교정한다. 기존 summary 및 v052의 역사적 진단을 덮어쓰지 않는다. 이 교정은 D 단독의 0/20 대응 성공을 바꾸지 않는다.

## 대립한 의견과 채택 기준

|관점|대립|채택|
|---|---|---|
|측정|유효 증명 40/40이면 D 성공 ↔ 방향이 바뀌어야 D 성공|동일 seed의 양방향 이행을 주지표로 사용|
|교정|참조를 자동으로 찾아 고치자 ↔ 원문을 그대로 측정|ID 보정 금지. 진단만 구분|
|연구 진행|더 큰 모델·다른 온도로 바꾸자 ↔ 원인 하나부터 비교|모델·옵션 고정, 정의 문단만 대조|
|원인|정의 누락이 원인 ↔ 규칙 순서나 지시 무시도 가능|정의 누락은 관찰 사실, 인과는 미확인. v053은 정의 추가만 시험|
|복원|기존 파일을 바로 바꾸자 ↔ 기존 증거의 재감사가 달라짐|옛 코어 보존, 새 모듈 추가|
|검증|생산 채점기로 재계산하면 충분 ↔ 같은 버그를 되풀이할 수 있음|별도 파서/그래프/깊이 구현과 오류 주입을 병행|

실제 별도 에이전트를 호출하지 않았다. 다각도 논쟁은 분석상의 심사 관점이고, 기술적 독립성은 생산 채점기를 import하지 않는 별도 코드로 확보했다.

## 구현 후 검사

처음 작성한 신규 시험은 테스트 파일의 여분 괄호를 고친 뒤 54개가 통과했다. 독립 검증기 반례 시험을 추가하면서 실제 schema 함수 이름에 맞게 테스트 import를 바로잡았다. 이 두 작성 오류를 연구 이론의 결함이나 새 측정 결함으로 보고하지 않았다. 추가된 독립 시험은 8개다.

테스트 제목이 목적과 맞도록 ‘사용되지 않은 노드’ 반례는 논리적으로 유효한 초기 사실 노드의 중복 등장(새 ID)을 사용했다. 다른 원인의 오류만 우연히 거부한 결과를 불필요한 노드 검사의 증거로 세지 않기 위해서다.

최종 전체 시험과 배포 후 재검사는 `validation/VALIDATION.ko.md` 및 실행 로그를 따른다. 성공 조건을 만족하는 합성 서버, 항상 같은 경로 서버, 존재하지 않는 최종 ID를 반환하는 서버를 각각 120회 실행하고 원문을 보존했다. 세 자료는 모두 synthetic_fixture로 표시한다.

## 복사 대조 해석의 추가 교정

최종 원문 교차검사에서 초기 분석 초안의 “복사 20/20” 표현을 폐기했다. 실제 값은 유효 응답 20/20, 완전 복사 0/20이다. 모든 응답이 제공된 universal_schema 표현을 instance로 바꿨다. 생산 코드의 copy_exact는 원래부터 이를 False로 기록하고 있었으므로 코드가 아니라 분석의 지표 해석 오류다. 원문 대응 검사 코드는 분석 묶음의 additional_raw_checks.py다. D 대응 0/20과 M 전환 7쌍은 바뀌지 않는다.

## 실제 수정하지 않은 것

목표, 사실, 규칙, 전체 seed, 모델 identity, 온도 및 나머지 옵션, JSON Schema의 허용 필드, 증명의 논리 계약, 미측정/오답 구분, 이전 실제 결과 및 성공률을 수정하지 않았다. A/M 격리와 통합 재실험은 이번 코드에 추가하지 않았다.
