# v049 사전 동결 실험 프로토콜

## 질문과 유지 조건

v048에서 확인한 원식/교환식 차이가 바깥 괄호를 제거해도 유지되는가? 모델을 바꾸거나 A/D/M을 조작하는 실험이 아니다. 목표는 동일한 `a AND NOT b`이다.

v048에서 가져온 모델 tag·digest·show 정보·서버 버전·시스템 지시·출력 schema·temperature와 나머지 옵션을 보존한다. seed는 v048의 10개 전체를 재사용하고, 응답 결과에 따른 선택은 금지한다. prepare는 원문 ZIP을 재감사한다. 보관된 코드 snapshot은 실행하지 않고 함께 배포한 고정 v048 감사기를 사용한다.

## 조건과 계산

| 내부 이름 | 실제 식/경로 |
|---|---|
| original | `(a AND (NOT b))` |
| commuted | `((NOT b) AND a)` |
| original_open | `a AND (NOT b)` |
| commuted_open | `(NOT b) AND a` |
| pipeline | `(NOT b)` → 실제 반환값 → `(a AND b)` |

10 seed × 4입력 × 2반복 = 80 대응 block. 각 block은 네 직접 호출과 실제 pipeline 두 호출이다. 최대 480회 추론, 최종 판단 400건이다. 부모 bool이 없으면 AND 호출만 blocked가 되므로 그 경우 실제 호출 수는 줄어든다. 잘못된 bool을 정상 정답으로 교체하지 않는다.

정상 수집 완료는 모델이 정답이라는 뜻이 아니다. 형식 오류는 실패로 분모에 포함하고, 실제 통신 실패는 자동 재시도 없이 미완료로 남긴다. 미실행 항목을 모델 오답으로 세지 않는다. 다른 모델의 응답은 인프라 정체성 오류다.

## 순서 설계와 반복

5조건에 대해 10개 균형 순서를 명시적으로 구성했다. 매 입력·cycle에서 전체 seed에 걸쳐 각 경로는 각 위치에 2번씩 등장하고, 서로 다른 두 경로의 블록 내부 직전-현재 관계도 각각 2번씩 등장한다. 두 번째 cycle은 같은 seed·입력의 첫 cycle 순서를 역전한다. seed와 순서의 대응, block 순서는 응답을 참조하지 않는 SHA-256 절차로 정한다.

균형은 전체 seed의 경로 단위이다. 각 seed 안의 모든 120순열, 전체 block 경계의 직전 조건, pipeline으로 인해 늘어나는 실제 HTTP 위치를 모두 통제했다는 뜻은 아니다. v048에서는 동일 요청 160종의 여섯 반복 모두 같은 content가 관측됐다. 따라서 이번에는 2회 재현 확인과 표현 확장에 예산을 배분했다. 이를 통계적 검정력 산출이나 독립 표본 증가라고 표현하지 않는다.

## 사전 등록한 판정

각 seed·각 입력의 최종값을 같은 목표 진리표로 비교한다. pipeline의 NOT 정확도, 공급된 값에 대한 AND 정확도, 전체 경로 정확도는 별도로 보고한다.

주요 비교는 `commuted-original`, `commuted_open-original_open`, `original-original_open`, `commuted-commuted_open`이다. 상호작용은 `(commuted-original)-(commuted_open-original_open)`으로 보고한다. 부호와 수치를 사후 바꾸지 않는다. pipeline은 네 직접식 각각과 최종값 정확도·비용을 비교한다. 최선 표현을 사후 골라 점수를 합성하지 않는다.

seed별 기술통계와 입력별 정답을 제공한다. p-value·문제 일반화 신뢰구간은 계산하지 않는다. 미완료시 전체 차이와 상호작용은 null이다. 실패 응답의 비용도 합산하고, missing usage는 0이 아니라 null이다.

## 기록과 보존

외부 계획은 `experiments_v049`에, 결과는 `results_llm`에 별도로 저장한다. 모든 실제 요청/응답 body, event 해시, 실제 부모 response 해시, 실행 코드 snapshot과 실행 전·cycle 경계·실행 후 식별 자료를 보존한다. 새 코드에서는 ZIP에 실제 들어갈 바이트를 임시 고정해 다시 감사한 뒤 묶는다. 기존 v047/v048 소스·계획·결과는 수정하지 않는다.

해시와 외부 계획은 자료 일관성을 확인하며, 전체 파일을 함께 변조하는 공격이나 서버 실행의 외부 전자서명까지 보장하지 않는다.
