# v0.4.5 단일 연산 진단 계약

## 질문

기존 다중 필드 기준 판정에서 남은 오류가, 복사/AND/NOT/AND-NOT를 각각 묻는 조건에서도 남는가?
원문에서 b를 정확히 전달한 것과 최종 응답에 b가 반영된 것은 구분한다.

## 단위와 분모

네 원문 입력의 이전 모델 중간값을 a,b로 투영한다. 연산 네 개 × 입력 네 개 = 새 호출 16회다.
네 입력을 여러 연산에서 사용하는 것은 독립된 16개 문제를 생성한 것이 아니다.
시드 1729 한 개와 원래의 0.7 온도를 유지한다. 가능한 명제 공간이나 모델 출력 분포를 전수 조사한 것이 아니다.

## 출력과 판정

반환 JSON은 `{"value": boolean}` 한 개다. true와 false 모두 허용하며 const/enum으로 정답을 주입하지 않는다.
입력/스키마/원문/종료 원인을 저장한다. 잘림, 중복키, 문자열 true, 설명문, 잘못된 불리언은 자동 복구하지 않는다.
평가용 진리표는 요청과 분리돼 있다. 원래 모델 중간값이 틀렸다면 전체 단계 성공으로 세지 않는다.

## 조립 경로

모델의 COPY(a), AND(a,b), AND(a,NOT(b)) 반환값을 각각 answer_only_accepts,
proof_and_goal_accepts, gap_detected로 일대일 대응한다. 이는 모델이 각각 계산한 값을 복사하는 것이지
호스트가 불리언을 계산해 결과를 만드는 것이 아니다. NOT 단독 응답을 정답 보충에 쓰지 않는다.
완료된 원래 응답을 이 조립값으로 대체하지 않는다. 이전 입력이 재사용된 조건부 진단이며 새 ADM 성공은 아니다.

## 대조

기본은 같은 모델/서버/시드/옵션이다. `--format`은 메시지를 그대로 두고 API format만 바꾼다.
`--comparison-model`은 명시적 별도 체크포인트 비교다. 같은 메시지/생성 옵션을 사용하지만
새 모델의 템플릿/학습/양자화가 함께 달라질 수 있으므로 한 원인으로 환원하지 않는다.

## 결과 판독

필드별 양성 검출, 거짓 양성, 단일 연산 성공을 우선한다. 상수 false가 다수를 맞힐 수 있으므로
평균 성공률이나 다수결로 실행을 승인하지 않는다. 모든 단일 연산을 맞혀도 원래 다중 출력 실패는 남는다.
같은 단일 연산 실패가 남으면 별도 모델/런타임 대조가 필요하다. 현재 기록만으로 NOT 내부회로 고장,
4B 전체의 능력 한계, 메모리 부족, 가중치 손상을 확정하지 않는다.

## 실행 경계

원본 raw 파일 해시와 동결 지문을 검사한다. 결과 스냅샷 코드를 실행하지 않는다.
CRLF/BOM 표현 차이는 허용하지만 실제 텍스트 변경은 차단한다. 과거 결과는 읽기 전용이다.
