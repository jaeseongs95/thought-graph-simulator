# v051 사전 실험 계약

## 연구 질문과 진입 근거

동일한 문제·목표에서 표현 수준 A, 실제 지지 깊이 D, 검토 대상 M의 요청을 바꿀 때 **실제 유효한 출력 기록**에 그 차이가 나타나는가? v050의 성공률은 진입 조건이 아니다. 감사 가능한 실제 v050 자료와 같은 모델 설정은 유지하되, 실패 사실을 보존한 채 조작의 실행 가능성을 검사한다.

이 실험은 A/D/M 본 연구로 돌아가는 첫 LLM 조작 예비실험이다. v050와 동일 작업의 성능 비교가 아니며 일반적인 세 축 독립성을 확증하는 규모도 아니다.

## 고정하는 것

```json
{"id":"K01","facts":["Ca"],"rules":[{"id":"k10","premises":["Ca"],"conclusion":"Cb"},{"id":"k17","premises":["Cb"],"conclusion":"Cc"},{"id":"k03","premises":["Ca"],"conclusion":"Cc"}],"goal":"Cc"}
```

모든 역할에 위 문제·목표·규칙을 같은 바이트로 제시한다. v050의 10개 seed 전부, 모델 digest·모델 정보·Ollama 버전, temperature 0.7 및 나머지 생성 옵션을 유지한다. 모든 역할에 동일한 출력 JSON schema를 적용한다. 대응하는 한 축 비교에서는 해당 역할 지시 한 줄만 달라진다. 요청 좌표를 모델 응답의 정답 라벨로 넣거나 점수로 읽지 않는다.

## 역할 12개

| 축 | 조건 | 외부 기록에서 측정하는 기준 |
|---|---|---|
| A | instance / schema | 모든 노드의 사례 표현 또는 접지·보편 타당성 검사에 통과한 도식 |
| D | shallow / deep | 실제 최종 지지 DAG에서 계산한 깊이 1 / 2 |
| M | 0 / 1 / 2 | 검토 없음 / 최종 증명 검토 / 평가 기준 검토 |

A의 schema는 단순 변수명 치환이 아니다. 각 변수의 실제 원자 대응이 일대일이어야 하고, 사용한 사실·규칙만 가정으로 가져와야 하며, 모든 Boolean 배정에서 가정이 성립하면 결론이 성립해야 한다. 목표를 가정으로 추가하거나 실제 증명과 무관한 전제를 넣으면 거부한다.

D는 사실 깊이0, 도출 깊이=1+max(부모 깊이)이다. 이 고정 규칙에서 직접 Ca→Cc는1, Ca→Cb→Cc는2다. 설명 길이·호출 수·검토 횟수로 D를 측정하지 않는다.

M0은 빈 reviews다. M1은 final을 대상으로 support_replay 하나를 요구한다. M2는 valid_proof_and_goal 기준에 대해 근거 없는 목표 주장(probe: atom=Cc, rule=null, parents=[]) 하나를 검사한다. **M2 조건에서 M1을 먼저 요구하지 않는다.** 이는 기존 연구 명세의 ‘M2가 반드시 M1에 의존하지 않는다’는 구분을 사용한 설계 선택이다. 이전 기본 simulator의 누적 검토 예시와 출력 배열 구성이 동일하다고 주장하지 않는다.

M2의 참인 판정값을 요청·schema에 정답으로 채워 넣지 않는다. 검토 대상의 수준이 맞는 것과 그 판정값이 맞는 것은 별개다.

## 생성과 측정의 분리

LLM은 nodes/final/views/reviews를 생성한다. 호스트는 증명 노드·도식·finding을 만들어 넣지 않는다. 실제 원문을 그대로 보존하며 잘못된 응답도 수정하지 않는다. 자동 재시도와 정답으로의 보완은 없다.

`measure(problem,payload)`는 요청 역할을 인자로 받지 않는다. 실제 증명과 도식을 검사한 뒤 A/D/M 관측을 반환한다. `role_match`는 별도 단계에서 그 관측과 요청을 대조한다. ‘shallow라고 지시했으므로 D=1’ 같은 순환 판정은 없다.

형식, 목표 문자열, 지지 증명, 표현, 검토 대상, finding 정답, 전체 유효성, 역할 부합을 따로 기록한다. 뒤쪽 finding 형식 오류가 있어도 JSON 객체 안에 이미 관측 가능한 정상 증명을 버리지 않는다. 그러나 전체 유효성과 역할 성공에는 정상 형식·증명·표현·검토 정답이 모두 필요하다.

## 규모와 실행 순서

10 seed × 12조건 × 2회 = 240개 슬롯이다. 한 슬롯은 실제 모델 호출1회다. 호출당 최대 토큰 한도는 기존 설정을 유지하므로 실제 출력 길이·토큰·시간은 역할마다 다를 수 있다.

seed별 역할 순서는 고정 해시로 정하고 두 번째 반복은 그 역순을 사용한다. seed 순서도 사전 고정한다. 이 순서는 각 조건의 앞뒤 위치를 완화하려는 선택이며 12조건의 모든 순열을 균형화한 설계가 아니다. 같은 seed의 두 반복을 새 문제로 세지 않는다.

## 비교와 성공 기준

각 seed·반복에서 다른 두 축이 같은 역할쌍을 비교한다. A 대조6종×20=120쌍, D 대조6종×20=120쌍, M의 0↔1·0↔2·1↔2 대조12종×20=240쌍이다. 동일 출력이 여러 대조에 참여하므로 이것을 서로 독립된 표본 수로 세지 않는다.

1. `coordinate_change_observed`: 증명·표현·검토 대상이 유효하고 요청한 축만 실제 관측에서 달라졌는가? finding 정답까지 보장하지 않는다.
2. `clean_requested_axis_change`: 양쪽 전체 기록이 의미상 유효하고 두 요청에 맞으며 다른 두 축은 유지됐는가?

전체 사전 배정 쌍을 분모로 한 값과 양쪽 기록이 유효한 쌍을 분모로 한 값을 함께 남긴다. 성공 조건만 골라 분리 가능성을 주장하지 않는다. 내부 모델 사고의 독립성 검정이나 유의확률을 제공하지 않는다.

`all_requested_roles_succeeded`는 이번 계획의 전 조건 성공 여부를 기술하는 값이다. 자료 무결성과 다르며 논문 전체의 진위 판정도 아니다. 모델이 전부 실패해도 자료 수집·감사가 완료됐다면 오답을 담은 증거 ZIP을 생성한다.

## 자료와 운영 계약

별도 동결 계획·코드 지문·실제 요청 바이트·응답 바이트·모델 식별 정보·event 연결을 검사한다. 표준 출력 CP949/UTF-8 보정은 기존 subprocess 경계에만 있고 실험 JSON은 UTF-8이다. 파일에 남긴 응답 JSON을 고쳐 통과시키는 기능은 없다. 잘린 응답·중복 키·잘못된 모델 응답은 오류로 남긴다. 통신 오류는 모델의 논리 오답과 구분한다.

원문·외부 계획을 ZIP에 넣기 직전 staging 복사본을 다시 감사한다. hash는 파일 일관성 검사이지 외부 실행 서명은 아니다. 모델·서버가 변했으면 기존 조건의 실행으로 통과시키지 않는다.
