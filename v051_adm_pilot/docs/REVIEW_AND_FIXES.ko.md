# 제3자 관점 검토·반례·교정 기록

## 검토 방식

외부 에이전트나 독립 학술 심사자를 호출한 결과가 아니다. 서로 다른 연구·측정·구현·자료 보존 기준을 적용해 대립 주장을 검토했고, 코드로 확인할 수 있는 주장은 실제 반례 시험으로 검사했다. 같은 작성자가 만든 별도 검사기는 구현 경로의 분리이지 완전한 저자 독립성이 아니다.

## 논쟁과 합의

| 관점 | 반론 | 결론 및 반영 |
|---|---|---|
| 연구 질문 | 기준 판정도 실패하는데 A/D/M으로 가면 안 되는가? | A/D/M 조작 질문 자체를 검사할 수 있다. 성공 기준선이라는 전제만 제거한다. |
| 교란 통제 | 역할마다 schema까지 바꾸면 형식 강제가 효과처럼 보일 수 있다. | 모든 역할 공통 schema, 한 축 비교에서는 해당 지시 한 줄만 변경한다. |
| 측정 | 역할 라벨이나 길이로 좌표를 측정할 위험이 있다. | 실제 지지 DAG·접지 도식·검토 대상을 역할 없이 측정한다. |
| 부분 실패 | M2만 실패한 기록의 A/D를 모두 버리면 유효한 관측을 잃는다. | 층별 관측 보존. 단 전체 유효성·역할 성공은 엄격하게 유지한다. |
| 선택 편향 | 유효한 결과끼리만 비교하면 실패 조건이 사라진다. | 전체 배정 분모와 양쪽 유효 분모를 함께 보고한다. |
| 범위 | 한 문제의 예비실험을 범용 축 독립성으로 읽을 수 있다. | 단일 K01·동일 모델·기존 seed라는 범위를 보고서에 고정한다. |
| 비용 | 같은1회 호출이면 계산량도 같은가? | 아니다. 실제 토큰·캐시·로딩·지연을 측정한다. |

## 실제 수정 전 실패

초기 측정 기능 시험33개 및 합성 정상 실행은 통과했지만, 아래 네 반례를 추가하자 세 assertion failure와 한 missing-field error가 발생했다. 파일: `validation/REVIEW_BEFORE_FIX.log`, 종료1.

1. M2 finding에 문자열 bool을 넣으면 앞서 유효한 증명과 A/D까지 사라졌다.
2. 한 노드의 view가 형식 오류일 때 유효한 지지 깊이도 측정되지 않았다.
3. HTTP 응답이 JSON 객체로 파싱되어도 전체 schema 실패 시 부분 자료를 측정기로 전달하지 않았다.
4. 보고서에 구조·대상 조작 지표가 없어 M2 finding 오류가 있는 A/D 대응 관측이 빠졌다.

두 근본 문제가 있었다. 첫째는 전체 형식을 먼저 요구하는 조기 탈락이 앞 단계 관측까지 지우는 구조다. 둘째는 전체 유효 비교만 있고 층별 조작 비교가 없는 보고 계약이다.

## 교정

유효한 JSON 객체는 보존한 뒤 graph/view/review 층별 형식을 검사한다. 객체 형태조차 아닌 값·중복 키·잘린 JSON을 정답으로 복원하는 동작은 없다. `strict_valid`는 여전히 전체 `format_valid`와 증명·표현·검토 의미 검사를 모두 요구한다.

M2 대상이 올바르고 finding만 틀렸을 때 실제 대상 수준 M=2와 A/D 관측을 보존한다. 전체 검토 정답과 전체 기록 성공은 실패다. 보고서에 `coordinate_change_observed`를 추가하고 기존의 더 엄격한 `clean_requested_axis_change`도 유지했다.

같은 네 반례를 수정 후 다시 실행해 4/4 통과했다. 파일: `validation/REVIEW_AFTER_FIX.log`, 종료0. 성공 기준을 완화한 것이 아니라 부분 관측과 전체 성공을 분리한 수정이다.

## 추가 방어 시험

목표 문자열만 맞는 무근거 증명, 순환·전방 참조, 무관한 노드, 규칙/전제 불일치, 목표를 추가 가정으로 넣은 도식, 잘못된 변수 접지, 검토 대상 위조, M2 판정 뒤집기, bool 자리에 int, 역할 정답 라벨 주입을 거부했다.

요청 역할을 무시하고 모든 조건에 같은 유효한 instance/shallow/M0 기록을 내면 전체 의미 유효성은 남지만 역할 일치는20/240에 그친다. 생성 역할명이 측정 결과를 결정하지 않는지 검사한 대조다.

raw 변경 후 일부 hash 재생성, 동결 계획 대신 내부 snapshot 사용, 미등록 응답 파일, 모형 식별 불일치, zip manifest 변경, stale PASS 보고서, 누락 자료를 완결처럼 묶기 등의 무결성 반례도 검사했다.

## 남아 있는 실제 범위

공통 schema도 모델이 그 schema를 따른다는 보장은 아니며 의미상 정답을 제공하지 않는다. 한 문제의 구조화된 출력 실험이다. 스키마 정답·graph 정답과 모델 내부 사고는 동일하지 않다. Windows PowerShell 자체는 이 환경에서 실행하지 못했으므로 Linux/Python 시험 결과와 구분한다. 사용자 Qwen의 실제240회 결과는 사용자가 실행한 뒤에만 나온다.
