# v048 사전 고정 실험 계약

## 연구 질문

v047의 동일 seed 1729에서 관측한 원식 실패·교환식 성공·연결식 성공이, 그 결과를 보고 고르지 않은 새 생성 seed 집합에서도 유지되는가? 조사 대상은 같은 논리식과 네 입력이다. 새로운 표현, 더 큰 모델, 전체 A/D/M 축 조작은 이번 실험에서 추가하지 않는다.

## 보존하는 조건과 바꾸는 조건

v047 원문에 포함된 모델 태그, digest, 모델 정보, Ollama 버전, endpoint, 시스템·사용자 문구, 타입 전용 bool 출력 스키마, non-thinking 방식, temperature 0.7 및 나머지 생성 옵션을 보존한다. 실제 사용자 입력에서 발견된 temperature 값이 0.7이라는 뜻이며, 프로그램이 다른 기준선의 temperature를 몰래 0.7로 고치는 것은 아니다.

새로 바꾸는 생성 조건은 seed다. 실행 순서는 v048에서 미리 동결한 균형 순서로 정한다. 과거 점수와 새 점수를 같은 표본으로 합치지 않고, 새 배치 안에서 세 조건을 함께 비교한다.

| 조건 | 식 또는 실행 | 입력당 최대 호출 |
|---|---|---:|
| original | `(a AND (NOT b))` | 1 |
| commuted | `((NOT b) AND a)` | 1 |
| pipeline | `(NOT b)`의 실제 bool 반환값을 `(a AND b)`에 전달 | 2 |

2차 AND의 `b`는 원래 입력 b가 아니라 실제 NOT 반환값이다. 잘못된 bool도 그대로 전달한다. 유효한 bool이 없으면 해당 AND만 blocked로 기록한다. 정답표와 식 파서는 오프라인 감사 단계에서만 채점에 사용한다.

## Seed 및 순서

기본 새 seed는 다음 10개다.

```text
580410664, 661935755, 209422594, 1790124989, 267101868,
752235971, 1292559482, 223674688, 860724506, 68285180
```

`thought-graph-simulator/v048/seed-expansion/2026-09-11/{index}`의 SHA-256을 정수로 바꿔 `1..2147483647` 범위에 대응시킨다. 발견 seed와 중복은 제외한다. 이 절차는 모델 응답을 읽지 않는다. 이는 고정 실험 집합의 선택 절차이지, 모든 seed 모집단에 대한 엄밀한 확률 표본 설계라고 주장하는 것은 아니다.

각 seed·입력마다 세 경로의 여섯 순열을 한 번씩 쓴다. 여섯 round 각각에 모든 seed와 네 입력을 배치하고, SHA-256 기반 순서 키로 섞는다. 한 seed의 요청 전체를 먼저 실행하고 다음 seed로 넘어가는 구조를 피한다. 경로가 pipeline이면 NOT와 AND는 연속 실행한다.

배정된 판단은 조건당 240개, 세 조건 합계 720개다. 입력·seed·round 대응 블록은 240개이며 호출은 최대 960회다. 960회를 960개의 독립 문제로 해석하지 않는다. 여섯 반복은 실행 순서 통제와 같은 요청의 재현 확인을 위한 비용이다. 이 수는 통계적 검정력 계산으로 산출한 표본 크기가 아니다.

## 분석 기준

주요 대조는 `commuted-original`이다. 직접식 두 조건이 한 번의 호출에서 식 문자열만 다르기 때문에, seed를 확장해 표현 차이가 유지되는지 확인하는 질문에 가장 직접적이다. `pipeline-original`은 연결 구성의 행동을 확인하며, `pipeline-commuted`는 이미 성공한 직접식을 상대해 비교한다.

각 seed의 24개 배정 판단에서 최종 정답률 차이를 계산하고 모든 seed를 표시한다. 전체 정답률과 함께 양성 입력 `(true,false)`, 전체 진리표 4/4 반복, 파이프라인 중간값 포함 성공을 표시한다. 대응 관측 개수와 seed별 승/무/패는 기술통계다. IID p-value나 일반 문제 모집단 신뢰구간은 산출하지 않는다.

`matches_v047_behavior`는 현재 조건에서 원식이 유효한 false만 출력하고, 교환식 최종값과 파이프라인 중간·최종값이 모두 정확한지 나타내는 기술적 패턴 표시다. 이 값이 False라는 것만으로 실험 실패라고 판정하지 않는다. 원식도 성공하거나 일부 seed에서만 차이가 나면, 그 결과 자체를 보존한다.

동일 요청 바이트별 응답의 content 해시와 의미·형식 상태를 집계해 반복 비결정성이 발생했는지 별도로 알린다. 부모값이 달라져 자식 요청이 달라지면 서로 다른 요청으로 분리한다.

## 자료 및 오류

`prepare`는 고정 v047 감사 코드로 원문을 재계산하고 자료 완결성과 비교 가능성을 확인한다. 높은 정답률을 기준선 선택 조건으로 삼지 않는다. 감사 전후의 원문 목록과 바이트 해시를 대조해 수입 도중 변경된 자료를 거부한다. 결과 내부 파일이나 snapshot의 하드링크는 외부 계획으로 표시하지 않는다.

v048 계획에는 baseline, 참조 영수증, seed 목록, 모든 블록, 판정 정책, 소스 fingerprint가 포함된다. 실행 소스와 감사 소스는 함께 스냅샷으로 보존한다. 해시는 파일 간 일관성을 검사할 뿐 실제 서버 실행의 외부 전자서명이 아니다.

추론 전·round 경계·추론 후에 모델 digest·정보·버전을 확인한다. 이 검사는 모든 순간의 내부 실행 상태를 증명하거나 다른 프로세스의 서버 사용을 잠그지는 않는다. 다른 서버 작업을 섞지 않는 실행 환경을 사용한다.

모델이 틀리거나 형식 계약을 어겨도 그 결과를 지우거나 재시도하지 않는다. 통신 오류·다른 모델 응답은 기반시설 오류로 중단한다. 미실행은 null/not_recorded이며 모델 오답과 구분한다. 완료되지 않은 실행에서는 완결 정확도 차이를 산출하지 않는다.

재감사가 실패하면 기존 PASS 요약을 현재의 유효한 결과로 남기지 않는다. `audit.json`, `summary.json`, `summary.ko.md`에 실패를 표시하되 원시 요청·응답·계획·event는 수정하지 않는다. CSV는 원문에서 다시 생성한 파생 자료이므로 최근 `audit.json` 판정과 함께 읽는다.

## 비용

모든 실제 호출의 입력·출력 토큰, 캐시 토큰, 서버 총시간·로딩·입력 처리·출력 처리 시간, 클라이언트 HTTP 시간을 보존한다. 숫자가 누락되거나 잘못된 경우 null로 남기고 알려진 값의 합과 관측 개수를 따로 적는다. 실패 응답의 사용량도 제외하지 않는다.

파이프라인 비용은 두 호출을 합산한다. 전체 호출 합계와 실제로 예정된 호출 수가 기록된 경로의 시간 분포를 분리한다. 후자는 정답인 경로만 고르는 지표가 아니다. 평균·중앙값과 로딩을 함께 표시하며 최초의 긴 요청을 사후 삭제하지 않는다. 서버 총시간에서 로딩을 뺀 값은 명시적인 산술 참고값이고 실제 FLOPs는 아니다. 서로 다른 모델의 동일 토큰 수를 동일 계산량으로 취급하지 않는다.

## 결과 이후

새 seed에서의 유지 여부를 확인하면 표현 일반화 또는 실패가 드러난 표현 요인을 다음 사전 고정 실험으로 넘긴다. 그 뒤 원래 전체 판단 작업에 재통합하고 A/D/M 축별 본 실험으로 복귀한다. 구성요소 검사를 끝없이 늘려 본 가설 검증을 대체하지 않는다.
