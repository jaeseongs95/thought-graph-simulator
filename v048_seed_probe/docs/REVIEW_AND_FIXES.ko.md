# v048: 제작 후 다각도 검토 및 실제 수정

## 종합 판정

**현재 연구 질문의 다음 단계로 다중-seed 대조는 타당하다.** 모델·표현·temperature를 동시에 바꾸지 않고, 성공한 교환식을 대조군에서 유지하며, 과거 발견 seed와 새 검증 seed를 분리하는 방향을 채택했다. 이번 모듈은 A/D/M 본 가설을 입증하는 새 추론 알고리즘이 아니라, 그 실험으로 이어질 seed 확장 실행·감사 도구다.

서로 다른 심사 관점의 상충 주장을 대조하고, 코드 검토·반례 주입·실행 기록으로 판정했다. 별도 외부 심사자나 독립 에이전트를 호출한 것은 아니다. 아래 합의는 가상 심사자들의 다수결이 아니라 실제 기록과 소스에 맞는 설명을 선택한 결과다.

## 1. 연구 설계: 다중 seed인가, 표현 확장인가?

**견해 A:** v047에서 표현 차이가 이미 재현됐으므로 다른 표현으로 바로 넓히는 편이 정보량이 많다.

**견해 B:** 아직 생성 seed는 1729 하나였다. 표현까지 바꾸면 새 결과가 seed 차이 때문인지 표현 차이 때문인지 다시 묻게 된다.

**판정:** 이번 v048은 seed 확장만 담당한다. 같은 세 경로와 같은 네 입력을 유지한다. 새 seed에서도 유지된다면 표현 확장으로 진행하고, 유지되지 않으면 seed별 실패 위치를 먼저 확인한다. 두 의견의 공통 목적은 실험을 끝없이 늘리는 것이 아니라 다음 원인 구분에 필요한 변수를 명확히 하는 데 있다.

## 2. 통계: 960회라는 수를 어떻게 읽을 것인가?

**견해 A:** 여섯 번씩 반복하면 표본 수가 많아져 결론이 강해진다.

**반론:** 같은 seed와 같은 요청에서 동일 응답이 반복되면 이를 독립 문제 표본으로 세는 것은 잘못이다. 10개 seed도 서로 다른 논리 문제 10개가 아니다.

**판정:** seed별 최종 정답률 차이, 양성 조건, 경로 성공을 모두 표시한다. 요청 수준 IID p-value나 일반 문제 모집단 신뢰구간은 만들지 않는다. 여섯 반복은 여섯 순서의 균형 배치와 동일 요청의 실행 재현성을 확인하는 용도다. 기본 10개 seed는 사전 고정한 실험 범위이지 통계적 검정력 계산으로 산출한 수가 아니다.

## 3. 비용: 160회가 아니라 960회가 필요한가?

**견해 A:** 출력이 결정적이면 seed마다 16회만 호출하는 160회 실험이 더 경제적이다.

**견해 B:** 원래 대조는 순서에 따라 달라지지 않는지도 확인했다. 반복을 하나로 줄이면 새 seed들에서 순서 통제의 수준도 함께 바뀐다.

**판정:** 이번 기본값은 기존 여섯 순서 반복을 유지한다. 그 비용을 6배 많은 독립 증거로 포장하지 않는다. 다음 실험에서 순서 효과가 충분히 작다는 자료가 쌓이면 별도 사전 계획에서 반복을 축소할 수 있다. 현재 결과를 본 뒤 유리한 순서만 남기는 방식은 허용하지 않는다.

## 4. 비교의 공정성: 연결식은 무엇과 비교해야 하는가?

**견해 A:** 원식보다 연결식의 정답률이 높으면 분해 효과로 보고하면 된다.

**반론:** 교환식도 한 번의 호출로 성공했다. 약한 원식만 비교하면 연결식의 비용 대비 우위를 과장할 수 있다.

**판정:** 주요 대조는 `commuted-original`로 두고 `pipeline-original`, `pipeline-commuted`를 함께 표시한다. 직접 경로는 최종값끼리 비교하며 파이프라인 중간값 포함 성공은 별도로 보고한다. 연결식이 정확하다는 것과 최선의 직접식보다 더 경제적이라는 것은 다른 주장이다.

## 5. 구현: 기존 v047에 `--seeds`만 넣으면 되는가?

**견해 A:** 기존 모듈에도 다중 seed 인자가 있으므로 새 모듈이 필요하지 않다.

**견해 B:** 단순 다중 seed 실행은 가능하지만, 직전 v047의 감사된 원문 수입, seed 간 시간 순서 편중 완화, 좋은 직접식과의 비교, seed별 현상 표시, 로딩·캐시를 분리한 비용 보고가 필요하다.

**판정:** 요청 생성과 primitive 계약은 바꾸지 않고, 다음 단계의 계획·수집·보고·감사를 보강한다. 실제 사용자 v047 자료에서 v048 요청 생성 결과를 고정 v047 생성기와 1,200가지 슬롯/부모값 조합으로 대조해 바이트가 같음을 확인했다. 원문 입력 파일은 변경하지 않았다.

## 6. 실행 실패를 모델 실패로 세어도 되는가?

**견해 A:** 답을 얻지 못하면 모두 오답으로 세면 단순하다.

**반론:** 모델이 잘못된 JSON을 낸 경우와 서버에 연결하지 못한 경우, 다른 모델이 응답한 경우, 아직 호출하지 않은 경우는 같은 관측이 아니다.

**판정:** 모델 오답/형식 오류는 배정 분모에 포함한다. 유효한 부모 bool이 없으면 자식 호출을 blocked로 남긴다. 통신 오류·다른 모델 응답은 실행 오류로 중단한다. 미실행은 null/not_recorded이며 완결 비교값을 산출하지 않는다. 실패 실행을 지우거나 자동 재시도해서 성공 실행으로 바꾸지 않는다.

## 7. 제작 후 반례 검토에서 실제 발견한 다섯 문제

최초 기능 구현은 신규 66개 시험을 통과했다. 이후 아래 다섯 회귀 시험을 추가하자 수정 전에는 다섯 개 모두 실패했다. 해당 코드를 수정한 뒤 같은 다섯 시험이 모두 통과했고 전체 시험도 다시 실행했다.

| 실제 발견 | 수정 전 재현 | 수정 | 근거 시험 |
|---|---|---|---|
| 실패한 재감사 뒤에도 과거 PASS 요약이 남음 | 응답 원문을 바꾸면 감사는 예외로 중단했지만 기존 `audit.json`의 True가 유지됨 | 재감사 실패 시 파생 요약 3개를 명시적 실패로 갱신. 원시 증거는 유지 | `test_reaudit_failure_replaces_previous_pass_reports` |
| 결과 폴더 안의 다른 이름 파일이 외부 계획으로 인정됨 | snapshot 복사본을 결과 내부에 다른 이름으로 두면 수입됨 | 외부 계획은 결과 폴더 바깥의 실제 경로여야 함 | `test_internal_plan_alias_not_external_anchor` |
| snapshot의 하드링크가 외부 계획으로 인정됨 | 경로는 달라도 같은 파일인데 통과함 | `samefile`로 동일 파일/하드링크를 거부 | `test_hardlinked_snapshot_not_external_anchor` |
| v048 감사에 자체 snapshot을 외부 계획으로 줄 수 있음 | 결과가 보유한 계획으로 스스로를 감사하면서 외부 대조처럼 읽힐 수 있음 | v048 감사도 별도 외부 계획을 요구 | `test_v048_audit_cannot_use_own_snapshot_as_external` |
| 기준선 감사 직후 원문이 바뀌어도 수입됨 | 감사 반환 직후 응답 파일을 변경하면 변경된 파일의 해시로 참조 영수증이 만들어짐 | 수입 전후 전체 입력 증거와 외부 계획 바이트를 비교해 변경 시 거부 | `test_reference_changed_during_audit_is_rejected` |

이 문제들은 과거 v047의 모델 점수를 바꾸는 근거가 아니다. 새 소스의 실패 처리·자료 고정 경로에서 재현한 문제이며 해당 경로를 수정했다.

수정 전 로그: `validation/REVIEW_BEFORE_FIX.log`.
수정 후 같은 다섯 시험: `validation/REVIEW_AFTER_FIX.log`.
최종 전체 시험: `validation/SELFTEST.log`.

## 8. 최종 합의

현재 범위에서는 배포 가능한 다음 단계 실험 도구로 판단한다. 실제 사용자 모델의 새로운 성공률은 사용자가 `run`을 실행한 뒤에만 생긴다. 이번 작업에서 확보한 근거는 소스 실행·합성 HTTP·원문 재감사·반례 검사 결과다.

최종 합의는 다음 세 문장으로 정리된다.

**이번에는 seed만 확장한다. 성공한 교환식도 계속 상대한다. 새 관측을 확보하면 표현 검증과 원래 전체 판단 작업·A/D/M 본 실험으로 돌아간다.**
