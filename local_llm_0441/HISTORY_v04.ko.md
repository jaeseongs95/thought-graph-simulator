# v0.3 → v0.4 수정 내역

기존 검증기와 원문 응답을 고치지 않고 실행 전제와 진단을 수정했다.

| 이전 분석에서 확인한 문제 | 소스 변경 | 확인 방법 |
| --- | --- | --- |
| `qwen3:4b` 별칭의 실제 Thinking-2507 정체를 보지 못함 | `model_policy.py`의 GGUF 기반 식별, 모드 일치 검사 | 실제 v0.3 메타데이터 픽스처, 모순/미확인 식별 시험 |
| `think:false`를 정상 전제로 고정 | Instruct 기본 모델, 모드 자동 해석, 불일치 거부 | Mock 호출 전에 중단하는 시험; 실제 LLM 미호출 |
| Thinking 응답의 최종 출력/사고 분리 확인 누락 | 채널 검사, `mode_error`, 토큰 한도 종료 별도 분류 | 사고 영역의 JSON을 정답으로 사용하지 않는 시험 |
| A/D/M 결합 예시 | `prompts_v4.py`의 구성요소별 설명과 예시 제거 대조 | 모든 역할의 공통 스키마/예산, 예시 차이 대조 |
| 예시와 비슷한 소수 문제 | `datasets_v4.py` 추가 구조 3개, 기존 `--suite legacy` 보존 | 깊이 집합, 전체 역할 구성 가능성 시험 |
| 검토 정답이 같은 패턴 | 별도 기준 판정 6회/정답 패턴 3종, 본 M2 한계 명시 | 패턴 분포 및 실제값/기대값 별도 검사 |
| 누적 도식 작성 부담과 의미 오류 혼합 | 같은 고정 증명의 전체/최종 노드 도식 쌍 | 범위 위반 거부, 결론을 사실로 조작한 도식 거부 |
| 평가 불가가 불일치로 집계됨 | `audit.py` 삼중값, `report.py` 분모 분리 | 기존 39건 판정 유지, 지시 조건 중 평가 불가 5건씩 분리 |
| 완료와 성능 성공 혼합 가능성 | `execution_completed`의 모드/통신/중단 실패 분리 | Mock 정상 완료/역할 실패/모드 중단 시험 |

구 출력 프로토콜과 과거 응답 재검사는 유지한다. 기존 원문 39건의 accepted 12, role_mismatch 14, invalid_trace 13은 바꾸지 않았다. 과거 실행 폴더를 새로운 기본 조건의 준비 증거로 재사용하지 않는다.

과거 단위시험의 Mock 모델 응답에는 새 필수 GGUF 메타데이터를 추가했다. 실제 과거 응답 픽스처·원문 요청 바이트·원래 성공/실패 기대값은 바꾸지 않았다. 새 하네스에서도 과거 형식으로 `run()`을 직접 호출하면 실제 추론 전에 모드 정책을 검사한다.
