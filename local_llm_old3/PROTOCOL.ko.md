# 실험 프로토콜 — v0.3.0

## 연구 질문과 측정 대상

동일한 사실·규칙·고정 목표에서 모델에 요청한 A/D/M 조건이 제출된 형식 증명 기록의 표현, 지지 깊이, 검토 대상에 대응하는지 측정한다.

A는 instance와 universal_schema의 표현 차이, D는 사실을 0으로 하고 규칙을 1+max(부모 D)로 재계산한 최종 지지 깊이, M은 검토 없음/M1 논증 검토/M2 논증과 수락 기준 검토다. 사용자의 폭넓은 이론을 이 작은 과제 전체와 동일시하지 않는다. 내부 hidden layer 조작이나 그 변화의 직접 측정은 이 런타임에 없다.

## 생성과 검증의 경계

모델이 제출할 노드·지지 참조·표현·검토를 생성한다. 호스트가 계산한 참조 깊이는 평가에만 사용하고 프롬프트에 전달하지 않는다. 호스트가 목표 경로를 선택하거나 틀린 부모·도식·검토를 보완하지 않는다.

기존 `adm_minimal.py`의 검증과 전체 증명의 지지 연결성 조건을 유지한다. 모델이 선택한 최종 노드와 무관한 노드를 남기면 전체 증명은 실패다. 선택 연결부 깊이를 별도로 관측하더라도 노드를 삭제하여 성공으로 승격하지 않는다.

분리 진단에서 호스트가 제공한 고정 증명, 진단용 instance view, 빈 reviews는 A/M 생성 성과로 세지 않는다. 손상된 증명·단독 probe에 대한 정답은 평가기가 계산하고 실제 출력과 비교한다.

## 게이트의 의미

기본 readiness 게이트는 실험 기록이 완결되어 있는지, 요청 원문이 재생성된 조건과 일치하는지, 정상 API 종료인지, 모델/소스/검증기 결합에 문제가 없는지 확인한다. `role_mismatch`, `invalid_trace`, 정상 API 안에서의 출력 계약 실패는 연구 관측으로 남긴다. 이 때문에 통과했다고 모델 성능이 PASS인 것은 아니다.

strict는 모든 응답의 성능 성공까지 요구하는 별도 선택이다. strict 결과로 선택된 실행만 일반적인 모델 성능처럼 해석하지 않는다.

v0.2 이관은 배포 당시의 런타임 15개 파일 해시가 승인 목록과 같고, 재구성한 HTTP 요청 바이트가 동일하며, 같은 모델·설정·문제·시드일 때만 허용한다. 스냅샷 Python을 동적으로 실행하지 않는다. 모델 digest와 서버 버전은 실제 실행 직전에 재조회한다. 내부 파일 해시는 일관성/변경 탐지 수단이며 외부 서명 기반 진본 증명은 아니다.

## 실험 조건

기본 `legacy-v2`는 이전 v0.2 요청 원문을 유지한다. `explicit-v3`는 새 프롬프트 조건이며 기본값이 아니다. 두 프로필 모두 같은 출력 JSON 스키마, 검증기, 참조 깊이, 모델·기본 생성 예산을 사용한다. 각 프로필의 모든 A/D/M 역할이 공유하는 예시는 같다.

프로필 간 차이는 프롬프트 묶음의 효과에 대한 탐색 비교다. 여러 설명이 동시에 바뀌므로 개선이 관측되어도 마지막 예시 위치나 어느 한 문구의 단독 효과라고 주장하지 않는다. 기본 과제와 예시는 작은 Horn 명제 구조가 유사하므로 임의 문제로의 일반화를 입증하지 않는다.

기본 pilot은 3문제×13조건=39회이고, full은 같은 구성을 세 시드로 반복하여 117회다. 같은 문제 반복을 새로운 독립 문제로 세지 않는다. 기존 smoke와 pilot의 중복 조건을 독립 표본처럼 합산하지 않는다.

## 집계

유효한 전체 제출물, 요청 전체 역할 준수, 각 축의 일치, 엄격 대조, 기술적 실행 완료를 구분한다. 실패·중단·미기록은 각 배정 분모에 남긴다. M 검토 문구가 존재하는 것과 실제 검토 판정이 맞는 것도 별개다.

`descriptive_contrasts`는 양쪽 전체 제출물이 유효한 경우 실제 관측 좌표가 어떻게 변했는지를 보여준다. 요청한 나머지 축의 절대값에 실패하더라도 실제 다른 축들이 같게 관측된 상태의 변화를 기록할 수 있다. 이는 엄격 대조 성공을 늘리지 않는다.

토큰·시간에는 실패 호출과 캐시·서버 상태 차이가 포함될 수 있다. 출력 과제량이 다른 조건을 단순 효율 개선으로 읽지 않는다. `/api/ps`의 size_vram은 조회 시점의 적재 정보이며 GPU 최고 메모리·이용률의 직접 측정이 아니다.

## 현재 확인된 결과의 범위

사용자가 실행한 v0.2 분리 진단 8건과 smoke 6건의 원문 판정을 재현했다. 수정된 게이트가 기존 smoke를 실행 준비 완료로 받아들이되 5건의 실패를 그대로 유지함을 오프라인 재검사했다. 새 모델 추론, 새 39조건, explicit-v3의 실제 정확도와 Windows 실행은 여기서 수행하지 않았다.
