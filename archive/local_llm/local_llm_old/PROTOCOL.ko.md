# 실험 계약 — 로컬 LLM 고정 목표 역할 수행

## 1. 기준과 범위

기준 저장소 커밋은 `254757486a987475d16541cf84b905d684c1c13d`다. `adm_minimal.py`, `README.md`, `examples/problems.json`, `docs/research_note.md`의 관련 정의·계약, `supplement/experiment_manifest.json`의 후속 연구 범위를 확인했다. 대화에서 확정된 고정 목표·역할극·A/D/M 정의와 저장소 연구자료를 교차 확인해 이번 확장을 작성했다. 논문 PDF 전체를 새로 심사하거나 다른 세션 원문 전체를 추출한 작업은 아니다.

이번 단계의 연구 질문은 다음과 같다.

> 동일한 사실·규칙·고정 목표 아래, 소형 로컬 LLM이 지정한 표현 방식 A, 지지 깊이 정책 D, 검토 대상 M을 갖는 유효 기록을 직접 작성할 수 있는가?

기존 결정론적 시험 결과를 실제 LLM 증거로 재사용하지 않는다. 이번 소스의 논리·테스트·실험은 배포 작성 시 실행되지 않았다. 원래 논문의 v1.0 또는 기존 연구자료 R0.1을 변경하지 않으며, 확장 소스 버전만 0.1.0이다.

## 2. 무엇을 모델이 만들고 무엇을 코드가 붙이는가

모델은 모든 증명 노드, 원자, 규칙 id, 부모 id, 표현 view, 최종 노드 id, 검토 레코드와 판정값을 작성한다. 코드는 원문 문제의 id·SHA-256·trace 형식 버전을 붙이고, 각 노드 내부의 `view`를 기존 검증기가 받는 별도 `views` 사전으로 옮긴다.

이 변환은 문제의 정답 경로를 찾거나 모델의 누락을 메우지 않는다. 모델이 내지 않은 표현이나 검토 레코드를 만들지 않는다. 문제 해시는 실험 호스트가 주어진 원문으로 계산한다. 모델이 SHA-256 문자열을 추측하게 하는 별개의 과제를 섞지 않기 위해서다.

전송 규격은 `protocol.TRANSPORT_SCHEMA`에 있다. 모든 조건에서 동일한 스키마를 사용하며 양쪽 A 표현, M0/M1/M2 레코드 형식을 모두 허용한다. 특정 역할의 정답 표현·깊이·판정값을 조건별 문법으로 고정하지 않는다. 따라서 문법 강제만으로 역할 준수를 만들어 내지 않는다.

## 3. A/D/M 조작과 관측

### A

역할은 모든 증명 노드에 `instance` 또는 `universal_schema` 표현을 요구한다. 관측 A는 검증된 최종 표현이고, 역할 준수는 모든 노드의 표현 종류까지 확인한다.

도식의 변수 바인딩은 해당 결론의 실제 지지 부분 그래프에서 사용한 원자와 일대일 대응해야 한다. 사용 사실과 규칙을 빠짐없이, 추가 없이, 중복 없이 가정으로 표현해야 한다. 기존 검증기는 모든 불리언 배정을 열거하여 도식의 타당성을 확인한다. A0~A4 세부 코드북을 새로 정의하지 않는다.

### D

D는 주어진 사실 0, 규칙 적용 `1 + max(부모 D)`다. 노드 수, 출력 길이, 모델의 thinking 토큰 수와 다르다.

역할 정책은 허용된 증명 중 최종 깊이 최소(`shallow`) 또는 최대(`deep`)다. 참조 깊이는 고정된 원문 규칙으로 별도 계산하며 모델 프롬프트에는 넣지 않는다. 참조 계산은 기존 `simulate()`나 `_plans()`를 호출하지 않는다.

최대 깊이가 무한히 부풀려지는 것을 막고 기존 생성기의 탐색 범위를 유지하기 위해, 한 부모 연결 경로에서 같은 원자를 다시 방문하지 않는 **단순 지지 경로**로 한정한다. 주어진 사실은 사실 노드에서 종결한다. 이는 LLM의 모든 추론에 관한 이론적 제약이 아니라 이번 최대 깊이 비교의 실험 규약이다.

기존 `verify()`는 노드 수준의 DAG를 검사하지만 같은 원자를 여러 번 도출한 DAG 자체는 수락할 수 있다. 따라서 `baseline_trace_valid`와 추가 규약을 포함한 `valid_completion`을 분리했다. 기존 검증기를 수정한 것처럼 표시하지 않는다.

### M

M0: 검토 없음. M1: 최종 증명의 지지 재검사 한 개. M2: 최종 증명의 지지 재검사 후, 목표를 단독 사실로 주장하는 probe를 사용한 수락 기준 검사 한 개.

M2 역할에 M1을 함께 요구한 것은 기존 기본 시나리오를 따른 실험 조건이다. M2의 일반 정의상 M1이 필수라는 주장으로 확장하지 않는다.

`M_target_observed`는 출력이 실제로 어떤 대상 종류를 지정했는지 나타낸다. M2라고 적은 레코드라도 판정이 틀리면 검토·전체 유효성은 실패한다. 대상 수준과 수행 정오를 구분한다. 검토 참조를 증명 지지 간선에 합쳐 D를 늘리지 않는다.

## 4. 판정의 순서

먼저 API가 요청 모델의 완료 응답인지 검사한다. `done_reason=length`라면 JSON이 닫혀 있어도 출력 한도 실패로 남긴다. 그다음 엄격한 JSON과 전송 스키마를 검사한다. 중복 키, 비표준 숫자, 코드 블록, 추가 좌표 필드, 누락된 view 등을 보정하지 않는다.

정상 전송이면 기존 `verify(problem, trace)`로 원본 전체를 검사한다. 진단용으로만 별도 사본에서 다음을 구분한다.

| 진단 | 사본에서 바꾸는 부분 | 알아보려는 것 |
| --- | --- | --- |
| proof_only_diagnostic | view를 사례 표현으로 두고 검토 제거 | 증명 지지 자체의 유효성 |
| representation_diagnostic | 검토만 제거 | 증명·표현의 유효성 |
| review_diagnostic | view만 사례 표현으로 바꿈 | 증명·검토의 유효성 |

**진단 사본은 원문 trace나 원본 전체 검사 결과를 대체하지 않는다.** 원본 전체 검사 실패를 진단 통과로 뒤집지 않는다. 원본 전체 유효성과 단순 지지 경로 규약을 통과해야 `valid_completion=true`다. 여기에 요청한 A, 깊이 극값, M 시나리오를 모두 맞춰야 `role_adherent=true`다.

주어진 목표 문자열과 최종 노드 원자가 같다는 `fixed_goal_match`는 별도 진단값이다. 이것만으로 성공 처리하지 않는다.

## 5. 축별 대조

A 대조는 같은 문제·시드·D 정책·M에서 A만 바꾼다. 양쪽이 유효하고 역할을 따르며 관측 D·M이 같아야 통과한다.

D 대조는 같은 문제·시드·A·M에서 D 정책만 바꾼다. 양쪽이 유효하고 역할을 따르며 실제 깊이가 증가하고 관측 A·M이 같아야 통과한다.

M 대조는 같은 문제·시드·A·D 정책에서 M0→M1, M1→M2를 각각 비교한다. 양쪽이 유효하고 역할을 따르며 관측 A·D가 같아야 통과한다.

지지 그래프의 직렬화 해시가 같은지도 보조로 기록한다. id·순서까지 같은지 보는 값이므로 의미상 동형 그래프 판정과 동일하지 않다. 기존 R0.1과 마찬가지로 주된 대조 게이트는 관측 좌표를 기준으로 한다.

미실행·실패한 쌍도 계획된 대조의 분모에 남는다. 하나라도 실패했다고 논문의 모든 가설이 반박되었다고 결론내리지 않고, 이 과제·모델·프롬프트·예산 조건에서 무엇이 실패했는지 기록한다.

## 6. 반례와 신뢰 경계

유효한 원본 trace에 잘못된 문제 결합, 자기 순환, 없는 규칙, 중복 노드, view 누락, 좌표 주입, 근거 없는 고정 목표 등을 적용한다. 해당되는 경우 도식 가정 제거와 검토 판정 뒤집기도 적용한다.

반례는 검증기 점검용이다. 모델이 반례를 발견했다고 집계하지 않는다. 목표가 이미 주어진 사실이면 ‘목표를 사실이라고 주장’하는 변조는 반례가 아니므로 적용 불가로 기록한다. 반례가 수락되면 하네스 오류로 중단한다.

파일 해시는 실행 자료의 변경·누락 탐지와 재현성 결합에 사용한다. 실행 환경을 악의적으로 통제하는 사람이 모든 파일과 해시를 다시 만들 수 없는 외부 서명·공증 체계를 구현한 것은 아니다. 모델 출력 자체에는 파일 변경이나 도구 호출 권한을 주지 않는다.

로컬 클라이언트는 숫자 루프백 주소 또는 정규화된 localhost만 허용한다. 프록시 환경변수를 사용하지 않고 HTTP 리다이렉트를 거부한다. 클라우드 모델 이름과 공개 메타데이터의 원격 모델 표시를 거부한다. 별도 제공한 서버 스크립트는 Ollama의 클라우드 기능도 비활성화한다. 이 프로그램이 로컬만 호출한다는 사실을 운영체제 전체의 모든 통신이 차단된다는 보장으로 확장하지 않는다.

## 7. 예산, 재현성, 중단

각 조건은 모델 호출 한 번이다. 자동 재시도·JSON 수리·검증 피드백·답안 재생성을 하지 않는다. 기본 조건 간 모델·스키마·문맥 길이·최대 출력·샘플링 설정을 맞춘다. 조건 지시와 출력량이 다르므로 실제 소비 토큰까지 같아진다는 뜻은 아니다.

모델 이름만이 아니라 설치된 digest, 양자화 정보, 템플릿·메타데이터 해시, Ollama/Python/운영체제·GPU 드라이버 정보, 프롬프트를 포함한 확장 소스 해시, 기존 검증기 해시, 원문 문제와 조건표를 저장한다. seed를 맞춘 것이 GPU 연산의 비트 단위 재현성을 보장한다고 표시하지 않는다.

미수신 토큰 비용은 미확인으로 남긴다. API의 토큰·캐시·duration 필드는 지원되는 범위에서 원문 그대로 보존한다. duration의 단위는 나노초이므로 초로 환산한다. 생성 토큰/초는 `eval_count / eval_duration`에서 계산하며 전체 요청 지연과 구분한다. 최초 로딩 시간과 캐시 히트도 별도로 남긴다. [S5–S7]

통신 실패 뒤에는 다음 추론을 즉시 보내지 않는다. 요청만 보존된 중단 조건을 `--resume`에서 재시도하지 않으며, 이미 보존된 응답만 재판정한다. 소켓 타임아웃은 엄밀한 전체 실행 시간 상한이나 서버 계산 취소를 보장하지 않는다.

## 8. 결과의 의미

성공하면 ‘이 로컬 모델이 이 형식 과제에서 지시한 A/D/M 조작을 유효 기록으로 구현했다’는 관측이 된다. 실패하면 전송 형식, 증명, 도식, 검토, 역할 극값 가운데 실패 층위를 확인할 수 있다.

이 결과만으로 모델의 내부 사고가 본질적으로 세 축으로 이루어져 있다는 결론, 모든 모델에서의 축 독립성, 파인튜닝 불필요, 연산량 감소, TTS 기반 라우팅의 효과를 선언하지 않는다. 그 대신 지금까지의 결정론적 명세 검증에서 **실제 모델 출력에 대한 검증**으로 연구 단계를 옮긴다.
