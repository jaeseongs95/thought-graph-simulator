# v0.3.0 변경사항

## 바뀐 부분

기본 게이트를 readiness로 분리했다. 기록·소스·모델·요청 조건이 정상이고 API가 완료되었으면 모델의 의미/역할 실패를 남긴 채 다음 실험으로 진행한다. strict 성능 게이트는 명시적으로 선택할 수 있다.

고정된 v0.2 배포 소스와 요청 바이트가 일치하는 기존 smoke의 이관을 지원한다. 이관은 임의의 변경 소스를 허용하는 옵션이 아니며, 모델/서버 버전은 실제 실행 전 다시 비교한다.

calibration 콘솔의 결합 불리언을 모델의 실제값처럼 읽기 어렵도록 `actual / expected / matches`를 분리했다. 선택 연결부 깊이와 무관한 노드 목록을 진단으로 추가했다.

축별 일치와 기술적 실행 완료를 전체 역할 성공에서 분리하고, 엄격 대조를 대체하지 않는 관측 대조를 추가했다. 기본 종료 코드 0은 완료를 뜻하며 성능 실패를 PASS로 바꾸지 않는다.

선택형 explicit-v3 프롬프트 프로필을 추가했다. 기본값이 아니며 모델 실행으로 개선을 확인한 프로필도 아니다.

## 바꾸지 않은 부분

기본 legacy-v2 프롬프트의 요청 바이트, 모델, 샘플링 설정, 출력 JSON 스키마, 기존 core 검증기, D 목표 계산, 역할 판정과 성공 기준을 유지했다. 노드 가지치기, 거짓 검토 수정, 정답 경로 제공, 실패 조건 자동 재시도는 추가하지 않았다.
