# v0.4.5 변경 내역

## 이번 자료가 보여 준 것

v0.4.4.1 factor 결과 16건의 기존 판정은 12 accepted / 4 invalid_task다. `b_last`의 핵심 행은
T,F,F이고 나머지 세 군은 T,T,F다. 정답은 T,F,T다. 그러므로 전체 성공 수만 같은 것이며
실패 내용까지 동일한 것은 아니다. `b_last`는 엄격 수락 오류를 없앴지만 gap 오류를 남겼다.

## 수정·추가

1. `decision_table.py`: 필드별 TP/FN/TN/FP, gap 양성 검출, 최종 필드의 자기 모순을 분리한다.
   기존 Markdown 표 중간에 주석 문단을 넣어 뒤의 행들이 표 밖으로 나가던 출력 결함도 수정한다.
2. `factor_audit.py`: 검토한 v0.4.4.1의 36개 소스 지문, core 스냅샷 raw 해시, 요청 wire,
   모든 16개 원문과 기존 판정을 다시 검사한다. 저장된 코드를 실행하지 않고 현재 배포 코드로 대조한다.
3. `operator_probe.py`: COPY/AND/NOT/AND-NOT 각각을 단일 출력으로 요청한다. 이전 모델이 낸
   중간값을 그대로 투영한다. 세 반환값의 조립은 값 복사만 하며, 코드가 정답으로 고치지 않는다.
4. `common.py`: 식별정보가 아예 없는 두 객체를 `None == None`으로 동일하다고 판단하던
   방어 결함을 수정한다. 이 결함은 합성 입력으로 확인했고 이번 사용자 실행에는 발생하지 않았다.
5. `runner.py`, `report.py`, `task_evidence.py`: 새 과제를 명시적 계약으로 처리하고
   원문/형식/의미/모델 메타데이터/과제 성공을 분리해 저장한다.

## 그대로 둔 것

- `adm_minimal.py`의 정답·검증 계약.
- 기존 factor/decision/micro 요청과 실제 판정값.
- 실패 응답의 보존, 실패 후 성공할 때까지 재시도하지 않는 정책.
- Windows CRLF/LF/BOM의 제한된 정규화 비교. 스냅샷 자체는 raw 해시로 확인한다.
- 기존 모델 및 생성 옵션. 비교 모델 선택은 명시한 경우만 허용한다.

## 해석 경계

새 단일 연산 과제는 문맥과 필드 수/입력 표현도 바뀐다. 성공하더라도 순수하게 호출 분리만의
인과효과라고 말하지 않는다. 일반 모델 능력이나 ADM 이론의 성공을 증명하는 시험도 아니다.
이번 수정이 실제 모델 정답률을 개선했다는 측정 결과는 아직 없다.
