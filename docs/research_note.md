# 고정 결과 기반 A/D/M 역할극 최소 실험계

## 대화 분석·연구 명세·구현·검증 결과

**연구자료 버전:** R0.1  
**작성 기준일:** 2026년 9월 10일  
**연구 방향 및 핵심 실험 아이디어:** 송재성  
**대화 분석·세부 명세·코드 작성 및 실행:** AI 보조 작업  
**구현 범위:** LLM 없는 결정론적 역할극, 구조화된 기록, 별도 재검사, 반례 시험

이 자료의 버전은 연구자료·실험 코드의 버전이다. 기존 논문의 버전을 변경하거나 그 논문 전체가 검증되었다고 선언하는 자료가 아니다.

## 1. 연구 목적과 현재 결론

이 채팅의 목적은 논문의 A/D/M 사고 상태 모델을 곧바로 대규모 모델 학습이나 정답률 경쟁으로 확장하는 것이 아니다. 사용자가 제안한 핵심은 **문제와 결과를 고정한 상태에서 서로 다른 사고 역할을 실행하여, 표현 수준·지지 의존 깊이·검토 대상의 차이를 구성하고 검사할 수 있는 최소 실험계를 먼저 만드는 것**이다. LLM을 연결한 실험은 이 실험계의 동작을 확인한 다음 단계로 명시적으로 분리했다. [U2, U3, U5–U7]

이번 산출물은 그 목적을 다음과 같이 구현한다. 동일한 사실·규칙·목표 아래서 역할을 바꾸고, 목표에 이르는 증명 경로를 생성한다. 생성기가 남긴 요청 좌표를 정답으로 읽는 대신, 검증기가 원문 문제와 실제 지지 관계, 표현의 의미, 검토 대상을 다시 검사한다. 최종 결과 문자열만 맞고 근거가 없는 기록은 거부한다.

실행 결과는 3개 문제의 36개 역할 조건에서 유효한 경로 생성, 60개 축별 대조 통과, 42개 손상 기록 거부, 39개 단위시험 통과이다. 이 결과가 뒷받침하는 결론은 **이 제한된 문제 언어에서 A/D/M의 구분을 실행 가능한 명세로 구성하고, 그 동작과 측정 규칙을 시험할 수 있다**는 것이다. 실제 LLM이 이 조작을 따르는지, 모델 내부의 사고와 어떤 관계가 있는지, 성능·비용이 개선되는지는 다음 단계의 연구 질문으로 남는다. [E1–E4]

## 2. 자료 범위와 근거의 구분

분석 대상은 이 채팅에 보이는 사용자 발화 7개와 그에 대응하는 기존 답변 6개이다. 최종 수행 요청까지 모두 포함했다. 사용자 발화는 부록 A에 원문으로 수록하고, 기존 답변의 주요 제안과 정정 사항은 본문에 대응시켰다.

논문의 A/D/M에 대해서는 이 대화에서 최종적으로 정정된 큰 정의를 기준으로 삼는다. 기존 논문 파일의 전체 원문은 이번 작업에서 확보하지 못했으므로, 논문 전체의 절·수식·A0–A4 세부 코드북과 완전히 대조한 구현이라고 표현하지 않는다. 특히 확인하지 못한 A0–A4의 개별 수준을 새로운 숫자 정의로 채우지 않는다.

근거는 네 종류로 구분한다. [U]는 사용자가 직접 제시한 목적과 조건이다. [D]는 그 조건을 구현하기 위해 이번에 추가한 설계 결정이다. [E]는 제공한 코드와 실행 기록이다. [R]은 외부 연구의 공개 초록·서지 정보에서 확인한 배경 자료이다. 기존 AI 답변의 평가나 예시 수치는 독립된 실험 근거로 사용하지 않는다.

## 3. 전체 대화의 전개와 결정 사항

### 3.1 구현 전환: 논문을 실행 가능한 대상으로 바꾼다

첫 발화는 “걍 논문갖고 구현할래”라는 실행 방향의 전환이다. 기존 답변은 이를 모델 학습, 그래프 엔진, 기존 LLM·CoT·ToT 대비 성능 비교까지 넓혔다. 그래프와 검증 기록을 명시하자는 제안은 현재 작업에 남기지만, 처음부터 성능 비교를 핵심 목표로 놓았던 해석은 이후 사용자의 설명에 맞춰 범위를 줄인다. [U1, D1]

### 3.2 핵심 실험 아이디어: 결과를 고정하고 역할을 바꾼다

사용자는 “애초에 결과값 자체가 고정이라면 역할극을 하자”고 제안했다. 이는 이번 최소 실험의 중심 선택이다. 결과를 새로 발견하는 능력보다, 같은 목표에 이르는 서로 다른 구조를 구성하고 비교하는 것이 우선이다. 고정 결과라는 조건과 역할극이라는 실험 방식은 사용자의 기여이다. 예시 정답 42, 역할 목록, 구체적인 데이터 구조는 기존 AI가 추가한 설명이었다. [U2]

이때 결과 고정은 아무 경로에나 목표 문자열을 덧붙여 성공으로 처리한다는 뜻이 아니다. 이번 구현에서는 고정 목표에 실제로 도달한 유효한 지지 구조가 있어야 통과한다. 도달 가능한 증명이 없으면 실패를 반환한다. [D2]

### 3.3 최소 구현이라는 성공 기준

사용자는 이 방향이 논문의 목적과 맞으며 구현도 쉬워지는지 확인한 뒤, “논문의 핵심을 찌르면서도 검증도 되는 최소구현”이라고 목적을 명확히 했다. 따라서 최소성의 기준은 단순히 코드 줄 수가 적다는 것이 아니다. 모델 연결·학습·성능 경쟁을 제거하되, 핵심 조작과 관찰, 실패 판정이 남아 있어야 한다. [U3, U5]

### 3.4 A/D/M의 의미를 바로잡는다

사용자가 각 축이 무엇을 뜻하는지 되물으면서 앞선 답변의 잘못된 해석이 드러났다. 초반 답변의 발산 거리·후보 다양성·사고 스타일은 이후 정정된 정의와 다르므로 설계에서 폐기한다. 이 정정은 명칭만 바꾸는 것이 아니라 역할 정책, 측정값, 그래프 해석 전체에 적용한다. [U4]

### 3.5 다음 단계와 이번 작업의 경계

사용자는 최소 검증 이후 자신이 보유한 4060급 GPU 환경에 소형 오픈모델을 붙이는 순서를 제시했다. 이어 최종 요청에서 “LLM 붙이고 테스트하는건 그 다음이니 거기는 만들진 마”라고 명시했다. 따라서 이번 패키지에는 API 클라이언트, 로컬 모델 로더, 모델 다운로드, 추론 서버, 모델용 프롬프트 템플릿, GPU 설정, 향후 연결용 빈 어댑터를 넣지 않는다. 하드웨어 가능성 평가도 이번 결과에 포함하지 않는다. [U6, U7]

### 3.6 기여의 귀속

사용자는 구현으로의 전환, 결과 고정, 역할극, 논문 핵심을 남긴 최소 검증, LLM 단계의 후속 분리를 결정했다. 이번 AI 작업은 이를 구체적인 Horn 명제 과제, 역할 정책, 표현 도식, 지지 DAG, 검토 레코드, 기각 규칙, 실행 코드로 내렸다. 사용자에게 AI가 만든 세부 알고리즘의 독자적 저작을 돌리거나, 반대로 사용자가 설정한 연구 방향을 AI의 아이디어로 바꾸지 않는다.

## 4. 기존 답변에서 폐기하거나 범위를 수정한 내용

**축의 오정의.** A를 “기존 경로에서 멀리 벗어나는 정도”, D를 “발산 후보의 수”, M을 “연역·유추·반례 등의 사고 스타일”로 둔 설명은 폐기한다. 현재 기준은 A=표상의 구체성·일반화 수준, D=현재 결론의 지지 의존 구조 및 기록된 논증 깊이, M=검토 대상의 수준이다.

**역할 이름을 측정값으로 쓰는 구조.** “High-A 역할이므로 A가 높다”거나 “후보를 많이 생성했으므로 D가 높다”는 판정은 허용하지 않는다. 생성 기록에는 요청 A/D/M 정답 라벨을 넣지 않으며, 역할 조건은 실험 결과의 바깥 메타데이터로만 보관한다. 측정은 실제 기록을 검사한 뒤 수행한다.

**검증 단계의 혼동.** 앞선 답변은 역할극 단계부터 LLM을 호출하는 구조로 설명했다. 최종 사용자 요청에 맞춰 첫 단계는 LLM 없는 결정론적 실험계로 확정한다. 여기서 성공한 뒤에야 모델의 역할 수행을 실험한다.

**증거 강도의 과장.** “역할극으로 이론의 존재를 검증했다”는 표현은 현재 산출물의 결론으로 사용하지 않는다. 미리 정의한 역할 정책이 의도한 구조를 생성하고 검사되는 것은 명세의 구성 가능성과 동작에 대한 증거이다. 실제 인간·LLM의 사고가 같은 차원으로 구성된다는 증거와는 연구 대상이 다르다.

**결과 고정의 과도한 해석.** 최종 결과의 변동을 통제하는 것은 맞지만, 이것만으로 모든 중요한 교란이 제거되지는 않는다. 경로 길이, 규칙의 세분성, 표현 도식의 추가, 검토 작업량은 여전히 관찰 대상이다. 이번 실험에서는 이를 기록하며, 통계적 인과효과나 보편적 축 독립성을 추정하지 않는다.

**성능 수치와 모델 규모 예시.** 기존 답변의 80%·52%·71% 같은 성능값, 크기별 향상폭, 1B·3B·7B 규모 제안은 실제 측정 자료가 아니었다. 이번 결과표에서 제외한다. 소형 모델 하나에서 재현되더라도 그 자체를 모든 모델에 대한 독립성으로 확대하지 않는다는 범위도 유지한다.

**선행연구·시스템 연결 제안.** CoT·ToT 대비 성능 비교, VibeMarshal과의 결합, 활성값 개입, 미세조정, 아키텍처 변경은 이번 코드의 구현 범위가 아니다. “중간 단계가 맞아도 전체가 틀릴 수 있다”는 검증 관점만 최종 목표 일치·전제 출처·전체 지지 연결성 검사로 반영한다.

## 5. 연구 질문과 최소 가설

**RQ.** 동일한 문제와 고정 목표 아래에서, 표현 수준 A·실제 지지 깊이 D·검토 대상 M을 구분하는 역할 실행을 구성하고, 그 차이와 위반을 별도 검사로 판정할 수 있는가?

이 질문을 이번 실험에서 다룰 수 있는 다섯 가지 검사 명제로 나눈다.

**H-Fixed.** 서로 다른 역할에서 출력 목표는 같아야 하며, 그 목표는 허용된 사실과 규칙으로 지지되어야 한다. 목표 불일치 또는 무근거 목표 복사 기록은 기각한다.

**H-A.** 같은 지지 그래프에 대해 특정 사례의 명제 기록과 보편적으로 양화된 증명 도식을 구분해 구성할 수 있어야 한다. 도식은 원래 사용한 전제에 정확히 접지되고, 모든 진리값 배정에서 유효해야 한다. 단순한 변수명 변경이나 A 라벨의 추가는 이 조건을 충족하지 못한다.

**H-D.** 같은 문제 안에서 얕은 경로와 깊은 경로가 존재할 때, 실제 지지 간선을 따라 계산한 깊이가 달라져야 한다. 문장 수나 무관한 노드의 추가는 깊이 증가로 인정하지 않는다.

**H-M.** 문제의 결론 도출, 특정 논증의 지지 검토, 평가 기준의 적합성 검토를 서로 다른 대상으로 기록하고 판정할 수 있어야 한다. 검토 수준과 검토 결론의 정오를 분리한다.

**H-Reject.** 정상 기록뿐 아니라 축의 의미·증명·출처·평가 내용을 훼손한 기록도 검사해야 한다. 잘못된 기록이 정상으로 승인되면 해당 검증 게이트는 실패한다.

이 명제들은 유한한 형식 과제에 대한 실행 가능한 명세 검사이다. 결과를 설계자가 구성하는 단계에서 가설의 통계적 효과를 추정하거나, 실제 모델의 특성을 발견했다고 해석하지 않는다.

## 6. 최소 문제 언어와 고정 결과의 의미

### 6.1 문제 정의

문제 P는 주어진 사실 집합 F, 허용된 Horn 규칙 집합 R, 고정 목표 원자 g로 구성한다. 규칙은 “모든 전제가 성립하면 결론이 성립한다”는 형식이다. 부정, 확률, 자유로운 자연어 해석은 이번 최소 언어에 포함하지 않는다. [D3]

예를 들어 F={p}, R={p→g, p→q, q→r, r→g}, 목표 g를 둔다. 같은 문제 안에 p→g라는 직접 경로와 p→q→r→g라는 합성 경로가 존재한다. 역할에 따라 사용하는 경로는 달라지지만 문제와 목표는 바꾸지 않는다.

여기서 g는 실험자가 정한 명제 기호이다. 기존 답변의 “42”는 설명을 위한 숫자 예시였으므로, 이번 코드의 결과가 반드시 숫자 42일 이유는 없다. 유한 명제 과제를 선택한 이유는 별도 모델 없이 모든 전제와 결론을 정확하게 검사할 수 있기 때문이다.

### 6.2 목표를 강제 출력하지 않는다

생성기는 주어진 규칙으로 가능한 유한 증명 경로를 구성한다. 최종 노드의 실제 결론이 g인지 검증기가 검사한다. 증명이 없으면 `UNREACHABLE` 오류를 내며, 마지막에 g를 강제로 붙여 성공 처리하지 않는다.

기록에 들어 있는 문제 id와 해시는 별도로 제공된 원문 문제와 대조한다. 검증기가 기록 속에서 새로 정의된 사실·규칙·정답을 그대로 믿지 않도록 하기 위한 바인딩이다. 해시는 파일 일치 확인용이며 외부 서명이나 공격자가 바꿀 수 없는 신뢰 기반을 제공하는 것은 아니다.

### 6.3 형식 언어의 경계

기본 한도는 문제당 원자 10개, 규칙 32개, 경로 후보 256개, 증명 노드 128개이다. 최대 후보 수를 넘으면 임의로 일부만 검사해 성공시키지 않고 제한 오류를 반환한다. 순환만으로 결론을 만들어내는 경로는 생성하지 않는다. 이 제한은 큰 문제를 푸는 성능 목표가 아니라 작은 검사 가능한 실험계를 유지하기 위한 선택이다.

## 7. A/D/M의 조작과 측정 코드북

### 7.1 A: 특정 사례와 보편 증명 도식

A의 논문상 큰 의미는 표현의 구체성·일반화 수준이다. 이번 최소 코드북은 `instance`와 `schema` 두 범주만 사용한다. 이는 논문 A0–A4 전체를 대체하는 서열 척도가 아니다. 각 수준의 세부 정의가 확보되지 않은 상태에서 A0 또는 A3 같은 번호를 임의로 붙이지 않는다.

`instance`는 이 문제에서 사용한 구체 명제와 규칙 적용을 나타낸다. `schema`는 같은 증명 부분구조를 변수에 대한 보편적 명제 도식으로 표현한다. 예를 들어 특정한 p, q, g 대신 변수 X, Y, Z를 사용하되, 단순히 이름만 바꾸지 않고 다음 조건문이 모든 진리값 배정에서 성립하는지 검사한다.

```text
forall X, Y, Z:
    [X and (X -> Y) and (Y -> Z)] -> Z
```

각 변수의 원래 명제에 대한 치환표를 함께 보관한다. 도식의 가정은 실제 증명에서 사용한 사실·규칙과 정확히 대응해야 하므로, 목표를 새로운 가정으로 슬쩍 추가해 도식을 참으로 만드는 행위는 거부된다. 검증기는 변수 치환의 일대일 대응, 가정·결론의 접지, 모든 진리값 배정에서의 타당성을 검사한다.

A는 이 형식 표현의 수준을 가리키며, 모델이 실제로 추상적으로 사고했다는 판정이 아니다. 단순 원자명 변경과 보편 도식을 분리한 것은 최소 실험에서 A의 의미를 장식적 라벨로 축소하지 않기 위한 선택이다.

### 7.2 D: 기록된 지지 DAG의 깊이

사실 노드의 깊이는 0이다. 규칙을 적용한 노드는 다음 식으로 계산한다.

```text
D(v) = 0                              (주어진 사실)
D(v) = 1 + max(D(u) for u in parents)  (규칙 적용)
```

최종 결론의 D는 그 결론의 조상으로 실제 연결된 지지 그래프에서 계산한다. 기본 예제의 직접 경로는 D=1, 세 단계 합성 경로는 D=3이다. 결합 전제가 있는 예제는 노드가 6개여도 최종 깊이는 4이다. 따라서 노드 수·분기 수·설명 길이는 D와 같은 지표가 아니다.

D는 선택한 기록 단위에 의존한다. 같은 연산을 하나의 규칙으로 묶거나 여러 규칙으로 나누면 기록 깊이가 달라진다. 이번 대조는 같은 문제의 고정된 규칙 집합 안에서만 수행한다. 인간·LLM의 잠재적인 정신적 노력이나 내부 계산량을 이 숫자와 동일시하지 않는다.

### 7.3 M: 무엇을 검토하는가

M0는 문제 대상에 대한 명제 도출이다. M1은 특정 증명 노드를 대상으로 근거 출처, 사용 규칙, 최종 결론을 다시 확인하는 `support_replay` 검토이다. 검토 대상 노드와 그 지지 근거의 id를 반드시 기록한다.

M2는 `valid_proof_and_goal`이라는 평가 기준을 대상으로 한다. 구체적으로 “정답 문자열만 g라고 적은, 근거 없는 사실 노드”를 시험 입력으로 만들고, 정답 일치만 보는 기준과 증명까지 보는 기준이 어떻게 다르게 판정하는지 비교한다. 기본 문제에서는 전자는 수락하고 후자는 거부한다. 이 차이를 실제 문제의 사실 집합에서 다시 계산한다.

M2 검토를 했다고 그 판정까지 자동으로 옳다고 보지 않는다. 테스트에서는 M2의 검토 대상을 유지한 채 판정값을 위조했을 때, M=2라는 대상 수준은 유지하되 전체 기록은 잘못된 검토 결과로 거부하는지 확인한다. 또한 M2가 존재하려면 반드시 M1을 먼저 거쳐야 한다는 일반 이론은 강제하지 않는다. 기본 역할 시나리오는 설명을 위해 M1 다음 M2를 배치할 뿐이다.

### 7.4 상태와 간선의 구분

기록에는 증명 노드의 지지 간선과 검토 레코드의 대상 참조가 구분되어 있다. 검토 레코드를 하나 추가했다고 원래 결론의 지지 깊이 D가 자동으로 증가하지 않는다. 검토 상태의 D는 해당 검토가 참조하는 대상 결론의 지지 깊이이며, 메타 논증 자체의 별도 추론 깊이는 이번에 모델링하지 않는다.

`states`에는 노드별 A/D/M 관측값과 검토 이벤트가 순서대로 기록된다. 증명 노드의 직렬화는 위상 순서이다. 병렬 지지가 있는 경우 단순 목록의 앞뒤 관계를 모든 노드 사이의 인과관계라고 해석하지 않고, 실제 의존관계는 `parents`를 읽는다.

A는 범주형, D는 그래프에서 계산한 정수, M은 검토 대상의 수준 코드이다. 이를 곧바로 균일한 3차원 유클리드 공간으로 가정해 거리나 평균 좌표를 계산하지 않는다. 이 단계에서 보여주는 것은 특정 형식 사례의 분리 가능한 조작이지, 일반적인 차원 독립성의 실증이 아니다.

## 8. 역할극 엔진과 별도 검증기의 구조

역할극은 자율적인 대화 인물을 만드는 방식이 아니라, 동일한 문제 위에서 서로 다른 명시적 행동 정책을 실행하는 방식으로 구현했다. A 정책은 사례·보편 도식 중 표현을 선택한다. D 정책은 가능한 유한 증명 중 얕은 경로 또는 깊은 경로를 선택한다. M 정책은 대상 수준에 맞는 검토 동작을 실행한다. [D4]

```text
원문 문제 P와 고정 목표 g
    -> 역할 정책 A / D_policy / M
    -> 규칙 기반 경로 구성 + 표현 + 검토
    -> 구조화된 trace
    -> 원문 문제를 별도로 받는 verify()
    -> 실제 좌표 / 유효성 / 반례 판정 / 비교 결과
```

생성 함수 `simulate()`는 `verify()`를 호출하지 않는다. 검증 함수는 생성기의 경로 선택 함수, 생성기 내부 깊이값, 역할 조건을 사용하지 않는다. 생성기가 증명 경로를 구성하면 검증기는 모든 규칙 적용을 다시 검사하고, 추상 도식은 진리값 배정을 열거하는 별도 절차로 확인한다. 정적 검사도 이 호출 분리를 확인한다.

여기서 “별도” 또는 “독립 재검사”는 코드 경로와 판정 입력의 분리를 뜻한다. 제3자가 독립적으로 작성한 구현이나 외부 학술 심사를 완료했다는 뜻은 아니다. 생성기와 검사기가 같은 명세를 공유하므로 명세 자체의 공통 오류는 별도의 연구 검토 대상이다.

최종 증명과 무관한 노드, 순환·전방·누락 참조, 허용하지 않은 규칙, 근거 없는 사실, 목표 불일치, 도식의 가정 추가·삭제, 존재하지 않는 검토 대상, 거짓 검토 판정을 거부한다. 허용 필드에 없는 `A`, `D`, `M` 정답 라벨을 trace에 주입하는 것도 스키마 위반으로 거부한다.

## 9. 실험 설계와 사전 성공 조건

기본 실험은 3개 문제 × A 2조건 × D 정책 2조건 × M 3조건, 총 36조건이다. 각 조건은 동일 입력으로 두 번 생성해 직렬화 결과가 정확히 같은지 확인한다. 반복은 결정론적 재현성 검사이며 통계적 표본을 늘리는 절차가 아니다.

`chain_2`는 사실 p에서 목표 g까지 직접 경로와 두 단계 경로를 갖는다. `chain_3`는 직접 경로와 세 단계 경로를 갖는다. `conjunction_4`는 사실 p와 s를 사용하고, 결합 전제가 포함된 네 단계 경로를 갖는다. 모든 조건에서 원문 문제의 사실·규칙·목표는 유지한다.

A만 바꾸는 대조 18개에서는 표현 범주가 달라지되 D와 M이 같아야 한다. D만 바꾸는 대조 18개에서는 실제 깊이가 증가하되 A와 M이 같아야 한다. 인접 M 수준을 바꾸는 대조 24개에서는 M이 바뀌되 A와 대상 결론의 D가 같아야 한다. 합계는 60개이다.

기각 시험은 문제별 14종, 합계 42개이다. 여기에는 다른 문제 해시, 지지 생략, 자기 순환, 없는 규칙, 잘못된 결론, 고정 목표를 근거 없이 사실로 선언한 경우, 중복 노드, 표현 누락, 빈 도식, 보편 양화 제거, M1 거짓 판정, M2 거짓 판정, 없는 검토 대상, 좌표 라벨 주입이 포함된다.

주 실험 전체가 통과하려면 36조건의 유효성, 두 번의 정확한 재현, 역할에 대한 실제 A·M 대응, 모든 축별 대조, 모든 고정 반례 거부가 동시에 성립해야 한다. 기본 실험에 필요한 서로 다른 깊이의 경로가 없는 사용자 정의 문제는 이 대조 게이트에서 실패할 수 있다. 이를 조용히 제외하지 않는다.

## 11. 이번 검증이 확보한 것과 다음 연구 질문

이번 단계는 연구 아이디어를 설명문에 머무르게 하지 않고 **실행 가능한 역할 정책, 관찰 가능한 기록, 좌표를 재계산하는 규칙, 실패를 확인하는 반례**로 내렸다. 같은 목표를 보존하면서 다른 표현과 의존 깊이·검토 대상을 갖는 경로를 구성할 수 있고, 그 기록이 계약을 위반하면 기각할 수 있는 기반이 생겼다.

결정론적 생성기는 연구자가 설계한 정책을 실행한다. 따라서 이 구성에서 축별 변화가 나타난다는 사실만으로 실제 모델이 자발적으로 같은 구조를 갖는지 판단하지 않는다. 이후 모델을 붙였을 때의 질문은 달라진다. 같은 고정 결과·같은 문제·같은 판정 계약 아래서, 모델이 유효한 기록을 생성하며 역할 조건에 대응하는 구조 차이를 재현하는지를 보게 된다.

A의 이번 두 범주는 논문 전체의 A0–A4 측정기를 완성한 것이 아니다. M은 등록된 형식 검토 대상과 실제 검사 증거를 판정하며, 임의의 자연어 문장에서 메타인지 수준을 해석하는 분류기가 아니다. D는 기록된 지지 그래프의 깊이이다. 이 구분 때문에 후속 모델 실험에서도 구조화된 출력과 실제 내부 계산을 자동으로 동일시하지 않는다.

이 경계는 해석 가능성 연구의 faithfulness 문제와 관련된다. Jacovi와 Goldberg는 설명의 평가 기준과 충실성 개념을 구분하여 정리했다. Turpin 등은 공개된 CoT 설명이 모델 예측의 실제 이유를 잘못 나타낼 수 있는 실험 결과를 보고했다. 이러한 연구는 이번 명세를 부정하는 근거가 아니라, 향후 모델의 출력 기록을 어떤 주장에 대한 증거로 쓸지 구분하는 배경이다. [R2, R3]

## 12. 관련 연구와 차별화 질문

Tree of Thoughts는 언어 모델이 중간 사고 단위의 여러 경로를 탐색하고 평가하도록 구성한 연구이다. 이 자료와 연결되는 지점은 중간 상태와 경로를 명시적인 실험 대상으로 취급한다는 점이다. 반면 이번 최소 구현의 질문은 LLM의 문제 해결 성능을 향상시키는 탐색 알고리즘을 제시하는 것이 아니라, 고정 목표 아래의 A/D/M 조작과 측정을 LLM 없이 먼저 검사하는 것이다. [R1]

이 차이만으로 논문의 학술적 신규성이 입증되었다고 주장하지 않는다. 여기의 참고문헌은 전체 선행연구 조사가 아니라, 경로 기반 방법과 출력 기록의 해석 한계를 구분하기 위한 최소 배경이다. 신규성 판단은 원 논문의 정확한 기여와 가장 가까운 연구들의 전체 방법을 대조하는 별도 작업이다.

## 13. 코드 구성과 재현 방법

핵심 런타임은 `adm_minimal.py` 한 파일이다. 형식 문제는 `examples/problems.json`, 시험은 `tests/test_adm.py`에 있다. 문서와 결과를 제외한 실행 자체에는 별도 패키지 설치가 필요하지 않다.

압축을 해제한 폴더에서 다음 명령을 실행한다.

```powershell
python adm_minimal.py run
python -m unittest discover -s tests -v
python adm_minimal.py verify --trace examples/valid_trace.json
python adm_minimal.py verify --trace examples/invalid_fixed_goal_trace.json
```

Windows에서 `python` 대신 Python 런처를 사용하는 환경은 명령의 `python`을 `py -3`으로 바꾸면 된다. 마지막 명령은 의도적으로 잘못된 기록을 검사하므로 거부되고 종료 코드 1을 반환하는 것이 정상이다. 정상 실행·승인은 0, 검사 실패는 1, 파일·입력·명령행 오류는 2이다.

원래 제공된 결과를 보존하며 다시 실행하려면 별도 출력 경로를 지정한다.

```powershell
python adm_minimal.py run --out results_local
```

`run`은 지정한 출력 폴더에 `runs.json`, `metrics.csv`, `summary.json`, `contrasts.json`, `negative_controls.json`을 쓴다. 같은 경로의 같은 이름 파일은 덮어쓴다. 다른 사용자 파일, 계정, 저장소 설정을 변경하는 동작은 없다.

LLM 연결용 라이브러리나 스텁은 없다. 다음 단계의 연결 지점은 이미 존재하는 데이터 계약, 즉 원문 문제와 구조화된 trace이다. 이번 패키지에 모델 호출 기능을 미리 넣었다는 의미는 아니다.

## 14. 다음 단계의 진입 기준

이번 결과를 기준선으로 보관하고, 후속 모델 실험에서도 생성기와 평가 계약을 구분한다. 모델 출력이 실패할 때 평가기를 그 출력에 맞춰 느슨하게 바꾸지 않고, 어떤 계약 조건을 충족하지 못했는지 먼저 기록하는 것이 이 기준선의 용도이다.

후속 단계에서는 소형 모델이 생성한 기록으로 같은 고정 목표 실험을 수행한다는 사용자 계획을 유지한다. 모델 선택, GPU 적재, 호출·서빙, 프롬프트·샘플링, 비용 측정, 결과 비고정 성능 비교는 이번 코드에 포함하지 않는다. 이 자료는 그 다음 실험이 무엇을 측정해야 하는지 판단할 수 있는 첫 기준선이다.

## 부록 C. 이번 작업의 추가 설계 결정

[D1] 현재 연구 단위는 LLM 없는 실행 가능한 명세 검사로 설정한다. [D2] 고정 결과를 실제 증명 조건으로 해석하여 무근거 목표 복사를 기각한다. [D3] 유한 Horn 명제 과제를 선택한다. [D4] 역할을 명시적 정책으로, A를 사례·보편 도식으로, D를 지지 DAG 깊이로, M을 등록된 검토 대상으로 구현한다. [D5] 생성·검증 경로를 분리하고 정상·손상 기록을 함께 검사한다. [D6] 실험 자료와 원 논문의 버전을 분리하며 LLM용 코드는 만들지 않는다.
