## 1. 작업 맥락과 원자료 확인

알려진 저장소 위치는 `D:\codex\AI논문\thought-graph-simulator`다. 실제 작업 위치와 현재 구조를 확인하고, 적용되는 AGENTS.md·AGENTS.override.md 및 관련 스킬 지침을 먼저 읽어라. 모델 배분과 검토 절차는 현재 적용되는 지침을 따르고, 과거 기록의 모델명·스킬 버전을 그대로 강제하지 마라.

다음 자료를 우선 확인해라.
- 현재 논문 초안, 연구 명세, simulator의 A/D/M 정의 및 측정 구현.
- v058~v063의 실험 프로토콜, 원문 evidence, 최종 분석·검증 기록.
- 이전 성공 기준선과 실제 모델 출력을 연결한 단계형 실행의 코드·기록. 관련 자료의 위치는 저장소에서 찾아라.

자료는 핵심 질문과 관련된 범위부터 읽어라. 이미 검증한 자료는 정확한 판본·해시를 확인해 재사용하되, 이번 결론을 좌우하는 원문과 측정 로직은 직접 대조해라. 과거 AI 답변, 감사자의 PASS, 테스트 개수를 새로운 독립 증거로 세지 마라. 서로 다른 문서에서 정의·범위가 다르면 차이를 명시하고 어느 판본을 이번 작업의 기준으로 사용하는지 정해라.

다음은 대화와 Codex 기록에 보고된 출발점이며, 원자료와 대조한 뒤 사용해라.
- v058의 해당 조건에서 Qwen은 얕은 그래프 생성 20/20, 얕은 규칙 선택 15/20이었다. 이 구성 성공을 선택적 D 제어 성공으로 확대하지도, 이후 Gemma 실패 때문에 지우지도 마라.
- v059~v060은 규칙 배열에 따른 선택 변화와 경쟁 설명을 구분했다. 관측된 선택 패턴을 모델 내부 알고리즘의 발견으로 표현하지 마라.
- v061은 깊이 지시를 바꿔도 40회 모두 k03을 선택했다.
- v062는 지정한 마지막 규칙 이름 39/40, 전체 증명 성공 0/40이었다.
- v063은 새 LLM 실험이 아니라 오프라인 진단 도구다. 짧은 조건 16/20의 오류가 최종 지지 연결 밖에 있었다는 진단은 기존 실패를 성공으로 재채점한 것이 아니다.

보고된 수치와 원자료가 다르면 원문을 우선하고 불일치와 영향 범위를 기록해라. 필요한 자료를 찾지 못하면 확인된 부분과 미확인 부분을 구분해 작업하고, 없는 내용을 만들어 채우지 마라.

## 2. 원래 연구 질문으로 돌아갈 기준

A/D/M의 의미는 실제 논문·명세를 기준으로 복원해라. 단순 정답률 개선, 규칙 ID 일치, 실행 도구의 정상 동작이 연구의 최종 목표를 대신해서는 안 된다.

이번 작업에서는 다음을 구별해라.
1. simulator에서 구조를 정의·구성할 수 있다는 것.
2. 실제 LLM이 지정된 구조를 유효하게 구성할 수 있다는 것.
3. 같은 문제·목표에서 A/D/M 제어 요구에 따라 실제 유효한 산출물의 구조가 선택적으로 달라진다는 것.
4. 그 결과가 설계에 사용하지 않은 문제·구조에서도 재현되고, 비용을 포함한 비교에서 어떤 가치가 있는지.

현재 어느 수준까지 근거가 있고 어느 수준은 미검증인지 정리해라. 작은 모델과 큰 모델의 동등 성능, 계산비용 절감, hidden layer의 내부 제어는 별도로 시험하지 않았다면 현재 성과에 포함하지 마라.

v063의 중단 결정은 존중해라. 같은 Gemma·K01에서 규칙 위치나 문구만 바꾸는 진단을 계속 이어가지 마라. 다만 그 진단 분기의 종료를 연구 전체의 종료로 확대하지 마라. Gemma의 단일 호출 완전 성공을 모든 후속 연구의 필수조건으로 임의 설정하지도 마라.

이전의 40/40 진입 기준과 공식 실패 판정은 소급 변경하지 마라. 새 실험의 진입·종료 기준은 그 실험의 목적에 맞는 근거를 제시하고, 결과를 보기 전에 정해라. 실제 구현 결함이 발견되면 원본을 보존한 별도 교정 판본과 영향 분석을 남겨라.

## 3. 구현 전에 다각도 검토로 다음 단계를 결정

최소한 다음 세 관점에서 독립 초기 의견을 도출하고 교차검토해라.
- 연구·측정: 다음 작업이 원래 가설의 무엇을 시험하며, 대리 지표를 핵심 성공으로 오인하지 않는가?
- 인과·실험 설계: 경쟁 설명들이 서로 다른 결과를 예측하는가? 반복·순서·문제 선택·추가 호출 비용이 비교를 흐리지 않는가?
- 구현·증거: 실행기·채점기·독립 검산기·보고서가 같은 계약을 구현하며, 오류를 보정해 성공시키는 경로가 없는가?

실제로 독립 검토자를 사용할 수 있으면 먼저 동일 원자료와 질문을 제공하고, 주 작업자의 결론을 정답처럼 전달하지 마라. 초기 의견 뒤 쟁점별 교차검토를 하고, 채택·기각·보류의 근거를 남겨라. 다수결이나 합의 자체를 사실의 증거로 삼지 마라. 실제로 호출하지 않은 검토자나 확인되지 않은 모델 설정을 사용했다고 기록하지 마라.

다음 세 방향을 비교하되 전부 구현하라는 뜻은 아니다.
- 기존 성공 기준선을 활용해 실제 D 제어 검증으로 돌아가는 경로.
- v063이 드러낸 사실·규칙 적용·부모 참조·불필요 노드 문제 중, 다음 결정을 바꾸는 최소 구성 검사들을 한 번의 제한된 묶음으로 확인하는 경로.
- 실제 모델 출력을 단계별로 연결하는 외부 실행 구조를 별도 대조군과 비교하는 경로.

각 후보에 대해 다음 내용을 표로 정리해라.
`연구 질문 → 기존 근거 → 아직 구분하지 못한 설명 → 조작·고정 변수 → 가능한 결과별 해석 → 다음 결정 → 진입·종료 기준 → 호출/토큰 예산`

정보 가치와 원래 가설에 대한 직접성을 기준으로 이번에 할 한 묶음을 선택해라. 반복 횟수·조건·버전 수부터 정하지 마라. 단순히 실패를 더 자세히 분류할 뿐 다음 의사결정을 바꾸지 못하는 실험은 제외해라.

## 4. 단계형 실행을 검토할 때 지켜야 할 경계

단일 호출만 허용하거나 모델 혼자 모든 실행 구조를 만들어야 한다는 조건을 새로 붙이지 마라. 호스트가 실행 순서와 인터페이스를 제공하는 것과, 정답을 대신 만들어 주는 것은 다르다.

단계형 방식을 채택한다면 다음을 명시하고 시험해라.
- 각 단계의 입력·원응답·전달값·출처와 변환 규칙을 기록한다.
- 모델이 반환한 실제 값을 다음 단계에 전달한다. 형식은 유효하지만 의미가 틀린 값도 정답으로 교체하지 않고 단계별·종단 간 결과에 반영한다.
- 허용할 직렬화·필드 이동·구조 조립은 사전에 정의하고 의미 보존을 검증한다. 누락 사실 추가, 규칙 ID 추정, 부모 연결 교정, 정답 경로 선택은 무보정 성과에 포함하지 않는다.
- 호스트가 어떤 노드·간선·호출 구조를 결정했는지와 모델이 무엇을 생성·선택했는지를 분리한다. 호스트가 깊이를 강제했다면 그 범위의 시스템 제어 결과로 보고하고, 모델의 자율적 깊이 선택이라고 하지 않는다.
- 정답 계산과 사후 채점 로직이 실행 중 답안 선택·수정에 유입되지 않도록 한다.
- 기존 직접 생성과 비교하고, 추가 호출·토큰·시간을 별도 기록한다. 개선을 모두 단계 분리 하나의 효과나 비용 절감으로 설명하지 마라.

지정 규칙으로 구성하기, 깊이 지시만으로 선택·구성하기, 새로운 문제에서 재현하기는 별개의 단계다. 어떤 단계가 이번 대상인지 명확히 하고, 다음 단계로 연결될 조건도 써라.

## 5. 실험 계약과 연구 복귀 계획

채택한 설계에 다음 항목을 결과 확인 전에 고정해라.
- 주 지표와 진단 지표. 실제 증명에서 재계산한 D와 선택 ID에 대응하는 implied_depth는 분리한다.
- 성공·실패·미관측·파싱 불가·측정 불가·실행 오류의 정의와 분모.
- 같은 문제·목표 안에서 조작할 변수와 고정할 변수, 적절한 직접 생성·중립 대조.
- 모델·문제·seed·반복·순서와 실행 예산. 선택 이유를 쓰고, 성공한 seed나 조건만 사후 선별하지 않는다.
- 개발용 문제와 최종 평가용 문제의 구분. 문제 고정은 비교쌍 안의 통제를 뜻하며, K01 하나를 영구히 반복한다는 뜻이 아니다.
- 기존 문제의 ID만 바꾸는 데 그치지 않는, 구조적으로 다른 문제로 평가할 계획. 이미 사용한 T02는 새로운 미관측 문제로 표시하지 않는다.
- 결과별 다음 행동과 이 진단을 종료할 조건.
- D 단독 진단을 언제 마치고 A·M 또는 A/D/M 통합 검증으로 돌아갈지의 조건.

한 문제의 seed 반복을 서로 다른 문제 표본으로 세지 마라. 같은 숫자 seed를 모든 모델·실행에서 동일 출력이 보장되는 장치로 취급하지 마라. 공유 호출과 원문 재집계를 독립 표본이나 비용으로 중복 합산하지 마라.

기존 성공 조건은 보존하되 선택적 제어 성공과 구분해라. 실패한 모델 하나가 전체 연구를 막지 않도록 모델별 다음 경로를 판단하고, 특정 모델에서 확인한 결과는 그 범위로 보고해라.

## 6. 채택한 범위의 구현

설계 문서만 쓰고 끝내지 말고, 근거를 검토해 채택한 범위의 실행·측정·검산 코드까지 만들어라. 단, 같은 진단을 연장하지 않기로 결론냈는데 버전 번호를 채우기 위해 새 추론 실험을 만들지는 마라. 정당한 후속 실험을 구성할 근거가 부족하면, 그 공백을 검증하는 오프라인 도구와 구체적인 연구 복귀 계획을 제공해라.

현재 저장소 구조를 따르고 새 번호는 실제 사용 현황을 확인해 정해라. 이전 소스·실험 계약·원문·최종 보고서는 보존한다. 작업 전 git 상태와 보호할 입력의 해시를 기록하고 사용자 수정사항을 reset·revert·삭제하지 마라. 재사용 가능한 도구를 무조건 다시 만들거나 과거 계획·소스를 무제한 중첩 복제하지 마라.

이번 개발 작업에서는 실제 Ollama 추론, 모델 다운로드·갱신, 서버 자동 시작을 하지 마라. 원자료 분석과 오프라인·합성 테스트만 수행해라. 실제 실험은 검증된 파일을 받은 뒤 내가 별도로 실행한다.

실행 코드를 제공하는 경우 Windows PowerShell에서 최소 조작으로 동작하도록 만들어라. 무추론 준비 검사, 환경·입력 확인, 새 RunName, 원문·부분 실행 보존, audit·bundle·독립 검산을 연결해라. 사용자 실행 시의 호출 한도와 종료 조건을 지키고, 실패 뒤 다른 이름으로 자동 재실행하거나 모델을 자동 갱신하지 마라.

## 7. 작성한 소스를 같은 관점으로 재검증

코드가 돌아간다는 확인과 연구 질문에 답한다는 확인을 별도로 수행해라. 가능한 경우 구현에 참여하지 않은 검토자가 고정된 최종 후보를 감사하게 해라.

반드시 다음 반대 결과와 실패 경계를 검사해라.
- 올바른 유효 증명과 실제 선택적 제어는 승인한다.
- 모든 지시에서 같은 유효 경로만 반복하면 선택적 제어로 승인하지 않는다.
- 규칙 이름만 맞고 실제 부모·전제·결론이 틀린 경우는 전체 증명 성공이 아니다.
- 지정 규칙 구성이나 작은 선택 과제의 성공을 자율적인 D 제어로 승격하지 않는다.
- 잘못된 중간값을 그대로 전달했을 때 앞 단계 오류·국소 결과·최종 결과를 구분한다. 결과가 우연히 맞았다고 전체 경로 성공으로 바꾸지 않는다.
- 미실행·파싱 불가를 논리 오답과 섞지 않고, 뒤 단계 실패가 이미 관측된 앞 단계의 성공을 지우지 않는다.
- 오류 노드 제거·정답 경로 선택·참조 수선으로 원래 실패를 성공으로 바꾸지 않는다.
- 원문·계획·요청·모델 식별자·측정값·최종 한국어 보고서의 변조를 검산한다. 해시를 다시 계산한 잘못된 보고서도 거부해야 한다.
- 실제 첨부 기준선의 크기, 중첩 증거, UTF-8, 한글·공백 경로, 네이티브 stderr와 종료코드, 기존 출력 충돌, 부분 실행을 시험한다.

생산 측정 결과를 그대로 답으로 가져오는 독립 검산기를 만들지 마라. 중요한 의미 계산은 별도로 구현하고, 두 구현이 공유하는 명세 자체도 수동 사례·반례로 점검해라. 무작위 그래프 수나 테스트 개수를 연구 가설의 증거 강도로 바꾸지 마라.

발견한 결함은 수정 전 재현 → 교정 → 관련 회귀 → 최종 재검증으로 남겨라. 수정 전 실패를 실행하지 않았으면 실행했다고 쓰지 마라. 모든 과거 테스트를 무조건 재실행해 시간을 쓰기보다 변경 영향에 맞는 회귀 범위와 재사용 근거를 명시해라.

최종 소스를 고정해 ZIP으로 만들고 새 빈 폴더에서 실행 검사해라. 감사 중에는 대상을 바꾸지 않는다. 수정이 필요하면 새 판본으로 다시 검증하고, 실제 전달 ZIP·현재 소스·감사 대상의 해시 일치를 마지막에 확인해라. 감사 기록을 추가하려고 승인된 ZIP을 다시 바꾸지 마라.

## 8. 최종 산출물과 보고

저장소 관례에 맞춰 다음 내용을 제공해라. 문서마다 같은 내용을 반복해서 늘리지는 마라.
1. 연구 복귀 결정서: 누적 주장/증거 상태, 아직 미검증인 핵심, 후보 설계별 반론, 선택 이유, 진입·종료 조건, A·M 복귀 및 새 문제 평가 계획.
2. 채택한 실험의 동결 프로토콜과 연구 주장 ↔ 조작 ↔ 측정 ↔ 반례 시험 대응표.
3. 실행 소스·Windows 자동화·독립 검산기 및 검증된 배포 파일.
4. 실제 시험 로그, 발견·교정 기록, 최종 감사 결과와 잔여 한계.

최종 답변은 다음 순서로 작성해라.
- 이번에 무엇을 결정했고 왜 그 방향인지.
- 원래 A/D/M 질문에 직접 가까워진 부분과 아직 준비 검사인 부분.
- 실제로 확인한 결과 및 완료한 구현·검증.
- 실행할 파일/명령과 실제 호출 예산.
- 다음 결과별 진행·중단 결정.

원자료 검증, 코드 테스트, 합성 서버 실행, 실제 모델 실험, 연구 가설의 지지를 별도로 표시해라. 핵심 주장은 근거 파일과 연결하고, 관측에서 확인한 것과 원인 가설을 구분해라. 이미 확인 가능한 내용을 다시 물어 작업을 멈추지 말고, 확인된 범위에서 이번 작업을 마무리해라.
