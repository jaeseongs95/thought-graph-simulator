512개 facts 응답 모두 사실 의미·ID 계약이 맞았고, 원자 출력 순서도 입력 facts 순서와 같았다. 전체 ID 지원 계약 역시 군당 128/128이었다. 최종 goal ID 자체의 지칭도 군당 128/128이었다. 따라서 이번 종단 차이는 선택 실패·facts 실패·ID 계약 불준수·final 지칭 실패로 설명되지 않는다. **후속 규칙의 부모 참조·직접 전제 연결에서 갈렸다.**

### 6.1 기존 U06 전제 누락의 종단 개선

U06 shallow의 최종 규칙은 `H15 AND H02 AND H44 → H74`다.

`t121_baseline_rule_04`의 실제 이력은 `n004→H15`, `n006→H02`, `n007→H44`를 포함한다. 그런데 부모를 `["n006","n007"]`로 출력하여 H15를 누락했다.

같은 unit의 alias는 `["H15","H02","H44"]`, tagged는 `["node_H15","node_H02","node_H44"]`로 정확히 출력했다. 두 의미 ID 군은 U06에서 새 facts부터 시작한 16/16 graph·8/8pair를 성공했다. baseline은 8/16·0/8이었다.

baseline도 missing_parent는 0이었으므로, alias의 개선은 단지 존재하지 않는 ID를 없애는 효과가 아니다. **존재하는 노드를 올바른 직접 전제로 연결하는 실패 일부를 줄였다.**

### 6.2 alias에 남은 7개 실패

- U03 shallow 3개: 첫 단항 규칙 `E95 → E88`에서 `parents=[]`로 출력했다. 입력에 E95 사실 노드가 실제 존재했다.
- U07 deep 4개: 둘째 규칙 `I91 AND I43 → I32`에서 부모를 `["I77","I11"]`로 출력했다. 요구된 두 전제 대신 다른 초기 사실들을 골랐다. 모두 seed 64001002의 네 표시에서 발생했다.

부모 수만 맞는지 확인해서는 U07 오류를 찾지 못한다. ID를 원자명과 같게 해도 직접 전제 선택·누락은 남는다. 이는 관측된 출력 오류이고 모델 내부의 특정 작동 원인을 식별한 설명은 아니다.

### 6.3 tagged의 실패 12개는 전부 U03

- 6개는 첫 단항 규칙의 부모 누락: deep `E95→E26` 5개, shallow `E95→E88` 1개에서 `parents=[]`.
- shallow 6개는 셋째 규칙 `E95 AND E24 AND E88 → E80`에서 `node_E24` 대신 **`node_24`**를 사용했다. 다른 두 부모와 현재 출력 ID는 맞았으나 그 부모 ID는 존재하지 않았다.

따라서 tagged는 다른 7개 구조에서 완전하게 작동했지만 U03에서는 전제 누락과 식별자 부분 누락에 매우 취약했다. 이를 전체 모델 능력 저하나 깊이 하나로 묶을 근거는 없다.

### 6.4 short도 명명 통일만으로 충분하지 않았다

U02 deep의 6개 graph는 첫 규칙에서 존재하지 않는 `n0501`/`n0502`를 부모로 사용했다. 예를 들어 `["n0001","n0502"]`라는 응답이 있었다. 실제 초기 ID는 n0001·n0002·n0003이며 facts 응답은 계약에 맞았다.

baseline은 이번에 5개 graph·5pair 낮았다. 같은 128개 경로의 성공은 양쪽 성공 100개, v089만 성공 11개, v090만 성공 6개, 둘 다 실패 11개였다.

그러나 v090의 주효과는 과거 baseline을 가져와 계산한 것이 아니라 **같은 v090 배치의 baseline과 의미 ID 군을 비교한 결과**다. baseline의 실행 간 변화가 있으므로 미래 실행에서도 효과 크기가 동일하다고 단정하지는 않지만, 이번 동시 대조의 +21.875%p를 지우는 이유도 아니다.

원응답까지 비교했다. compare 128개 요청과 content는 모두 같았다. select는 요청 128개가 모두 같지만 content가 같은 것은 111개였다. 선택된 candidate는 모두 옳았으며 이 content 차이는 공백·표현을 포함하는 바이트 차이다. 해당 차이를 그대로 generator에 전달하므로 facts 요청 중 17개도 달라졌다. facts의 동일 요청 111개 중 content까지 같은 것은 51개였다. rule은 560개 중 133개 요청이 같고 그중 94개 content가 같았다. 특정 runtime·GPU·캐시를 차이의 원인으로 추정하지 않았다.

v089의 의미 ID 성과 29/32·28/32는 유효 facts 지원 이후의 연속 생성이었다. 이번 121/128·116/128은 새 선택·새 facts 종단이다. 두 비율을 빼서 ‘fresh facts 자체의 효과’를 계산할 수는 없다. **지원된 연속 진단에서 발견한 유망한 절차가 새 출발점의 동시 대조에서도 유효했다**는 연결이 맞다.

## 10. 연구상 판단과 다음 확인

이번에 말할 수 있는 성과는 다음과 같다.

> 고정 primitive inference system과 정확한 외부 D를 사용하는 two-stage 선택에서, 새 선택·새 facts부터 시작하는 동일 종단 평가를 실시한 결과 일관된 원자명 기반 ID 지원 절차가 기존 자유 ID baseline보다 구조 동일가중 양방향 D 종단을 개선했다. 같은 ID 지원을 받는 중립 이름 대조보다도 높았으며, 효과와 남은 실패는 구조에 따라 달랐다.

이전처럼 ‘전체 종단 효과는 아직 비교하지 않았다’고 평가할 단계는 지났다. 이번에 그 비교를 실제로 수행했고 개선을 얻었다. 다만 검증한 구조는 이미 알려진 U01~U08이다.

다음 확인의 우선순위는 **baseline·short·alias·tagged의 절차와 채점 규칙을 동결한 채 신규 구조 holdout으로 옮기는 것**이다. U03/U07을 보고 그 사례만 통과하도록 표현을 고치는 것과 신규 구조 재현을 분리해야 한다. 현 자료로는 alias가 주평가를 충족한 유망한 후보이고, tagged는 실패 집중도가 다른 비교 후보다. 단일 의미 ID 방식이 모든 구조에서 baseline을 지배한다고 말할 수는 없다.

의미 ID를 적용할 때 동일 원자가 여러 번 도출되는 일반 proof에서의 ID 유일성도 별개다. 이번 동결 경로는 사실·도출 원자가 중복되지 않도록 제한했다. 이 범위를 벗어나는 확장에서는 계약을 새로 정하고 검증해야 하며, 현재 실패를 사후 재명명으로 구제하지 않는다.

이 문서는 결과 분석이다. v091 설계·소스·실제 추가 inference는 작성하거나 실행하지 않았다.
