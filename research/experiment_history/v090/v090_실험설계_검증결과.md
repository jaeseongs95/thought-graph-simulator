# v090 새 facts 포함 의미 ID D 종단 대조 — 실험설계·검증결과

작성일: 2026-09-16 KST

## 1. 이번 변경의 목적

v089의 atom_alias 유지 29/32와 atom_tagged 유지 28/32는 과거 유효 facts에서 시작한 연속 생성 결과였다. 이 수치를 새 선택·새 facts의 baseline 111/128과 직접 비교할 수 없었다. v090은 **새 공통 two-stage 선택과 각 생성군이 새로 출력한 facts에서 시작하는 전체 D 종단**으로 비교 조건을 맞춘다.

이번 문서는 구현과 사전 검증 결과다. **실제 v090 Qwen 추론은 0회이며 연구 결과는 아직 없다.**

## 2. 네 생성군

| 군 | facts ID | 이후 규칙 ID | 역할 |
|---|---|---|---|
| baseline | 기존 자유 ID | 기존 자유 ID | v089 기존 요청을 그대로 보존한 기준선 |
| short_uniform | n0001 계열 | 같은 계열 연속 번호 | ID 지정 지원 수준을 맞춘 중립 대조 |
| atom_alias | 원자명과 동일 | 현재 규칙 결론 원자명 | 사전 주평가 대상 의미 ID |
| atom_tagged | node_원자명 | node_결론 원자명 | 의미 단서를 포함한 보조 대조 |

세 지정군은 동일한 facts ID 표·지시문·schema 지원과 현재 규칙 ID 지정을 사용한다. facts의 atom→ID 표는 이미 문제에 공개된 facts로만 구성된다. atoms/rules/parents/final은 모델이 작성한다. facts에는 허용 ID enum, 규칙에는 현재 ID singleton enum을 제공하며, 정답 부모 목록·필터링된 노드 inventory·정답 proof는 제공하지 않는다.

네 군이 같은 선택 원응답을 공유하지만, facts와 그 이후 graph는 각 군이 새로 생성한다. 원문에서 오류가 나도 그대로 history에 전달한다. 잘못된 ID를 재명명하거나, 충돌을 피하려고 새 ID를 할당하거나, 전제를 보충하거나, 성공한 군으로 답을 대체하지 않는다.

baseline과 의미 ID의 주대조는 지원을 포함하는 절차의 효과다. 의미적 명명 자체에 가까운 대조를 위해 같은 지원을 받는 short_uniform을 추가했다.

## 3. 주평가·보조평가

**주평가: atom_alias − baseline의 엄격 양방향 D 종단 성공률 차이.** 각 구조의 2 seed×4 표시=8쌍을 집계하고, 8개 구조를 동일 가중한다. 결과를 보고 tagged로 주평가를 교체하지 않는다.

보조 대비는 tagged−baseline, short−baseline, alias−short, tagged−short, tagged−alias로 고정했다. 단일 종단, 네 표시 전체, fresh facts 의미, facts ID 계약, 전체 ID 계약, 유효 graph, 요구 D, 선택 trace를 분리해 보고한다.

실패는 최초 발생 단계와 이후 오류 전파를 구분한다. 단계별 위험집합은 직전까지 facts·의미·지원 계약이 유효했던 경로만 포함한다. 대응 경로별 성공 소실·획득·참조 실패→전제 실패 전이도 기록한다. 호출·토큰·응답 시간은 공유 선택을 중복 합산하지 않는다.

## 4. 동결 조건과 규모

기존 U01~U08, 2 seed, 위치×후보 ID 4표시를 유지한다. 신규 구조 holdout은 0개다. Ollama 0.34.1, qwen3:4b-instruct, 기존 digest와 sampling을 유지한다. 실제 요청은 num_ctx=8192, num_predict=4096이다.

| 공유 선택 | compare 128 + lookup 128 |

| 전체 새 graph | 512 |
| 각 군 양방향 pair | 64 |
| 각 군 네 표시 bundle | 16 |
| 목표 경로 선택 시 실제 호출 | 3,520 |
| 매핑 가능한 선택에서 경로 길이별 호출 범위 | 3,392–3,648 |

선택 실패로 경로를 매핑하지 못하면 이후 생성은 사전 규칙에 따라 skip한다. 관측된 선택 실패는 전체 trace 실패로 남기되, 미실행 graph의 의미 판정을 실패나 깊이 0으로 채우지 않는다.

잘못된 facts, ID 계약만 어긴 유효 graph, 없는 부모, 전제 누락, 틀린 비교값, 매핑 불능, incomplete HTTP, 길이 종료, 추론 전 identity 불일치, dispatch 후 중단, 원문·집계·source tampering도 시험했다. 개발 중 발견한 호출수 경계 시험의 D/규칙수 혼동은 시험 자체를 수정했으며, 최종 배포본의 위 결과는 수정 후 설치본 전체 재실행 결과다.

독립 verifier의 요청·의미 판정은 생산 구현과 별도이며, 그룹·pair·bundle·구조별 주평가 등 핵심 집계도 audit_metrics090에서 별도로 대조한다. 집계의 한국어 출력과 diagnostics 일부는 공유한다.

## 6. 검증 환경과 남은 실제 제약

검증은 **Linux / Python 3.13.5**에서 수행했다. Windows/Python 3.12 네이티브 실행을 수행한 것은 아니다. 제외 1개는 PowerShell 실행 파일이 없어 수행하지 못한 네이티브 파서 시험이다. 사용자 Windows CheckOnly에서는 파서가 있으면 이 시험도 실행된다.

자체시험과 별도 전체 합성 실행에는 실제 교환기를 합성 교환기로 바꿨고, 검증 환경의 port 11434·외부 호스트 접속도 차단했다. 테스트용 localhost 임시 HTTP 서버만 허용했다. 합성 출력의 성공률이나 주평가 0은 실제 모델 성과가 아니다.

이름별 표상 효과와 전체 D 제어를 검증하는 기존 구조 진단이며, 내부 hidden-state·A/M 축·새 구조 일반화의 증거로 확대하지 않는다. 현재 primitive 경로의 atom 유일성을 검사하므로 동일 atom의 중복 도출이 가능한 임의 graph에 의미 ID를 그대로 일반화하지 않는다.

## 7. 사용자 실행

Run-v090-Auto.ps1 하나에 source ZIP이 들어 있다. Downloads에 저장한 뒤:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v090-Auto.ps1" -CheckOnly -AllTests
```

자체시험·calibration·prepare 모두 성공한 후:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v090-Auto.ps1"
```

기준선은 **v089_idcross_20260916_122755_207556_evidence.zip**이다. 자동화가 v089/results_llm과 Downloads에서 SHA-256 일치 파일을 탐색한다. 없으면 -Baseline에 기존 원본 경로를 지정한다. 기존 v089/v088 source, manifest, guard, 로그, evidence를 삭제하거나 수정하지 않는다.

설치 위치는 llm_experiments/v090/probe이다. 실행명은 v090_freshid_<timestamp>이며 CheckOnly 이름을 재사용하지 않는다. 서버 시작·모델 다운로드·자동 재시도는 없다. 실제 실행은 사전 고정 runtime identity가 맞는지 확인한 뒤 시작한다.

완료 후 분석 파일: v090_freshid_<timestamp>_evidence.zip 및 _independent.json.
