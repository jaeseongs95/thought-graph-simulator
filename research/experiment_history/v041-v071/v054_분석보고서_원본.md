### K01: 순서 효과는 명확하지만 방향 제어는 없다

원래 규칙 목록은 연쇄가 먼저다.

```text
k10: Ca → Cb
k17: Cb → Cc
k03: Ca → Cc
```

교환 목록은 직접 경로가 먼저다.

```text
k03: Ca → Cc
k10: Ca → Cb
k17: Cb → Cc
```

내용은 같고 배열 순서만 다르다. 모델은 첫 목록에서 Ca→Cb→Cc, 두 번째 목록에서 Ca→Cc를 생성했다. shallow/deep/neutral30개의 대응 모두에서 깊이2→1 변화가 있었다. 그러나 각 목록 안에서 방향 지시를 바꾸어도 경로가 바뀌지 않았다.

따라서 '이 문제에서는 제시 순서가 경로 선택에 영향을 준다'는 관측을 인정한다. 모델 내부가 실제로 '첫 번째 규칙부터 선택' 알고리즘을 사용한다고 직접 밝힌 결과와는 구분한다.

### T02: 마지막 규칙의 전제가 잘못 연결됐다

T02의 긴 경로 마지막은 다음과 같다.

```text
r69: Lt → Lg
```

따라서 r69 노드의 부모는 Lt를 증명한 노드여야 한다. 그런데 swapped30개는 모두 마지막 r69 노드의 실제 부모를 초기 사실 Lp와 Ls 쪽으로 연결했다.

```text
필요한 연결: Lt ──r69──▶ Lg
실제 연결:   Lp, Ls ──r69──▶ Lg  (이 규칙에는 맞지 않음)
```

Lp와 Ls를 직접 사용하는 규칙은 r83이지 r69가 아니다. 등록된 마지막 규칙과 그 규칙의 실제 부모가 다르므로 증명 실패다. 올바른 결론 문자열 Lg가 있고 중간 연쇄 노드가 있다고 해서 전체 증명이 유효해지지 않는다.

30개 중3개는 추가로 중간 부모를 node ID가 아닌 원자 문자열 Lq/Lr로 가리키는 누락 참조도 있었다. 이3개는 첫 오류가 누락 참조로 보고되지만 마지막 r69 부모 오류는 동일하게 존재한다. 27개와3개를 서로 다른 '마지막 원인'으로 임의 추정하지 않고 두 오류의 겹침을 기록했다.

최종 노드 ID는30개 모두 실제로 존재했다. 따라서 `final_ref_valid=true`, `proof_valid=false`, `D=null` 판정이 맞다. r69를 r83으로 고치거나 부모를 Lt 노드로 바꾸면 호스트의 답안 보정이 되므로 하지 않았다.

## 6. v055 구현 내용

기준선 Qwen과 `gemma3:4b`를 비교한다. Gemma3의 공개 Ollama 패키지는4.3B, Q4_K_M로 표시되어 현재4.0B Q4_K_M 기준과 규모/양자화 수준이 가깝다. 이것은 선정 기준이지 D 우월성을 미리 알고 고른 근거가 아니다. 실제 후보 digest는 사용자의 로컬 metadata에서 조회해 고정한다.

2모델×2문제×2규칙 순서×3방향×10seed=240회다. 모델당 shallow/deep 대응40쌍과 두 순서에 걸친20묶음을 검사한다. 기준선의 전체 seed, 사실/규칙/목표, 옵션, schema, 한국어 지시를 유지한다.

실제 첨부 v054에서 가져온 Qwen 요청120개는 새 요청과 바이트가 같았다. 후보120개는 model 필드만 다르다. 실제 프롬프트는 한국어다. 이전 대화에서 영어 위주라고 설명한 부분은 원문과 다르며 그 설명에 맞추어 번역하지 않았다.

실행은 seed별 모델당12개 블록이고 모델 선행 순서를5:5로 나눈다. 같은 seed 안의 두 모델은 같은12조건 순서를 사용한다. 총20블록 각각 전후의 model digest/show/server를 확인한다. metadata40개는 추론240회와 별도다. capture에는 모델 추론/다운로드/자동 재시도가 없다.

기존152개 Python 파일과 그중 생산83개는 바이트 보존했다. 새 생산11개를 추가했다. 동일한 측정기를 두 모델에 적용하며 새 모델 비교 집계만 추가했다. 부모 보정·규칙명 수선·정답 경로 선택·실패 조건 제거는 없다.

### v055 결과가 말할 수 있는 것

Gemma가 D 지시를 따르고 Qwen이 따르지 않으면 이 계약에서 모델별 제어 가능성이 다르다는 직접 증거가 된다. 그러나 그것이 학습된 우선순위 하나의 차이 때문인지, 한국어 지시 해석/구조화 출력/tokenizer/native template 차이인지는 모델 교체만으로 분리되지 않는다.

둘 다 유효한 증명을 만들지만 방향을 따르지 않으면 그다음은 D 요구 인식과 그래프 구성 단계를 분리하는 진단을 검토한다. 어느 쪽이 형식이나 증명부터 실패하면 그 실패 층을 먼저 읽는다. 성공한 문제/순서가 있으면 그 범위의 성공을 인정한다. 후속 실험에서 쉬운 조건의 점수로 어려운 조건 실패를 덮지 않는다.
