# v047 실제 실행 결과 분석

## 1. 결론

이번 v047은 계획했던 동일 배치 대조를 완료했다. 같은 작은 모델·같은 생성 설정에서 원식은 유일한 양성 입력에 반복해서 실패하고, 논리적으로 동치인 교환식과 실제 NOT→AND 연결은 네 입력 전체에서 반복 성공했다. v046에 남아 있던 ‘과거 배치의 실패와 현재 배치의 성공을 비교한다’는 제한을 해소한 진전이다.

현재 가장 직접적으로 지지되는 결론은 **고정된 모델과 생성 설정에서 표현 변경으로 이 논리식의 오답을 제거할 수 있었고, 단계 연결 역시 중간값을 포함해 올바르게 실행됐다는 것**이다. 교환식도 한 호출로 성공하므로 이 실험에서 단계 분해가 필수라는 결론은 채택하지 않는다.

## 2. 이번 검토에서 실제 수행한 작업

첨부 `v047_paired_01.zip`을 별도 폴더에 풀어 검토했다. 원본 ZIP과 실행 결과 파일은 수정하지 않았다.

- 기존 v047 감사기를 동봉 `plan.snapshot.json`에 대해 `write_report=False`로 재실행했다. 재계산한 전체 결과 객체가 저장된 `summary.json`과 완전히 일치했다.
- 기존 채점 코드를 사용하지 않는 표준 라이브러리 기반 검토기를 작성하고 실제로 실행했다. 별도 재귀 하강 식 파서와 명시적 진리표로 96건 모두를 채점했다.
- 요청 96건을 기준 템플릿·실제 입력·seed·부모 반환값에서 독립 재생성했고, 보존된 요청 본문 바이트와 전부 일치했다.
- 96개 요청과 96개 응답의 해시, 96개 이벤트의 연결, 계획 해시, 마지막 이벤트 해시가 일치했다.
- 직접식 24쌍에서 expression 문자열 외 요청 필드가 같은 것을 확인했다.
- 연결식 24건에서 부모 NOT의 실제 반환값·응답 원문 해시·ID가 자식 AND 요청과 일치했다.
- 실행 전후 모델 digest·show 정보·서버 버전의 일치를 확인했다.
- 실행에 보존된 소스 7개가 앞서 전달한 배포 ZIP의 소스와 바이트 단위로 일치했다.
- 배포 패키지의 기존 오프라인 시험 75개를 재실행해 모두 통과했다. 이 시험에는 가짜 HTTP 서버가 포함되며 새 실제 모델 추론은 아니다.

별도 외부 위치에 저장한 `experiments_v047/v047_paired_01.plan.json`은 첨부되지 않았다. 따라서 이번 계획 검사는 ZIP 내부 스냅샷과 원문 사이의 일관성 검사이며, 독립 보관본과의 대조로 표현하지 않는다. 이는 원문에서 답을 다시 채점한 결과와 구분되는 보존·감사의 범위다.

검토자는 이번에 새 LLM 추론을 실행하지 않았다.

## 3. 실행 조건과 원문 결과

| 항목 | 기록된 값 |
|---|---|
| 모델 | qwen3:4b-instruct |
| 모델 정보 | 4.0B, Q4_K_M |
| Ollama | 0.34.0 |
| seed | 1729 |
| temperature | 0.7 |
| top_p / top_k | 0.8 / 20 |
| 실행 | 네 입력 × 여섯 순서 반복, 총 96회 |
| 출력 | 96건 모두 정상 종료·엄격한 bool JSON |
| 추론 채널 | 보존된 응답에 별도 thinking 출력 없음 |

| 입력 a,b | 정답 | 원식 정답 횟수 | 교환식 정답 횟수 | 연결식 최종값 정답 횟수 | 연결식 중간값 포함 정답 |
|---|---|---:|---:|---:|---:|
| false,false | false | 6/6 | 6/6 | 6/6 | 6/6 |
| false,true | false | 6/6 | 6/6 | 6/6 | 6/6 |
| true,false | true | 0/6 | 6/6 | 6/6 | 6/6 |
| true,true | false | 6/6 | 6/6 | 6/6 | 6/6 |
| 합계 | | 18/24 | 24/24 | 24/24 | 24/24 |

원식 `(a AND (NOT b))`의 실제 출력은 24건 전부 `false`다. 현재 네 입력에 대한 행동은 ‘무조건 false’ 기준선과 동일하다. 75%라는 전체 정답률만 제시하는 것보다 양성 조건 0/6을 함께 제시하는 편이 현상을 정확히 설명한다. 이번 네 입력의 목표값 분포는 false 3개, true 1개다. 균형 정확도는 원식 50%, 교환식·연결식 100%다.

96개 개별 호출 중 국소 정답은 90개이며, 오답 6개는 모두 원식의 `(true,false)`다. 연결식의 NOT 호출은 24/24, 실제 공급값에 대한 AND 호출도 24/24다. 최종값만 맞고 중간값은 틀린 파이프라인은 없다.

모든 입력에서 original/commuted/pipeline의 여섯 순열이 각각 한 번 실행됐다. 원식이 첫 번째·두 번째·세 번째로 배치된 경우 모두 같은 오류 패턴이 있었다. 각 위치에서 원식은 6/8, 교환식과 연결식은 각각 8/8이다. 따라서 이번 차이는 특정 경로가 항상 먼저 실행됐다는 단순한 배치 불균형으로 설명되지 않는다.

## 4. v046 대비 무엇이 더 확실해졌는가

v046은 과거 원식 실패와 이후 두 경로의 성공을 비교했다. v047에서는 원식을 현재 배치에서 함께 실행했고, 원식 실패와 교환식·연결식 성공이 같은 배치의 여섯 실행 순서에서 재현됐다.

원식과 교환식의 대응 요청 24쌍은 expression 문자열만 다르다. 모델·시스템 지시·입력 a/b·출력 스키마·seed·샘플링 옵션은 같다. 따라서 현재 실험 설정에서 **표현 변경에 따른 행동 차이**는 관찰로 뒷받침된다. ‘작은 모델이 이 복합 논리식 자체를 전혀 수행하지 못한다’는 설명은 한 호출의 교환식 성공과 맞지 않는다.

파이프라인의 성공은 **주어진 연결 구조에서 실제 모델 출력이 다음 단계로 전달되고, 모든 국소 연산과 최종값이 맞았다**는 성공이다. 교환식도 성공했으므로 파이프라인만의 최종 정확도 우위는 이 식에서 관찰되지 않았다.

두 성공 경로 모두 NOT를 앞에 제시한다는 공통점이 있다. 이는 후속 실험에서 NOT의 제시 위치를 분리해 조사할 이유가 된다. 그러나 출력 JSON만으로 모델 내부에서 실제로 어떤 연산 순서를 사용했는지 알아낸 것은 아니다.

## 5. 반복과 seed의 해석

96개 요청은 바이트가 다른 16종의 요청을 각각 여섯 번 실행한 것이다. 같은 요청의 여섯 응답은 content가 전부 같았다. 응답 봉투는 타임스탬프·측정값을 포함해 96개 모두 서로 다른 해시를 갖는다.

따라서 여섯 반복은 동일 seed의 재현성과 실행 순서 변화에 대한 일관성을 확인한다. 서로 다른 문제 24개를 독립적으로 풀었다거나 서로 다른 seed 여섯 개에서 성공했다는 뜻은 아니다. 이번 결과에 독립 과제 24개를 가정하는 p-value나 일반화 신뢰구간을 붙이지 않았다.

실제 temperature는 0.7이다. Ollama는 seed를 생성에 사용하는 난수 시드로 설명하며, 같은 seed와 같은 prompt에서 같은 텍스트를 생성하도록 하는 설정이라고 안내한다. 이번에 동일 응답이 반복된 사실은 이 설정과 일치한다. 다음에는 temperature를 유지하고 사전에 정한 다른 seed에서도 세 경로를 대응 비교할 수 있다.

공식 설명: https://docs.ollama.com/modelfile

## 6. 호출·토큰·시간 분석

다음은 각 경로의 최종 판단 24건에 필요한 호출을 합산한 값이다. 파이프라인 시간은 NOT와 AND 두 요청의 클라이언트 측 소요 시간을 합산했다. 파일 기록 등 호출 사이의 호스트 작업 전체를 포함하는 종단 간 지연시간과는 구분한다.

| 지표 | 원식 | 교환식 | 연결식 |
|---|---:|---:|---:|
| 실제 호출 수 | 24 | 24 | 48 |
| 입력 토큰 합계 | 3,648 | 3,648 | 7,176 |
| 이 중 캐시에서 읽은 입력 토큰 | 3,255 | 3,117 | 6,541 |
| 출력 토큰 합계 | 144 | 144 | 288 |
| 입력+출력 토큰 합계 | 3,792 | 3,792 | 7,464 |
| 판단당 요청 시간 중앙값 | 202.112 ms | 203.979 ms | 399.733 ms |
| 판단당 요청 시간 평균 | 206.830 ms | 302.307 ms | 410.724 ms |
| 총 서버 시간 | 4.490 s | 6.783 s | 8.901 s |
| 총 서버 시간에서 보고된 로딩 시간을 뺀 값 / 판단 수 | 169.389 ms | 176.531 ms | 336.159 ms |

교환식은 원식과 입력·출력 토큰 수 및 호출 수가 같다. 따라서 이번 정답 개선을 ‘더 많은 호출이나 더 긴 생성 결과를 사용한 효과’로 설명할 필요가 없다. 다만 캐시 이용량이 서로 다르므로 토큰 수가 같다는 것과 실제 FLOPs가 정확히 같다는 것은 구분한다.

교환식과 연결식은 둘 다 정답 24/24지만, 연결식은 호출 수 2배, 출력 토큰 2배, 입출력 토큰 합계 약 1.97배를 사용했다. 이 식의 최종값만 필요한 현재 구성에서는 교환식이 더 적은 호출과 토큰으로 같은 관측 정확도를 달성했다. 연결식은 별도 중간값을 기록하고 검증할 수 있다는 기능 차이가 있다.

첫 요청은 교환식이었다. 이 요청의 클라이언트 측 시간은 2.354초, 서버가 보고한 `load_duration`은 2.127초였다. 나머지 요청보다 긴 로딩 시간이 교환식의 평균에 포함됐다. 따라서 평균 207ms 대 302ms만 보고 교환식 자체가 약 46% 느리다고 해석하지 않는다. 기록을 삭제하거나 점수를 바꾸지 않고 평균·중앙값·로딩 시간을 구분해 보고한다. 로딩 시간을 산술적으로 뺀 값도 사후 기술 통계이지 새로 수행한 통제 성능 벤치마크는 아니다.

Ollama는 `prompt_eval_count`를 입력 토큰 수, `prompt_eval_cached_count`를 캐시에서 읽은 입력 토큰 수로 정의하고, `prompt_eval_duration`을 캐시되지 않은 입력 처리 시간으로 설명한다. `eval_count`는 생성 토큰 수이며 시간 단위는 ns다.

공식 설명: https://docs.ollama.com/api/chat 및 https://docs.ollama.com/api/usage

## 7. 연구 판단과 바로 다음 단계

**이번 결과의 다각도 합의는 다음과 같다.** 실행·채점 관점에서는 유효한 결과이며, 모델 행동 관점에서는 표현에 따른 실패/성공 차이가 같은 배치에서 재현됐다. 통계 관점에서는 단일 seed 재현과 새 조건에 대한 일반화를 구분해야 한다. 비용 관점에서는 이 식에 대해 교환식이 연결식보다 적은 호출·토큰으로 같은 정답률을 냈다. 연구 관점에서는 중간값을 검증할 수 있는 연결 기반이 정상 작동한다는 점을 확인했으므로 다음 범위의 실험으로 진행한다.

진행 상태:

```text
v046: 성공하는 교환식·연결식 확보                      완료
v047: 같은 배치에서 원식 실패와 두 경로 성공 재현       완료
다음: 같은 모델에서 새 seed와 사전 고정 표현 집합 검사
이후: 원래 전체 판단 작업에 재통합
그다음: 고정 문제·고정 목표의 A/D/M 축별 본 실험
```

다음에는 현 모델·temperature=0.7·요청 계약을 유지하고 새 seed 목록을 결과 확인 전에 정해 세 경로를 대응 비교한다. 기존 1729 결과는 발견·회귀 기준선으로 보존하고 새 seed 결과와 구분한다. 예비 확장으로 새 seed 10개를 기존 여섯 순서에 실행하면 960회지만, 10개는 통계적 검정력 계산에서 나온 확정 표본 수가 아니라 시작 규모다.

그다음 NOT의 제시 위치, 괄호 배치, 변수 이름 등의 변경을 한 번에 뒤섞지 말고 조건별로 나누어, 동치식의 목표 진리표를 고정한 상태에서 비교한다. 정답이 잘 나오는 표기만 사후 선택하지 않도록 평가 집합을 먼저 동결한다. 더 복잡한 식과 원래 전체 작업으로 확장할 때도 개선된 직접식과 연결식을 모두 대조군으로 유지한다.

현재 성공은 A/D/M 본 가설을 시험할 기반이 정상 작동한다는 결과다. 구성요소 대조만 계속 늘리는 것이 아니라, 필요한 범위의 일반화 검사 후 원래 전체 판단 작업으로 돌아가야 한다. 모델 크기 비교는 이 다음 단계의 우선 작업이 아니다.
