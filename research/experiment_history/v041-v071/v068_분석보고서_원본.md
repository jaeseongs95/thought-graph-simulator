# v068 원문 재검산 및 v069 설계 결정

작성일: 2026-09-13 KST

## 결론

v068의 공식 결과는 **direct 4/12, nodes→final staged 8/12**다. 원응답 36개와 종단 graph 24개를 확인하고 생산 계산·기존 별도 검산·새 원문 검산을 대조했으며 판정 차이는 없었다. 기존 independent PASS를 별도의 실제 실험으로 세지 않았다.

staged는 6개 짝에서 direct 실패를 성공으로 바꾸었지만, direct가 성공한 E01 짧은 경로 2개를 실패했다. 전체 12/12 gate는 두 방식 모두 불통과다. 따라서 v068의 제한된 nodes→final 진단은 종료한다. 성공한 T02만 사후 선택하여 전체 생성기를 확보했다고 바꾸지 않는다.

다음 소스 v069는 같은 분리를 문구만 고쳐 반복하지 않고, **정상 참조 규칙을 한 단계씩 적용하는 append-only 구성 양성 대조**로 작성했다. 규칙 선택을 모델이 했다는 주장은 하지 않는다. 단계별 정답 rule ID도 실험자가 제공하는 더 강한 안내 계약이다.

## 1. 검토한 자료와 범위

입력 evidence:

`v068_nodesfinal_20260913_201436_736799_evidence.zip`

SHA-256: `4206bfaacef17b811e232d05a458bbd9b90e8661d69dba3cd2feaf4f11790ad2`

첨부 independent JSON과 다시 실행한 검산 결과가 일치한다. 번들 상태는 live / complete, started_actions=48, completed_actions=48, inference_calls=36, observed_calls=36, pending_action=null, differences=[]다. 단, 이것은 보존된 원문과 실행 기록의 내부 일관성 검산이지 외부 Qwen 실행의 서명 인증이 아니다.

검산 흐름은 원응답 확인 → 생산 summary/한국어 보고서 재생성 → 고정 v068 검산기 재실행 → 별도 알고리즘으로 원문 graph 재계산 → 실제 번들의 재해시 변조 시험 순서다. 기존 생산 채점기를 import하지 않는 `review_raw_v068.py`도 함께 제공한다. 이 스크립트는 새로운 모델 호출 없이 같은 원문을 재계산한다.

staged 12건의 실제 이전 응답 content와 SHA-256이 다음 요청에 그대로 전달된 것을 확인했다. direct 12건은 v067 대응 요청과 바이트 단위로 동일했고, 원응답 message.content도 12건 모두 동일했다. 따라서 이번 direct가 과거와 다른 요청을 받아 생긴 차이는 없다.

## 3. 원응답에서 확인되는 차이

### T02 long

두 seed의 direct는 `r21 → r57 → r04 → r69`의 노드와 부모 연결을 작성했지만, 존재하지 않는 `final_node_id: r83`을 지정했다. 실패 판정은 유지한다.

staged에서는 실제 생성된 노드가 `n0..n5`이고 최종 응답이 `n5`를 지정했다. 최종 goal 지지 DAG는 D=4이며 참조 규칙 순서와 일치한다. 호스트가 direct 응답의 ID를 수정한 것이 아니라, 새 배치의 staged 원응답으로 성공한 것이다.

### E01 short와 long

short에서 staged는 요구한 `n52` 외에 `n08`, `n91`을 만들었다. 최종 `n52`는 초기 Aa/Ab만 사용하므로 추가 두 노드는 goal ancestry에 포함되지 않는다. 국소 논리 proof_valid는 참이지만 strict는 거짓이다. 불필요 노드를 삭제해 재채점하지 않는다.

long의 direct도 n08/n91 뒤에 짧은 규칙 n52를 적용해 실패했다. 반면 staged는 최종 노드에 n37을 쓰고 n08/n91의 결과와 Ab를 실제 부모로 연결했다. D=2의 strict 증명이 두 seed 모두 완성됐다.

따라서 이번 차이는 최종 ID 선택에만 한정되지 않는다. 노드 생성 내용도 바뀌었고, 어떤 조건에서는 좋아졌지만 다른 조건에서는 나빠졌다.

### E02 short와 long

short의 staged는 `m18 → m76` 경로의 실제 부모 ID와 최종 목표 노드 ID를 올바르게 연결했다. 두 seed 모두 strict 성공이다.

long의 staged는 두 seed 모두 참조에 없는 m18을 먼저 추가했다. m05는 `Pu, Pb`가 필요한데 `Pu, Pc`를 부모로 사용했고, m84는 `Pv, Pc`가 필요한데 Pv만 연결했다. 최종 ID는 존재하는 Pg 노드를 가리켰지만 그 노드의 전체 지지 증명이 유효하지 않으므로 실패다.

### 최종 ID에 관한 정확한 범위

staged의 최종 ID 12개는 모두 해당 응답에 존재하는 goal atom 노드를 가리켰다. 그러나 유효 증명은 8/12다. 나머지 4개에서 최종 참조가 맞았다는 이유로 노드 구성 실패를 덮지 않는다.

## 4. 관찰·추론·원인 가설

**관찰:** v068의 요청/응답 연결과 채점은 정합적이다. staged는 8/12지만 E01 short/E02 long을 실패한다. 마지막 ID뿐 아니라 생성된 graph 내용도 direct와 다르다.

**현재 가능한 추론:** 정상 참조를 전체 nodes 배열로 실현하는 계약은 모든 조건에서 안정적이지 않다. ID 선택을 별도 호출로 분리하면 일부 조건에서 유효한 긴 증명도 완성되지만, 생성 과정 전체를 해결한 것은 아니다. 이번 전송 경로의 호스트 보정이나 raw 누락으로 8/12가 만들어졌다는 설명은 원문 대조 결과와 맞지 않는다.

**미확인 원인 가설:** 전역 경로 유지의 부담, 노드 생성 중 참조 규칙의 혼합, JSON 생성 순서, 모델의 학습 패턴 등이 가능한 설명일 수 있다. 그러나 이번 비교는 출력 schema와 호출 구조를 함께 바꿨으므로 이 중 어느 하나가 실제 내부 원인인지 식별하지 못했다. v069도 그 내부 원인을 직접 증명하는 실험으로 설계하지 않는다.

## 6. 사전 기준에 따른 결정

v068 `data/protocol.json`과 PROTOCOL의 결정은 partial_scope_preserved_close_diagnostic이다. 이를 그대로 적용한다. 두 방식 모두 12/12가 아니므로 자율 D 선택→검증된 전체 생성기 연결로 바로 넘어가지는 않는다.

대신 새 출력 계약을 한 번만 검사한다. v069는 초기 사실 배열을 모델이 작성한 뒤, 참조 경로에 지정된 규칙을 한 노드씩 적용하고 마지막에 실제 ID를 모델이 지정한다. 호스트의 도움은 실행 순서와 단계별 규칙 안내이며, 노드/부모/최종 ID 정답을 작성하지 않는다.

이 설계는 정답 안내가 늘어난 **단일 방식 양성 대조**다. v068을 다시 대조군으로 실행하지 않으므로 과거 8/12와 새 성공률의 차이는 인과 효과로 해석하지 않는다. 기존 실패를 고치거나 성공한 조건만 고르지 않고, 세 문제의 short/long과 두 seed를 모두 유지한다.

## 7. v069 실행 및 종료 규칙

12개 trial, 최대 54회 추론이다. facts 12회, rule 30회, final 12회이며 metadata 12묶음을 합하면 66개 action이다. 개별 trial 호출 수는 T02 3/6, E01 3/5, E02 4/6이다.

모든 이전 원응답 문자열을 후속 요청에 그대로 포함한다. 잘못된 중간값도 삭제·치환하지 않는다. 종단 graph는 최초 facts.nodes와 각 rule.node를 순서대로 연결하고 모델이 출력한 final_node_id를 붙이는 것만 허용한다. 모든 단계 계약과 전체 strict 증명·참조 순서·실제 D를 함께 통과해야 성공이다.

54회 완료 및 12개 trial 모두 측정되어 12/12이면 이 계약에서 제한된 참조 구성 기준선을 확보한다. 0/12는 종료, 부분 성공은 범위를 보존하고 종료, 미완료/미측정은 gate=null이다. 자동 재시도·새 seed 루프·모델 변경·후속 실험 자동 실행은 없다.

최종 증명 채점기 measure.py는 v068과 바이트 동일하게 유지했다. 새 검산기는 생산 모듈의 계산을 읽는 대신 별도로 요청/단계/graph/보고서를 재계산한다. 코드/합성 HTTP 시험과 실제 Qwen v069 추론은 별개이며, 이 환경에서 새 Qwen 추론은 실행하지 않았다.

## 8. 함께 보존한 검증 자료
