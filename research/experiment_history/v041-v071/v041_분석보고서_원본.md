# v0.4.1 보존 로그의 원인 분석과 v0.4.2 수정

## 결론

새 추론 12건은 증명 4/6, 도식 0/3, 수락 기준 1/3이 통과했다. 실패는 하나의 문제가 아니다. K03의 두 잘못된 부모 연결, 도식의 최초 사실절 누락, JSON-only 출력의 bindings 자료형 위반, 입력 조건이 달라도 바뀌지 않는 기준 판정이 각각 확인된다. `adm_minimal.py`가 이 기록을 거부하는 것은 타당하다.

확인된 `local_llm` 결함은 도식 비교 결과를 덮어쓰는 보고서 집계와 불충분한 오류 설명이다. 이것들은 실패를 분석하기 어렵게 하지만, 원래 잘못된 증명을 만들거나 정상 증명을 FAIL로 바꾸는 원인은 아니다.

현재 가장 먼저 분리할 대상은 **고급 A/D/M 역할보다 기본 입력 민감도와 정확한 판정의 안정성**이다. 간결 프롬프트로 바꾸는 기존 대조는 세 문제 모두에서 증명 구조를 바꾸지 못했다. 모델을 무작정 크게 바꾸거나 출력 한도를 늘리는 대신, 입력복사·문자열 비교·사실 포함 여부·논리 결합의 관측을 분리한다.

여기서 특정한 것은 실제 거부를 일으킨 출력상의 원인과 재현 가능한 소프트웨어 결함이다. 가중치·양자화·서버 내부 디코딩 중 어느 것이 그 출력을 유발했는지는 아직 분리되지 않았다. 아래 수정은 이 경계를 흐리지 않는다.

## 2. 증명: 프롬프트 길이를 바꿔도 같은 관계 오류

| 고정 문제 | 기존 프롬프트 | 간결 프롬프트 | 노드 ID 재명명 후 구조 |
| --- | --- | --- | --- |
| K01 | 성공 | 성공 | 동일 |
| K02 | 성공 | 성공 | 동일 |
| K03 | 실패 | 실패 | 동일 |

공백과 노드 이름은 달라도 규칙·원자·부모 관계가 같다. 이번 간결화가 성공률 또는 증명 구조를 개선했다는 관측은 없다. 그러나 모든 프롬프트가 효과 없다는 일반적 결론도 아니다.

K03의 실제 규칙은 `Ea→Eb`, `Eb→Ec`, `Eb→Ed`, `Ec AND Ed→Ee`이고, 별도의 `Ea→Ee` 얕은 경로가 있다. 요청은 깊은 경로다. 정상 깊이는 3이다.

| 노드 명제 | 실제 모델의 부모 명제 | 규칙이 요구하는 부모 명제 |
| --- | --- | --- |
| Ea | 없음 | 최초 사실 |
| Eb | Ea | Ea |
| Ec | Eb | Eb |
| Ed | **Ec** | **Eb** |
| Ee | **Ed** | **Ec, Ed** |

두 프롬프트 모두 이 구조다. 분기/합류를 직렬 연결처럼 작성했다. K02에서는 합류가 포함된 증명이 성공했으므로 AND 자체의 전면적인 수행 불가능으로 해석할 수는 없다.

### 최소 변경 반례

두 응답을 각각 복사해 원래 것, Ed 부모만 바꾼 것, Ee 부모만 바꾼 것, 두 항목을 모두 바꾼 것을 비교했다. 두 오류를 모두 수정한 복사본만 통과한다. 별도의 원문 규칙 대조기도 같은 판정을 냈다.

이는 **거부에 충분한 실제 오류 두 곳을 특정한 분석**이다. 수정된 복사본을 모델의 성공으로 집계하지 않았고, 런타임이 그 연결을 자동 완성하지 않는다.

증거: [proof_pairs.json](proof_pairs.json), [20개 복사본 변경 검사](counterfactuals.json).

## 3. 도식: 규칙 네 개는 맞았지만 최초 사실을 빠뜨림

`union`과 `schema_only`의 원문 content는 바이트 단위로 같다. 두 도식 모두 다섯 원자의 일대일 대응과 네 규칙 절, 결론 변수를 맞췄다. 그런데 아래 한 절이 없다.

```json
{"if": [], "then": "x"}
```

여기서 `x`는 `Ea`에 대응한다. `if=[]`는 빈 내용이 아니라 **Ea가 초기 사실임을 선언하는 절**이다.

모델이 제출한 것은 대략 `x→y, y→z, y→w, z&w→v` 네 조건과 결론 `v`다. 모든 변수를 false로 두면 네 함의는 모두 참이지만 v는 거짓이다. 따라서 “모든 진리값 배정에서 결론이 성립한다”는 도식이 아니다. 엄격한 형식 조건을 떠나 실제 논리 반례가 있다.

두 정규 형식 응답의 복사본에 **최초 사실절 하나만 추가**하면 통과한다. 그러므로 이번 도식 실패를 추상화 전체의 붕괴라고 표현하는 것도 부정확하다. 보존된 출력의 구체적인 결함은 근거 집합에서 초기 사실을 누락한 것이다.

### JSON-only는 형식 오류도 겹친다

JSON-only 응답은 `bindings`를 요구된 배열이 아닌 객체로 작성했다.

```json
{"bindings": {"a":"Ea", "b":"Eb"}}
```

계약은 다음과 같은 배열이다.

```json
{"bindings": [{"variable":"a", "atom":"Ea"}, {"variable":"b", "atom":"Eb"}]}
```

그리고 초기 사실절도 똑같이 빠져 있다. 복사본의 자료형만 바꾸면 의미 오류로 실패하고, 사실절만 넣으면 형식 오류로 실패한다. 둘 다 수정한 복사본만 통과한다. 새 진단기는 객체를 읽을 수 있을 때 관측용 원자 대응을 표시하지만, 정규화한 출력을 채점기에 넘기지 않는다.

기존 `anyOf` 오류는 `view` 전체가 맞지 않는다는 수준에서 끝나 원인을 가렸다. v0.4.2는 추가 증거에 `$.node_views[0].view.bindings`의 자료형 오류를 표시한다. 원래 판정과 오류 문자열은 재현을 위해 그대로 둔다.

증거: [읽기 전용 상세 진단](v041_reaudit/task_evidence.json), [복사본 변경 검사](counterfactuals.json).

## 4. 기준 판정: 도출 가능성 오해만으로 설명되지 않음

세 요청의 실제 출력은 모두 `(true, true, false)`다. 순서는 `answer_only_accepts`, `proof_and_goal_accepts`, `gap_detected`다.

| 입력 | 목표와 같은가 | 초기 사실인가 | 정답 | 모델 |
| --- | --- | --- | --- | --- |
| K01의 Cc | 예 | 아니오 | T,F,T | T,T,F |
| K01의 Ca | 아니오 | 예 | F,F,F | T,T,F |
| K11의 Cc | 예 | 예 | T,T,F | T,T,F |

세 번째는 맞았지만 입력 민감성이 입증된 성공은 아니다. 같은 상수 패턴이 그 조건의 정답과 우연히 일치한 관측이다. 이것은 내부적으로 반드시 복사했다는 주장과 다르다.

첫 번째만 보면 모델이 ‘규칙으로 도출 가능한 목표’를 ‘단독 사실의 근거’로 잘못 취급한 가설을 세울 수 있다. 그러나 두 번째에서는 **Ca와 Cc가 다른데도 목표와 같다고 답했다.** 따라서 도출 가능성 오해 하나로 세 결과를 전부 설명할 수 없다.

입력을 잘못 읽었는지, 문자열 동일성/배열 소속을 틀렸는지, 마지막 JSON의 불리언을 고정해 출력했는지는 기존 세 최종 값만으로 분리되지 않는다. 새 과제는 모델에게 `observed`, `primitives`, `finding`을 각각 작성하게 한다. 이것은 출력된 중간값의 오류 위치를 구별하는 진단이지 비공개 사고 과정을 측정한다는 주장이 아니다.

증거: [criteria.json](criteria.json), `adm_minimal.py`의 `verify` 내 acceptance_criterion 분기.

## 5. core를 의심한 별도 검사

동일 함수를 반복 호출하는 것으로 끝내지 않고, 원문 규칙 대조와 전방 고정점·직접 진리표로 교차검사했다.

| 대조 | 실제 실행 수 | 일치 | 유효한 합성 입력 |
| --- | ---: | ---: | ---: |
| K03 고정 노드의 가능한 앞선 부모 부분집합 | 1,024 | 1,024 | 1 |
| K03 다섯 사실/규칙 절의 부분집합 | 32 | 32 | 1 |
| 기준 입력 4가지 × 출력 불리언 8조합 | 32 | 32 | 4 |

이 1,088개는 **합성 대조 입력**이며 LLM 표본이 아니다. K03 고정 구조와 기준 판정의 유한 영역을 검사한 것이지 임의 입력에 대한 core 무결성 증명은 아니다. 이번 실제 실패를 오채점으로 설명할 반례는 발견되지 않았다.

새 코드도 기존 모델 응답을 성공으로 바꾸지 않는다. `adm_minimal.py`를 교체할 근거가 없으므로 배포 소스 ZIP에 대체 core를 넣지 않는다.

증거: [targeted_crosscheck.json](targeted_crosscheck.json), 재현 코드 `scripts/targeted_checks.py`.

## 7. 실제로 고친 보고서 결함

기존 `component_report.py`는 같은 `problem_id`와 `view_scope`에 한 객체만 저장했다. K03의 union/schema_only/json은 모두 final_node_only여서 마지막 union 한 건만 남는다.

수정본은 모든 조건을 `schema_scope_conditions`에 보존하고, 같은 범위에 복수 조건이 있으면 `ambiguous_scope_comparison=true`와 전체 목록을 남긴다. 원인 분리 전용 `causal_probe.json`과 총 성공 건수는 원래부터 세 건을 보존했으므로, 이것을 원래 모델 성능 FAIL의 원인이라고 부르지 않는다.

또한 `inspect-results`의 `final_is_goal_atom:0`은 ‘목표에 도달한 노드가 0개’라는 뜻이 아니었다. 최종 **포인터**에 노드 ID 대신 목표 원자 문자열을 넣었는지 세는 오류 지표다. 과거39건은 실제 최종 노드 명제는 모두 목표와 같았다. 새 분석은 설명을 붙이고 `selected_final_node_atom_matches_goal:39`를 별도로 표시한다. 전체 증명 실패39건은 유지된다.

증거: [수정 전후 집계](component_report_before_after.json), [과거39건 재검사](v04_pilot_reaudit/reanalysis.json).

## 8. 제3자적 관점별 주장·반박·채택

별도 에이전트/외부 심사자를 실제 호출한 것이 아니다. 사용 가능한 연결에서 독립 심사 실행 도구를 확보하지 못했다. 아래는 동일 분석자가 서로 다른 심사 기준을 적용한 주장·반박이며, 독립성의 기술적 보완은 별도 알고리즘과 반례로 수행했다.

### 형식 검증 관점

주장: 전제 집합과 사실절이 틀렸으므로 거부가 맞다.
반론: 계약이 너무 엄격해 사용자가 체감하는 성공을 가릴 수 있다.
대조: K03은 실제 전제 대체/누락이다. 도식에는 모든 변수가 false인 논리 반례가 있다. 표현상의 까다로움만의 문제가 아니다.
채택: 기존 엄격 판정은 유지한다. 부분적으로 맞은 연결·규칙·바인딩은 별도 증거로 제시한다.

### 런타임 관점

주장: 작은 모델에 명백히 쉬운 판정조차 틀리면 모델/디코딩/입력 전달도 의심해야 한다.
반론: 모델·모드·요청·템플릿은 기록상 적합하다.
대조: 적합한 메타데이터는 실제 생성의 정상성을 증명하지 못하지만, 과거 모드 불일치를 원인으로 재활용할 수도 없다.
채택: 불필요한 모델 재다운로드/메모리 증설부터 요구하지 않는다. 입력복사와 문자열 비교를 가장 먼저 검사하고 format만 바꾼 대응 실행을 지원한다.

### 모델 행동 관점

주장: K03 분기/합류를 직렬화하고 기준 결과를 고정하는 경향이 직접 드러난다.
반론: K02는 합류 증명을 성공했고 schema의 네 규칙은 모두 정확하다.
대조: 전면적인 논리 능력 부재가 아니라, 현재 작업에서 관계 연결과 필수 가정·입력 조건 유지가 불안정하다.
채택: 전체 증명 계획과 고정된 노드의 부모 연결을 나눠 검사한다. 성공한 보조 과제를 전체 D 계획 능력으로 승격하지 않는다.

### 측정 설계 관점

주장: 모호한 형식 지시와 opaque 최종 판정만으로 원인을 특정하려 한 설계가 진단력을 떨어뜨렸다.
반론: 초기 사실절과 기준 정의는 기존 프롬프트에도 명시되어 있었다.
대조: 따라서 지시가 완전히 없었다고 해명할 수 없다. bindings의 배열 형식은 format 제거 시 부족했고, 중간 판정은 원래 수집하지 않았다는 한계가 정확하다.
채택: 새 요청은 전체 스키마를 메시지에 명시하고, 모델이 입력 복사·원자 판정·최종 결합을 모두 작성하도록 한다. 원래 실험과 다른 보조 조건임을 명시한다.

### 반증·인과 관점

주장: 간결 프롬프트 무효, schema 종류 변경 무효라는 대응 관측으로 일부 가설의 우선순위를 낮출 수 있다.
반론: 한 시드/적은 문제로 프롬프트나 디코딩 전반을 배제할 수는 없다.
대조: 비교 단위를 특정 입력의 바이트/구조 변화로 한정하면 충돌하지 않는다.
채택: 다수결 대신 직접 반례·동일 조건 대조에 견디는 주장만 남긴다. 변경 요인 외 요청 필드가 달라지면 비교 도구가 거부한다.

### 종합 판정

‘core를 느슨하게 바꾸면 된다’, ‘4B니까 전부 못 한다’, ‘non-thinking이라 논리를 못 한다’, ‘사실 도출 가능성 하나를 오해한 것이다’, ‘프롬프트 길이만 줄이면 된다’는 설명은 현재 전체 증거와 맞지 않거나 아직 분리되지 않았다.

가장 잘 뒷받침되는 결론은 **실제 출력 의미 오류는 확정되어 있고, 기본 입력 민감도까지 검증하지 않은 채 상위 역할 실험을 반복한 진단 절차가 비효율적이었다**는 것이다. 채점기 완화가 아니라 기초 대조·중간값 수집·대응 요인 검증을 먼저 수행한다.

## 9. v0.4.2 수정 범위와 다음 실행

기본 모델, 샘플링, 기존 causal/pilot 프롬프트, core는 유지한다. 새 `micro_probe`는 별도 계약이다.

| 구성 | 회수 | 의미 |
| --- | ---: | --- |
| 입력복사2 + 정확한 문자열 동일성2 | 4 | 전달/기초 지시 대조. 입력복사는 추론 성과 아님 |
| 기준 입력4종의 observed/primitives/finding | 4 | 입력 읽기·동일성·사실 소속·논리 결합의 출력상 오류 분리 |
| 전체 K03 증명 / 고정 경로의 부모 연결 | 2 | 계획+표현과 연결 작업 분리. 고정 경로는 호스트 보조 |
| 같은 도식 / 사실절 우선 작성 지시 추가 | 2 | 초기 사실절 누락을 겨냥한 지시 대조 |

첫 실행은 control+criterion 8회만 권한다. 이전69회를 반복할 필요 없다. 나머지 그룹은 필요할 때만 실행한다.

`--format-mode schema|json|none`은 메시지 속 완전 스키마를 같게 유지하면서 HTTP format 필드만 바꾼다. `compare_runs`는 format/temperature/seed/model/server 중 선택한 요인 외에 코드·문제·요청 필드까지 바뀌면 비교를 거부한다. 모델 교체는 가중치·양자화·템플릿 묶음의 대조로 표시하며 순수 양자화 효과라고 자동 결론내지 않는다.

## 10. 수행 한계와 검증 결과

오프라인 회귀/단위/모의 API 시험 172개, selfcheck21개를 수행했다. 별도로 위 1,088개 유한 core 대조와20개 실제 출력 복사본 변경을 수행했다. 이 수는 LLM 호출 수에 포함하지 않는다.

새 모델 다운로드, 실제 LLM 추론, GPU 실행, Windows 실행은 하지 않았다. 새 진단의 실제 성공률은 아직 없다. 수정본이 어떤 오류를 더 정확히 구분하고 기존 판정을 유지하는지는 오프라인에서 확인했고, 실제 모델 출력의 개선은 주장하지 않는다.
