# v051 원문 검증과 연구 방향 판단

## 결론

전체 역할 성공 0/240은 채점 오류로 확인되지 않았다. 실제 원문에서도 최종 노드 참조와 하나의 증명 경로 선택이 모두 실패했다. 다만 '모든 논리 연산이 틀렸다'는 해석은 틀리다. 개별 규칙 적용 960/960은 정상이었다.

현재 결과는 v051의 실제 LLM 통합 생성·제어가 실패했다는 증거다. 제한된 형식 명세 자체에 논리 모순이 있다는 증거나 A/D/M 연구 전체의 반증으로 확장할 수는 없다. 반대로 현재 결과에서 실제 모델의 A/D/M 제어를 지지하는 성공을 얻었다고 말해서도 안 된다.

## 검사한 자료와 절차

첨부 파일 `v051_adm_01_evidence.zip`에는 manifest를 제외한 537개 파일이 있다. 파일 목록·SHA-256를 검사하고 동봉 외부 계획, 원문 요청·응답, 실행 코드 snapshot을 대조했다. 기존 감사기를 재실행한 report 전체 객체가 저장된 `summary.json`과 일치했다.

이후 별도 코드로 240개 응답의 노드·전제·규칙 적용·최종 참조·목표 후보·M1/M2 판정을 검사했다. 원문을 교정하거나 재채점하여 PASS로 바꾸지 않았다. 중복 JSON 키가 있는 응답의 진단은 일차 채점과 분리했다. 해당 응답에서는 중복 없는 nodes/final/reviews 필드의 관찰만 활용했으며, 중복 views의 마지막 값을 정답으로 채택하지 않았다.

세부 수치는 `independent_verification.json`, `calls_diagnostics.csv`, 대표 원문은 `examples.json`에 있다. 이 검토에서 새 LLM 추론은 실행하지 않았다.

나머지 1건은 중복 키 없이 JSON 객체로 읽히지만 views 속성 수 계약을 위반했다. schema 역할에 중복 키가 집중됐다는 사실은 형식 문제가 실제 존재함을 보여 주며, 그 원인을 특정 모델 내부 메커니즘이나 특정 엔진 버그로 단정하지는 않는다.

## 1. final의 참조 실패

모든 240개 응답은 final="Cc"를 출력했다. 그러나 nodes의 id는 n0/n1/n2/n3 또는 다른 별도 ID였다. final은 목표 원자 문자열이 아니라 실제 목표 노드의 id를 요구하는 필드다. 따라서 최종 노드가 없다는 실패 판정은 맞다.

## 2. final 하나만 고쳐도 해결되지 않는다

모든 응답에는 다음 두 대안 경로가 함께 들어 있었다.

```text
Ca → Cb → Cc   (깊이 2)
Ca → Cc        (깊이 1)
```

각 규칙 적용은 맞지만, 어느 목표 노드를 선택하더라도 다른 경로의 노드가 남는다. 계약은 '선택된 최종 목표의 지지 조상만 있는 한 증명'이다. 목표 원자 이름을 노드 id로 바꾸는 것만으로는 240개 모두의 무관한 노드 문제가 해소되지 않는다.

shallow/deep 요청에 맞는 하나의 경로가 선택되지 않았으므로, 후보에 깊이 1과 2가 모두 들어 있다는 사실을 D 제어 성공으로 바꿀 수 없다. 호스트가 shallow면 짧은 경로, deep이면 긴 경로를 골라주면 모델 대신 프로그램이 역할을 수행하는 것이 된다.

## 3. A와 M도 단순 참조 문제만은 아니다

schema 조건 120개 중 110개에 중복 JSON 키가 있었다. 일부 응답은 instance를 반복하거나 실제 노드 외의 키에 도식을 붙였다. 엄격한 decoder가 중복을 거부한 것은 타당하다.

M1 요청 80개에는 argument 검토가 있었지만 target은 실제 노드 id가 아니라 Cc였다. M2 요청 80개에는 요청하지 않은 M1까지 함께 들어 있었으며, 기준 검토 finding은 모두 틀렸다. 단독 목표 주장은 goal 문자열은 맞지만 초기 facts에는 없는데 proof_and_goal_accepts=true, gap_detected=false를 출력했다.

따라서 현재 결과를 '노드 id 이름만 잘못 쓴 것이 전부'라고 축소해도 안 된다.

## 4. 미측정과 오답의 구분

기존 요약은 올바른 전체 실패를 보여주지만, A·D별 0이라는 숫자만으로는 직접 오답과 선행 실패 때문에 측정되지 않은 경우가 구분되지 않는다. 특히 JSON 전체 decode가 거부되면 뒤 의미 측정 자체가 수행되지 않는다.

이 때문에 v052에서는 성공/실패/미측정을 별도 집계하고 개별 노드 검사와 최종 증명 검사를 분리한다. 전체 성공 조건은 유지한다. 유효한 부분을 보존하는 것과 전체 기록을 성공으로 승인하는 것은 다르다.

## 5. 길이 제한인가?

서버 기록의 입력 토큰은 요청별 1,609~1,617, 출력은 267~836이며 모든 응답은 stop으로 종료됐다. 설정은 num_ctx=8192, num_predict=4096이었다. 이번 원문에는 출력 토큰 상한 때문에 잘렸다는 증거가 없다. 긴 계약이 인지적 부담을 줬을 가능성과 실제 토큰 한도 절단은 구분한다.

## 6. 원인 후보와 구별할 증거

| 후보 | 현재 증거 | 필요한 대조 |
|---|---|---|
| 채점기가 틀려서 정상 증명을 거부 | 원문·독립 규칙 계산이 전체 거부를 지지 | 성공 기준을 바꾸지 않고 유지 |
| 최종 원자/노드 id 및 직렬화 혼동 | final=Cc 240/240, 중복 키 110건 | 명시적 참조·배열 직렬화 arm과 legacy 대응 |
| 경로 선택 실패 | 모든 응답이 대안 두 경로를 동시 나열 | D 단독 생성과 통합 역할 대조 |
| 과제 통합 부담 | 개별 규칙은 맞는데 전체 계약 실패 | 복사 진단, D 단독, 전체 factorial 분리 |
| M2의 평가 기준 혼동 | v050에 이어 현재 80/80 오답 | 별도 상태로 기록, A/D와 판정 성공 분리 |
| 이론 전체의 논리 모순 | 이 기록만으로는 제시되지 않음 | 형식 구성 가능성과 실제 생성·제어를 별개로 검증 |

'인터페이스 혼동'과 '통합 부담'은 원인 가설이며 내부 원인을 밝혀냈다는 뜻이 아니다.

## simulator가 잘 됐는데 LLM은 실패하는 이유

원래 simulator는 후보 증명을 코드로 열거하고 shallow/deep에 따라 최소/최대 후보를 선택한다. 표현·검토도 프로그램이 구성한다. 성공 기준을 갖춘 형식적 실험계를 구성할 수 있었다는 뜻이다.

실제 LLM 연결 단계에서는 모델이 그 일을 직접 수행해야 한다. 생성기 교체 후 같은 계약을 이행하지 못한 것이 이번 실패다. simulator가 통과했다는 이유로 실제 모델의 실패를 채점 오류로 추정할 근거는 없고, 실제 모델이 실패했다는 이유로 형식 명세의 구성이 논리적으로 불가능해진 것도 아니다.

## 논문 핵심과 실험 설계의 평가

연구 명세의 핵심인 고정 문제·목표, 역할 조작, 실제 trace 검사, 손상 거부는 v051에 있었다. 그러나 한 번에 복잡한 전체 계약을 생성시켰고, 형식 경계 복사·D 단독·중립 대조가 없어 실패 층을 분리하기 어려웠다. 이는 실험 설계상의 보완점이다.

또한 외부 증명/도식/검토 기록을 제어하는 것과 hidden layer의 실제 사고 좌표를 제어하는 것은 다른 측정 대상이다. 현재 코드와 simulator는 전자에 대응한다. 후자에 대한 주장을 현재 출력 trace만으로 입증한 것처럼 표현하면 이론과 측정 사이에 연결 공백이 생긴다.

## 다각도 합의

형식 심사는 0/240을 유지한다. 행동 심사는 960/960 국소 연산 정답을 보존한다. 인과 심사는 관찰된 오류와 원인 가설을 분리한다. 연구 설계 심사는 단순 형식 패치만으로 끝내지 말고 중립군·실제 factorial·구조 전이를 유지하도록 요구한다. 검증 심사는 정답 제공 복사를 본 가설 성과에서 배제한다.

합의: v051은 실패 기준선으로 보존한다. v052는 전체 성공을 얻기 위해 채점기를 완화하는 코드가 아니라, 핵심 A/D/M 제어와 형식/구성요소 진단을 분리하는 실험으로 구성한다.
