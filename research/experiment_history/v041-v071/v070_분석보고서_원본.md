# v070 원응답 분석 및 v071 설계 결정

## 결론

**v070은 후보 경로 복사·유효성 40/40, 올바른 D 방향 선택 20/40, 선택적 비교 쌍 0/20이다. 20쌍 모두 shallow/deep 요구를 바꾸어도 같은 경로를 선택했다.** 50%는 D 제어가 절반 성공했다는 의미가 아니다. 각 쌍에서 같은 답을 반복하여 한 방향만 맞았다. 사전 종료 기준에 따라 v070의 단일 호출 선택 계약을 종료한다.

v069의 정상 경로/단계별 규칙 제공하 graph 구성 12/12는 보존한다. v070에서는 생성기를 호출하지 않았으므로 이 결과를 합쳐 종단 D 제어가 성공했다고 세지 않는다.

## 1. 입력과 실제 수행 범위

- 입력 ZIP: `v070_select_20260913_213212_243277_evidence.zip`
- ZIP SHA-256: `b91117c7b65bd60d5dc187251f9880e272d1224d3bf615e32354a382df98ebc6`
- 계획 SHA-256: `6a7ce8c31c36a9da2677299a7b36bbb1f7f8e5ef9dbbc011494b082b247aa060`
- 첨부 기록: live / complete, 추론 40회, 완료/시작 action 60/60, pending 없음.
- 수행: 원응답 40개와 실제 요청, 생산 채점 재실행, 고정 배포본의 독립 검산 재실행, 생산 모듈을 사용하지 않는 별도 역방향 DAG 재계산, 재해시 변조 10개 시험.
- 결과: 세 재계산 경로의 판정 차이 없음. 변조 10/10 거부.
- 독립 PASS를 반복 실행 횟수나 새로운 실험 표본으로 세지 않았다. 표본은 원래 40호출/20쌍 그대로다.
- 이 작업에서 실제 Qwen 모델을 호출하지 않았다. 번들 내부 일관성 검산은 사용자 장비 실행 사실의 외부 인증이 아니다.

## 3. 관찰, 추론, 원인 가설

### 관찰

실제 요청에는 서로 다른 D 방향 요구가 들어갔고, 후보 순서 교차도 계획과 일치했다. 모델 출력은 모두 스키마에 맞고 정확히 후보 중 하나였다. 20쌍의 규칙 ID 배열은 의미적으로 같았으며, 원문 공백까지 모두 같았다는 주장은 아니다.

### 현재 가능한 추론

이번 계약에서는 후보 복사/형식 작성보다 요구 깊이에 따른 선택이 실패 지점이다. T02/E01의 결과와 나머지 세 문제의 결과를 모두 “항상 첫 후보” 또는 “항상 짧은 경로”라는 하나의 행동 규칙으로 설명할 수 없다. 현재 모델이 모든 외부 지시를 무시한다는 결론도 아니다.

### 아직 구분되지 않은 원인

v070은 모델이 계산한 깊이를 출력하지 않았다. 따라서 깊이 계산 실패, 숫자의 크기/요구 방향 선택 실패, 두 작업과 후보 복사를 함께 시킨 계약의 문제를 원문만으로 분리하지 못한다. 특정 내부 계층이나 학습 원인을 밝혔다는 주장을 하지 않는다.

## 4. v071: 계산과 비교를 분리한 한정 실험

같은 5문제·2seed·2후보 순서를 유지한다. 각 20개 단위에서 깊이 계산 1회, 그 원문을 이용한 shallow/deep 선택 2회, 정답 깊이를 이용한 shallow/deep 양성 대조 2회를 실행한다. 총 100호출/140action이다.

깊이 계산의 출력은 `{"depths":[d0,d1]}`다. 선택 단계의 출력은 `{"candidate_index":0}` 또는 `{"candidate_index":1}`다. 인덱스와 원래 후보의 대응은 고정되어 있고 호스트가 실제로 어느 후보를 선택할지 결정하지 않는다.

모델 선택군에는 앞선 `message.content` 문자열을 공백과 오류까지 그대로 전달한다. 정답 깊이로 교체하거나, 잘못된 JSON을 고치거나, 실패한 계산을 성공으로 재채점하지 않는다. 정답 깊이 제공은 별도로 표시한 양성 대조군에만 적용한다.

두 선택은 같은 계산 원문을 공유한다. 따라서 40개의 모델 선택을 40개의 독립적인 깊이 계산으로 세지 않는다. 잘못된 계산이 순서를 유지해 선택만 맞는 경우는 선택 성공으로 따로 보고하되 계산→선택 전체 성공은 아니다.

v071은 generator를 호출하지 않는다. v070과 동시 대조하거나 동일 비용으로 비교한 실험도 아니다. 성공 시 후보 목록 내 계산·선택 기준선을 얻고, 실제 generator와의 연결은 별도 설계가 필요하다.

## 5. 동결 판정과 종료

모두 완료·측정 가능한 상태에서 깊이 계산 20/20, 정답 깊이 선택 40/40 및 20/20쌍, 모델 계산→선택 40/40 및 20/20쌍을 충족하면 이번 기준선을 확보한다. 중간값 오류, 선택 오류, 형식/파싱 오류, 미실행, HTTP/identity/예산 오류는 분리한다. 미완료/미측정이면 전체 gate는 null이다.

정답 깊이 대조 실패, 깊이 계산 실패, 모델 원문 선택 실패를 구분해 범위를 그대로 보고한다. 한 배치 이후 이 계약은 종료하며 동일 문구·seed 변경 자동 반복은 없다. 후속 모델/축/출력 계약은 별도 연구 결정과 실행이 있어야 한다.

## 6. 재현 파일

`raw_recalculation.json`과 `recalculate_raw.py`는 생산 모듈과 분리한 40원응답 계산이다. `production_reaudit.json`은 생산 summary/한국어 보고서의 재실행 일치 확인이다. `independent_rerun.json`은 고정 v070 검산기 재실행이며, `tamper_results.json`은 실제 v070 변조 시험 결과다. 다음 v071 소스와 코드 시험 결과는 별도 배포/검증 자료에 있다.
