## 1. 판정

**값 비교→후보 ID 조회로 선택 절차를 분리한 v085는, 기존 수치 지원군에 남아 있던 D 선택의 위치·ID 의존성을 이번 평가 조건 전부에서 제거했고 실제 D 양방향 종단도 크게 높였다.**

같은 v085 배치 안에서 기존 수치 지원군의 양방향 종단은 31/64, 두 단계군은 60/64다. 구조별 동일 가중치 차이는 **+45.3125%p**, 8개 구조 모두 개선이다. D 선택은 98/128→128/128, 네 표시 전체 양방향 종단은 0/16→13/16이다. 남은 두 단계군 D 실패 4건은 모두 생성 단계에서 발생했다.

이로써 v084의 주된 선택 병목은 이 절차와 평가 범위 안에서는 해소됐다고 판단할 수 있다. W는 비교 64/64이지만 조회 56/64로 남아 있으며, D의 성과를 모든 지표의 완전한 선택 제어로 확대하지 않는다.

T01~T08은 **v084에서 이미 관측한 8개 구조**다. 이번 실험은 그 구조에서 사전 고정한 새 절차를 비교한 결과이며, 새 holdout 8개가 추가된 것은 아니다. 제공되는 D/W는 실험자가 계산한 정확한 외부 정보다. 모델이 수행한 것은 해당 값의 비교·ID 조회와 실제 proof graph 생성이다.

## 4. 구조별 결과와 주평가

D와 W는 얕은 경로 / 깊은 경로 순서다. W는 규칙 수다.

| 구조 | D | W | 직접 양방향 | 수치 지원 양방향 | 두 단계 양방향 |

| T01 | 2 / 3 | 4 / 4 | 0/8 | 6/8 | **8/8** |
| T02 | 3 / 4 | 4 / 4 | 0/8 | 3/8 | **7/8** |

| T08 | 3 / 4 | 5 / 4 | 1/8 | 3/8 | **8/8** |

구조별 두 단계−수치 지원 성공률 차이는 다음과 같다.

```text
T01  +25.000%p
T02  +50.000%p
T03  +37.500%p
T04  +50.000%p
T05  +50.000%p
T06  +50.000%p
T07  +37.500%p
T08  +62.500%p
----------------
동일 가중치 평균 +45.3125%p
개선 8 / 악화 0 / 동일 0 / 미판정 0
```

동일 규칙 수의 T01~T04는 수치 지원 18/32→두 단계 31/32, 규칙 수 역전 T05~T08은 13/32→29/32다. 같은 규칙 수에서 D가 다르고, 얕은 경로에 규칙이 더 많은 구조에서도 성과가 관측됐다. 규칙 수를 D로 대체한 성과가 아니다.

T01·T03·T04·T06·T08의 **5개 구조는 두 seed와 네 표시의 8쌍 전체가 실제 D 종단까지 성공**했다. 나머지 T02는 7/8, T05는 6/8, T07은 7/8이다.

13/16이라는 전표시 성공은 문제×seed 묶음 수다. T02의 첫 seed, T05의 첫 seed, T07의 둘째 seed에서 각각 실패가 남아 세 묶음이 제외됐다. T05의 실패 두 건은 같은 seed에 있으므로 묶음 실패는 한 개다.

구조 수는 8개다. 각 구조의 두 seed×네 표시를 8개의 독립 문제로, 이번 재사용 구조를 새 holdout으로 가산하지 않는다. IID 모집단 추론을 위한 p값은 계산하지 않았다.

## 5. 무엇이 가능해졌는가: 비교와 조회의 관측 분리

| 단계 | D | W |
|---|---:|---:|
| 두 단계군의 정수 min/max 비교 | **128/128** | **64/64** |
| 모델 보고값에 대한 ID 조회 준수 | **128/128** | **56/64** |
| 실험자 정답값을 준 oracle 조회 | **128/128** | **56/64** |

실험자가 계산한 정확한 후보 D/W가 시작 입력이지만, 두 단계군에서 작은/큰 정수를 고른 출력과 해당 후보 ID를 고른 출력은 모두 실제 모델 원응답이다. Python의 argmin/argmax로 최종 후보를 대신 골라 정답 증명을 주입한 실험이 아니다.

첫 단계는 후보 ID·규칙·문제를 받지 않고 숫자와 방향만 받는다. 둘째 단계는 방향을 받지 않고 수치표·metric·첫 응답 원문만 받는다. 192건에서 이 경계와 원문 전달을 검산했다. 비교 스키마는 0~128 정수 범위이며 정답 후보 값만 허용하는 enum이 아니다.

이 결과는 **분리된 입력 계약에서는 값 비교와 D에 대한 ID 조회를 모두 수행할 수 있음**을 보여준다. 기존 결합 입력의 실패를 단순한 정수 비교 능력의 부재나 ID 조회 자체의 불가능으로 설명하기 어렵다. 다만 새 절차는 단계 분리, 입력 문맥 축소, 프롬프트, 출력 형식, 호출 수를 함께 바꿨다. 원래 모델 내부의 특정 계산 하나가 실패 원인이었다고 식별한 결과는 아니다.

### oracle 대조의 해석

실제 비교값이 192/192 모두 정확했기 때문에 두 단계 조회와 oracle 조회의 **요청 바이트는 192쌍 모두 동일**했다. 선택한 ID도 192쌍 모두 같았다. 원문 content까지 같은 것은 177쌍이며 나머지는 표현 차이가 있어도 후보는 같았다.

따라서 oracle 성과를 별도의 192개 독립 조회 문제로 중복 증거화하지 않는다. 이 배치에서는 정확한 목표값을 주어도 W 조회의 동일 오류가 남는다는 진단 역할을 한다.

### 고유 입력 수

D 비교 128호출의 고유 요청은 seed 포함 16종, seed를 제외하면 8종이다. D 조회 128호출은 seed 포함 80종, seed 제외 40종이다. W 비교는 64호출 중 각각 16/8종, W 조회는 64호출 중 32/16종이다. 숫자 하위 과제의 100%를 128개의 서로 다른 산술 문제 해결로 기술하지 않는다. 실제 graph 종단은 8개 구조의 각 조건에서 별도로 측정했다.

ID만 바꾸는 실제 조회 입력 64쌍, 경로와 ID 연결을 유지하며 배열 위치만 바꾸는 64쌍을 검산했다. 기존 수치군은 각각 26쌍·30쌍에서 선택한 실제 경로가 바뀌었다. 두 단계군은 각각 **0/64**다. 이 두 짝짓기는 같은 원응답에 대한 대조이며 128개 추가 추론 표본이 아니다.

기존 수치군이 전부 실패했던 ‘얕은 route_1 첫 번째 / 깊은 route_0 두 번째 / deep 요구’에서는 두 단계군의 선택·종단이 모두 **16/16**이다. 같은 표시의 양방향 종단은 shallow 생성 실패 한 건 때문에 15/16이다. 선택 개선과 생성 한계를 분리해야 하는 구체적 사례다.

## 8. W 결과와 metric-only 조회 대조

| W 지표 | 직접 | 기존 수치 지원 | 두 단계 |

| 네 표시 전체 양방향 선택 | 0/8 | 0/8 | **0/8** |

W도 평균 선택은 개선됐지만 표시 전체 성공은 확보되지 않았다. 같은 조건의 선택 비교에서 두 단계만 성공 22건, 기존 수치군만 성공 4건이다. W의 양방향에서는 각각 16쌍과 2쌍이다.

### 값과 후보가 같은데 metric만 바꾸면 선택이 바뀜

T05 / seed 64001001의 실제 조회 대조:

```text
첫 번째 route_0: goal_depth=3, rule_count=3
두 번째 route_1: goal_depth=2, rule_count=4
value_original: {"target_value":3}

metric=D → 응답 route_0 (정답)
metric=W → 응답 route_1 (오답)
```

두 요청의 원문을 대조했으며 **metric 필드만 D/W로 다르다.** 수치표, 후보 ID·순서, target_value, schema, 안내문, API 옵션, seed는 동일하다. 정답도 두 경우 모두 route_0이다. 조회기에는 min/max 방향을 제공하지 않는다.

이런 D-deep↔W-small 조회 대조는 32쌍이며, D는 32/32 정확하고 W는 24/32 정확하다. **8쌍에서 metric 한 필드 변경에 따라 후보 선택이 뒤집혔다.** oracle 군에서도 동일 결과지만 같은 입력의 반복 진단이므로 새로운 32개 독립 문제로 합치지 않는다.

이 사례에서 target_value=3은 첫 후보의 D와 W 모두에 일치한다. 따라서 관측된 오답을 단순히 W 대신 D 필드를 참조한 것만으로 설명할 수도 없다. 현재 확인된 것은 이 명시적 조회 계약에서의 지표별 응답 차이다. 내부 원인까지 단정하지 않는다.

[D 조회 원요청](v085_review/outputs/selected_raw_examples/t092_two_stage_values_select/request.wire.json) · [D 원응답](v085_review/outputs/selected_raw_examples/t092_two_stage_values_select/response.raw.json) · [W 조회 원요청](v085_review/outputs/selected_raw_examples/t090_two_stage_values_select/request.wire.json) · [W 원응답](v085_review/outputs/selected_raw_examples/t090_two_stage_values_select/response.raw.json).

## 11. 현재 가능한 연구 결론과 다음 우선순위

현재 결과에 맞는 기술:

> 동일한 로컬 모델과 고정 primitive rule 체계에서, 정확한 외부 수치를 제공하는 선택 절차를 값 비교와 후보 ID 조회로 분리했을 때, 기존에 관측한 8개 구조에서 실제 proof DAG의 양방향 D 종단이 기존 수치 지원군 31/64에서 60/64로 증가했다. 사전 구조별 동일 가중치 효과는 +45.3125%p였고 모든 구조에서 개선됐다. 평가한 후보 위치·ID 교차 조건에서 D 선택은 128/128 정확했으며, 실제 graph를 포함한 네 표시 전체 양방향 종단은 13/16이었다.

이 결과는 외부로 관측 가능한 proof structure의 선택적 제어에 대해 이전보다 강한 증거다. 선택 절차의 두 호출 자체를 D=2로 센 것이 아니라, 별도로 생성된 최종 goal의 유효 proof DAG에서 D를 다시 측정했다.

추가로 확보되지 않은 핵심 범위는 **새 절차를 적용한 새 독립 구조집합의 재현**이다. 절차와 생성기를 동결한 신규 구조 검증으로 넘어가는 것이 현재 D 연구의 주된 다음 질문이다. 생성 오류 4건과 W 조회의 metric 민감성은 별도 진단 항목으로 유지하되, 같은 8개 구조에서 계속 표현을 조정하는 작업이 본 연구를 대체하지 않게 하는 것이 맞다.

새 절차는 문맥·형식·호출 수를 포함한 묶음 처치이며, 특정 내부 기제 또는 hidden-state 깊이를 단독으로 제어했다는 결과가 아니다. 또한 제공된 D 수치를 스스로 계산한 실험이 아니다. 이 제한은 실제 D 종단 개선의 관측을 취소하지 않고, 해당 개선이 성립하는 조건을 정한다.

이번 분석에서는 새 모델 호출과 v086 생성 없이 결과 검산·해석만 완료했다.
