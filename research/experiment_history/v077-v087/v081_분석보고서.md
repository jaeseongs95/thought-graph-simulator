## 3. 두 선택 계약과 공통 성공 기준

`candidate_id`군은 `{"candidate_id":"route_0"}`처럼 후보 ID를 답한다. `rule_ids`군은 `{"rule_ids":["u50","u25","u07"]}`처럼 선택한 후보의 규칙 ID를 주어진 순서대로 답한다.

문제·목표·규칙·후보 목록·후보 위치·후보별 ID·seed·API 설정은 같은 조건에서 유지했다. 96개 군간 선택 요청의 실제 input 객체가 같고, 메시지·출력 스키마를 제외한 API 설정도 같음을 확인했다. 달라진 처치는 선택 출력 안내와 JSON 스키마 전체다. 후보 ID는 새 군의 **입력에는 남아 있다**.

규칙 목록 출력 스키마는 문자열 배열 형태만 제한한다. 정답 후보의 목록이나 첫 후보의 목록으로 강제하는 enum은 없다. 출력 목록은 후보의 원래 규칙 순서와 정확히 같을 때만 매핑한다. 호스트의 정렬·누락 보충·가까운 경로 선택이 없음을 원문 재구성으로 확인했다.

공통 생성기는 `explicit_rule`이다. 선택 원문은 각 군의 실제 문자열 그대로 생성기에 전달한다. 따라서 이 실험은 출력 형식이 선택뿐 아니라 후속 생성 입력에 미치는 영향도 포함하는 종단 비교다.

D는 유효한 최종 goal 지지 DAG의 최장 의존 깊이, W는 그 goal을 지지하는 규칙 적용 노드 수다. 생성 성공은 초기 사실·각 규칙 단계·전체 graph·선택 경로 충실성·그 경로의 D/W를 검사한다. 요구한 지표까지 맞아야 종단 성공이다. 잘못 선택한 경로를 정확히 구성한 경우는 생성 성공·종단 실패로 남긴다.

### H01의 직접 사례

H01 두 후보는 규칙 수가 모두 3개이고 D는 2와 3이다. 작은 D 후보가 첫 번째이고 route_0인 표시에서, 기존 ID군은 작은 D에는 D2, 큰 D에는 D3를 골랐다. 목록군은 두 요구 모두 첫 후보의 `["u50","u25","u07"]`를 반환하여 D2를 골랐다. 두 seed에서 같은 선택 패턴이 나타났다.

후보 위치를 뒤집으면 목록군은 작은 D를 요구해도 첫 위치의 D3 경로 `["u76","u70","u79"]`를 골랐다. H01의 증명 생성은 두 군 모두 16/16이므로, 이 양방향 차이는 생성 오류가 아니라 선택 오류다.

규칙 단계 분모가 다른 것은 두 군의 선택 경로가 달랐기 때문이다. 초기 사실·final은 모두 맞았지만, 787개 규칙 단계 중 45개가 실패했다. 45개 모두 실제 전제와 부모 노드의 원자가 맞지 않는 오류였고, 실패 증명은 41개다. 규칙 오류 수와 증명 실패 수를 섞지 않는다.

### 같은 경로를 선택한 조건끼리만 보면

같은 경로를 선택한 조건은 D 58개, W 17개, 합계 75개다. 이 75개에서 전체 생성은 양쪽 성공 53, **ID군만 성공 11**, **목록군만 성공 1**, 양쪽 실패 10이다.

따라서 생성의 낮아진 총계를 ‘더 어려운 경로를 골랐기 때문’ 하나로 전부 설명할 수 없다. 반면 선택 출력 원문이 생성 입력에 그대로 들어가므로, 이것을 생성기 코드 자체만의 인과 효과로 부르지도 않는다.

### H03 긴 경로의 연결 오류가 커졌다

본실험 D/W를 합친 H03의 D3 경로 생성은 ID군 **19/22**, 목록군 **1/16**이다. D2 경로는 각각 10/10, 16/16이다. 두 군의 경로 배정이 다르므로 이 분모를 같은 표본으로 취급하지 않는다.

남은 긴 경로의 대표 규칙은 `w04: L76 → L96`이다. 목록군은 16회 중 15회에서 필요한 L76 대신 그 앞 단계의 L54와 L50을 연결했다. 현재 고정 규칙 계약에서 이는 w04의 전제를 충족하는 부모 연결이 아니다.

`t065_explicit_rule_rule_02`와 `t065_rule_ids_rule_02`는 문제·규칙·선택 경로·이전 모델 응답 문자열·현재 operation·API 설정이 같았고, **selection_original.content만 달랐다.**

```text
공통 이전 노드:
n003 = L50
n004 = L54
n005 = L76

공통 현재 규칙:
w04: L76 → L96

ID군 선택 원문:
{"candidate_id":"route_0"}

목록군 선택 원문:
{"rule_ids":["w96","w89","w04"]}

ID군 실제 부모:   [n005]       → L76       → 유효
목록군 실제 부모: [n004,n003]  → L54,L50   → 실패
```

이 사례만으로 내부 메커니즘을 특정하지 않는다. 같은 종류의 통제에서 반대 방향 사례도 있었다. H04 `t108`의 `x21: M46 → M19`에서는 ID군이 M32,M60을 연결하여 실패했고 목록군은 M46을 연결하여 성공했다.

이전 원응답까지 같고 선택 원문 내용만 다른 규칙 단계 151개에서는 양쪽 유효 144, ID군만 유효 1, 목록군만 유효 1, 양쪽 실패 5였다. 이 부분집합을 독립 문제 151개 또는 전체 생성 악화의 단독 원인 추정치로 쓰지 않는다. 분석의 의미는 **선택 출력 형식이 후속 생성 입력과 무관하지 않다**는 것과, 실제로 관측한 양쪽 방향의 차이를 보존하는 것이다.

### H02의 잔여 문제

H02 D4 경로는 ID군 0/10, 목록군 0/8, 참조 0/2로 모두 실패했다. 특히 `v15: K36 AND K98 → K43`에서 부모를 잘못 연결하는 문제가 남았다. H02 D3 경로는 ID군 6/6, 목록군 8/8, 참조 2/2로 모두 유효했다.

H02 D 종단의 2/16 → 4/16 증가는 일부 단방향 성과이며, 깊은 경로 생성이나 양방향 제어의 해결로 바꾸어 쓰지 않는다.

## 11. v080과의 비교

이번 ID군의 선택 96개는 v080과 **요청 bytes 96/96, 응답 content 96/96, 응답 JSON 96/96 모두 같았다.** 기존 ID군의 선택 패턴은 이번 배치에서도 그대로 관찰됐다.

본실험 ID군과 공통 참조의 생성 호출 643개는 v080과 다음과 같았다.

```text
요청 bytes 동일: 607/643
응답 content 동일: 610/643
응답 JSON 값 동일: 629/643
요청 bytes가 같지만 응답 content가 다른 경우: 14개
```

따라서 선택 96개가 같다는 사실을 생성 원응답 전체의 완전 동일성으로 확대하지 않는다. 같은 요청·seed에서 다른 content도 관찰되지만, 실제 원인을 GPU·캐시·서버 등으로 특정하지 않는다.

이 대조는 기존 결과를 새 응답 대신 재사용했다는 뜻이 아니다. 현재 v081 원응답을 먼저 채점한 뒤 보존된 v080 원문과 비교한 것이다.

## 13. 연구상 해석과 종료 판단

### 이번 자료가 직접 지지하는 것

1. 이번 목록 출력 계약에서 복사·매핑 자체는 실패하지 않았다.
2. 요구에 따른 양방향 선택은 개선되지 않았고, 첫 후보 반환과 96/96 일치했다.
3. ID 출력 의무를 제거하는 것만으로 위치 민감성까지 해결되지 않았다.
4. 선택 출력 원문은 후속 생성 입력의 일부이므로, 동일 경로에서도 생성 성과 차이가 관찰됐다.
5. 기존 ID군의 H01 부분 성공과 W 적게 선택 성공은 보존됐다.

### 이번 자료로 판단하지 않는 것

- 모든 규칙 목록 출력 계약이 항상 실패한다는 결론.
- 4B 모델의 내부 용량이나 깊이 계산 능력이 확정 원인이라는 결론.
- 모델이 D 계산·값 비교·지시 적용 중 어느 내부 단계에서 실패했는지의 확정.
- D를 최장 의존 경로로 계산한 기존 지표가 잘못됐다는 결론.
- 네 진단 구조·두 seed·여러 표시를 새로운 독립 문제 수로 확장하는 결론.

이번 자료의 부정적 결론은 구체적으로 **‘출력에서 후보 ID 대신 규칙 목록을 요구하는 이번 개입이 선택과 종단 제어를 개선한다’는 가설**에 해당한다. 후보 ID가 입력에도 없어진 실험은 아니다. 두 군의 실제 처리 내부를 관측하지 않았으므로 내부 원인을 새로 만들어 설명하지 않는다.

**운영 판단:** v081은 완료한 짝대조 배치로 종료하고 보존한다. `rule_ids`를 기본 선택기로 승격하지 않고, 기존 `candidate_id + explicit_rule` 계약을 비교 기준으로 유지한다. 이 기준을 안정적인 D 제어의 완성본이라고 부르지는 않는다.

다음 연구의 주된 과제는 여전히 요구 지표를 실제 선택에 반영하는 것이다. 단순한 출력 형식 변경을 계속하면 해결될 것이라고 이번 결과로 예측할 근거는 없다. H02 긴 경로와 H03 목록군의 연결 오류는 별도 생성 문제로 기록한다. 이번 분석에서는 v082나 다른 신규 실험 소스, 가드 삭제, 모델 재실행을 수행하지 않았다.
