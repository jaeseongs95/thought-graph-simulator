## 1. 결론

**현재 계약에서 D와 W를 요구 방향에 맞게 양방향으로 구별하고, 후보 위치·ID를 바꾸어도 유지되는 제어는 확보되지 않았다.** D 본실험 종단은 25/64, 양방향 종단은 2/32쌍이다. 위치2×ID2의 네 표시 모두에서 양방향 성공한 문제×seed 묶음은 0/8이다. H03/H04에서 D 작게·크게, W 적게·많게의 네 요구를 모두 맞힌 조건은 선택 및 종단 모두 0/16이다.

그러나 이전 H01 부분 성공은 이번에도 존재한다. 원래 표시 조건에서는 규칙 수가 각각 3개인 두 유효 증명의 실제 D가 2와 3으로 요구에 맞게 달라졌고, 두 seed에서 반복됐다. ID 배정만 바꾸면 이 양방향 성공이 사라졌다. 따라서 **부분 성공을 폐기할 결과가 아니라, 그 성공이 후보 표시를 바꾸어도 유지되지는 않는다는 범위를 더 정확히 확인한 결과**다.

## 4. D 선택은 첫 위치에 강하게 좌우됐다

D의 32개 양방향 쌍은 정방향 2쌍, 요구가 바뀌어도 같은 후보 26쌍, 역방향 4쌍이다. 역방향 4쌍 중 H03의 2쌍은 두 graph도 모두 유효하며 실제 D가 요구와 반대로 바뀌었다. H02의 역방향 2쌍은 긴 경로 생성에 실패했으므로 유효 두 graph의 역전으로 세지 않는다.

전체 D 선택에서 첫 위치 58/64, `route_0` ID 30/64였다. 후보 ID가 첫 위치에 붙어 있던 기존 설계와 달리, 이제 두 수치를 분리해 볼 수 있다.

원요청 bytes를 대조하여 두 가지 비교를 각각 만들었다.

| 유지한 것과 바꾼 것 | D에서 실제 선택 경로가 바뀜 | W에서 실제 선택 경로가 바뀜 |
|---|---:|---:|
| 문제·후보 순서 고정, 후보 ID만 교환 | 6/32짝 | 7/16짝 |
| 문제·후보별 ID 연결 고정, 두 후보의 표시 위치만 교환 | 26/32짝 | 1/16짝 |

두 번째 비교는 단순히 `order` 인덱스만 바꾼 비교가 아니다. 후보별 ID 연결을 보존하기 위해 `order`와 `labels`를 함께 반전하여, 실제 입력에서는 **candidates 배열의 순서만 바뀐 것**을 확인했다. 첫 번째 비교에서는 배열 순서는 그대로 두고 후보의 두 ID만 교환했다. 출력 스키마 enum 순서, seed, 나머지 요청 설정은 동일했다.

따라서 현재 관찰에서 **D는 첫 위치에 대한 반응이 우세하지만, ID 영향도 존재**한다. 단순 빈도를 모델 내부 원인의 확정적 설명으로 바꾸지 않는다. 위 짝비교들은 기존 조건의 재분석이며 새 실험 표본이 아니다.

## 5. W는 일부 비교가 명확하게 작동하지만 양방향은 ID에 취약했다

W 작은 값 요구는 **16/16 선택 정답**이다. H03/H04의 두 seed와 네 위치×ID 표시 전부에서 규칙이 적은 후보를 골랐다. 이 한 방향의 성공은 실제로 유지됐다.

그러나 W 큰 값 요구는 9/16이며, **16회 중 15회 `route_1`을 선택**했다. H03에서는 큰 값 요구 8/8이 `route_1`, H04에서는 7/8이 `route_1`이었다. 큰 값 후보가 어느 ID에 붙었는지에 따라 상당수 정오가 달라졌다.

| 요구 방향 | 선택 | 경로 생성 | W 종단 | route_1 선택 |
|---|---:|---:|---:|---:|
| 규칙 수가 적은 후보 | 16/16 | 15/16 | 15/16 | 8/16 |
| 규칙 수가 많은 후보 | 9/16 | 16/16 | 9/16 | 15/16 |

따라서 W를 완전히 제어한다고 보고하지 않는다. 동시에 W 비교가 전혀 없었던 것도 아니다. ‘적은 것 선택’은 모든 표시에서 정확했고, ‘많은 것 선택’에서 특정 ID 고정이 강하게 나타났다.

위치만 바뀌고 후보별 ID가 유지될 때 W 경로는 15/16짝에서 같았지만, ID만 교환하면 7/16짝에서 경로가 바뀌었다. 그 7짝은 모두 큰 값 요구다. D의 우세한 첫 위치 반응과 W 큰 값의 ID 반응이 구별된다.

## 6. D와 W를 같은 조건에서 비교하면

D 전체에는 H01/H02도 포함되므로, D 30/64와 W 25/32만으로 직접 비교하지 않는다. 두 요구가 모두 배정된 H03/H04에 한정하면 다음과 같다.

| 동일 문제·seed·위치·ID 조건 | D 요구 | W 요구 |
|---|---:|---:|
| 선택 | 14/32 | 25/32 |
| 선택 경로 생성 | 29/32 | 31/32 |
| 요구 지표 종단 | 13/32 | 24/32 |
| 양방향 선택 | 0/16 | 9/16 |
| 양방향 종단 | 0/16 | 8/16 |

생성기는 두 지표 조건에서 동일하며, 선택된 경로를 구성한다. 경로 배정과 실제 응답이 다르므로 생성률 차이를 W 지시가 생성기를 직접 개선한 효과로 해석하지 않는다.

이 조건의 후보들은 D와 W가 반대로 움직인다. 그런데 네 요구를 전부 맞힌 조건은 0/16이다. 생성기를 제거하고 선택만 보더라도 이미 0/16이므로, 이 구별 지표의 실패를 생성 오류로 설명할 수 없다.

### 구체적인 네 요구 사례: H03, seed 64001001, order=0, labels=1

```text
첫 후보 A = route_1: D=2, W=4
둘째 후보 B = route_0: D=3, W=3
```

| 요구 | 정답 | 실제 선택 | 판정 | 해당 시행 |
|---|---|---|---|---|
| D 작게 | A | A | 성공 | t049 |
| D 크게 | B | A | 실패 | t048 |
| W 적게 | B | B | 성공 | t046 |
| W 많게 | A | A | 성공 | t047 |

네 번 모두 실제 graph는 유효하다. **D/W 지시를 바꿨을 때 반응이 전혀 없는 것이 아니라, 필요한 네 선택 중 큰 D 요구를 놓쳤다**는 사례다. 전 조건에서 안정적인 구별은 미확보지만 일부 방향의 구별은 보존해야 한다.

같은 문제·표시·seed·방향에서 D와 W 요청을 비교한 32짝 중 경로가 달라진 것은 13짝, 두 선택이 각각 모두 정답인 것은 10짝이다. 그러나 이를 네 요구 전부의 성공으로 승격하지 않는다. 나머지에는 한 지표만 맞거나 두 지표 모두 틀린 반응도 있다.

H04 seed 64001001, order=0, labels=0은 특히 주의할 사례다. D 요청에서는 두 방향 모두 첫 후보, W 요청에서는 두 방향 모두 둘째 후보를 골랐다. 지표를 바꿀 때 두 방향의 선택이 모두 뒤집혔지만 네 정답 중 2개만 맞았다. 따라서 ‘D와 W의 선택이 달라졌다’만으로 성공 처리하지 않은 사전 기준이 필요했다.

이 결과만으로 D를 계산했는지, 비교 단계에서 틀렸는지, 선택할 후보를 ID에 대응시키다가 틀렸는지는 구분하지 못한다. 현재 모델 응답은 candidate_id 하나이며 숫자 계산이나 내부 처리 이력은 관측하지 않았다. D와 W의 지시문·입력 키도 의미에 맞게 서로 다르므로, 특정 단어 하나의 순수한 효과나 일반적인 인지 난이도 비교로 확장하지 않는다.

## 8. v079와의 비교에서 유지할 것

기존 ID 배정에 해당하는 D 선택 32개를 v079의 실제 요청과 대조했다. **요청 bytes 32/32, 응답 content 32/32, 선택 JSON 32/32가 모두 같았다.** 기존의 선택 패턴이 이번 배치에서 그대로 관찰됐다.

## 9. D 정의와 연구 방향에 대한 의미

이번 결과는 **D를 규칙 개수와 분리해서 측정하는 계산식 자체가 틀렸다는 결과가 아니다.** 실제 후보와 생성 graph에서 규칙 수 동일/D 상이, 규칙 수-D 역전 관계가 재계산으로 확인됐고, 별도 오프라인 교정도 87/87 통과했다.

반면 올바른 측정 도구를 사용한다는 사실과 모델이 그 지표를 안정적으로 제어한다는 사실은 다르다. v080에서 부정적으로 나온 것은 **현재 모델·프롬프트·선택 인터페이스에서 D와 W 요구를 양방향으로 구별하고 표시 변화에도 유지하는 행동**이다.

원 연구의 D=Decomposition 전체를 재정의하거나 포기한 실험도 아니며, 인간의 사고 깊이 또는 모델 내부 hidden state를 직접 측정한 실험도 아니다. 현재 조작적 지표는 고정 규칙 체계에서 실제 산출한 유효 증명 DAG의 의존 깊이다. 규칙 단위를 분할·압축하는 실제 모델 실험은 이 배치에 포함되지 않았다.

현재까지 유지할 결론은 다음과 같다.

- 서로 다른 D의 유효한 graph 생성은 실제로 관찰됐다.
- 같은 규칙 수에서 요구에 맞는 양방향 D 부분 성공도 H01의 기존 표시에서 재관찰됐다.
- 그 성공은 후보 ID·위치를 바꾸어도 유지되는 제어로 일반화되지 않았다.
- W 작은 값 선택은 두 진단 구조·두 seed·네 표시 모두에서 정확했다. W 큰 값과 D 양방향까지 일반화하지 않는다.
- H03/H04의 네 요구 모두 정답은 0/16이다. 현재 계약의 지표 구별 양방향 제어는 미확보다.

4개 구조를 이미 관찰한 진단으로 사용했다. 96개 선택, 112개 증명, 여러 seed·ID 조합 또는 여러 검산 구현을 새 독립 구조 수로 세지 않는다. 단순 정답률의 유의성이나 모델 전체에 대한 순위를 이 자료에서 추정하지 않았다.

## 10. 소스와 운영 판단

검토한 범위에서 생산 집계의 D/W 혼합, 잘못된 후보 ID 매핑, 실제 경로 보정, 잘못된 부모의 사후 수정은 발견하지 않았다. 사전 기준대로 선택·생성·종단·표시 전 조건·네 요구 구별을 각각 계산하고 있다. D/W 네 요구를 모두 틀리게 뒤집어도 단순 차이만으로 통과시키지 않는 반례도 재검사했다.

`pairs.valid_graph_direction`의 `unmeasured`는 이번 완료 배치에서는 유효한 두 graph가 모두 성립하지 않아 방향을 계산하지 않았다는 뜻이다. 실행이 미관측이었다는 뜻과는 다르다. D에는 이런 쌍이 8개, W에는 1개다. 본 보고서는 이를 ‘유효 두 graph 미성립’으로 구별한다.

**운영 판단:** v080은 계획된 진단을 완료한 배치로 닫고 결과를 보존한다. v079의 생성 개선과 H01의 부분 성공을 지우지 않되, 현재 표시 변화에 강한 D 제어를 확보했다고 보고하지 않는다. 다음 종단 연구의 우선 대상은 여전히 선택기다. 다만 ID/위치에 대한 행동 패턴과 내부 원인을 혼동하지 말고, H02의 긴 경로 구성 실패도 별도의 잔여 문제로 남긴다.

이번 분석에서는 v081 또는 다른 신규 실험 소스 작성, 가드 삭제, 모델 재실행, 자동 후속 실행을 하지 않았다. 생성한 Python 파일은 기존 evidence의 읽기 전용 분석·검산 코드다.
