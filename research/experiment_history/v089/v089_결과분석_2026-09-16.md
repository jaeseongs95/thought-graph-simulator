초기 ID 방식: atom_alias는 ID=원자명, atom_tagged는 `node_원자명`, short는 `n0001`, long은 `v087_node_0001` 계열이다. 후속 출력에도 같은 네 방식을 적용했다.

독립적으로 확인한 통제는 다음과 같다.

- 초기 facts 512개 재명명: 순서·원자·사실 의미는 같고 ID만 지정 방식으로 변경.
- 후속 ID 2,240개: 원자·순번으로 별도 재구성해 요청과 일치.
- 동일한 후속 ID 방식의 초기 4군: 128세트에서 새 ID sequence가 동일.
- 128세트의 첫 요청: 초기 facts ID만 정규화하면 나머지 요청이 동일.

## 6. 원인 해석: v088의 구조별 혼입을 줄였지만 단순한 하나의 법칙은 아니다

### 6.1 atom_alias에서 중립 ID로 전환하는 조건의 실패가 직접 재현됐다

v088에서는 초기 ID 유형이 구조·경로와 함께 달라져 유형별 대조가 제한됐다. v089는 모든 구조·경로·seed에 네 초기형을 교차했다. `atom_alias→long`의 32개 실패 전부와 `atom_alias→short`의 27개 실패 전부는 **없는 부모 ID 참조가 최초 오류**였다.

규칙 단위로는 각각 84개·79개에서 missing_parent가 발생했고, 이 모든 규칙의 누락 ID 문자열은 이미 존재하는 원자명과 일치했다. 이 수에는 이전 실패 후의 오류 전파가 포함되므로 graph 실패 수와 합산하지 않는다.

초기·후속 모두 long 또는 short로 통일하면 missing_parent는 0개였고, 남은 최초 실패는 전제 연결 오류였다. 따라서 초기 원자–ID 대응에 개입한 것이 후속 참조 오류와 종단 성공을 바꾼다는 증거가 됐다.

### 6.2 ‘이름이 섞이면 무조건 실패한다’는 설명은 맞지 않는다

`short→long`은 13/32, `long→short`는 12/32였다. 이들은 서로 다른 이름 계열이 섞이지만 atom_alias→중립형의 0/32·5/32보다 높다. `atom_tagged→long`은 20/32로 long→long 19/32보다 1개 많다. 따라서 이름 계열 혼용 그 자체만으로 전체 차이를 설명할 수 없다.

반대로 중립형에서 atom_alias로 바꾸는 역방향도 short→alias 7/32, long→alias 8/32였다. 후속 ID를 읽기 쉬운 원자명으로 바꾸는 것만으로는 충분하지 않다. 이 방향은 최초 전제 오류가 22개·19개로 많고 최초 참조 오류는 3개·5개였다. 전환 방향에 따라 실패 유형도 다르다.

**현재 가능한 결론은 원자–ID 대응 계약의 초기·후속 조합이 중요하다는 것**이다. 모델 내부의 attention, 학습된 복사 경향, 토큰화 등 어느 기제가 이 차이를 만들었는지는 직접 분리하지 않았다.

### 6.3 완전 동일 문자열만이 유리한 조건은 아니다

alias 유지 29/32 외에 tagged 유지도 28/32였다. tagged는 ID와 원자명이 완전히 같지는 않지만 원자명을 포함한다. 따라서 ‘ID=atom이어야만 가능하다’보다 **원자명을 식별할 수 있는 일관된 명명 체계가 유망하다**는 해석이 결과와 맞는다. 문자열 길이만의 효과를 분리한 실험은 아니다.

short 대조에서는 참조 실패 27개가 uniform에서 성공 13개와 전제 실패 14개로 나뉘었다. long 대조에서는 참조 실패 32개가 성공 19개와 전제 실패 13개로 나뉘었다. 따라서 전제 오류가 더 많이 집계된다는 사실만으로 uniform이 전제 판단을 악화시켰다고 결론 내리지 않는다. 개별 경로의 실패 유형 전이를 봐야 한다.

`atom_alias→long`과 `atom_alias→short` 모두 첫 규칙은 32/32 성공했다. 두 번째 규칙에서 각각 18/32가 처음 실패했다. 같은 단계에서 short→short는 2/32, long→long은 0/32가 실패했다. 첫 규칙 뒤 새 노드가 history에 들어간 다음 단계가 분기점이라는 기존 관찰이 재현됐다.

다만 모든 조합의 첫 규칙이 100%인 것은 아니다. tagged→alias는 첫 규칙부터 13개가 실패했고 tagged 유지에서도 첫 규칙 전제 누락 2개가 있었다. 따라서 ‘모든 이름 효과는 반드시 두 번째 이후에만 나타난다’고 일반화하지 않는다.

A 전체의 303개 실패 graph의 최초 오류는 참조 163개와 전제 140개였다. A final 지칭 실패 2개는 이미 앞 규칙에서 실패한 graph의 후속 오류다. 이를 별개의 실패 graph로 더하지 않는다.

## 8. 실제 원응답 사례

### 8.1 같은 U04 shallow의 두 번째 규칙

규칙은 `F83 AND F78 AND F85 → F58`이다. alias→long에서는 facts ID가 F83·F78인데 새 F85 노드의 ID는 v087_node_0004다. 모델은 `parents=["F83","F78","F85"]`를 출력했다. F85라는 ID는 없으므로 실패다.

long→long의 같은 위치에서는 `parents=["v087_node_0002","v087_node_0003","v087_node_0004"]`로 정확히 연결했다. 두 조건의 현재 출력 ID는 모두 v087_node_0005다. 즉 현재 ID 지정 준수와 후속 parent 재참조는 분리된다. 요청과 응답은 `examples/x03s0_shallow_*_rule_01/`에 그대로 보존했다.

### 8.2 U06의 직접 전제 H15 누락

규칙은 `H15 AND H02 AND H44 → H74`다. long 유지에서는 H02·H44에 해당하는 ID만 부모로 출력해 H15를 누락했다. alias 유지에서는 `parents=["H15","H02","H44"]`로 맞았다. 같은 두 seed에서 U06 shallow는 중립 유지 두 군 모두 0/2, alias 유지와 tagged 유지는 모두 2/2였다.

이는 이전에 전제 오류로 남았던 경로도 표상을 바꾸면 성공할 수 있음을 보여준다. 하지만 별도의 원인 기제를 식별한 것은 아니며, 전제 오류가 전부 ID 문제라고 환원하지 않는다.

## 9. 높은 성과의 두 의미 ID 조건에도 서로 다른 실패가 남았다

### atom_alias 유지: 3개 실패

- U07 deep / seed 64001001: `I91 AND I43 → I32`에서 부모를 I77·I43으로 출력. I91 대신 다른 사실 I77을 선택했다.
- U08 deep / 두 seed: `J07 AND J31 AND J03 → J74`에서 J03을 누락했다.

세 오류는 전부 두 번째 규칙에서 처음 발생했다. ID 조회를 원자명 복사로 단순화해도 잘못된 직접 전제 선택·누락은 남는다. 이 조건은 U01~U06에서 각 4/4 성공했지만 U07 3/4, U08 2/4였다.

### atom_tagged 유지: 4개 실패

- U03의 두 경로·seed 조합에서 첫 단항 규칙의 parents를 빈 배열로 출력했다.
- U06 deep의 두 seed에서 `node_H28`, `node_H96` 대신 `node_28`, `node_96`를 출력했다. 접두부는 유지했지만 원자명의 H를 빠뜨려 존재하지 않는 ID가 됐다.

따라서 모든 uniform 조건에서 참조 오류가 0이라는 법칙은 아니다. 이번 short/long/alias 유지에서는 0이었지만 tagged 유지에서는 2개였다.

두 의미 ID 군의 실패 경로는 겹치지 않았다. 둘 다 성공 25개, alias만 성공 4개, tagged만 성공 3개다. 이것은 경로별 표상 민감성에 대한 추가 관찰이다. 둘을 사후에 합쳐 32/32를 하나의 생성기 성과로 보고하지 않는다. 두 번 실행해 검증기로 선택하는 전략은 호출량과 성공 정의가 다른 별도 실험이다.

### 동일 입력의 실제 재현성

v088과 비교한 compare·select 각 128개는 요청과 reply content가 모두 동일했다. facts 128개는 요청이 모두 같지만 content가 동일한 것은 110개였다. rule은 560개 중 요청이 동일한 것이 333개, 그중 content까지 동일한 것은 255개였다. final은 128개 중 요청이 동일한 32개가 모두 같은 content를 냈다.

이는 같은 보존 요청에서도 일부 생성 content가 달랐다는 관찰이다. 공백 차이까지 포함하는 바이트 비교이며, 곧바로 의미 차이나 특정 runtime 원인으로 해석하지 않는다. source·모델·요청 조건이 유지됐다는 사실과 응답이 완전히 동일하다는 주장을 구분한다. 변경 원인으로 업데이트·GPU·캐시 등을 특정하지 않았다.

## 12. 연구상 의미와 다음 판단

이번 결과는 v088의 ‘초기 ID 유형과 구조가 함께 달랐다’는 공백을 동일 구조의 4×4 교차로 줄였다. 사전 주평가가 양수였고, 참조 오류에서 성공 또는 전제 오류로 이동하는 대응 경로가 확인됐다. 따라서 기존 실패를 모델 크기나 추론 깊이 하나로 묶기보다 **표현 계약의 전환, 식별자 참조, 직접 전제 연결**로 나눠 분석할 근거가 강화됐다.

또한 국소 alias 140/140에서 곧바로 종단 100%를 가정하지 않고 실제 연속 생성으로 확장한 결과가 29/32였다. 유망한 효과는 이어졌지만 국소와 연속 성공은 다르다는 기준도 유지됐다.

현재의 직접 성과는 고정된 primitive inference system에서 외부 proof DAG의 D를 다시 계산한 결과다. 교차군은 유효 초기 facts·경로·규칙·현재 ID를 지원받았다. 따라서 29/32를 새 facts·선택 포함 D 종단의 개선 수치로 바꾸지 않는다.

다음 단계에서 우선 확인할 것은 **baseline과 의미 ID 유지 두 군을 같은 ‘새 선택·새 facts’ 출발점에서 비교하는 것**이다. 지원 정보·부모 자유도·실패 채점·모델 호출수·원응답 무보정 원칙을 맞춰야 한다. 그 절차를 사전에 동결한 뒤 신규 구조에서 재현해야 기존 구조에 맞춘 개선인지도 구분할 수 있다. 현재 baseline을 즉시 교체할 종단 대조는 아직 없다.

이 문서는 실제 v089 결과 분석이다. 다음 버전 설계·소스나 추가 모델 실행을 생성하지 않았다.
