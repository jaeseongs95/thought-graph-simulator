# v089 실험설계 및 최종 배포 검증

작성일: 2026-09-16 KST

## 작성 완료

v088 결과의 초기 ID 유형–구조 혼재를 줄이기 위해 **동일 구조·경로·seed에서 초기 ID 4종 × 후속 ID 4종**을 완전 교차한다. 16조합은 각각 32개 지원 연속 graph다. 기존 D baseline은 별도로 새 선택·새 facts부터 128개 graph를 생성한다. 실패했던 allocated_id를 기본 생성기로 승격하지 않는다.

명명 방식은 atom_alias, short, long, atom_tagged다. 같은 후속 방식의 새 ID sequence는 초기 방식이 달라도 동일하다. 모든 교차군은 같은 ID 지정 header/enum을 사용하며, 부모·원자·규칙의 정답을 새로 강제하지 않는다. 의미 ID는 이미 제시된 규칙 결론의 의미 단서를 포함하는 처치로 명시했다.

주평가는 각 구조의 양방향 성공률에서 `0.5 × [(short→short − atom_alias→short) + (long→long − atom_alias→long)]`을 구한 뒤 8개 구조를 동일 가중한다. 중립 이름끼리 전환하는 조건 및 alias 연속 조건 등은 사전 보조 대비로 둔다. 전체 세부 계약은 PREREGISTRATION_v089.ko.md와 protocol.json에 있다.

## 배정

| 항목 | 수 |
|---|---:|
| 구조 / seed | 8 / 2 |
| 4×4 지원 연속 graph | 512 |
| 새 선택·새 facts baseline graph | 128 |
| 전체 trial | 640 |
| 목표 경로 선택 시 inference | 3,824 |
| 최대 inference slot | 3,856 |
| metadata action | 32 |
| 전체 action slot | 3,888 |

위 수는 새 모델 성과가 아니라 동결한 실행 배정이다. 목표 경로를 선택한 경우 남는 32개의 규칙 슬롯은 조건부 skip이다. 미관측 응답과 혼동하지 않는다.

## 실제 수행한 검증

최종 source ZIP을 추출해 기존 v088 manifest·guard·실패 로그가 있는 모사 저장소에 설치한 뒤 시험했다. 이후 실제 `launch.py --check-only --all-tests` 전체 흐름도 같은 설치본으로 실행했다.

- 고유 자체시험 88개: **87 pass, 0 failure, 0 error, 1 skip**. 두 번 수행한 같은 테스트를 176개 새 테스트로 세지 않았다.
- 제외된 1개: 이 환경에 PowerShell 실행 파일이 없어 네이티브 파서 시험 제외.
- 정상/반례 calibration **22,160개 통과**: 규칙 19,600 + graph 2,560.
- 생성기와 별도 구현의 요청 재구성 **3,824건 byte-identical**.
- 생산/독립 의미 판정 **640 trial 일치**.
- 기존 v088 실제 baseline 요청 **1,072건 byte-identical**.
- 이전 v088 실행 소스 **115파일 byte-identical**.
- Python 3.12 문법 **108파일 통과**.
- 설치 manifest와 ZIP, PS1 내장 ZIP, selftest 및 합성 실행 source snapshot **146파일 일치**.
- 전송 오류/identity 중단/중단된 dispatch/응답 저장 후 event 미기록/변조/잘못된 manifest/guard 재시작 차단 시험 통과.
- CheckOnly는 live guard와 plan.started를 생성하지 않았으며 v088 manifest·guard·실패 로그를 그대로 보존했다.

## 사용 명령

먼저 Run-v089-Auto.ps1을 Downloads에 저장하고:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v089-Auto.ps1" -CheckOnly -AllTests
```

검사 완료 후 실제 실험:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v089-Auto.ps1"
```

실제 실행은 기존에 켜져 있는 Ollama 0.34.1 및 동일 qwen3:4b-instruct를 확인한다. 서버 시작·모델 다운로드/갱신은 하지 않는다. 중단된 배치의 guard를 삭제하거나 새 RunName으로 우회하지 않는다.

새 설치 경로는 llm_experiments/v089/probe, 전용 manifest는 RELEASE_MANIFEST_v089.json이다. v088는 수정하지 않는다. CheckOnly에서 만든 RunName은 실제 실행에 다시 지정하지 않는다.

## 남은 실제 제약

개발 검증은 Linux/Python 3.13.5에서 수행했다. Windows 네이티브 PowerShell/Python 3.12 실행 여부는 사용자 로컬 CheckOnly에서 확인한다. 여기서 실제 Qwen 추론이나 v089 연구 결과를 생성하지 않았다. 현재 8개 구조 범위를 넘어선 holdout, 새로운 facts부터 시작하는 alias 종단, 모델 내부 제어를 달성한 것으로 기록하지 않는다.
