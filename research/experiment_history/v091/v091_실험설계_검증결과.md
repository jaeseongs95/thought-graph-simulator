# v091 — 신규 구조·재명명 분리 실험: 설계와 검증 결과

작성일: 2026-09-16 KST. 이 문서는 소스 제작과 배포 검증 결과다. **실제 v091 Qwen 실험은 아직 수행하지 않았다.**

## 1. 구현한 실험

v090에서 사용한 네 생성군의 절차·프롬프트·schema·sampling·채점을 동결했다. 새 선택과 각 군의 새 facts에서 시작하는 종단 평가를 유지하며, 다음 세 묶음을 하나의 배치에서 실행하되 결과는 분리한다.

| 평가 묶음 | 대상 | 새 graph | 목적 |
|---|---|---:|---|
| known_original | U01~U08 원형 | 512 | 같은 배치에서 기존 성과와 실패 재확인 |
| known_renamed | 같은 U 구조의 R1 재명명 | 512 | 구조를 유지한 원자명·규칙명 변경의 효과 |
| new_topology | V01~V08 | 512 | 새로운 의존 구조에서의 효과 검증 |

주평가는 **신규 8개 구조의 atom_alias − baseline 엄격 양방향 종단 성공률 차이를 구조별로 동일 가중한 값**이다. 기존·재명명 성적을 합산하거나, 결과를 본 뒤 tagged로 주평가를 교체하지 않는다.

생성군은 baseline, short_uniform, atom_alias, atom_tagged다. 전체 1,536개 graph, 768개 pair, 192개 네 표시 bundle을 평가한다. 원형과 R1은 같은 topology이므로 구조 수는 기존 8개 + 신규 8개 = 16개이고, 제시되는 문제 표면형은 24개다. 각 cohort의 각 군에는 128개 graph, 64개 pair, 16개 bundle이 배정된다. seed 2개·표시 4개·요구 방향 2개는 기존과 같다.

## 2. 구조 검사와 새 진단

신규 16개 경로는 보존 자료에서 확인한 과거 39개 고유 경로 및 서로 간에 비동형이다. 생산 정규형과 별도로 간선 보존 기반의 독립 동형성 비교 744회를 수행했다. 새 경로는 대응 U 경로의 D·규칙 수·facts 3개·전제 수 범위 1~3을 맞춘다. 개별 규칙의 전제 수나 결합 형태까지 동일하게 유지한 것은 아니다.

생성 seed 9101601, 재명명 seed 9101602를 고정했고, 모델을 호출하지 않은 상태에서 사전 조건을 처음 만족한 후보를 채택했다. 이는 보존 자료와의 구조 비중복 검사이지 모델 사전학습 미노출의 증명은 아니다.

R1은 원자명·규칙명의 전단사 변환이다. topology·D·규칙 수·facts 순서·premise 순서·rule 제시 순서를 보존하고, 기호의 prefix와 문자 길이도 유지한다. 원형/R1의 모델 입력에서는 problem ID와 논리 source ID를 맞추고, 물리 실행 ID만 별도로 관리한다. 실제 입력의 감사용 metadata를 제거하는 처치는 넣지 않았다.

새 진단에는 이전 parents 배열과의 일치, 다른 과거 배열과의 일치, 필요한 전제의 조상 선택, 첫 규칙의 빈 parents가 포함된다. **현재 직접 전제가 틀린 경우에만 잘못된 부모 재사용으로 분류한다.** 부모는 맞고 현재 node ID 중복 때문에 실패한 경우를 stale 부모 오류로 분류하지 않는 반례도 시험했다.

최초 실패·직전까지 유효한 경로의 위험집합·누적 오류를 구분하며, 진단 결과로 응답을 고치지 않는다. 모델 내부 복사 원인을 확정하는 진단도 아니다. 원본 wire 해시와 source ID만 정규화한 감사용 해시는 별도로 기록하고, 실제 요청과 모델 응답 content는 바꾸지 않는다.

## 4. 실행 방법

Run-v091-Auto.ps1 하나에 소스 ZIP이 들어 있다. Downloads에 저장한 뒤 먼저 다음을 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v091-Auto.ps1" -CheckOnly -AllTests
```

자체시험·calibration·prepare가 모두 통과하면 다음으로 실제 실험을 시작한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v091-Auto.ps1"
```

기준선은 `v090_freshid_20260916_145527_520790_evidence.zip` 원본이다. 자동화가 v090/results_llm 또는 Downloads에서 SHA-256으로 찾는다. 필요한 경우 -Baseline으로 해당 원본의 경로를 지정한다.

설치 위치는 llm_experiments/v091/probe, 실행명은 v091_structural_<timestamp>다. 기존 소스·manifest·guard·로그·evidence를 삭제하지 않는다. CheckOnly의 실행명은 plan과 log를 보존하므로 실제 실행에서 재사용하지 않는다.

**목표 경로가 선택됐을 때 10,560회로, v090의 세 배 규모다.** 최대 추론은 10,944회, metadata를 포함한 최대 action은 10,976개다. 실제 호출 수는 선택된 경로에 따라 달라지며, 같은 unit의 선택 원응답은 네 군이 공유한다.

Ollama 0.34.1과 동일 qwen3:4b-instruct digest를 유지한다. CheckOnly는 Ollama를 조회하지 않고, 실제 배치도 서버 시작·모델 다운로드·갱신·자동 재시도를 하지 않는다. 완료 후 v091_structural_<timestamp>_evidence.zip과 _independent.json을 분석한다. 중단되면 로그와 guard를 보존하고 새 이름으로 우회하지 않는다.

## 5. 배포 자료와 남겨둔 질문

v091_사전실험계획.md는 세부 동결 계약이고, VALIDATION_RESULT_v091.json은 실제 검증 영수증이다. validation/에는 고유 시험 ID·원문 로그·설치 영수증·calibration·합성 집계·독립 검산·파일 대조 결과가 들어 있다. 약 222 MiB인 합성 원 evidence와 v090 원 evidence는 중복 배포하지 않으며, 설치 소스의 reproduce_synthetic.py로 합성 실행을 재현할 수 있다.

신규 구조에서 개선이 유지되는지는 실제 실험 후 판단한다. R1은 각 기존 구조당 하나이며, 임의 명명 분포 전체를 검증한 것이 아니다. history 순서 개입, metadata 제거, 부모 자동 복구, 문제별 생성기 선택, 중복 원자 허용, 엔진 대규모 리팩터링은 이번 배치에 섞지 않았다.
