# v088 r2 실험설계·배포 검증 결과

작성일: 2026-09-16 KST  
상태: **r2 배포본 생성 및 오프라인 검증 완료 / 사용자 환경 CheckOnly 대기**

## 1. r2의 목적

v088 r1의 실제 첫 실행 `v088_idcontinuity_20260916_081431_746223`은 첫 metadata action에서 fail-closed 되었고 Qwen inference와 observed response가 모두 0회였다. 따라서 r1에서 연구 표본은 생성되지 않았다.

r2는 새 연구 설계가 아니다. **v088 r1의 연구 조건을 유지하고 Ollama 0.34.1 runtime/API metadata identity만 다시 동결한 runtime revision**이다.

보존한 연구 조건:

- U01~U08 구조
- seed 및 평가 배정
- 평가 A/B/C
- prompt와 JSON schema
- sampling 설정
- 채점·무보정 원칙
- v087 baseline 의존 관계
- 주평가 및 보조평가 정의
- trial/slot/action schedule

## 2. r1 → r2 변경 범위

r1 protocol SHA-256:

```text
7ecd08b6ad79d52a1fec5add10b972b4906f94c11a029d2ee0ae6df62035a422
```

r2 protocol SHA-256:

```text
ab6be8138b470abcad871faa9ef882203cdd3fe513a1c0bae38dce32743883b4
```

`contract` 및 runtime identity를 제외한 protocol 차이:

```text
없음
```

runtime identity 차이는 다음 5개 경로와 정확히 일치한다.

```text
server.version
native.model_info.general.tags
native.model_info.tokenizer.ggml.merges
native.model_info.tokenizer.ggml.tokens
native.model_info.tokenizer.ggml.token_type
```

값 변화:

```text
server.version:                         0.34.0 -> 0.34.1
general.tags:                          null   -> ["text-generation"]
tokenizer.ggml.merges:                 null   -> []
tokenizer.ggml.tokens:                 null   -> []
tokenizer.ggml.token_type:             null   -> []
```

현재 동결 model identity:

```text
model:              qwen3:4b-instruct
digest:             0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0
parameter_size:     4.0B
quantization_level: Q4_K_M
context_length:     262144
Ollama server:      0.34.1
```

모델 digest는 r1과 동일하다. r2 provenance에는 r1의 0-inference 중단과 r2가 runtime identity refreeze라는 점을 명시적으로 기록했다.

## 3. r1 실패 evidence/guard 보존 방식

r2는 r1 실패 실행을 덮어쓰거나 guard를 삭제하지 않는다.

- r1 설치/실행 영역: 기존 `probe`, 기존 r1 guard 보존
- r2 설치 영역: `llm_experiments/v088/probe_r2`
- r2 guard: `results_llm/frozen_batch_r2.started.json`
- r2 기본 RunName: `v088_r2_idcontinuity_<timestamp>`
- 공통 automation lock은 유지하여 동시 v088 workflow 실행을 막는다.

즉 기존 r1의 실패 evidence와 started/frozen 상태는 연구 provenance로 남고, r2는 별도 runtime revision으로 실행된다.

## 7. runtime identity fail-closed 단위검사

실제 모델 호출 없이 metadata fixture로 검사했다.

정상 r2 identity:

```text
identity_ok = true
chat_calls  = 0
```

의도적으로 identity를 깨뜨린 경우:

```text
identity_ok = false
chat_calls  = 0
```

따라서 metadata mismatch가 있으면 모델 inference 전에 중단하는 fail-closed 계약은 유지된다.

## 9. 사용자 환경에서 먼저 실행할 명령

r1 실패 evidence/guard를 삭제하지 않은 상태에서 다음 명령을 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Run-v088-Auto-r2.ps1" -CheckOnly -AllTests
```

이 단계에서는 실제 frozen batch를 시작하지 않아야 한다.

CheckOnly/전체 자체시험과 현재 Ollama 0.34.1 identity 검증이 정상인 경우에만 실제 실행한다.

```powershell

```

## 10. 결론

v088 r2는 **v088 r1의 연구 설계 변경판이 아니라 Ollama 0.34.1 runtime/API metadata identity를 재동결한 별도 runtime revision**으로 생성했다. r1의 0-inference 실패 provenance와 guard는 보존하며, r2는 별도 설치 경로·guard·RunName을 사용한다. 오프라인에서 확인 가능한 범위에서는 연구 schedule과 핵심 연구 로직의 불필요한 변경 없이 배포본이 구성됐고, 다음 단계는 사용자 Windows 환경의 `-CheckOnly -AllTests` 검증이다.
