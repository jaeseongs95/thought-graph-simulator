## 4. A — 고정된 유효 이력의 ID 재명명

같은 직전 유효 proof history의 node ID와 내부 parents 참조를 함께 바꾸고, 다음 규칙 하나를 새로 생성한 평가다. 70개 규칙 위치 × 2 seed = 군당 140개다. 현재 출력의 새 ID는 강제하지 않는다.

|---|---|---|---|

| atom_alias | 140/140 (100.00%) | 0 | 0 |

### 4.1 통제 확인

140개 대응 단위 각각에서 네 군의 history ID를 전단사 정규화한 뒤 비교했다. **네 요청은 모두 같았다.** 즉 문제, 규칙, 의미 구조, seed, 출력 schema 등의 차이가 아니라 제공된 history의 ID 표현 차이를 측정했다. 새 모델 출력에는 이 정규화를 적용하지 않았다.

### 4.2 관찰과 해석

`atom_alias`는 모든 140개 규칙에서 성공했다. ID와 atom 문자열이 같으므로 이 조건은 **의미 단서가 있는 명명 방식**이다. ID–atom을 별도로 연결해야 하는 부담을 없앤 입력 계약이지, 중립적 이름의 단순 단축이 아니다.

나머지 세 군의 총 26개 실패는 모두 `premise_counter_mismatch`다. **A에서는 없는 ID를 부모로 쓰는 실패가 0건**이다. 긴 이름을 읽거나 출력하는 행위 자체를 전반적으로 못 한 결과가 아니다. 실제로 존재하는 ID 중 다른 원자의 ID를 택하거나 직접 전제를 누락했다.

사전 A 대비 short → legacy_long의 140개 짝은 다음과 같다.

| 짝 결과 | 수 |
|---|---:|
| 둘 다 성공 | 127 |
| 둘 다 실패 | 7 |
| short만 성공 | 5 |
| legacy_long만 성공 | 1 |

따라서 long의 순감소는 4/140, −2.86%p다. 이름 계열·접두어·토큰화가 함께 다른 대비이므로 **문자열 길이만의 효과**로 쓰지 않는다.

### 4.3 atom_alias의 성과 범위

A의 140/140은 ‘고정 유효 history에서 다음 규칙 하나’의 결과다. **facts부터 연속 생성한 atom_alias graph나 새 선택을 포함한 전체 D 종단은 이번에 실행하지 않았다.** 국소 성공을 그 종단 성공으로 바꾸지 않는다.

## 5. B — 초기 명명 체계와 연속 참조

B는 과거의 유효 facts 3개를 지원받고 이후 규칙과 final을 새로 생성한다. selector와 facts 생성은 포함하지 않는다. 8개 구조 × 2 seed × shallow/deep = 군당 32개 경로, 16개 양방향 pair다.

mixed는 초기 facts의 과거 ID를 유지하고 새 규칙 노드에 short/long ID를 사용한다. uniform은 초기 facts부터 같은 이름 계열로 바꾼다. 같은 계열의 mixed/uniform은 **모든 새 출력 ID sequence가 동일**하다.

| 군 | 연속 graph 성공 | 양방향 성공 | 새 ID 계약 준수 | 첫 규칙 성공 |

| short_uniform | 19/32 (59.38%) | 6/16 (37.50%) | 140/140 | 32/32 |

새 ID는 schema enum을 포함한 사전 지원 계약으로 지정되어 있다. 140/140 준수는 지원 계약 준수이며, 자율적인 ID 생성 능력으로 해석하지 않는다.

단일 경로에서 long_uniform은 long_mixed 대비 13개 성공을 얻고 2개 기존 성공을 잃어 순증가 11개였다. short_uniform은 11개를 얻고 기존 성공 소실은 없었다.

### 5.2 보조평가와 이름 계열 상호작용

short_uniform − short_mixed의 양방향 차이는 6/16 − 0/16 = **+37.50%p**다. uniform 효과의 계열 간 차이, 즉 `(long_uniform − long_mixed) − (short_uniform − short_mixed)`는 **−12.50%p**다.

두 uniform의 단일 성공률은 19/32로 같지만 같은 19개가 아니다. 둘 다 성공 12개, short만 성공 7개, long만 성공 7개, 둘 다 실패 6개다. 단순 총합이 같다는 이유로 이름 표현의 영향이 사라졌다고 보지 않는다. 이 대조는 같은 응답의 추가 짝분석이지 새 표본이 아니다.

규칙 오류 수는 실패 graph 수와 다르다. 앞 단계가 실패한 뒤의 후속 규칙도 무보정으로 계속 생성하므로 같은 graph에서 여러 오류가 나올 수 있다. 처음 깨지는 단계로 따로 집계하면 long_mixed의 24개 실패는 missing_parent 최초 16개 + 전제 multiset 최초 8개, short_mixed는 18개 + 6개다. uniform은 각 13개 모두 전제 multiset 최초 오류다.

## 6. C — 기존 D 종단 성과와 실패 처치의 동시 대조

C는 공통 two-stage 선택을 새로 실행하고, 두 생성군이 각자 facts부터 graph를 새로 생성한 평가다. B와 다른 평가 단위다.

공통 선택은 **128/128**이다. 비교값 판단, 그 값에 맞는 candidate ID 조회, 최종 선택 방향이 모두 맞았다. 비교 128회 + 조회 128회 = 256회 호출이며 생성군별로 중복 합산하지 않는다.

| 생성군 | 실제 요구 D 종단 | 양방향 D 종단 | 네 표시 전체 성공 |
|---|---|---|---|
| baseline | 112/128 (87.50%) | 49/64 (76.56%) | 10/16 (62.50%) |
| allocated_id | 31/128 (24.22%) | 8/64 (12.50%) | 1/16 (6.25%) |

allocated_id는 baseline 대비 실제 종단 −63.28%p, 양방향 −64.06%p다. 8개 구조 모두 양방향 성공률이 감소했다. 대응하는 128개 경로에서 baseline과 allocated_id가 함께 성공한 것은 31개, baseline만 성공은 81개, 함께 실패는 16개이며 **allocated_id만 성공한 경로는 0개**다.

C에서도 새 지정 ID는 560/560 규칙 응답에서 준수됐다. 그러나 allocated_id의 560개 규칙 중 167개에서 없는 부모를 참조했고, 이 중 151개는 누락된 ID 문자열 전부가 이미 존재하는 원자명과 같았다. 이 오류가 있는 graph는 61/128개다. baseline에서는 missing_parent가 0개였다.

초기 facts와 final의 단순 goal 참조는 두 생성군 모두 각각 128/128이다. 최종 goal 이름이 맞아도 중간 proof가 틀리면 성공으로 세지 않았기 때문에 allocated_id의 전체 성공은 31/128에 머문다.

| allocated_id | 32/128 | 31/128 | 11/64 | 8/64 |

기존 baseline의 양방향 49/64 및 네 표시 전체 10/16이 다시 관측됐다. 실패했던 allocated ID 보강의 큰 악화 방향도 동시 C 대조에서 재현됐다. baseline 생성기는 유지하고 allocated_id를 기본안으로 승격하지 않는 기존 판단이 유지된다.

v087과 v088 사이에는 Ollama runtime 0.34.0 → 0.34.1 전환이 있었다. 따라서 두 시점의 1개 경로 또는 3개 pair 차이를 특정 runtime 영향으로 돌리지는 않는다. 주요 판단 근거는 **같은 v088 배치 안의 C 대조**다.

## 7. 이번 결과가 연구에 추가하는 것

**첫째, D 선택과 graph 생성의 병목 분리가 유지됐다.** 선택은 128/128인데 생성군에 따라 종단이 112/128과 31/128로 벌어진다. 선택 실패로 생성 실패를 설명할 수 없다.

**둘째, ID를 정확히 부여하는 것과 나중에 그 ID를 부모로 다시 사용하는 것이 다르다는 v087 관찰에 개입 증거가 추가됐다.** 같은 새 출력 ID sequence를 유지하면서 초기 facts의 명명만 바꾸자 없는 ID 참조가 이번 uniform에서 사라지고 연속 성공이 증가했다.

**셋째, 참조 안정화 후에도 직접 전제 선택·누락 문제가 독립적으로 남았다.** uniform에서 13/32씩 실패했고, 이들의 최초 오류는 모두 전제 multiset이었다. `missing_parent=0`을 의미적 생성 전체 해결로 쓰지 않는다.

**넷째, ID와 atom의 의미적 정렬은 국소 진단에서 유효한 다음 실험 후보를 제공했다.** A atom_alias 140/140이 근거다. 그 성과를 새 선택·새 facts·연속 생성 전체로 확장해 확인하는 것이 다음 측정 공백이다.

현재 직접 측정하는 것은 여전히 외부 proof DAG의 D_DAG다. 이번 결과는 A/D/M 전체나 모델 내부 hidden-state 제어의 새로운 측정 결과가 아니다.

## 8. 후속 실험 판단

운영상 기본 생성기는 기존 baseline을 유지한다. B uniform은 mixed보다 개선됐지만 지원받은 연속 생성 19/32이고, C baseline과 시작 조건·분모가 달라 직접 우열 비교나 기본 생성기 교체의 근거가 아니다.

가장 직접적인 후속 질문은 **‘A의 atom_alias 장점이 초기 facts부터 최종 graph까지 이어지는가’**다. 새 node를 만들 때부터 그 이름을 사용하도록 사전 계약을 동결하고, 기존 baseline 및 중립 ID 체계와 구분하여 평가할 수 있다. 원자–ID 일치가 의미적 지원이라는 사실을 유지해야 하며, 응답 후 ID를 바꾸거나 부모를 자동 복구하면 안 된다. 같은 실패에 맞춰 프롬프트를 계속 손보는 대신, 후속 절차를 동결하고 신규 구조에서 별도로 재현 여부를 확인하는 순서가 적절하다.

이 문서는 결과 분석이다. 새로운 v089 설계·소스나 실제 추가 inference는 생성·실행하지 않았다.
