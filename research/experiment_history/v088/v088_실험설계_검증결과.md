**이번에는 실패한 ID 지원을 기본 생성기에 채택하지 않는다.** 기존 두 단계 선택기와 생성기를 보존하고, 이름 표현을 바꾸는 진단·명명 체계를 유지하며 진행하는 연속 생성·기존 D 종단 대조를 분리한다. 새 노드 표, 부모 정답 enum, 자동 부모 복구를 추가하지 않는다.

U01~U08은 이미 관측한 진단 집합 8개다. 이번 새 holdout은 0개다. 처치·평가·순서를 모델 응답을 보기 전에 고정했다. 상세 사전등록 원문은 소스의 `docs/PREREGISTRATION.ko.md`다.

## 2. 세 평가와 배정

| 평가 | 배정 | 측정 범위 |
|---|---:|---|
| A. 같은 유효 prefix의 ID 재명명 | 70규칙 × 2 seed × 4군 = **560호출** | 다음 한 규칙의 의미 정확도 |
| B. 초기 명명 범위 × 새 ID 계열 | 16경로 × 2 seed × 4군 = **128개 continuation**, 688호출 | 주어진 과거 유효 사실부터 모든 새 규칙·final까지 |
| C. 기존 파이프라인 동시 대조 | 공통 비교·조회 256호출 + 2군의 **256개 새 graph** | 새 선택·새 facts를 포함한 실제 D 종단 |

모든 선택이 목표 경로이면 **3,136회 추론**, 사전 최대 **3,200회**, metadata를 포함한 전체 action **3,232개**다. 선택 경로 길이에 따른 여분 슬롯 제외는 미실행 실패가 아니다. A/B/C 시행은 총 944개지만, 서로 다른 평가를 합쳐 944개 독립 문제 또는 전체 종단으로 세지 않는다.

### A. 같은 이력에서 ID만 바꾸는 대조

| 군 | 선행 이력 ID |
|---|---|
| `observed` | 기존 ID |
| `atom_alias` | 해당 노드의 atom과 같은 ID |
| `short` | `n0001`, `n0002`, … |
| `legacy_long` | `v087_node_0001`, `v087_node_0002`, … |

70개 규칙 위치는 v087 baseline의 **대상 규칙 직전까지 유효한 prefix** 중 사전식 순서가 가장 이른 요청을 선정한다. 대상 규칙 응답, 이후 응답, 최종 graph의 성공을 읽지 않는다. 원요청·원래 slot/trial·해시·유효 후보 수·선정 정책을 고정 보존한다.

ID를 변경할 때는 모든 `node.id`와 내부 `parents` 참조를 같은 전단사 대응으로 치환한다. atom·rule·규칙 전제·후보 ID는 바꾸지 않는다. **observed를 포함한 네 군 모두 같은 serializer로 이력 JSON을 다시 직렬화**하여, 공백 정규화가 이름 변경과 섞이지 않게 했다. 현재 새 노드 ID에는 별도의 할당 제약을 주지 않는다. header, schema와 기타 입력도 같다.

이 변환은 유효한 과거 이력에서 새 진단 입력을 만드는 사전 처치다. 기존 실패 응답을 고쳐 성공으로 소급 분류하는 작업이 아니다. 변환은 역변환 가능성과 의미 보존을 검사하며, 원본 bytes는 보존한다.

`atom_alias`는 의미와 이름이 결합된 조건이지 중립적인 ID 길이 조건이 아니다. `short`와 `legacy_long`도 접두사·길이·문자 구성이 함께 달라지므로 이름 계열의 효과로 해석한다.

### B. 새 ID가 누적되는 연속 생성 — 주평가

| 군 | 과거 초기 사실 ID | 이후 새 규칙 ID |
|---|---|---|
| `short_mixed` | 관측된 이름 유지 | 짧은 n 계열 |
| `short_uniform` | 짧은 n 계열로 통일 | 짧은 n 계열 |
| `long_mixed` | 관측된 이름 유지 | v087_node 계열 |
| `long_uniform` | v087_node 계열로 통일 | v087_node 계열 |

같은 경로의 과거 유효 **초기 사실만** 출발점으로 사용하며, 모든 규칙과 final은 새로 생성한다. 이전 전체 성공 graph를 제공하지 않는다. 과거 사실과 경로가 주어져 있으므로 이 결과를 신규 선택·facts 생성까지 포함한 종단 성공으로 표현하지 않는다.

같은 이름 계열의 mixed/uniform에 **동일한 새 rule ID 순서**를 배정한다. 원래 사실 이름과 통일한 사실 이름의 합집합을 피하고 사실 개수 이후 번호부터 예약한다. 따라서 초기 명명 범위를 비교할 때 새 ID의 번호가 달라지는 문제가 없다.

배정된 ID는 현재 `node.id`만 제한하며, atom·rule·parents의 정답은 주지 않는다. 초기 사실을 변환한 뒤 **모든 새 모델 응답은 공백·오류까지 그대로 후속 이력으로 전달**한다. 생성한 이름을 다시 바꾸거나, 원자를 올바른 ID로 바꾸거나, 잘못된 부모를 교체하지 않는다. 이로써 새 이름을 만드는 한 단계뿐 아니라 그 이름을 다음 규칙에서 실제로 참조하는 과정까지 측정한다.

관측된 사실 ID가 이미 n 계열이면 short 조건의 mixed/uniform 차이가 작을 수 있다. 실제 변환표와 바뀐 ID 수를 기록하므로 각 조건의 차이를 없는 것으로 가정하거나 과장하지 않는다.

**사전 주평가:** 같은 구조·seed에서 shallow/deep continuation이 모두 성공했는지 판정하고, `long_uniform − long_mixed`의 성공률 차이를 8개 구조에 동일 가중치로 평균한다. 군당 16쌍, 구조별 2쌍이다. 이는 continuation의 양방향 성공이며 C의 새 D 제어 종단과 구분한다.

보조 대비는 짧은 계열의 통일 효과, 각 명명 범위에서의 계열 차이, 두 차이의 상호작용이다. 구조별 개선·악화·동일·미관측도 보고한다. 불완전한 배치의 전체 주효과는 계산하지 않는다. B가 좋아져도 기본 생성기를 바로 바꾸지 않고, 향후 새 facts부터 시작하는 종단 대조가 필요하다.

### C. 실제 D 종단 기준선과 기존 부정 처치의 재확인

`baseline`과 v087의 기존 `allocated_id`를 같은 배치에서 비교한다. 각 128개 graph, 양방향 64쌍, 네 표시 전체 16묶음이다. 공통 두 단계 선택은 128조건에서 새로 실행한 비교·조회 256호출이며 두 군이 동일 원문을 공유한다.

각 군은 facts부터 새 graph를 생성한다. 첫 facts 요청은 같지만 실제 응답·후속 이력은 달라질 수 있다. ID군은 현재 실패한 처치의 동시 대조이지 채택된 새 기본 생성기가 아니다. 과거 v087의 49/64를 이번 대조군의 성공률로 대신하지 않는다.

## 3. 채점·진단·보존

graph의 실제 부모 원자 multiset, rule, 중복 ID, 방출 순서, 순환, 최종 goal ancestry를 검사한다. 초기 사실은 depth 0, 결과 depth는 `1 + max(부모 depth)`로 재계산한다. 호출 수·모델의 D 자기보고·출력 길이를 D로 사용하지 않는다.

다음은 서로 다른 필드로 보고한다.

- 실제 graph 또는 규칙의 의미 유효성.
- 새 ID 등 사전 지원 계약 준수.
- A의 규칙 진단, B의 continuation 성공, C의 엄격 종단 성공.
- C의 비교·조회 오류 뒤 우연한 목표 도달과 실제 전체 성공.

`diagnostics.json`과 한국어 보고서에는 변환된 prefix 인증, B의 초기 사실 ID 변경 수·같은 계열의 동일 미래 ID, 할당 ID가 포함된 이력, 첫 규칙/이후 규칙, 실패 코드, 존재하지 않는 부모가 원자 이름과 같은지, 고유 요청 수와 사용량이 들어간다. 원자-부모 문자열의 유형을 분류할 뿐 자동 변환해 채점하지 않는다.

원문 요청·응답, plan·source snapshot, event chain, dispatch와 보존 응답, 중단 상태, 조건부 skip을 증거에 보존한다. 논리 오류와 미실행·HTTP·identity·JSON/schema·길이 종료를 분리한다. 오류 후 재시도하거나 새 RunName으로 이미 시작된 배치를 우회하지 않는다.

새 배정·변환·요청 재구성과 의미 판정은 생산/독립 경로에서 별도 구현했다. 표 집계와 보조 바이트 진단은 공유하므로 알려진 정오·효과 방향·미관측·변조를 별도 반례로 시험한다. `verified`는 번들 내부 일관성 검산이며 외부 실행 사실 인증이 아니다.

전체 합성 검증은 설치한 `probe`에서 다음으로 재현한다. `--out`은 존재하지 않는 새 폴더여야 한다.

```text
python -X utf8 -B reproduce_synthetic.py --baseline <원본 v087 evidence.zip> --out <새 검증 폴더>
```

소스의 `selftest088.py`가 모든 회귀/반례 시험을, `calibrate088.py`가 1,504개 기대 판정 대조를 제공한다. 로그 속 개발 환경 절대 경로는 실제 수행 기록이지 사용자 환경에 요구하는 경로가 아니다.
