# v0.1 실험결과 분석보고서 복원본

> 상태: **복원본**
>
> 독립 분석보고서 파일 자체는 현재 ChatGPT Library에서 확인되지 않았다.
> 당시 보존된 대화 원문과 v0.2 상세 분석에서 확인되는 실제 실행 수치만 정리했다.

## 1. 결론

v0.1의 핵심 실패는 A/D/M 축 자체의 실패를 판정하기 전에,
**공통 출력 계약과 node reference를 안정적으로 구성하지 못한 것**이었다.

`smoke_01` 6건과 `pilot_01` 39건, 총 45건의 저장 응답은 이후 재검사에서
기존 상태와 최초 오류가 45/45 재현됐다.

## 3. 가장 큰 인터페이스 문제

모델은 다음처럼 명제와 node ID를 구분하지 못했다.

```json
{"id": "step2", "atom": "g"}
```

를 만든 뒤 최종 참조를

```json
"final": "g"
```

처럼 기록했다.

`g`는 목표 명제이고 `step2`가 실제 node ID다.
검증기가 이를 거부한 것은 계약상 타당했다.

pilot 39건 중 34건은 `final`에 목표 명제 `g`를 넣었고,
나머지 5건은 문제 ID인 `chain_2` 또는 `chain_3`를 넣었다.

## 4. 그렇다고 모든 추론이 실패한 것은 아님

28/39에서 개별 규칙 적용 자체는 맞았다.
따라서 이 결과는 “모델이 논리 규칙을 전혀 수행하지 못했다”가 아니라,
**유효한 비교를 하기 전에 graph reference·제출 범위·도식·검토가 섞인 통합 계약에서 무너졌다**고 읽어야 한다.

## 5. 이후 수정 방향

v0.2에서는 다음을 수정했다.

- `id`, `atom`, `rule`, `final` 역할을 더 명확히 분리
- node reference 명칭을 구체화
- 동적 schema binding 구조를 고정 필드 배열로 변경
- 통합 과제 전에 구성요소별 calibration 추가
- 최초 오류 하나만이 아니라 확인 가능한 오류를 함께 기록

이 단계에서 고정 목표·A/D/M 연구 방향 자체는 폐기하지 않았다.
