>
> v0.4.0의 상세 분석은 보존 대화와 이후 v0.4.1/v041 forensic 문서의 근거가 되었지만,

> 아래는 당시 보존된 수치와 원인 경계만 정리한 것이다.

## 1. 결론

v0.4.0은 이전 버전의 모델/모드 confound를 제거하기 위해
`qwen3:4b-instruct` / Instruct-2507 기준선을 사용했다.

그럼에도 통합 smoke/pilot은 전부 실패했다.
이번 실패는 JSON 형식이나 통신이 아니라
**규칙이 요구하는 premise를 실제 올바른 parent node에 연결하는 의미 binding 오류**가 중심이었다.

## 4. 대표 오류: 분기·합류를 직렬 chain으로 변형

문제 일부가 다음 구조일 때:

```text
Ea → Eb
Eb → Ec
Eb → Ed
Ec AND Ed → Ee
```

모델은 다음처럼 연결했다.

```text
Ea → Eb → Ec → Ed → Ee
```

즉 `Ed`에 필요한 parent는 `Eb`인데 `Ec`를 연결했고,
`Ee`에는 `Ec`와 `Ed`가 모두 필요하지만 `Ed`만 연결했다.

이는 출력 형식은 맞더라도 실제 proof 의미는 틀린 경우다.

## 5. core verifier 오판정 여부

당시 `adm_minimal.py`가 정상 proof를 잘못 거부하는지 별도 알고리즘과 반례로 교차검사했다.

검사에는:

- 수동 유효/변이 기록
- 작은 Horn 문제 120개
- 그 문제의 A/D/M 조합 1,440개
- parent 삭제 변이 3,366개
- JSON 경계 입력 671개

등이 포함됐고,
현재 v0.4.0 실패를 설명할 verifier 오판정은 발견되지 않았다.

따라서 당시 결론은 `adm_minimal.py`의 기준을 느슨하게 하는 것이 아니라
모델 출력의 실제 premise↔parent 오류를 그대로 실패로 보존하는 것이었다.

## 6. 별도의 harness 결함

`local_llm`의 `all_schema` 진단에는 실제 false-positive 결함이 있었다.

기존 구현은 최종 노드의 A 값만 보고 전체 node가 schema인지 판정할 수 있었다.
따라서 앞 노드가 instance인데 최종 노드만 schema여도 잘못 PASS할 수 있었다.

이 버그는 수정 대상이었지만,
**현재 0/39 실패를 만든 원인은 아니었다.**
즉 실패 원인과 별개의 평가기 결함을 구분했다.

## 7. v041로 이어진 이유

v0.4.0에서 premise↔parent 의미 연결 문제가 명확해지자
다음 단계는 같은 69조건을 반복하는 대신 원인 분리용 소규모 probe로 이동했다.

이 흐름이 v0.4.1 소스와 `v041_probe_01`로 이어졌고,
v041부터는 prompt, schema, criterion, 입력 민감도 등을 더 작은 단위로 분리하기 시작했다.
